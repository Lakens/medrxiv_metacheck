Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

How Ethics Approval Check works

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How StatCheck works

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Non-Significant P Value Check works

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). Embedded haven labels from data files are also harvested directly.

Each data column is then matched against the parsed variable definitions with match_column_labels(), using normalised-name matching with experiment-group scoping, haven-label priority, and rule-based label-equivalence merging.

Beyond the variable label, the module harvests the DDI-style per-variable properties a source supplies: the value labels / code list (the 1=“Strongly disagree”…5=“Strongly agree” mapping — from SPSS/Stata value labels and from a codebook “values”/“coding” column), the missing-value scheme (which codes denote missingness, from haven declared missings and labels that read as “refused”/“n/a”), and question text and columns when present. These are carried onto the matched data columns and exported into the Psych-DS variableMeasured (as a schema.org code list plus namespaced metacheck: fields).

The module defaults to rules-only when llm_use(FALSE). When llm_use(TRUE), three optional LLM tiers run: parsing unstructured codebook text that the rules could not handle, fuzzy-matching still-unlabelled columns to still-unmatched codebook variables, and merging conflicting label definitions into a single canonical label.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. The present analysis includes the complete cohort of 50 participants (22 experimental, 28 control).

The last visit of the last participant occurred on January 2025, and the final database lock was completed on February 2025. Where the two reports overlap (basal inspiratory expansion, FVC and FEV1 up to 30 days), the estimates presented here supersede those of [18]; they differ because the sample is larger and because a different statistical model was used (linear mixedeffects models in the present study instead of the repeated-measures ANOVA used in [18].

The study was approved by the Research Ethics Committee of the University of Seville, Spain (ref. 1032-N-23) and was conducted in accordance with the Declaration of Helsinki. All participants provided written informed consent before enrolment. The trial protocol approved by the ethics committee is provided as S1 Protocol, and the completed CONSORT 2025 checklist as S1 CONSORT Checklist. A related cross-sectional analysis of the baseline data of this cohort has been published separately [22]. The protocol approved by the ethics committee (S1 Protocol) differs from the conduct and analysis of the trial in the following respects. (1)

The protocol did not designate a primary outcome. (2) The protocol planned repeated-measures analysis of variance; linear mixed-effects models with false discovery rate correction were used instead to model all six assessments with a participant-level random effect, and the moderator and sensitivity analyses were not prespecified. (4) Handling of missing data and adverse-event monitoring were not specified in the protocol.

2.2. Participants, randomization and blinding

Recruitment took place at a private physiotherapy clinic in Chiclana de la Frontera (Cádiz, Spain) between December 2023 and September 2024 [18]. The source population consisted of patients referred through a private health insurance network; we ensured that no participant had an open compensation claim or active litigation related to their back pain. Eligible participants were adults aged 18 years or older with a specialist diagnosis of subacute or chronic NSLBP (ICD-10 M54.5)-defined as symptoms lasting between 4 and 12 weeks for subacute, or more than 12 weeks for chronic-and diaphragm dysfunction (≥2 of: apical breathing pattern, accessory muscle overactivity at rest, breath-holding time <15 s, and restricted costal mobility) [23] [24] [25]. Exclusion criteria were specific structural spinal pathology, recent spinal or . thoracoabdominal surgery, systemic or neurological conditions affecting the lumbar spine or diaphragm, pre-existing primary respiratory diseases (such as asthma or COPD), and previous diaphragmatic manual treatment, among others listed in [18].

Of 64 people assessed for eligibility, 9 were excluded because they could not attend ten consecutive sessions, and 55 were randomized (27 to the experimental group, 28 to the control group). Five participants allocated to the experimental group withdrew after randomization and before the baseline assessment (work commitments, n=1; travel, n=1; declined participation, n=3) and contributed no data. One control participant discontinued after session 1, and the last observed values were carried forward (LOCF) for all later assessments. Fifty participants ( 22experimental, 28 control) were analyzed, 49 of them with observed data at all six assessments (Fig 1). There was no patient or public involvement in the design, conduct or reporting of the trial.

Regarding trial methodology details previously reported [18], the sample size was calculated to ensure 90% power to detect a clinically meaningful difference in the primary outcome. An independent researcher generated the simple randomization sequence using computergenerated random numbers. Allocation was concealed using sequentially numbered, opaque, sealed envelopes, and only the unblinded treating physiotherapist had access to the sequence.

Crucially, all baseline assessments were conducted strictly after randomization. Both the outcome assessor and the data analyst were blinded to group allocation; this blinding was maintained by explicitly instructing participants not to disclose their treatment and by masking group identifiers in the final database. after session 1 was retained in the analysis using last observation carried forward for subsequent assessments; therefore, the number analysed equals the number allocated in that group.

2.3. Intervention

Both groups received standard physiotherapy consisting of tetrapolar transcutaneous electrical nerve stimulation, infrared lamp therapy, therapeutic ultrasound over the quadratus lumborum, and ischemic compression with analytical stretching of the quadratus lumborum, multifidus and iliocostalis muscles, delivered across ten daily sessions, as previously described [18]. At the end of six sessions (1, 3, 5, 6, 8 and 10), the experimental group also received manual diaphragmatic stretching technique. Supported by established manual therapy frameworks [26] [27] [28]: the therapist placed the ulnar borders of both hands on the lower costal margin (approximately ribs 8 to 10) with the patient supine and a cushion under the knees. The therapist applied bilateral cephalad traction at the beginning of deep inspiration, maintained it at peak inspiration and throughout expiration, and kept verbal contact with the patient for ten breathing cycles (about 3 to 5 minutes). A brief guide to diaphragmatic breathing was provided strictly on an-as-needed basis to those specific participants who had difficulty initiating deep breaths on demand; it was not routinely administered to the entire cohort. All treatments were delivered by one physiotherapist, with a minimum of 15 years of clinical experience. To ensure intervention fidelity and consistency, the therapist completed a 50-hour standardization workshop prior to the trial, and the exact same personnel treated participants in both the experimental and control groups. The remaining four sessions of the experimental group and all ten control sessions comprised standard physiotherapy only. While no home exercise program or other care was prescribed during the trial or the 120-day follow-up, participants were systematically asked about the use of any non-prescribed co-interventions (e.g., analgesic use or independent exercise routines) at each assessment, and these were prospectively . recorded. A treatment manual and completed TIDieR checklist [29] are available as S1 Appendix.

2.4. Outcome measures

All outcomes were assessed at baseline, immediately after the first and tenth sessions, and 7, 30 and 120 days after the last session. All measurements across all time points were performed by a single blinded assessor who had completed a specific 20-hour standardization training program prior to the trial.

Thoracic wall expansion was measured by cirtometry with a non-elastic tape at three standardised anatomical levels -axillary, xiphoid, and basal -with the patient standing, performing maximal inspiration and maximal expiration. The amplitude coefficient at each level was calculated as previously described [18, 30], and, unlike the primary report (which considered only inspiratory expansion at the basal level), both the inspiratory and expiratory phases at all three levels are analyzed here. Spirometric parameters (FVC, FEV1, PEF, FEF25%, FEF75% and FEF25-75%) were obtained with a portable spirometer (CONTEC SP10W, Contec Medical Systems, Qinhuangdao, China) using the protocol described in the interim report [18]. Device calibration was checked before each testing session following American Thoracic Society recommendations. With the participant seated, each manoeuvre consisted of a maximal inspiration followed by a forced expiration lasting at least 1.5 s; at least two manoeuvres were performed, separated by one-minute rest intervals, and the mean of the two manoeuvres was recorded [31]. FVC values in this study therefore represent the volume exhaled during a short forced manoeuvre on a portable device, which depends on participant effort and technique. Only FVC and FEV1 were reported in the interim publication [18].

Adverse events were monitored by the treating physiotherapist and the outcome assessor at every session and assessment. In the interim report, mild transient muscular discomfort and fatigue were reported by one participant in the experimental group and two in the control group, all resolving without intervention [18]. No further adverse events were recorded through the 120-day follow-up.

2.5. Statistical analysis

Continuous variables are described as mean (standard deviation); values by group and time point are given in S1 Table. Between-group differences over time for each outcome were modeled using linear mixed-effects models with group, time and the group × time interaction as fixed effects and a random intercept per participant, fit by restricted maximum likelihood.

All 50 analysed participants were included in every model (modified intention-to-treat; see 2.2 for the single LOCF imputation). Estimated between-group differences with 95% confidence intervals are reported at each post-baseline time point; the estimates for basal inspiratory expansion, FVC and FEV1 up to 30 days are re-estimated here, in the complete cohort, for context alongside the new 120-day time point (see 2.1). Given the acknowledged measurement variability and debated clinical interpretability of FEF25%, FEF75% and FEF25-75% [13], these three indices were treated as exploratory. Within each outcome family (thoracic expansion, six variables; spirometry, six variables), p-values across all post-baseline time points were corrected for multiple comparisons using the Benjamini-Hochberg false discovery rate procedure [32]; both uncorrected and FDR-corrected p-values are reported, and statistical significance was defined as FDR-corrected p<0.05. To assess the robustness of the 120-day estimates, we performed two sensitivity analyses. First, the 120-day value of each outcome was compared between groups using analysis of covariance with the baseline value as covariate.

Exact uncorrected and FDR-corrected p-values for all comparisons are given in S2 Table, and full regression results of the moderator analysis in S3 Table. Analyses were performed with R version 4.6.2 with package lme4. A two-sided alpha of 0.05 was used.

2.6. Moderator analysis

As an exploratory secondary aim, we tested whether a participant's baseline value on each outcome moderated the magnitude of their 120-day change. For each of the 12 outcomes, change from baseline to 120 days was regressed on group, mean-centered baseline value, and their interaction; the group × baseline interaction term tests whether baseline severity differentially predicts the treatment effect (moderation), as distinct from simple within-group regression to the mean [33]. This analysis was limited to the outcome's own baseline value, since demographic and clinical covariates beyond age, sex, height, weight and BMI (Table 1) were not available for this analysis; a fuller moderator analysis incorporating symptom chronicity, if available, would be a natural extension.

Interaction p-values across the 12 outcomes were FDR-corrected.

4. Discussion

In the complete DIAFRAGMA cohort, the between-group differences in inspiratory thoracic expansion, FVC and FEV1 previously reported to 30 days in an interim analysis [18] were maintained at 120 days. The differences arose during the ten-session treatment period and remained stable thereafter, while values in the control group declined slightly over the same period. The same pattern extended to the axillary and xiphoid expansion levels and to peak expiratory flow, none of which had previously been reported for this trial. Maintenance of the difference contrasts with the broader manual therapy literature for chronic low back pain, 357 where treatment effects more typically diminish over time [19]; whether this reflects a feature of diaphragm-targeted techniques or of the respiratory and mechanical outcomes examined here, rather than pain-based outcomes, cannot be determined from a single trial. A lasting change in the mechanical or fascial properties of the diaphragm and chest wall has been proposed for these techniques [6, 7].

. The magnitude of the spirometric differences requires cautious interpretation. A mean FVC increase of 1.23 L (about 33% of baseline) in adults without respiratory disease is far larger than the 100-200 mL changes usually considered clinically important [18] and the control group also showed a decline in FVC of about 0.3 L over four months. Some features of the trial may have contributed. First, participants were not blinded, and those in the experimental group received additional hands-on contact and, when needed, guidance on diaphragmatic breathing, which may have improved their performance of the manoeuvre (a learning effect), while control participants may have become less motivated over repeated testing. Second, a single assessor performed all measurements. For these reasons, the spirometric findings should be read as changes in the volume exhaled during a short forced manoeuvre on a portable device, and they need confirmation with laboratory spirometry in a sham-controlled trial.

The picture was materially different for expiratory-phase mobility, which showed no benefit and, at the xiphoid and basal levels, numerically favored the control group from day 7 onward.

This asymmetry between inspiratory and expiratory phases is consistent with the diaphragm's primary biomechanical role in inspiration, and mirrors the interim report's own observation that expiratory expansion did not change at the basal level [18]; the present results extend that observation to all three levels and to a much longer follow-up, and additionally suggest the difference may not be a null finding so much as a genuine divergence between phases that merits its own mechanistic explanation, which the present data cannot provide. Similarly, the null or fragile findings for FEF25%, FEF75% and FEF25-75% should not be read as evidence against the intervention: these indices carry substantial between-subject measurement variability, and their incremental clinical value beyond FEV1 has been directly questioned in the pulmonary function literature [20]. FEF25% additionally showed a nominal baseline imbalance between groups, further limiting confidence in any isolated significant finding for that index.

. The exploratory moderator analysis found no baseline patient characteristic that robustly predicted a larger or smaller 120-day response. This null result should be interpreted cautiously rather than as evidence of true non-moderation: interaction effects generally require substantially larger samples than main effects to detect reliably, and with 50 participants this analysis was likely underpowered for anything but a large moderation effect. It was also limited to each outcome's own baseline severity, since symptom chronicity and other clinical covariates were not available for this analysis; these remain plausible candidate moderators for future, adequately powered work.

From a clinical standpoint, these findings suggest that patients and clinicians should not expect the respiratory and chest-wall-mobility benefits of this technique to fade after treatment ends: on this evidence, the opposite pattern was observed. This has practical implications for how the technique is positioned within a physiotherapy plan of care -as an intervention whose value may become more, not less, apparent at longer-term review -while the corresponding absence of benefit for expiratory-phase mobility indicates that clinicians should not extrapolate this durability to every dimension of respiratory function.

This study has several limitations. First, the diaphragmatic technique was delivered on a fixed schedule (sessions 1, 3, 5, 6, 8 and 10) interspersed with conventional-physiotherapy-only sessions in the experimental group; the present analysis cannot isolate the contribution of any single session, and does not attempt to. Second, no home exercise programme or maintenance strategy was prescribed between the end of treatment and the 120-day assessment, and unmonitored self-directed activity during this period could contribute to the observed durability. Third, all participants were recruited from a single private clinic, which may limit the generalizability of these findings to other clinical settings or populations. Fourth, the moderator analysis, as noted above, was likely underpowered and restricted to baseline severity.

Fifth, participants could not be blinded to group allocation given the hands-on nature of the intervention, and no sham diaphragmatic technique was used as a comparator; expectation effects cannot be ruled out, and confirmation in a shamcontrolled design is warranted.

5. Conclusions

Adding manual diaphragmatic stretching to conventional physiotherapy for non-specific low back pain was associated with greater inspiratory thoracic expansion, and with higher FVC, FEV1 and peak expiratory flow measured with a portable spirometer, than conventional physiotherapy alone. These differences arose during the treatment period and were maintained 120 days after treatment ended. Expiratory-phase chest wall mobility and mid-tolate expiratory flows did not benefit. The size of the spirometric differences, the lack of participant blinding and of a sham comparator, mean that these findings need confirmation in sham-controlled trials using laboratory spirometry. No baseline characteristic moderated the long-term response, although this exploratory analysis was likely underpowered.
