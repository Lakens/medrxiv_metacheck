This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. 4.2 SegmentaLon performance and influencing factors

UnLl recently, most work on intracranial artery segmentaLon has focused on imaging modaliLes with higher spaLal resoluLon and signal quality, such as TOF-MRA, CTA, and DSA (Kim et al., 2025; Min et al., 2025; Su et al., 2024). In contrast, 4D Flow MRI typically has lower spaLal resoluLon, and its relaLvely long acquisiLon Lme increases the risk of moLon arLfacts, further degrading image quality. Consequently, segmentaLon research in 4D Flow MRI has concentrated on large vessels such as the aorta and pulmonary arteries, where parLal-volume effects are less severe relaLve to lumen size. Several deep learning approaches have been developed in that se}ng, including the DenseNet U-Net, which was originally designed for aorLc segmentaLon (Aviles et al., 2021; Berhane et al., 2020; Manokaran et al., 2023). Winter et al. later applied DenseNet U-Net to intracranial vessel segmentaLon and achieved a DS around 0.85 for the CoW when trained on over 100 4D Flow MRI scans (Winter et al., 2024). However, because the trained model weights were not publicly available, we trained the DenseNet U-Net from scratch on our own 4D Flow MRI data. While training the same architecture from scratch on our limited 7T cohort (11 paLents) did not achieve comparable performance, the fine-tuned nnU-Net achieved a DS around 0.86 using the same cohort for fine-tuning. AddiLonally, extending DenseNet U-Net training from 100 to 300 epochs as in Winter et al. did not consistently improve segmentaLon performance (supplementary table 8) (Winter et al., 2024). In contrast, the pretrained U-Net baseline was applied as a direct-transfer model from TOF-MRA to 4D Flow MRI without domain-specific finetuning. Therefore, the performance difference between U-Net and the fine-tuned nnU-Net may be largely influenced by the lack of domain adaptaLon in addiLon to differences in the model framework.

The nnU-Net ablaLon experiments further clarified the role of TOF-MRA pre-training and 4D Flow MRI fine-tuning. Although both modaliLes are flow-sensiLve, TOF-MRA primarily relies on inflowrelated enhancement, whereas 4D Flow MRI-derived PCMRA combines magnitude and velocity informaLon, potenLally highlighLng addiLonal vascular structures, including veins and extracranial vessels. Furthermore, TOF-MRA retains some anatomical background informaLon from staLonary brain Lssue despite RF saturaLon, while PCMRA largely suppresses staLonary Lssue signals, resulLng in less visible anatomical background structures. These differences in both vascular appearance and surrounding Lssue contrast may affect the transferability of learned features between the two modaliLes. Indeed, visual inspecLon of the direct-transfer nnU-Net predicLons suggested that some segmentaLon errors arose from false-posiLve predicLons of non-target vascular structures rather than inaccurate delineaLon of intracranial arteries alone.

These observaLons may partly explain why TOF-MRA pre-training alone was insufficient for direct applicaLon to 4D Flow MRI and why domain-specific fine-tuning improved segmentaLon performance. With all 11 training cases, the from-scratch nnU-Net achieved slightly bexer mean Dice and HD95 on the low-resoluLon test set, whereas the fine-tuned nnU-Net performed bexer on the high-resoluLon test set. Since fine-tuning was performed exclusively on low-resoluLon 4D Flow MRI, this suggests that TOF-MRA pre-training may have improved generalizaLon to acquisiLon se}ngs not represented in the fine-tuning data. However, this benefit cannot be axributed to spaLal resoluLon alone, as the low-and high-resoluLon datasets also differed in VENC and other acquisiLon parameters. The fine-tuned nnU-Net also showed more stable performance on the high-resoluLon test set when fewer training cases were available. In addiLon, extending from-scratch training from 200 to 1000 epochs did not consistently improve performance, parLcularly on the high-resoluLon test set, suggesLng that longer training alone may not improve robustness in limited-data se}ngs. Together, these findings suggest that TOF-MRA pre-training followed by 4D Flow MRI fine-tuning may help achieve robust segmentaLon performance with limited 4D Flow MRI annotaLons. Because these ablaLon experiments used a single nested subset sequence without repeated random sampling, the observed robustness across reduced fine-tuning subsets should be interpreted as exploratory. In addiLon to this robustness, the study-specific subgroup analysis suggests potenLal generalizability across acquisiLon protocols, as the fine-tuned nnU-Net showed more stable performance across the Flow@Aneurysm and DETAILING subsets than the DenseNet U-Net and from-scratch nnU-Net.

However, this observaLon should be interpreted cauLously given the small size of the DETAILING subset and should be validated in larger cohorts.

When interpreLng the segmentaLon performance, several factors beyond model architecture and training strategy should be considered. First, differences in acquisiLon may have influenced imaging provides the benefits of a broader velocity dynamic range and higher SNR, parLcularly when segmenLng both arterial and venous structures with a wide range of flow velociLes (Aviles et al., 2021). However, our study only focused on the arteries within the CoW, which may reduce the relaLve importance of the broader velocity coverage provided by dual-VENC imaging.

Compared with 3T, 7T MRI is more suscepLble to B1 field inhomogeneity, which may result in spaLally variable flip angles, signal amplitudes, and local SNR (Schmixer et al., 2016). No dedicated B1 correcLon was applied in the present study. Therefore, B1 field inhomogeneity at 7T may have contributed to spaLal variaLons in signal intensity in the PCMRA images. In addiLon, complex flow paxerns, parLcularly in or near aneurysmal regions, may cause intravoxel dephasing and flow-related signal dropouts, potenLally reducing local vessel conspicuity in PCMRA images. However, the higher field strength also provides increased SNR, which can be used to acquire images with higher spaLal resoluLon (Goxwald, Töger, et al., 2020). Accordingly, our data included near-isotropic 0.7 mm and isotropic 0.5 mm acquisiLons, in contrast to the approximately 1 mm spaLal resoluLon used in Winter et al. (Winter et al., 2024). Second, the preprocessing pipelines differed across the three evaluated models, including differences in intensity normalizaLon, patch-based processing, fixed cropping or padding, and sliding-window inference. Nevertheless, these implementaLon differences may have contributed to the observed performance differences in addiLon to the network architectures themselves. An addiLonal consideraLon when interpreLng the segmentaLon results is the uncertainty associated with the manual reference. Inter-observer analysis demonstrated that manual segmentaLons themselves exhibit variability, indicaLng that the reference standard is not perfectly reproducible. Therefore, part of the observed difference may arise from uncertainty in the reference segmentaLon itself.

4.3 Impact of segmentaLon and methodological factors on hemodynamic quanLficaLon

The bias paxern in vessel area closely aligns with the errors observed in flow and velocity. Physiological variability, such as sex-, age-, and side-related differences, may also affect cerebral hemodynamics (Bakker et al., 2004; Marinoni et al., 1998; Wu et al., 2017). For instance, Fico et al. reported a mean blood flow difference of approximately 0.4 mL/s between young and older adults in the lee M1 segment of MCA measured by 4D Flow MRI (Fico et al., 2023). Notably, the mean blood flow derived from different segmentaLon models in our study showed a similar magnitude of variaLon (e.g., U-Net 2.45 mL/s versus DenseNet U-Net 2.02 mL/s in the lee MCA; Δ = 0.43 mL/s). This indicates that the variability in hemodynamics introduced by the different segmentaLon models may equal or exceed the biological effects, underscoring the importance of precise vessel delineaLon for reliable hemodynamic quanLficaLon.

A further contributor to hemodynamic differences is the fact that dynamic flow fields are evaluated on a staLc segmentaLon. Blood flow is pulsaLle, and intracranial arteries are compliant, changing their lumen throughout the cardiac cycle, whereas the manual reference used in our analysis was derived from a Lme-averaged PCMRA image that cannot capture phase-specific vessel geometry. Although the segmentaLon models could in principle generate Lme-resolved masks, producing a Lme-resolved manual reference would require frame-by-frame manual annotaLon and extensive quality control, which is impracLcal. In addiLon, because centerlines and analysis planes were generated separately for each segmentaLon, the observed hemodynamic differences may reflect both vessel segmentaLon differences and variability introduced by plane placement. However, this approach reflects a realisLc downstream workflow, and variability was minimized as much as possible by selecLng analysis planes at corresponding anatomical locaLons across methods. In addiLon, QVT-based flow analysis was restricted to vessel segments that could be successfully analyzed across all four segmentaLon pipelines, the reported agreement may be overesLmated and does not account for segmentaLon or analysis failures. Furthermore, parLal-volume effects and flow-related signal loss cause uncertainty in both the vessel boundary and the near-wall velocity gradient, thereby affecLng not only segmentaLon accuracy but also WSS esLmaLon. Therefore, both manual and automated PCMRAbased segmentaLons can deviate from the physical vessel wall, and the reported WSS agreement should be interpreted as agreement relaLve to the reference segmentaLon.

4.4 LimitaLons and future work

Our study has some limitaLons that also highlight paths for future research. First, since the orientaLon and posiLon of scan volumes were adjusted according to the aneurysm locaLons, there were minor variaLons in the coverage of CoW. Combined with the relaLvely small 4D Flow MRI dataset, this may have limited the model's ability to learn robust and generalizable representaLons. Although transfer learning from a large public TOF-MRA dataset may have miLgated this issue to some extent, future work should evaluate this effect on a larger and more diverse 4D Flow MRI cohort.

Second, the comparison with baseline models should be interpreted as a pipeline-level comparison rather than a fully architecture-matched comparison. This design was moLvated by the available implementaLons of the baseline models and by our aim to preserve their published or default se}ngs as much as possible. Therefore, the evaluated baseline models differed not only in architecture but also in training strategy and preprocessing pipeline. Future studies should include architecture-matched transfer-learning experiments to further isolate the effects of model architecture and training strategy.

Third, future studies could include topology-aware metrics, such as clDice, or centerline-based measures to bexer evaluate vessel connecLvity and small-branch preservaLon in branching vascular trees. Furthermore, this framework was developed and evaluated using 7T data, whereas most clinical 4D Flow MRI acquisiLons are performed at 3T and oeen at lower spaLal resoluLon.

Therefore, future work should evaluate whether the transfer-learning strategy can be adapted to 3T 4D Flow MRI through dedicated fine-tuning on representaLve clinical datasets.

Finally, although most subjects in the 4D Flow MRI cohorts were paLents with IAs, our segmentaLon focused only on the intracranial arteries and did not include the aneurysm sacs.

Previous work has demonstrated the feasibility of automated aneurysm segmentaLon and WSS quanLficaLon using 4D Flow MRI (Winter et al., 2025). However, obtaining reliable manual reference segmentaLons of aneurysm sacs was challenging in our dataset, parLcularly for smaller aneurysms with heterogeneous signal and pronounced flow-related signal loss, limiLng the reliable evaluaLon of aneurysm-specific segmentaLon accuracy and WSS measurements. Given the potenLal clinical value of IA segmentaLon and aneurysm-specific hemodynamic assessment for treatment planning and risk evaluaLon, extending the current framework to jointly segment intracranial arteries and aneurysm sacs represents an important direcLon for future research.
