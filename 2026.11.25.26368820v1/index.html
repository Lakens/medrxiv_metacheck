To fix Exact P-Values

What we found

Show details

Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (e.g., “decreased at the p < .05 significance threshold”).

What we found

We found 17 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Adaptive deep brain stimulation could make the treatment of essential tremor more responsive to patients' needs, delivering stimulation when tremor-provoking movements occur rather than continuously, thereby potentially reducing habituation-related loss of efficacy and stimulationinduced adverse effects. Its success, however, depends on neural control signals that remain measurable and meaningful long after surgery, at home rather than in the laboratory, and while stimulation is running. Thalamic local field potentials offer such candidate signals, yet they have largely been characterised intraoperatively or in the early postoperative period, under supervised conditions that reveal little about their behaviour in daily life. We therefore followed nine patients with essential tremor implanted with a sensing-enabled neurostimulator targeting the ventral intermediate nucleus and posterior subthalamic area, combining in-clinic recordings three and six months after surgery with weekly, patient-performed home recordings.

We extracted 13 spectral features encompassing canonical and tremor-frequency band power, aperiodic spectral properties and periodic beta activity, and evaluated their agreement between home and clinic recordings, between-session reliability and movement-related modulation across recording settings and stimulation states. Oscillatory features did not differ systematically between home and clinic, whereas the aperiodic background was consistently steeper at home and poorly reproducible. Periodic beta measures emerged as the most robust candidates: with stimulation off, their clinic-home reliability approached that observed between the two clinic visits, and a postural task suppressed beta activity across recording settings, an effect carried by the periodic component rather than by the aperiodic background.

Stimulation, however, reduced the reliability of beta measures and markedly attenuated their.

Introduction

Essential tremor is one of the most common movement disorders in adults, affecting approximately 1% of the general population, with prevalence increasing markedly with age. 1 It is characterised by a progressive action tremor predominantly affecting the upper limbs, with substantial inter-individual variability in severity and clinical course. 2 Although several pharmacological treatments are available, many patients remain refractory to medication and experience considerable impairment in activities of daily living. 3, 4 For these patients, deep brain stimulation (DBS) of the ventral intermediate nucleus (VIM) of the thalamus or the posterior subthalamic area (PSA) has been an established surgical treatment for decades 5 providing substantial and sustained tremor reduction. 6 Maintaining long-term efficacy, however, remains a major challenge in thalamic DBS for essential tremor. A substantial proportion of patients experience a decline in stimulation benefit over years of follow-up, [7] [8] [9] a phenomenon thought to reflect, at least in part, neural adaptation to chronic thalamic stimulation. 8 Loss of efficacy is commonly managed by escalating stimulation parameters, which increases exposure to adverse effects such as dysarthria and gait disturbance. 10 More fundamentally, this long-term limitation may relate to how stimulation is delivered. Conventional DBS is applied continuously, irrespective of tremor state, whereas the clinical expression of essential tremor is strongly state-dependent, with disability occurring predominantly during voluntary movement and sustained posture. 2, 11 This mismatch provides a strong physiological rationale for closed-loop, demand-driven stimulation that delivers therapy selectively during tremor-provoking motor states, an approach already shown to be feasible in essential tremor. 11, 12 Implementing such systems requires reliable neural, state-dependent biomarkers that can, ideally, be measured directly from the implanted electrodes. Local field potentials (LFPs) recorded at the stimulation target provide access to oscillatory activity within the cerebellothalamo-cortical circuit implicated in tremor generation. 13, 14 Several candidate control signals have been identified in the VIM, including oscillatory activity at tremor frequency [15] [16] [17] [18] and movement-related suppression of beta-band activity. 19, 20 Proof-of-concept studies in which thalamic local field potentials triggered stimulation during tremor-provoking movements achieved tremor control comparable to continuous stimulation, albeit acutely, within days of implantation; 11, 21 chronic embedded closed-loop systems in essential tremor have so far relied on cortical sensing. 12, 22 A major limitation, however, is that most characterisations of VIM local field potential biomarkers have been either performed intraoperatively or during the early postoperative period. Recordings obtained shortly after electrode implantation may be influenced by the microlesion effect, which can suppress tremor for weeks to months after thalamic surgery 6, 23 and transiently alters local field potential dynamics, as shown in the subthalamic nucleus. 24 More importantly, biomarkers intended for long-term adaptive DBS (aDBS) must remain detectable and physiologically meaningful months after implantation and under the less controlled conditions of everyday life. 22, 25 Chronic and repeated recordings have been investigated in the subthalamic nucleus in Parkinson's disease, 26, 27 whereas longitudinal thalamic recordings in essential tremor remain confined to small cohorts studied in the laboratory. 19, 22 In particular, it is not known whether candidate VIM/PSA spectral biomarkers measured in the clinic can be reproduced reliably during repeated, longitudinal ecological recordings at home. Bidirectional neurostimulators capable of chronic, home-based spectral recording 28, 29 now make it possible to address this question directly.

In this study, we characterised VIM/PSA LFP features across two in-clinic assessments and repeated, patient-performed home recordings acquired weekly in the intervening period, first to evaluate their reproducibility across sessions, recording environments and stimulation states, and second to characterise their movement-related modulation.

Materials and methods

Participants and study design

We prospectively studied ten patients with severe, disabling, medication-refractory essential tremor treated with bilateral DBS of the ventral intermediate nucleus/posterior subthalamic area (VIM/PSA) using the Percept bidirectional neurostimulator (Medtronic, Minneapolis, MN) as part of standard clinical care. All participants fulfilled the 2018 consensus criteria of the International Parkinson and Movement Disorder Society. 2 Full inclusion and exclusion criteria, as well as detailed surgical procedure are provided in Supplementary Methods S1 and S2. The study was approved by the Comité de Protection des Personnes Nord Ouest IV (Lille, France; no. 22.04558.000153), and all participants provided written informed consent.

Participants were studied over a three-month period, from three (M3) to six months (M6) after implantation, with two in-hospital supervised recording sessions at M3 and M6 and weekly patient-performed home-based "snapshot" recordings between visits (Fig. 1A).

Tremor severity was assessed at M3 using the Fahn-Tolosa-Marin Rating Scale and compared with the preoperative assessment to quantify DBS-associated clinical improvement.

Stimulation settings were largely unchanged between M3 and M6 (Supplementary Table 2).

Stimulation contacts, pulse width and frequency remained unchanged in all patients except P02, in whom the left directional contact was changed between sessions. Per-contact current was self-titrated between visits by less than 0.5 mA in three patients (P01, P02, P04) to optimise clinical outcome.

LFP acquisition in clinical and home settings

Local field potentials were recorded from the DBS electrodes in two complementary settings and under four conditions: rest and a tremor-provoking postural task, each with stimulation OFF and ON (Fig. 1B).

In-hospital: Recordings were performed at M3 and M6 using two "sensing" modes. With stimulation OFF, time-domain signals were streamed simultaneously from all available bipolar contact pairs ("Indefinite streaming") after a 5-min stimulation washout (Fig. 1C). With stimulation ON, sensing was restricted to a single bipolar configuration comprising the two contacts flanking the active stimulation contact, allowing recording during ongoing stimulation ("BrainSense streaming"). This sensing-friendly bipolar montage was subsequently used for the home recordings and for all analyses. Neural signals were recorded simultaneously with accelerometry positioned on the dorsal aspect of the index, surface EMG and ECG, and a brief transcutaneous electrical pulse was delivered to synchronise neural and peripheral signals.

Home setting: Patients performed standardised home recordings once weekly between M3 to M6 using the sensing-friendly configuration defined above. For each of the four conditions, three 30-s recordings were acquired and stored as device "event" snapshot. Home recordings therefore comprised device-derived spectral data rather than stored time-domain signals (Fig. 1C). Stimulation-OFF recordings were obtained upon waking, following an overnight stimulation washout, to minimise carry-over effects. Recordings were initiated by an accompanying person using the handheld controller, and patients documented any deviations from the protocol. At M6, patients rated the ease of performing the home procedure on a 10point visual analogue scale (0 = very difficult,10 = very easy).

LFP preprocessing and spectral estimation

Clinical recordings acquired at M3 and M6 consisted of raw LFP time series sampled at 250 Hz. To maintain comparability with the minimally processed spectra generated on-chip by the implanted device, no band-pass or notch filtering and no automated artefact correction were applied. Recordings were visually inspected for transcutaneous electrical nerve stimulation (TENS) synchronisation pulses, high-amplitude transients and other technical artefacts, and segments containing clearly identifiable artefacts were excluded.

Home event snapshots contained spectra computed on-chip by the implanted neurostimulator. These were expressed as single-sided fast Fourier transform (FFT) amplitudes in microvolt-peak per frequency bin (µVp), rather than as conventional power spectral density in µV²/Hz. Clinical spectra were therefore estimated offline using parameters chosen to reproduce the device output. For each channel, Welch's method was applied using 1-s Hann windows (250 samples), 80% overlap and a 256-point FFT, with zero-padding from 250 to 256 samples.

The resulting spectral density, Pxx (µV²/Hz), was converted to microvolt-peak amplitude as √Pxx × 1.695, where the scaling factor accounts for the Hann-window root mean square (RMS), peak-to-RMS conversion, single-sided scaling and zero-padding.

All subsequent analyses were performed in the power domain. Spectral amplitudes in µVp were squared to obtain power-like values in µVp². For clinical recordings, Welch's method yielded a single mean spectrum per channel. For home recordings, the corresponding µVp² spectra were averaged across repeated snapshots.

Spectral feature extraction

Given the limited availability of spectral data from home recordings, analyses requiring access to the underlying time series, such as burst detection, phase-based coupling and time-resolved spectral estimation, could not be performed consistently across settings. To ensure direct comparability between clinical and home recordings, we therefore focused on features that could be extracted from the available spectra in both settings. Three complementary families of spectral features were considered. First, power within canonical frequency bands was quantified to enable comparison with previous thalamic LFP studies. Second, given the interindividual variability in tremor frequency and its proximity to canonical band boundaries, power was estimated within patient-specific bands centred on the tremor frequency and its second harmonic. Third, because changes in band power may reflect variations in the broadband aperiodic background rather than oscillatory activity alone, spectra were parameterised to distinguish periodic and aperiodic components. This allowed the extraction of additional candidate biomarkers and band-power measures adjusted for the aperiodic background.

Canonical band power. Absolute band power was computed by summing the squared values over all frequency bins falling within each predefined band: delta (1-4 Hz), theta (4-8 Hz), alpha (8-13 Hz) and beta (13-35 Hz). For each participant, session, condition and hemisphere, this procedure yielded a single band-power estimate for each predefined frequency band.

Gamma power (>35 Hz) was excluded because of high-frequency censoring (see Supplementary Methods S8 and Supplementary Tables 5 and 6).

Tremor-frequency band power.

Participant-and hemisphere-specific tremor-frequency bands were centred on the individual tremor fundamental frequency (f₀) and its second harmonic (2f₀).

The fundamental frequency was estimated from upper-limb accelerometer recordings acquired during the in-hospital M3 and M6 sessions, with surface EMG used when accelerometry was unavailable or insufficient. Estimates from M3 and M6 were combined to obtain a single f₀ per participant and limb. Because each thalamic electrode was related to tremor in the contralateral limb, hemisphere-specific f₀ values were assigned accordingly. The full estimation procedure is described in Supplementary Methods S8, and individual f₀ values are reported in Supplementary Table 7. Two frequency bands were then defined for each hemisphere: f₀ ± 1 Hz and 2f₀ ± 1 Hz. Across the 20 hemispheres, f₀ ranged from 3.42 to 5.86 Hz (median 4.27 Hz).

Power within the fundamental (f₀) and second-harmonic (2f₀) bands were calculated using the same procedure as for the canonical frequency bands.

Aperiodic and periodic spectral parameterisation.

For each participant, session, condition and hemisphere, the mean squared amplitude spectrum was parameterised with the FOOOF/specparam 30 algorithm to separate the aperiodic background from superimposed oscillatory peaks. The model was fitted per channel over 1-40 Hz in fixed aperiodic mode (no knee), with peak-width limits 2-12 Hz, a maximum of three peaks, minimum peak height 0 (no height gate), and a peak threshold of 1.5 standard deviations of the flattened spectrum.

Extracted aperiodic features were the exponent and the offset (log₁₀ µVp²), and aperiodic broadband power -the aperiodic fit re-expressed in linear units and summed over the fitrange bins. Aperiodic-corrected band power was calculated as the FOOOF log-space residual (log₁₀(spectrum) -log₁₀(aperiodic fit)) summed over the bins of each band. Periodic peaks were characterised by their centre frequency, amplitude (log₁₀ power above the aperiodic fit) and bandwidth.

Electrode localisation and impedance assessment

Electrode locations were reconstructed using Lead-DBS, 31 and the position of the active contact level relative to the ventral lateral posterior nucleus (VLPv), which corresponds to the VIM of Hassler's nomenclature, 32 was described from participant-specific HIPS-THOMAS segmentations. Electrode impedance was evaluated at M3 and M6 as an additional technical stability measure, with longitudinal changes assessed using paired non-parametric tests. Full details of electrode localisation and impedance assessment are provided in Supplementary Methods S3 and S9.

Software

Percept recordings were imported and organised in MATLAB using the Percept toolboxes. 33 Subsequent analyses were performed in Python, using MNE-Python 34 for signal processing, FOOOF for spectral parameterisation, 30 and statsmodels 35 for linear mixed-effects modelling and multiple-comparison correction. Intraclass correlation coefficients, permutation tests, and bootstrap procedures were implemented in Python following established definitions and procedures. Figures were generated using Matplotlib. 36 Specific software and package versions are provided in Supplementary Methods S10. Analysis code is available at https://github.com/sahar-allouch/ecolovim-dbs-lfp-home-vs-clinic.

Statistical analysis

Analyses were performed using bilateral values, calculated for each participant, session and condition as the equal-weight mean of the corresponding left-and right-hemisphere feature values. Canonical and tremor band power, aperiodic broadband power and the aperiodic exponent were natural-log transformed before statistical analysis. Aperiodic offset, aperiodiccorrected band power and beta peak amplitude were retained on their native log₁₀ scale. Beta peak centre frequency and bandwidth were analysed in Hz without transformation.

Session-related differences

Systematic differences between M3, home and M6 were assessed using linear mixed-effects models fitted separately for each feature and recording condition (rest and movement, with stimulation OFF and ON). Timepoint was included as a fixed effect and participant as a random intercept, with home as the reference level. This provided direct estimates of M3-home and M6-home differences, while the M3-M6 contrast was derived from the same fitted model. Models were estimated by restricted maximum likelihood.

Inference was based on within-participant permutation testing (5000 permutations), with 95% confidence intervals (CIs) obtained by participant-level bootstrap resampling (2000 resamples). Effects are reported as model coefficients (β), 95% confidence intervals, permutation P-values and standardised effect sizes, calculated as d = β/√(τ² + σ²), where τ² and σ 2 denote the between-participant and residual variance components, respectively. For logtransformed features, model coefficients were back-transformed where appropriate to aid interpretation.

Benjamini-Hochberg false discovery rate (FDR) correction was applied separately within each session contrast across all 13 features and four recording conditions, yielding 52 tests per contrast and analysis unit. Statistical significance was defined as FDR-adjusted P < 0.05. Models used all available observations for each feature and condition. Full details of the resampling procedures, singular-fit handling, back-transformations and sensitivity criteria are provided in Supplementary Methods S9.

Between-session reliability

Between-session agreement was assessed using two-way random-effects, absolute-agreement, single-measure intraclass correlation coefficients (ICCs; ICC(2,1)). 37, 38 ICCs were calculated for M3-home, M3-M6 and home-M6 for each feature and recording condition (rest and movement, with stimulation OFF and ON). Ninety-five per cent confidence intervals were obtained from 5000 participant-level bootstrap resamples. ICCs were classified as poor (<0.50), moderate (0.50-0.75), good (0.75-0.90) or excellent (>0.90). 39 Complete cases were used for each comparison (n = 9 for M3-M6 and n = 8-9 for comparisons involving home); beta peak analyses included 7-9 pairs because a peak was required at both sessions.

Movement-related modulation

Movement-related modulation was quantified within each participant, session and stimulation state as the paired difference between movement and rest recordings. For log-transformed features, this corresponds to the log ratio of movement to rest.

Results

Study population

Ten patients with essential tremor treated with bilateral DBS of the VIM/PSA (20 hemispheres) were enrolled (seven women; mean age 63.5 ± 8.1 years, range 46-74; mean disease duration 20.9 ± 12.0 years, range 11-49). Baseline characteristics are given in Supplementary Table The analysed dataset comprised in-clinic recordings at M3 and M6, each condition yielding one spectrum per hemisphere from on average 61-105 s of usable signal (Supplementary Table 4), and 770 home event snapshots of 30 s (≈6.4 h of recording; 179-203 per condition; median 87 per participant; Supplementary Table 3), which were averaged within participant and condition before analysis. Fig. 2 provides an overview of the resulting spectral profiles.

Group-level spectra at M3 and M6 were closely overlapping across all four conditions, whereas home spectra were comparable to clinic spectra at lower frequencies but showed progressively lower power at higher frequencies, consistent with a steeper aperiodic slope (Fig. 2A). At the participant level, oscillatory features (alpha, beta and tremor-frequency power) showed relatively stable trajectories across sessions, whereas the aperiodic exponent and offset increased at home before returning towards M3 values at M6 (Fig. 2B; remaining features in Supplementary Figs 2 and 3; descriptive statistics in Supplementary Table 8). These differences are examined quantitatively in the following sections.

Oscillatory features were largely preserved between home and clinic

No oscillatory feature differed systematically between home and clinic recordings after correction for multiple comparisons (Fig. 3 and Supplementary Fig. 5). This held for canonical band power, tremor power, and periodic beta features.

For canonical band power, clinic-home differences were small and of the same order as those between the two supervised clinical visits (median |d|: 0.30 for M3-home, 0.37 for M6-home, and 0.22 for M3-M6). Tremor power was similarly stable, with clinic-home differences no larger than those between the two clinical visits (median |d|: 0.28 for M3-home and 0.30 for M6-home vs. 0.37 for M3-M6; minimum clinic-home P = 0.089).

Periodic beta features, including peak centre frequency, bandwidth, peak power, and aperiodiccorrected power, also showed no clinic-home difference that survived correction (median |d|: 0.29 for M3-home and 0.25 for M6-home; minimum PFDR = 0.16), although these differences were larger than those between the two clinical visits (median |d| = 0.09 for M3-M6). Beta peaks were detected in 89-100% of usable recordings in each hemisphere across sessions.

Home recordings showed a selective shift in aperiodic spectral structure

The aperiodic exponent was the only feature to show systematic home-clinic differences after correction for multiple comparisons, with four clinic-home contrasts surviving correction (Fig. 3 and Supplementary Fig. 5); 18 of 104 clinic-home contrasts were nominally significant.

The aperiodic exponent was consistently higher at home, indicating a steeper 1/f spectral slope.

The direction of this effect was consistent across rest and movement and with stimulation both OFF and ON, occurring in all eight clinic-home comparisons (all uncorrected P ≤ 0.008; PFDR ≤ 0.068; Fig. 2A and Supplementary Fig. 3). Effect sizes were large relative to both M3 (median d = -1.55) and M6 (median d = -1.24) and exceeded the difference between the two clinical visits (median |d| = 0.41). The offset showed the same directional tendency, being higher at home in all eight comparisons, although the effect was more pronounced relative to M3 (median d = -0.71) than M6 (median d = -0.29) and did not survive correction (minimum PFDR = 0.055).

By contrast, aperiodic broadband power showed no consistent home-clinic difference. The M6-home difference (median d = 0.41) was comparable in magnitude to the change between M3 and M6 (median |d| = 0.47), consistent with session-related variability rather than a systematic home-clinic shift.

Electrode impedance remained stable between M3 and M6, with no hemisphere-or contactlevel difference surviving correction for multiple comparisons. Detailed results are presented in Supplementary Results S11 and Supplementary Fig. 6.

Between-session reliability varied across features and stimulation states

Between-session reliability varied substantially across feature types and stimulation states (Fig. 4 and Supplementary Fig. 4). Across all features, median ICC(2,1) was 0.47 for M3home, 0.55 for M6-home and 0.62 for M3-M6.

Periodic beta features showed the highest reliability, particularly during stimulation OFF. Peak bandwidth was less reliable in both states, Tremor-frequency power showed moderate clinic-home agreement overall (median ICCs 0.56 for M3-home and 0.58 for M6-home, versus 0.69 for M3-M6). Among canonical bands, alpha and beta were the most reliable during stimulation OFF (clinic-home ICCs 0.50-0.79 and 0.49-0.80, respectively), whereas theta was more variable (0.19-0.70) and delta showed the lowest agreement (-0.26 to 0.41). During stimulation ON, alpha remained moderately reliable (0.63-0.69), whereas beta agreement decreased (0.23-0.53); theta and delta ranged from 0.31-0.61 and 0.34-0.50, respectively. Aperiodic features showed low between-session reliability, particularly during stimulation OFF. Median clinic-home ICCs were 0.04 for the exponent, 0.12 for the offset and 0.19 for broadband power, during stimulation OFF, with similarly limited reliability between the two clinical visits. Reliability generally improved during stimulation ON, particularly for offset and broadband power. The exponent remained less reliable between clinic and home than between the two clinical visits; however, ICC(3,1) exceeded ICC(2,1) for clinic-home comparisons (0.50-0.70 versus 0.15-0.36; stimulation ON), indicating better preservation of betweenparticipant ranking than absolute agreement in the presence of the systematic home-clinic shift.

Movement modulated oscillatory beta activity during stimulation OFF

With stimulation OFF, movement produced a consistent reduction in beta power across all three sessions (Fig. 5A), extending approximately from 13 to 25 Hz. Beta power decreased by 18% (β = -0.20 ln, 95% CI [-0.29, -0.10], P = 0.004, PFDR = 0.025), with no evidence that this effect differed across sessions (movement × session, all PFDR ≥ 0.89; Fig. 5B and Supplementary Table 9). Power at the tremor frequency tended to increase with movement (β = 0.18 ln, [0.06, 0.38], P = 0.020), although this did not survive correction (PFDR = 0.064).

Delta, theta, alpha and second-harmonic tremor power were not significantly modulated (all |β| ≤ 0.14 ln, all P ≥ 0.09, all PFDR ≥ 0.19). Movement-related effects were consistent between home and clinic recordings. None of the 13 features showed a setting-related difference in movement response after correction for multiple comparisons (all PFDR ≥ 0.45).

Discussion

In this study, we investigated whether thalamic spectral features proposed as biomarkers for aDBS in essential tremor when acquired at home, are comparable to in-clinic measurements, and whether they exhibit similar movement-related modulation across recording settings. To this end, we first examined the feasibility of unsupervised home thalamic recordings in patients with essential tremor. We then characterised the agreement between spectral features derived from home and in-clinic recordings using two complementary approaches: linear mixed-effects models to identify systematic between-session differences, and intraclass correlation coefficients to assess the reliability of individual feature values across sessions. Finally, we used linear mixed-effects models of the movement-rest difference to test whether movementrelated modulation varied across recording settings and stimulation states.

Patients completed weekly sessions and rated the procedure as easy to perform. This is an important step towards clinical translation, since candidate aDBS biomarkers must ultimately be characterised beyond supervised clinical setting. In Parkinson's disease, subthalamic and pallidal signals acquired in daily life are increasingly used to inform adaptive stimulation strategies, 25, 40 and recent work has extended this approach to gait-responsive stimulation during everyday activities. 41 Comparable evidence remains scarce in essential tremor, where thalamic activity has mostly been studied in small cohorts under supervised conditions. Our study helps to fill this gap by assessing the reliability and movement-related modulation of candidate thalamic biomarkers during patient-managed home recordings.

Several key findings emerged. Oscillatory features were broadly consistent between home and clinic, whereas the aperiodic background showed a systematic shift towards steeper spectra at home. Reliability differed markedly across features: periodic beta measures showed the highest clinic-home reliability, approaching that observed between clinic visits, whereas aperiodic measures were less reliable. Stimulation was associated with lower beta reliability, highlighting the dependence of these measures on stimulation state. Movement-related beta suppression was observed across recording settings and was predominantly associated with periodic activity rather than changes in the aperiodic background. However, this modulation was markedly attenuated during stimulation.

Across oscillatory features, home-clinic differences were generally comparable in magnitude to those between the two clinic visits. Absolute beta power was a notable exception, being higher in the clinic in all eight contrasts, although none survived correction for multiple comparisons. In contrast, aperiodic-corrected beta power, which measures beta activity relative to the fitted aperiodic background, tended to be higher at home (seven of eight contrasts). These opposing trends may reflect the systematic shift in aperiodic activity between settings, as a flatter spectrum can increase absolute beta power without a corresponding increase in periodic beta activity. 42 This distinction has implications for aDBS: although oscillatory features may be reproducible across settings, current device controllers measure total band power, including its aperiodic contribution. Consequently, beta-power thresholds calibrated in the clinic may not transfer directly to home recordings.

The aperiodic component, the broadband 1/f activity on which oscillatory peaks sit, is characterised by its exponent and offset. 30 The exponent and offset were consistently higher at home across all eight clinic-home comparisons, with large differences relative to both M3 and M6 that exceeded those between clinic visits. On the other hand, aperiodic broadband power showed no significant difference between settings. Together, these findings suggest a change in spectral slope rather than a uniform shift in broadband power, with relatively greater lowfrequency and lower high-frequency aperiodic activity at home. A similar dissociation has been reported in the subthalamic nucleus following levodopa administration, where the exponent increased without a corresponding change in aperiodic broadband power. 42 A postoperative trajectory is unlikely to fully explain this pattern. Because home recordings were acquired between M3 and M6, a monotonic postoperative change would be expected to produce intermediate values rather than consistently higher values at home than at either clinic visit.

Previous subthalamic recordings have also shown no significant changes in exponent or offset between one to three months and one year after implantation. 43 Nevertheless, changes in aperiodic exponent can arise from multiple mechanisms, 42, 44 and the present finding remains descriptive and should not be interpreted as evidence of altered excitation-inhibition balance.

Three explanations remain possible. The first is recent stimulation history: home stimulation-OFF recordings followed an overnight interruption, whereas clinic recordings were obtained after only a 5-min washout. In the subthalamic nucleus, stimulation increases both the aperiodic exponent 45, 46 and offset. 46 Any residual stimulation effect after the shorter clinic washout would therefore be expected to increase these parameters in the clinic rather than at home, contrary to the observed pattern. The second possibility is vigilance. Home stimulation-OFF recordings were obtained on waking, and it has been reported that both the aperiodic exponent and offset increase during the transition from wakefulness to sleep in cortical and subthalamic recordings. 47 Then, we hypothesise that residual drowsiness after waking could therefore account for the steeper spectra and higher offset observed at home, although this mechanism has not yet been established in the thalamus.

Lastly, although clinic spectra were processed to approximate the device output, differences between offline Welch estimates and on-chip FFT snapshots could affect the fitted aperiodic parameters. Whether these differences contributed to the systematic home-clinic shift remains uncertain.

Between-session reliability differed markedly across features. Periodic beta measures were the most reproducible, with clinic-home ICCs approaching those observed between clinic visits, whereas the aperiodic exponent and offset were poorly reliable, a pattern also reported in subthalamic recordings in Parkinson's disease. 27 Aperiodic broadband power, proposed as a within-patient marker of subthalamic activity, 42 was poorly reliable with stimulation OFF and only moderately reliable with stimulation ON. Stimulation, in turn, reduced the reliability of all five beta features, both between clinic and home and between the two clinic visits, indicating that this decline reflected the stimulated state rather than the home setting. These findings warrant two caveats. First, ECG contamination may have contributed to the lower beta reliability during stimulation, when the device case serves as the reference; rightsided implantation, as in our cohort, reduces but does not abolish this risk. 48 ECG contamination was more apparent in our clinic recordings during stimulation ON but could not be assessed at home, where time series were unavailable, and a subthalamic study found no loss of beta-peak reliability during stimulation once the recording configuration was matched and ECG contamination removed. 27 Second, low ICCs should not be equated with random measurement noise. ICCs depend on between-participant variability as much as on measurement error, 39 and absolute-agreement estimates are further penalised by systematic shifts. With stimulation, the between-participant standard deviation of beta-amplitude measures fell to 25-51% of its OFF value, consistent with the suppression of subthalamic beta power by stimulation, 49 which mechanically lowers ICCs. For the aperiodic exponent, between-participant ranking was largely preserved despite poor absolute agreement (ICC(3,1) 0.50-0.70 versus ICC(2,1) 0.15-0.36 with stimulation ON), pointing to a consistent settingrelated bias that could, in principle, be corrected by calibration.

Movement-related thalamic beta suppression, a promising candidate signal for aDBS, was observed across recording settings. With stimulation OFF, beta power decreased during the postural task, with no significant differences in the beta response between home and either clinic visit. Averaged across sessions, movement reduced absolute beta power (β = -0.20 ln, PFDR = 0.025) and corrected beta power (β = -1.15 log₁₀, PFDR = 0.025), while increasing beta peak frequency (+1.10 Hz, PFDR = 0.034). No corresponding modulation was detected in aperiodic parameters (all PFDR ≥ 0.28), suggesting that beta suppression predominantly reflected changes in periodic activity rather than the aperiodic background. These findings are consistent with previous reports of thalamic alpha and low-beta suppression during cued button presses in externalised recordings, 50 and sustained beta modulation during posture and action over 24 months of chronic recording. 19 By contrast, tremor-frequency power showed no significant modulation during the postural task (all PFDR ≥ 0.06). This dissociation suggests that beta activity primarily reflects motor state rather than tremor expression, consistent with thalamic decoding studies in which low-beta activity tracked voluntary movement whereas theta activity tracked postural tremor. 20 The absence of robust tremor-frequency modulation may reflect the spatial variability of thalamic tremor-related activity, as previous work has shown that its relationship with tremor depends on electrode location and the distribution of tremor-related neurons. 16 Stimulation markedly attenuated movement-related beta modulation. Absolute beta power no longer decreased during the postural task, with a significant reduction in the movement response relative to stimulation OFF (PFDR = 0.003). Although a smaller movement-related decrease persisted in corrected beta power (-0.49 log₁₀ (95% CI -0.83 to -0.11)), this residual modulation does not establish reliable movement detection during stimulation. This distinction is particularly relevant for movement-triggered aDBS, in which movement onset and the return to rest are detected under different stimulation states. In a previously tested thalamic aDBS system for essential tremor, stimulation was activated upon movement detection and discontinued when movement ceased. 11 Movement onset was therefore detected during stimulation OFF, when beta modulation was strongest in our recordings, whereas the return to rest had to be detected during stimulation ON, when beta modulation was substantially attenuated. This challenge has been recognised in earlier systems: stimulation-related interference prevented reliable detection of movement cessation with a previous-generation device, 12 while He et al. used separate movement decoders for stimulation OFF and ON. 11 Similar stimulation-dependent changes in beta activity have been shown to impair motor-state classification in Parkinson's disease. 42 These findings highlight the need to evaluate movement onset and cessation separately, with detection thresholds established under their respective stimulation states.

The stability of the monitored frequency band presents a further challenge for thalamic aDBS.

Current implantable controllers typically monitor power within a narrow frequency band defined during calibration, often centred on an individual beta peak in Parkinson's disease. 51 In our recordings, beta peak frequency increased during the postural task, the magnitude of this shift varied across sessions, and peak bandwidth showed poor reliability. Such variability may compromise fixed-band monitoring, even when movement-related beta modulation remains consistent. Similarly, a chronic closed-loop study in essential tremor identified shifts in the centre frequency and bandwidth of thalamic oscillations as major obstacles to reliable control, requiring frequent recalibration. 22 Integrating beta power over a wider frequency range or dynamically adjusting the monitored band to track the beta peak may reduce sensitivity to these shifts, although neither approach was evaluated here. Complementary signals may also improve the robustness of adaptive control. Sensorimotor cortical activity has shown greater long-term stability than thalamic signals 22 and has supported closed-loop stimulation with reduced energy consumption. 12 Peripheral sensors have also enabled responsive stimulation with tremor control comparable to continuous stimulation, 52 supporting the potential of multimodal approaches that combine neural and peripheral signals. 53 Limitations. The sample of nine participants limits precision and precludes formal equivalence testing. Home spectra were averaged across weekly recordings acquired between M3 and M6 and compared with single clinic sessions; therefore, the reported agreement reflects the mean home signal rather than week-to-week repeatability or the reliability of a single snapshot. Home task performance was patient-reported and without objective kinematic verification. Wearable sensors, which capture aspects of tremor burden not reflected by clinical scales, 54 could provide such information in future studies. Tremor severity was assessed only at M3, limiting inference on associations between spectral features and longitudinal changes in tremor clinical severity.

Stimulation history and recording conditions differed between settings by design, and minor stimulation adjustments were required in some participants between visits. A residual stun effect, reported to persist up to three months after thalamic surgery in a randomised trial, 6 may therefore have influenced M3 recordings and was not independently tracked. However, the stability of measure between M3 and M6 rules out this hypothesis. ECG contamination could not be quantified in the home recordings. Finally, because the sensing pair was determined by the active stimulation contact, recording locations varied across hemispheres: both contacts of the sensing channel lay within the VLPv, used here as an imaging surrogate of the VIM, in only 6 of the 18 analysed hemispheres, at least one contact lay within it in 11. The stability of electrode impedances argues against a drift in recording quality as the primary explanation for session-related effects.

This study demonstrates the feasibility of patient-managed thalamic LFP recordings in essential tremor and provides a detailed characterisation of thalamic spectral features across recording settings and stimulation states. Periodic beta measures showed relatively high clinichome reliability and consistent movement-related modulation; stimulation, however, attenuated both, exposing a key challenge for adaptive control. Thalamic beta thus remains a meaningful marker of motor state in daily life, but not yet a stand-alone control signal during stimulation; complementary cortical or peripheral inputs, together with validation in the stimulated state, will be needed before thalamic adaptive stimulation can be broadly implemented in essential tremor.

For

each feature, a linear mixed-effects model was fitted to the movement-rest difference, with timepoint (M3, home and M6) and stimulation state (OFF and ON) as fixed effects and participant as a random intercept. Home and stimulation OFF were used as reference levels. The model therefore tested whether the movement effect differed between home and either clinical visit and whether it differed between stimulation OFF and ON. Models were estimated by restricted maximum likelihood. Movement effects within stimulation OFF and ON were additionally estimated from statespecific models as the average movement-rest contrast across M3, home and M6. These state-specific estimates describe the magnitude of movement modulation within each stimulation state; differences between stimulation states were assessed from the stimulation term in the full model. Statistical inference was permutation-based, with 95% confidence intervals obtained by participant-level bootstrap resampling. Benjamini-Hochberg false discovery rate correction was applied across the 13 features separately for each model term and for the stimulationspecific movement contrasts. Statistical significance was defined as FDR-adjusted P < 0.05. Full details of the permutation and bootstrap procedures are provided in Supplementary Methods S9.

As the bipolar sensing pair was consistently centred on the stimulating level, the midpoint of the recording contacts corresponded to the same location. On patient-specific HIPS-THOMAS segmentations, both contacts of the bipolar sensing channel lay within the VLPv (≥ 50% of the contact volume) in 6 of the 18 hemispheres, one contact in 5 and neither contact in 7 (Supplementary Methods S3); contacts lying outside the nucleus were mostly located ventral to it, towards the posterior subthalamic area. Stimulation produced the expected clinical benefit: the total Fahn-Tolosa-Marin score fell from 53.2 ± 11.5 before surgery to 20.5 ± 11.8 at M3 with stimulation ON (Wilcoxon signedrank test, P = 0.002), every patient improving, by 31% to 86% individually (mean 63.1 ± 15.5%). Patients rated the home procedure as easy to carry out, 8.7 ± 1.1 on a 10-point visual analogue scale (range 7-10).
