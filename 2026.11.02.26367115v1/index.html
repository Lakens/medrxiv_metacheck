indices The modeling framework described in the Measured Variables section is designed as a proxy for the ability of a set of factors to capture contributors/indicators to realized depression impact. The incremental predictive validity of a given factor layer (one of S, Q, T) is represented by how well regression models are able to explain variance in depression impact, given a difference of performance between models with and without that layer. The coefficient of determination (R²) is utilized as a primary performance metric because it measures explanatory power, that is, how much of the variance in reported depression impact is explained by a given model. This is more relevant here than others such as MSE, RMSE, and MAE because it allows for an interpretable measure of how well realized depression is captured by a model compared to a simple guess of the mean, as opposed to a raw measure of error in the model.

Because of limited dataset size, a stratified 10-repeated 3-fold cross-validation (CV) approach was utilized in the development set to explore and select final configurations. This CV framework employed a unique random seed for each of 10 repeats to split data into 3 subsets, stratified again by eligibility group. The designated metric for base evaluation of model performance was repeat-aggregated R² score, which is calculated by concatenating out-of-fold (OOF) predictions across the 3 folds within each repeat, calculating the R² within each repeat, then taking the average over the 10 resulting R² scores. This metric differs slightly from repeat-fold-aggregated R² score, which calculates R² for each set of OOF predictions, averaging over a total of 30 scores. Repeat-aggregated R² score was chosen as the base exploratory metric because it is subject to lower variance, whereas repeat-fold-aggregated R² score was used for formal exploratory model comparison because it allows for insight at a more granular scale.

In the confirmatory analysis, because only a single train-test split will be employed, the metric of interest will simply be the R² score of test-set predictions. Effect size certainty will be quantified via 1000-iteration bootstrap-derived 95% confidence intervals.
statistical_tests For convenience, the following description is also attached as a pdf with formatted equations.

Hypotheses 1A/1B: Open-text responses carry signal in predicting depression impact incremental to what is found in structured questionnaire responses. This hypothesis can be represented more formally as:

H_A: Δ(R²_full, R²_reduced) > 0
H_0: Δ(R²_full, R²_reduced) ≤ 0

where Δ(x, y) represents the difference x − y, R²_full is the test-set R² of some full model including T, and R²_reduced represents the test-set R² of some reduced model excluding T. Three full/reduced pairs will be evaluated: (ST, S), (QT, Q), and (SQT, SQ).

The null hypothesis states that T carries no predictive information, meaning that a model including T performs no better than the same model without it. To construct this null, a permutation procedure will destroy the link between each participant and their text-derived vector while leaving all other data intact. For each of 1000 iterations, a unique random seed will be used to shuffle the text-derived vectors among participants in the train set, stratified by eligibility group, such that a participant only receives the vector of another participant within the same eligibility group. Within each iteration, the same shuffled train set participants are used for all three full models: each of ST, QT, SQT is refit on the shuffled train set and evaluated on the un-shuffled test set, yielding a null R² for each. The reduced models (S, Q, SQ) contain no text features and are therefore unaffected by the shuffle; their observed test-set R² values are held fixed across iterations, so each iteration yields three null differences Δ(R²_ST, R²_S), Δ(R²_QT, R²_Q), and Δ(R²_SQT, R²_SQ).

Because T should demonstrate incremental value regardless of which structured-response baseline it supplements, the three pairwise differences are treated as a family of hypotheses, with family-wise error rate (FWER) controlled at α = 0.05 using the Westfall-Young step-down max-T procedure.

Let the observed differences be the set d = {d₁, d₂, d₃}, where

d₁ = Δ(R²_ST, R²_S)
d₂ = Δ(R²_QT, R²_Q)
d₃ = Δ(R²_SQT, R²_SQ)

and let d_ji denote the corresponding null difference from permutation iteration i for hypothesis j. The observed differences are ordered from largest to smallest, d₍₁₎ ≥ d₍₂₎ ≥ d₍₃₎, where d₍k₎ denotes the k-th largest observed difference in d. Adjusted p-values are computed step-down. The null statistic for step k = 1 in permutation iteration i is m₍₁₎i = max_j d_ji across all three permuted differences. The corresponding hypothesis of d₍₁₎ is then removed from consideration for further testing. Accordingly, for step k = 2 in permutation iteration i, m₍₂₎i is the maximum across the two remaining hypotheses {d₍₂₎i, d₍₃₎i}, and m₍₃₎i is simply the single remaining permuted difference d₍₃₎i. The raw adjusted p-value for the k-th ordered hypothesis is

1 + Σ(i = 1 to 1000) 1[ m₍k₎i ≥ d₍k₎ ]
p̃₍k₎ = ──────────────────
1000 + 1

after which monotonicity is enforced by taking successive maxima across all p-values, p₍k₎ = max(p̃₍₁₎, …, p̃₍k₎). Because all three null differences within an iteration are computed from a single shared shuffle, the permutation distribution preserves the dependence among the hypotheses, so the procedure adapts to their correlation rather than assuming independence, serving to increase power over conservative alternative FWER controls such as the Bonferroni correction. A hypothesis is rejected if its adjusted p-value falls below α = 0.05. 1000-iteration paired bootstrapping will be used to generate 95% CIs for each of Δ(R²_ST, R²_S), Δ(R²_QT, R²_Q), and Δ(R²_SQT, R²_SQ).


Hypotheses 2A/2B: The incremental signal of open-text responses, in supplement of sum scores, exceeds that of granular structured questionnaire responses. This question can be represented more formally as:

H_A: Δ(R²_ST, R²_SQ) > 0
H_0: Δ(R²_ST, R²_SQ) ≤ 0

where Δ(x, y) represents the difference x − y, and R²_ST and R²_SQ represent the test-set R² of the stacked ST and SQ regressor models, respectively. A one-sided test is pre-specified based on the direction indicated by Bayesian post-hoc comparisons in the development set during exploratory analyses. Unlike Hypothesis 1, the null hypothesis here does not assert that T carries no information. Under H_0, both T and Q may carry signal, and the claim is only that ST does not outperform SQ, meaning a train-set shuffle would therefore construct the wrong null. Instead, a per-participant prediction-swap (sign-flip) procedure will be employed, under which the null of exchangeability states that the assignment of the labels “ST” and “SQ” to each participant’s pair of predictions is arbitrary.

The frozen ST and SQ configurations will each be trained once on the full development set, producing a pair of test-set predictions (ŷ_ST,i , ŷ_SQ,i) for each of the n test participants. The observed statistic is computed on these baseline predictions as t_obs = Δ(R²_ST, R²_SQ). For each of 1000 iterations, a unique random seed will be used to swap ŷ_ST,i and ŷ_SQ,i independently for each participant i with probability 0.5. Both R² values are then recomputed on the swapped prediction vectors and their difference recorded as t_i. Note that models are trained only once, as permutation applies exclusively to test-set predictions. This contrasts with the Hypothesis 1 procedure, which retrains models under each train-set shuffle. Significance will once again be set at α = 0.05, and p-value defined as:

1 + Σ(i = 1 to 1000) 1[ t_i ≥ t_obs ]

inference_criteria Specific testing procedures for hypotheses are described in further detail in the Statistical models section. This section provides further detail into inference criteria.

Hypothesis 1A and 1B will test text’s incremental explanatory value to structured questionnaire responses in adolescent- and parent-reported DAWBA responses, respectively, in relation to reported depression impact scores. For each of the two hypotheses, 3 p-values will be obtained: one pertaining to each of ∆(R²_ST, R²_S), ∆(R²_QT, R²_Q), ∆(R²_SQT, R²_SQ). These tests are not independent, so a Westfall-Young step-down max-T procedure will be employed to control the FWER at α = 0.05, and monotonicity will be enforced such that p_k = max(p̃_1, …, p̃_k) for each pair’s p-value. exploratory_analyses In addition to assessing the incremental signal of T, and how it compares to that of Q in supplement of S, the contributions of individual components of T are also of interest. This planned exploratory analysis in the test set is supported by a number of methods employed in the development set. Note that all completed preliminary and planned future analyses were performed separately for adolescent and parent cohorts.

Given final selected model configurations, an exploratory analysis of feature contributions will be performed for indication of how each feature affects model output in practice, using the test set. Explored in two dimensions, the salience of features and incremental R² provide a holistic view of each feature’s effect on both raw output and aggregated performance. Because the SQT set-up explained the most variance (via development repeat-aggregated R²) in both adolescent and parent cohorts, this is the only stacked framework in which contribution was, and will be, analyzed.

To gain insight into how, on average, the values of features push predictions up/down, a salience analysis was performed in the development set. Given a frozen residual regressor model trained on the development set, recorded feature values in the development set were multiplied by the learned weights of corresponding features in the model. Values across records for each feature were aggregated across minimum, maximum, average, and standard deviation. The same procedure will be performed in the held-out test set, where learned weights from frozen SQT models will be multiplied by corresponding feature values in the held-out test set. These values have the ability to uncover that a feature with a relatively low/high weight magnitude is counterintuitively affecting model output by a large/small magnitude, given the distribution of recorded values for a given feature. Additionally, the results of the salience mapping in the development and held-out test sets will be compared for insight into feature consistencies across the two sets.

A salience analysis provides insight into model behavior given feature values, but an analysis of behavior given the target variable provides insight into how informative or degradative the learned signal from a feature is, providing a more holistic heuristic of desirable feature contribution. The Lindeman, Merenda, and Gold method, also known as LMG decomposition, apportions variance explained among individual predictors by recording incremental variance explained given the presence/absence of a feature. Because the incremental R² of a feature may differ depending on the pre-existing feature set, the process of adding a given feature and recording incremental performance must be repeated many times with many different pre-existing feature sets.

Because T enters the stacked framework as its final layer, the decomposition is applied to the T layer alone: every ordering begins from the fitted SQ prediction, so the recorded increments apportion the incremental variance explained by the text vector over and above sum score and structured responses, rather than the total variance explained by the SQT model. The S and Q layers are not apportioned. The 80 text-feature contributions therefore sum to ∆(R²_SQT, R²_SQ) for a given iteration of LMG. Note that this total is invariant to the ordering in which features are added; only its allocation across features depends on the ordering. Two distinct implementations were preliminarily explored in the development set.

Single-split Implementation The first, and the simpler of the two, used the same exploratory dataset that final models were trained on as an ad-hoc evaluation set. For a single final trained model, 500 random feature orderings of the 80-text derived features were generated, each from a unique random seed, and each was evaluated alongside its reverse, for 1000 orderings in total. The process of iteratively adding features and recording evaluation-set performance was carried out for every one of the 1000 orderings, and each text feature’s incremental variance explained was averaged to give a single contribution value per feature. This method is heavily biased, since it is simply a measure of how much each feature helps the model memorize the training data.

CV Implementation The second implementation addressed this limitation by embedding LMG within the same stratified 10-repeated 3-fold CV framework employed to select final model configurations. Here, 1000 random feature orderings were generated, each from a unique random seed, and each was again evaluated alongside its reverse, for 2000 orderings in total. A given ordering was evaluated in all 30 (repeat, fold) cells of the CV framework: within a cell, the model was fit on the two training folds and features were added iteratively, with the incremental OOF R² recorded at each addition. Each feature’s final contribution was the mean of its increment across all 1000 × 2 × 30 = 60,000 (ordering, direction, cell) evaluations. Unlike the first implementation, contributions were estimated out of fold, so a feature whose learned signal does not generalize received a low or negative average contribution.

A secondary exploratory analysis will be performed in the held-out test set. This exploration will employ the single-split implementation of LMG on the held-out test set over 1000 iterations and their reversals, for a total of 2000. Since the frozen models are not trained on the held-out test set, LMG results via the single-split method will provide an unbiased estimate of each feature’s unique predictive power. These results will be compared to those of the CV Implementation in the development set, providing insight into the consistency of individual contributions.

Additionally, exploratory sensitivity analyses will be performed for insight into any potential biases or unforeseen relationships between test-set performance and aspects of the data. For example, we will look at the pairwise relationship between performance and sex, missingness, and/or date of questionnaire completion. An analysis on the characteristics of excluded participant records will also be performed to uncover potential biases caused by our filtering framework. Further, a comparison of single-layer S, Q, and T model test-set performance will be performed, as there was no clear trend in predictive ability across adolescent and parent cohorts in the development set.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. Abstract

Depression in adolescents has grown in prevalence in the past decade. Despite indications of differences in symptom presentation, measurement properties, and treatment response between adolescents and adults, research is dominated by adult participants. Qualitative work has identified symptomatic and functional domains important to depressed adolescents and those around them; however, there remains little quantitative evidence of how these domains relate to the functional impact of the disorder. In this preregistered study, we use adolescent self-report (n = 153) and parent-report (n = 106) responses in the depression section of the Development and Well-Being Assessment (DAWBA) to examine what information relevant to reported depression impact may be missing from its structured symptom-scale. We apply Large Language Models (LLMs) to participant free-text answers to extract information on a taxonomy of 80 outcomes. Through a sequential residual stacking framework that estimates incremental information in symptom sum-scores (S ), item-level symptom-scale answers (Q), and LLM-derived text representations (T ), we find that parent text contains information relevant to their report of depression impact that is not available in the structured symptom-scale, with the largest contributions concentrated in functioning-related domains (e.g., professional responsibilities, social exclusion, autonomy, coping). No such evidence was found in adolescent self-reports. Given the moderate sample size, these results are preliminary. Nonetheless, we provide a proof-of-concept framework for extracting information from open-ended free text in large existing datasets, and estimating incremental information across sources, which could be applied to uncover specific aspects of adolescent mental disorders across populations.

1 Introduction

Indicators of poor mental health among adolescents have risen in the past decades. In the United States, rates of major depressive episodes among adolescents increased by 52% (8.7% to 13.2%) from 2005-2017 (Twenge, Cooper, Joiner, Duffy, & Binau, 2019), and persistent sadness or hopelessness among U.S. high school students rose from 30% in 2013 to a peak of 42% in 2021 before falling to 40% in 2023 (Verlenden et al., 2024). Adolescent depression has also been found to be highly predictive of prolonged struggle with mental health into adulthood, with an estimated 2.78 times increased likelihood of adult depression when diagnosed as an adolescent, and additional associations with adult anxiety and suicidality (Johnson, Dupuis, Piche, Clayborne, & Colman, 2018). However, the majority of Major Depressive Disorder (MDD) research has been conducted in adults, despite numerous studies suggesting potential differences in manifestation, latent structure, and response to treatment of the disorder between adolescents and adults (Rice et al., 2019; Wight, Sepúlveda, & Aneshensel, 2004). We aim to address this gap directly through perspectives of adolescent experiences.

MDD is an inherently hard phenomenon to measure. It is heterogeneous and manifests in many different ways, with low overlap in symptoms across individuals (Fried & Nesse, 2015) and moderate overlap across established scales (Fried, 2017 (Fried, , 2020)). A systematic review of 138 studies spanning 170 different study populations by Haroz et al. (2017) found that only seven of fifteen frequently mentioned features of depression worldwide are part of the DSM criteria for MDD. Similarly, a study of 8790 Brazilian students found numerous features that differentiated depressed and non-depressed participants, and yet were absent from the DSM and ICD (Manfro et al., 2023). Failing to adequately measure the effects of depression that people experience, and care about, contributes to incomplete assessments of severity (Stringaris & Goodman, 2013) and skewed perspectives on treatment efficacy.

In response, numerous qualitative studies have been conducted to derive factors relevant to depressed people that may not be captured adequately in standard instruments. Krause, Midgley, Edbrooke-Childs, and Wolpert (2021) conducted a post-hoc qualitative analysis of interview data collected for the IMPACT-ME study (Goodyer et al., 2011; Midgley, Ansaldo, & Target, 2014), with adolescent, parent, and therapist participants. A taxonomy of 29 outcome domains most prominently discussed by participants was derived, with very few of them consistently reported in recent quantitative treatment outcome studies. Similarly, Chevance et al. (2020) surveyed patients reporting a depressive disorder, informal care-givers, and healthcare professionals about their perspectives of the expected benefits of depression treatment. From these responses, a taxonomy of 80 outcome domains was derived. These studies identify what matters to people with depression and those around them, but do not directly quantify how much these additional domains contribute to the impact a disorder has on a person's life. Testing this quantitatively may be accomplished with: 1) an open description of experiences from participants alongside structured symptom measures, 2) a measure of the impact of depression, and 3) a method for extracting numerical representations of potentially relevant domains from those descriptions.

The Development and Well-Being Assessment (DAWBA) provides the first two requirements (R. Goodman, Ford, Richards, Gatward, & Meltzer, 2000). It features responses from adolescents, their parents and, occasionally, their teachers on a set of questionnaires, impact ratings, and structured free-text interviews for a number of mental-health disorders, including depression. Recent advancements in natural language processing (NLP), specifically in large language models (LLMs), have made the third possible. For example, Xin et al. (2026) developed logistic regression classifiers operating on text embeddings to classify transcribed interview text as exemplifying a given outcome, after training on human-coded labels (Krause et al., 2021). However, this framework of training classifiers operating on text embeddings requires large amounts of human-coded data, which may not always be available for the outcomes of interest. The latest LLMs make a different approach feasible, namely to predict the presence (or absence) of each outcome directly, after reading a prompt defining the outcome and the text to be classified. In this way, it is possible to efficiently quantify elements of already-collected semi-structured text at a large scale.

In this preregistered study (Matar, Lossio-Ventura, Pereira, & Nielson, 2026), we combine these elements to test whether free text contains information relevant to the impact of depression beyond that which is present in symptom rating scales. Using already-collected depression data from adolescent and parent responses to the DAWBA, we hypothesize that text adds information above symptom rating scale sumscores, item-level symptom ratings, and their combination. We also hypothesize that supplementing sumscores with information derived from text will be more predictive than when supplementing with individual symptom ratings. We test this with a residual stacking framework that allows for the isolation of contributed signal to specific sources, and additionally attribute added signal to specific outcome domains. In testing our hypotheses, we also demonstrate an analytical framework that makes it possible to exploit existing free-text data to discover and assess the importance of previously unmeasured aspects of adolescent mental health disorders across cultures, ages, and/or sex. All hypotheses were motivated by exploratory analyses in a development set. Models frozen prior to confirmatory analyses were fit on the development set and evaluated on participants in the held-out set. 2.1.2 Data Split & Further Processing

The preprocessed dataset of 327 paired parent-adolescent records was initially split into development (n=219, ∼ 67%) and held-out (n=108, ∼ 33%) sets, stratified by eligibility to the CAT-D study. The following processing steps were decided upon and performed in the development set, followed by the held-out set after preregistration. While all of these data were used as part of the screening process for the CAT-D study, we did not access the held-out set for other purposes prior to the execution of the preregistered analyses.

Each adolescent participant is the subject of both a self-report and parent-report response set. Exclusion criteria were applied to responses independently, such that excluding an informant's response in one sample did not necessarily remove the matched response in the other sample. Consequently, the final samples contain partially overlapping, rather than matched, sets of adolescent self-and parent-responses. Additionally, splitting into development and held-out sets prior to separating the two response samples ensured that there was no overlap of adolescent participants across splits.

Four symptom-scale items (18i-18l, covering ideation and attempt of self-harm/suicide) were largely missing in both samples and thus excluded from analysis. The DAWBA uses skip logic, prompting informants to complete later sections only on the basis of their earlier answers. As such, the responses of informants not prompted to answer semi-structured free-text questions were removed. Missing values for symptom-scale items as a result of not being prompted were simply marked as 0. For all other cases of missing entries in symptom-scale items, the whole response was removed. Responses with 6 or more missing text entries were dropped, and any missing answers were filled as "Not answered" for responses with 5 or fewer missing entries. After all cleaning steps, the adolescent and parent development sets contained 103 and 71 responses, respectively, over 120 unique adolescent participants. 2.2 Residual Stacking Prediction Framework

The target outcome for prediction is Impact Score, which is taken as the sum of five depression impact questions at the end of the depression section of the DAWBA (shown in Table 12 in the Supplemental Materials). This target is predicted within a residual stacking framework, which makes it possible to isolate the incremental signal present in three classes of predictor features. The first class of features, denoted as S, is the sum of 23 individual items in the depression symptom-scale section of the DAWBA, with a possible discrete range of [0,25]. The second, Q, is a 23-dimensional vector of item-level answers to the symptom-scale section of the questionnaire, with response options of {0,1} or {0,1,2}. The third class is T, which is an 80-dimensional numerical representation of informant answers to free-text prompts. The signal of a given class of features is quantified as the out-of-sample coefficient of determination (R² ) of a linear regression predicting Impact Score from the input features chosen. This metric was selected over others such as MSE, RMSE, or MAE because it provides insight into performance relative to a simple guess of the mean, rather than raw error.

In each sample, S, Q, and T were used to predict Impact Score. A number of residual stacking setups were explored, including single-layer (S, Q, T ), two-layer (ST, QT, SQ), and three-layer (SQT ) setups. All S -layer models were simple linear regressions, whereas Q-and T -layers were ridge regressions, regardless of position in a given stacked setup. Multi-layer setups were implemented such that a given layer's residuals served as the target of the subsequent layer. For example, in the SQT model, a linear regression was fit on S to predict Impact Score, then a ridge regression model was fit on Q to predict the error of the S model. This resulted in an SQ model whose final output was the sum of S -model outputs and its predictions of S residuals. Finally, another ridge regression model was fit on T to predict the error of the SQ model, whose final outputs were the sum of the SQ model and its prediction of the SQ model error. This framework is outlined in Table 3.

The difference in R² (variance explained) between S /SQ or SQ/SQT provides insight into incremental signal available in Q or T when they are added. Furthermore, any shared variance is assigned to the lower level models, so that the difference in out-of-sample R² between SQ and SQT only represents the unique additional variance explained by T. We use the out-of-sample R² because in-sample R² is trivially non-decreasing as features are added, but out-of-sample R² reflects generalized performance and penalizes overfitting. All the prediction models tested were fit using the entirety of the development set, and out-ofsample prediction results were obtained by deploying them on the held-out set.

2.2.1 T-layer Configurations

The development set was used to select lambda regularization penalties for Q-and T -layers, as well as a number of methods and configurations to derive numerical representations of text. The first, LR, involved embedding text and using the resulting numeric vectors as inputs to previously trained logistic regression models for each outcome domain, similar to work done by Xin et al. (2026). The second, LLM Prompting, involved prompting LLMs to test the presence of the outcome domain in the text directly. The ultimate goal in both cases was to represent text as a numeric vector reflecting some taxonomy of mental health symptoms/outcomes/domains. This exploration is described in further detail in the Model Configuration Selection section of the Supplemental Materials.

Ultimately, we chose LLM Prompting as the method of derivation, using the taxonomy of 80 mental health outcomes derived by Chevance et al. (2020). For this method, the 10 free-text items, including both question and answer, were first concatenated into one large block of text before wrapping in a broader prompt, which gave context to the text and provided instructions for what to output. LLMs were prompted independently for each outcome in the taxonomy and for each response. The resulting feature vector for each instance of T was an 80-dimensional concatenation of LLM output.

There were multiple decisions to make regarding the configuration of LLM prompting, which we will refer to as pseudo-hyperparameters. Namely, these involve the LLM base-model, temperature, prompting method, and output type. Pseudo-hyperparameters were selected separately for each residual setup including T (T, ST, QT, SQT ) within each response-sample, for a total of eight selected sets of pseudo-hyperparameters. LLM base-models were selected from Gemini 2.5 Pro, Qwen 3.6 27B and Llama 3.3 70B Instruct. Qwen and Llama are open-weight models, which we ran on local hardware. Gemini was run through HHS Enterprise Gemini with FedRAMP High authorization. These models, developed by different entities, differ in size, capability, and price. Estimated performance rankings varied across residual setups and response-samples in the development set. Temperature, a true hyperparameter of LLMs, controls the stochasticity of output. Smaller temperature settings result in more deterministic and consistent output across runs, but may limit variation in LLM output and ability to capture nuance. We also considered two different LLM prompting approaches. In our zero-shot prompting, we provided a description of the source of the text, a concatenated block of DAWBA free-text questions and answers, the target domain, a definition of that domain, and instructions for output. In contrast, our few-shot prompting supplemented the provided description of the domain with a few examples of text and expected output, providing further information about the intended interpretation of the domain. An important consideration of few-shot prompting is that, if provided examples are too narrow, LLMs may not be able to generalize or capture more nuanced information as intended. Similarly, if they are too broad, LLMs may have a wider view of a domain than is appropriate. Further, all chosen pseudo-hyperparameter sets employed a Scale output type, which prompted LLMs to output the severity ({0,1,2,3,4}) of an outcome. This is in contrast to the Binary output type, which prompted LLMs to simply output whether the outcome was present in the text or not ({0,1}). An example of zero-shot, scale prompting is displayed in the Supplemental Materials.

4 Discussion

The starting point for our work was the availability of the DAWBA instrument, used in the context of depression. There, adolescents and parents answer a structured questionnaire composed of symptom-scale items (Q), which can be aggregated into sum-scores (S ), as well as providing short free-text narratives. Using LLMs, the latter can be transformed into quantitative features representing a taxonomy of 80 mental-health outcomes (Chevance et al., 2020) (T ). Our main objective was to determine if there was information in free text relevant to the impact of depression that was not captured by the structured symptom-scale. We operationalized this through a residual stacking framework capable of isolating predictive capability of each source in prediction of adolescent-and parent-reported impact of depression.

We hypothesized that T would increase variance explained over S, Q, and stacked SQ models in both adolescent-and parent-response samples. This was supported in the parent-response sample over Q (∆R² = 0.068, p minP = 0.033) and SQ (∆R² = 0.060, p minP = 0.033), but not S (∆R² = 0.039, p minP = 0.11). No significant increases from T were found in adolescent responses (∆R² between -0.107 and 0.049, p minP between 0.26 and 0.76). We additionally hypothesized that the incremental signal of T as a supplement to S would exceed that of Q, but found no significant results in either sample, with near-zero or negative observed differences in performance between ST and SQ (∆R² = -0.027 and -0.004 for adolescent and parent responses, respectively).

Given the limited power of this proof-of-concept study, we did not aim to draw conclusions about the difference between adolescent self-report and parent-report. While we did observe a difference in significance for Hypothesis 1, we did not test the difference in incremental R² between parents and adolescents. This difference may partly reflect the longer written answers by parents, whose median free-text word count exceeded that of adolescents by 19 in the held-out set (182 vs 163 words) and 51 in the development set (249 vs 198 words). It is also possible that there is greater inter-individual consistency between parent free-text responses than there is between adolescent responses.

Our results in the parent-response sample are consistent with semi-structured text containing information about depression impact that is not available in structured symptom-scale items. Although T alone explained far less variance in parent-reported impact than S or Q alone (0.073 vs. 0.297 and 0.272), its contribution was almost entirely complementary: T increased explained variance by 0.068 over Q and 0.060 over SQ, nearly its full standalone value. This suggests that the information T carries about parent-reported impact overlaps little with that captured by the symptom-scale items. This was not the case for S (∆R² = 0.039, p minP = 0.11). It is noteworthy that the two significant comparisons both used zero-shot Qwen, whereas few-shot Llama was employed for ST. We selected Llama for the S to ST comparison because of its superior performance in the development set. In an exploratory sensitivity analysis, ST did explain significantly more variance than S (∆R² = 0.088, p = 0.04) when free-text features were extracted with zero-shot Qwen instead of few-shot Llama. Thus, the failure to confirm this hypothesis was likely due to noise in the selection of models in the development set.

Given the indication that T contains predictive information disjoint from that in the symptom-scale in parent responses, it is worth exploring the nature of that unique signal. T was extracted from semistructured text following a taxonomy of 80 domains originally derived from a qualitative study by Chevance et al. (2020). These outcomes were segmented into two classes of symptom-(64 total) and functioningrelated (16 total) domains, as psychiatric classifications often distinguish between the two. Symptom-related domains, pertaining to the manifestations of a disorder, are among the most studied, whereas functioningrelated domains, pertaining to the extent to which those manifestations affect various aspects of daily life, receive less attention (Krause et al., 2021). The two, which are both typically required for a diagnosis of MDD (American Psychiatric Association, 2013), are related but do not fully overlap. Functional impairment has been found to be only partially explained by symptom severity and, in children and adolescents, functional impact has been shown to predict later psychiatric disorder over and above baseline symptoms (Stringaris & Goodman, 2013). Thus, it is plausible to conclude that consideration of both may provide a better picture of a disorder than either alone. Because the structured DAWBA items primarily capture symptoms (R. Goodman et al., 2000), remaining relevant information not already captured might therefore be expected to concentrate in functioning-related domains.

Consistent with this, functioning-related domains were over-represented among the features contributing to T 's increment in the parent QT and SQT models, the only two residual setups where T added significant gains. Of 18 LLM-derived features, selected as the union of the top 10 contributors across development and held-out sets in each model, eight contributed positively in all four groups. Five of the eight were functioningrelated domains (Professional responsibilities, Personal development, Social exclusion, Autonomy, Coping with life events), whereas three were symptom-related (Cognitive flexibility, Irritability, Self-confidence), despite functioning domains making up only 16 of the 80 in the taxonomy. Their prevalence in the original study deriving them (Chevance et al., 2020) is mixed. Professional responsibilities (11%) was among the most mentioned by all participants. Self-confidence (4.2%) was less mentioned, followed by Autonomy (4%), Coping with life events (4%), Irritability (3%), Personal development (1%), Social exclusion (< 1%), and Cognitive flexibility, which was only mentioned in the French cohort (< 1%). Suicidal Ideation (symptomrelated, 23%) was the most frequently mentioned domain, but was not determined to be a major contributor when supplementing Q and SQ in our data. The predominance of functioning-related domains among these contributors may explain the discrepancy between significant results in the two responder samples, as parents tend to focus more on functioning than adolescents (Krause et al., 2021).

There are two potential interpretations relating to the prevalence of functioning-related domains in the extracted set of top contributors. The first offers that T recovers clinically meaningful content (the consequences of depression for school, peer, family life, etc.) that symptom-oriented structured items do not elicit. The second understands T as simply providing a finer-grained description of the outcome itself. The DAWBA impact score is defined as the sum of five prompts relating to distress and interference in everyday domains such as family life, friendships, and schoolwork, so parent descriptions of social exclusion or difficulties with schoolwork overlap in content with the construct being predicted. These interpretations are not necessarily mutually exclusive. A deeper understanding of these results would benefit from further analyses distinguishing between text serving to effectively extend the structured screening and text merely refining the measure of impairment that structured impact items already target.

Outside of the results' implications in depression screenings, this study also serves as a proof-of-concept framework for evaluating the utility and/or nature of semi-structured text in relation to associated structured data, allowing for analysis of already-collected data at large scales in mental health domains. Previous work has explored similar residual stacking approaches in bioinformatics (Boulesteix & Hothorn, 2010; Boulesteix & Sauerbrei, 2011), and others have employed both feature extraction from social media postings via NLP and residual stacking broadly applied in health, psychology, and economics (Zamani & Schwartz, 2017; Zamani, Schwartz, Lynn, Giorgi, & Balasubramanian, 2018). However, to our knowledge, this is the first preregistered test of whether LLM-derived text features add predictive value above structured symptom scale questions in relation to depression impact. Although our framework is not specific to the DAWBA, the assessment is a particularly well-suited instrument for further investigations, as it was developed to be administered by lay-interviewers (R. Goodman et al., 2000), lowering barriers for administration and making collection more accessible. The DAWBA also features various skip rules throughout, making assumptions that a section is unlikely to be relevant given previous responses, and in turn reducing the burden of completion for participants. In addition to further investigations exploring the questions posed by this study, any number of taxonomies may be used to assess differences in information found in free-text across age, cultural, or sex groups, in prediction of reported impact of depression, or any other mental-health disorder in the DAWBA. There have already been numerous collections of the DAWBA across cultural (Alyahri & Goodman, 2006; A. Goodman et al., 2012; Zeinoun et al., 2013), age, and sex groups (Baser, Ford, Delgado, O'Logbon, & Cross, 2023).

4.1 Limitations

A major limitation of this study is the relatively small sample sizes. In the held-out set, this lowers power and decreases reliability of observed effect sizes, as evidenced by wide CIs. Model and hyperparameter selection within the development set are also affected by this, given potential variance in results, although comparisons were conducted across aggregated 10-time repeated 3-fold CV scores to minimize the volatility of model performance estimates and rankings.

Additionally, the sample was purposefully filtered to exclude participants not prompted to respond to freetext questions, removing a vast majority of healthy volunteers with 0 impact and avoiding spurious inflation of variance explained. This, paired with included participants being help-seeking, may have reduced the proportion of explainable variance by increasing the homogeneity of our sample. This may explain the low magnitude of observed R² , though these values are comparable with similar analyses predicting depression impact from symptoms (Stringaris & Goodman, 2013).

Another potential limitation is that explained variance estimates may be inflated by shared-informant variance (also referred to as shared-rater or shared-method variance), which may produce artifactual covariance between predictors (S, Q, T, and their stacked setups) and reported impact (Podsakoff, MacKenzie, Lee, & Podsakoff, 2003). Because the same respondent provides the symptom-scale ratings, free text, and impact ratings within each sample, variance explained may reflect genuine capture of contributors to impact, but it could also reflect the consistency of a respondent in describing the adolescent's experiences across all three sources. Cross-informant analyses, such as predicting adolescent-reported impact from parent text, or prediction of clinician-rated outcomes, would help separate these possibilities. Additionally, statistical corrections may be effective, but likely require larger datasets than available here (Podsakoff et al., 2003).

Finally, our selected LLMs may not remain accessible for validation in the future. Gemini is closed-source and the specific version used here may be discontinued later. Open-weight models were purposefully explored with this in mind, although they present a barrier of their own by requiring access to one or more GPUs to run locally. This may also be the only option if cloud-based models cannot be used with data containing PHI or PII.

4.2 Future Directions

These findings, although preliminary, have implications in our understanding of adolescent depression, specifically in the operationalization of that understanding through screenings. Significant increases in parentreported impact variance explained with the inclusion of LLM-derived text features over structured item responses suggest that semi-structured interview responses may contain explicit, unique information unavailable in the structured symptom-scale.

This claim would benefit from further testing on larger samples to decrease uncertainty in observed effect sizes, increase efficacy of statistical corrections for potential shared-informant variance, and allow for rigorous cross-respondent prediction. Further, more data may uncover additional informative domains not found to be prominent in this study, and sensitivity analyses assigning uncertainty to domain contribution estimates would also allow for more definitive indications of what symptom-scales might be missing. Moreover, pairing these methods with separation of symptom-and functioning-related domains extracted from text may also provide further insight into the nature of unique information in text relevant to impact.

This project also serves as a proof of concept for a framework that has many applications. With more data, modeling paradigms more complex than regression (such as tree-based methods or neural networks) could capture non-linear feature interactions in both Q and T, increasing understanding of the relationships of factors both within and across these sources. Different taxonomies and/or combinations of taxonomies could also be explored to find differences between populations (sex, age, culture, etc) at a mass-scale, given the availability of structured and unstructured data across these groups. Additionally, beyond specifically S, Q, and T, this residual stacking framework may also be applied to any combination of sources, aiding in isolating signal within frameworks previously thought to be inseparable.

5 Conclusion

Depression is common and increasingly prevalent among adolescents, yet it remains less studied in this population than in adults, and is difficult to measure with structured instruments alone. Free-text descriptions from adolescents and their parents offer a way to capture aspects of the experience that fixed questionnaire items may miss. In this preregistered study, we tested whether LLM-derived features of free text add predictive signal for depression impact beyond structured symptom-scale items in the DAWBA depression section.

In parent reports, text features explained additional variance in impact beyond item-level symptom ratings, both alone (QT vs. Q) and combined with sum-scores (SQT vs. SQ). This contribution was approximately additive to that of the structured items, suggesting that parent free text carries information about impact that the symptom-scale does not. These effects were not observed in adolescent self-reports, and text did not outperform item-level symptom ratings as a supplement to sum-scores in either response sample. Exploratory attribution analyses indicated that the added variance explained by text in these parent-report models was concentrated in functioning-related domains, such as social exclusion, professional responsibilities, and autonomy, rather than in the symptoms the structured symptom-scale items are designed to assess. Whether this reflects capture of the content that the structured symptom-scale items miss or a finer-grained description of the impairment being predicted remains to be determined. Given the modest sample and wide uncertainty in effect sizes, these findings should be regarded as preliminary. More broadly, the residual stacking framework outlined here offers a way to quantify what semi-structured text adds to structured measurement using data that has already been collected. It can be extended to other taxonomies, populations, informants, and outcomes to test what any one source of data contributes to a given measure beyond the others.

The 31 outcomes were derived from the original 30 by splitting "Other peer relationships" into "Peer relationships" and "Romantic relationships." We similarly classified the presence of these outcomes for each of monologue (interviewee utterances) and dialogue (interviewer-interviewee) transcription segmentation types, using logistic regression classifiers trained to predict human-coded labels from embeddings of segmentations derived via Llama 3.3 70B Instruct (temperature=0.6). Due to outcome prevalence imbalances, classifiers were not developed for three of the 31 outcomes. A number of aggregation methods for the 10 question-answer pairs of DAWBA free-text was also explored: Max, Avg, Block. For Max and Avg, each of the 10 question-answer pairs were embedded and passed through logistic regression models separately, resulting in 10 feature vectors of length 28. The maximum and average was then taken over the 10 vectors at each position for Max and Avg, respectively, resulting in a single 28-dimensional feature vector for each. In the Block method, all 10 question-answer pairs were concatenated to form one large block of text, which was embedded and passed through logistic regression classifiers as a single entity, resulting in a single 28-dimensional feature vector.

Llama 3.3 70B Instruct with temperature of 0.6 was the only configuration utilized for all embeddings of this method. The class of segmentation type and aggregation method were deemed pseudo-hyperparameters, and their selection is described in further detail in Model Configuration Selection.

9.2.2 Selection Framework/Criteria

There are no hyperparameters to select for S -layers. For Q, only λ regularization values were selected, chosen as those that resulted in the highest repeat-aggregated R² performance in the development set. Tlayers required the selection of both pseudo-hyperparameters and λ. For each selection of T, ST, QT, and SQT, configurations were ranked on repeat-aggregated R² scores, the top 25 of which were compared for final selection.

Of the top models, further comparisons were made via repeat-fold-aggregated R² score, which averages 30 OOF R² results across each of the 3 folds in each of the 10 repeats. Although prone to more variance, this metric allows for comparison at a more granular scale. A second filtering step was performed among top models using the baycomp (Benavoli, Corani, Demšar, & Zaffalon, 2017) package's two on single() function, which performs a pairwise Bayesian correlated t-test, on the 30 paired repeat-fold-aggregated R² observations across 2 given models, with the area of practical equivalence set to 0.01 (1% variance explained). The configuration with the highest repeat-aggregated R² score was compared to each of the subsequent 24 within this framework. 9.2 Model Configuration Selection

The primary goal of the work described in this section was to identify a specific best configuration to use for each residual prediction setup being considered, separately for each response sample. All this work was carried out within the development set, and the resulting configurations were then pre-registered for deployment in the held-out set.

Final model configurations differ across response-samples (adolescent/parent) and residual setups. The method of deriving feature vectors from text is considered a pseudo-hyperparameter, and was chosen in the development set alongside λ ridge regression penalties. Note that S -layers utilize simple linear regression, whereas all Q-and T -layers employ penalized ridge regression. As such, the selection of LLM-derivation method was only relevant to setups involving T, and ridge penalties only relevant to setups involving Q or T.

Also note that pseudo-hyperparameters and ridge parameters were selected independently for each response-sample/residual-setup pair, since each combination presents a unique model. Let λ XY represent the regularization parameter assigned to layer Y in an XY setup. In an SQT model, distinct values of λ may have been selected for the Q-(λ SQ ) and T-(λ SQT ) layers. Additionally, the value of λ SQ may differ from that of λ Q , and λ SQT may differ from λ QT . Further, the LLM-derivation configuration may differ across T, QT, ST, and SQT, both within and across response-samples. The full search space is outlined in Table 7.
