How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. Abstract

Hospital admission authorizations from publicly financed health systems are increasingly used to describe gender-affirming surgery, although they record billed procedures whose feminizing or masculinizing direction can be inferred from the code, without identifying people, self-reported gender identity or clinical need. This nationwide descriptive study examined the authorizations for gender-affirming surgery processed by the Brazilian Unified Health System from 2014 to 2025, which were selected from 3,888 public monthly state files of the Hospital Information System with a historically versioned classification of procedure codes. Of the 1,375 selected authorizations, 711 corresponded to directly feminizing procedures, 428 to directly masculinizing procedures and 236 to a complementary procedure that was analyzed separately. The feminizing share of the directly classified authorizations decreased from 81.7% (196/240) in 2014-2018 to 72.2% (213/295) in 2019-2023 and to 50.0% (302/604) in 2024-2025, proportions that describe composition within periods of unequal length and cannot be read as population rates. In 2024-2025, bilateral mastectomy accounted for 264 of the 302 masculinizing authorizations (87.4%), whereas bilateral breast reconstruction with silicone implants accounted for 118 of the 302 feminizing authorizations (39.1%). The median recorded age was 35 years in feminizing and 30 years in masculinizing authorizations over the whole period, and 34 and 29 years when the comparison was restricted to 2024-2025. The brown (parda) race/color category was recorded in 42.6% (303/711) of feminizing and 61.0% (261/428) of masculinizing authorizations, in a comparison pooled over the whole period and not adjusted for period or procedure. The number of hospitals habilitated for these surgeries remained at five from 2014 to 2022 and doubled in 2023. All aggregate results were reproduced by an independent pipeline that re-read every original public file. It was observed that the equal numbers of feminizing and masculinizing authorizations in the most recent period resulted from markedly different procedure.

Discussion

The present study showed that the convergence of feminizing and masculinizing authorizations in 2024-2025, with 302 authorizations in each group, resulted from procedure portfolios of very different composition, since bilateral mastectomy accounted for almost nine in ten masculinizing authorizations, whereas breast reconstruction accounted for about four in ten feminizing authorizations and the remainder was distributed among genital procedures, thyroplasty and other operations. Although the masculinizing genital procedure and neophalloplasty entered the procedure table in 2019 and 2024, all procedures other than mastectomy, including hysterectomy, contributed only 38 of the 302 masculinizing authorizations of the recent period. This observation suggests that the expansion of the coded portfolio had a small direct weight in the convergence and that the growth was concentrated in a single operation. This small contribution may reflect the staged character of masculinizing genital reconstruction and the fact that the national ordinance classified vaginectomy and neophalloplasty as experimental procedures restricted to accredited teaching hospitals [1], which may have delayed their provision. In the feminizing group, the genital procedure remained stable across the three periods, with 151, 138 and 150 authorizations, so that the recent growth of both groups was concentrated in breast and chest surgery. In this . sense, a ratio between feminizing and masculinizing counts may be misleading as an indicator of balance in service provision, because hospital authorizations are administrative outputs of coded procedures and do not measure the number of people served, the availability of each procedure, need, waiting time or equity of access.

The annual counts of bilateral mastectomy observed in the present study, 24 in 2023 and 162 in 2025, coincide with those reported in an independent analysis of the same information system [13], which reinforces the reproducibility of the selection. On the other hand, another conference analysis reported 1,268 hospitalizations from January 2014 to November 2025 [14], against the 1,375 authorizations selected here. Since both series start with 24 hospitalizations in 2014, it is possible that the difference arises from the shorter observation window of that analysis, which did not include December 2025, and from differences in procedure groupings, aspects that the available information does not allow to reconcile fully.

The predominance of breast and chest surgery among masculinizing authorizations is also consistent with national estimates from the United States, in which breast and chest procedures were the most frequent group of gender-affirming surgery [6, 7], although differences in health systems, coverage rules and units of analysis limit direct comparison.

Nevertheless, the concentration of recent growth in one operation suggests that changes in a single line of care, such as the accreditation of new services or the organization of surgical queues, may be sufficient to modify national aggregates, hypotheses that cannot be tested with the present data. In this direction, the number of establishments habilitated for these surgeries doubled in 2023, from five to ten, and from September 2023 the SIGTAP also accepted the habilitation of the national program for reducing elective surgery queues, changes that coincide with the increase in authorizations, although the authorizations could not be attributed to each establishment or program. The decrease in selected authorizations in 2020 and 2021 coincides with the COVID-19 pandemic, when a reduction of 46% in elective gender-affirming intervention is heterogeneous and that part of trans people do not wish to undergo surgery [32, 33]. These interpretations refer to needs and preferences that billing records do not measure and would require patient-reported data to be confirmed.

In relation to race/color, the larger share of the brown category among masculinizing authorizations, 61.0% against 42.6%, was observed in a comparison pooled over the whole period and not adjusted for period, procedure or establishment. Considering that the masculinizing group was concentrated in 2024-2025 and in mastectomy, this difference may reflect changes in the regional distribution of accredited services and in the composition of the recent series, since an independent analysis reported the largest number of mastectomies in the Northeast region [13]. This possibility is supported by the observation that, within 2024-2025, the brown category was recorded in 75.0% of mastectomies and in 63.6% of breast reconstructions, both above the pooled share of the feminizing group, although these procedure-specific figures were not adjusted for establishment. In addition, in the 2019 National Health Survey, private health insurance covered 38.8% of white people, against 21.4% of black and 20.1% of brown people [34], so that a greater dependence on the SUS among black and brown people may contribute to their larger share among publicly financed authorizations, a relationship that was not examined among trans people. For this reason, the finding was not interpreted as a racial disparity at the person level. It should also be noted that race/color recorded in hospital authorizations depends on recording practices that were not characterized and that the small number of authorizations recorded as black, 64 and 17, limits the analysis of this population, although black and brown people together accounted for the majority of authorizations in both groups. The interpretation of these categories requires attention to the local social context, as studies with patient-reported data have shown [17].

From the perspective of global public health, the findings suggest that administrative surveillance of publicly funded gender-affirming surgery may document the volume and . composition of billed care and raise questions for service planning, provided that indicators are disaggregated by procedure and that code definitions are versioned over time. The nearuniversal recording of a principal diagnosis in category F64 (97.7%) is consistent with the SIGTAP rule that accepts only F64.0, transsexualism, as the principal diagnosis for these procedures [23], a category that the ICD-10, still used in the SIH/SUS, places among mental disorders. The ICD-11 reconceptualized this category as gender incongruence and moved it to a chapter on sexual health [35, 36], so that the adoption of the ICD-11 by the information systems may require a revision of this rule that preserves access to care. The investigation of access, continuity of care and equity would require person-linked records, waiting-list denominators and patient-reported experiences [16]. Relative to previous Brazilian descriptions of policy and surgical volumes [2] [3] [4] [5] 13, 14], the contribution of the present study lies in the joint description of historically eligible procedure codes, recorded age and race/color and the procedure composition behind the recent convergence of counts, together with the reproduction of all aggregate results from the original public files.

The present study was limited to administrative episodes, and an authorization may recur for the same person, since no validated person-level linkage was available, while the direction of the procedure does not measure self-reported gender identity, sex assigned at birth, clinical indication or preference. Fields such as date of birth, sex and municipality of residence could support a probabilistic approximation of unique persons, an approach that was not adopted because it has not been validated for these records and would increase the risk of reidentification in small groups. For the same reason, it was not possible to estimate how many people completed the successive stages of masculinizing genital surgery. Eligibility rules, financing and recording practices changed over 2014-2025, the periods compared have unequal durations, and shifts in the feminizing share cannot be read as population rates or as effects of policy. The same-period age comparison reduces historical heterogeneity but does . not adjust for procedure or establishment, and race/color findings are pooled over the whole period, not adjusted and not confirmed as self-declared. The independent replay reproduced all aggregate results from the original files but cannot verify the clinical validity of the coding or the total care delivered, and the agreement with the national establishment register refers only to administrative geography, without information on place of residence or travel.

However, it should be noted that the use of all public files of the period, the historical versioning of procedure codes and the independent reproduction of the results allow other researchers to repeat and extend the analysis with the same public sources.

Conclusions

The study made it possible to identify that, in the SUS, the equal numbers of directly feminizing and masculinizing surgical authorizations in 2024-2025 corresponded to different procedure portfolios, with bilateral mastectomy accounting for 87.4% of masculinizing authorizations and breast reconstruction for 39.1% of feminizing authorizations. It was also observed that a difference of about five years in median recorded age persisted within the recent period, whereas the race/color differences remained pooled and unadjusted. These findings support procedure-specific and historically versioned monitoring of publicly funded gender-affirming surgery and indicate that conclusions about gender identity, individual demand or equity of access would require data on people and on their experiences of care.
