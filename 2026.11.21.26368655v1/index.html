Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

Power analyses need to contain the following information to be interpretable: the type of power analysis, the statistical test, the software used, sample size, critical alpha criterion, power level, effect size, and an effect size metric. In addition, it is recommended to make sure the power analysis is reproducible (by sharing the code, or a screenshot, of the power analysis), and to provide good arguments for why the study was designed to detect an effect of this size.

For an a-priori power analysis, where the sample size is determined, reporting all information would look like:

An a priori power analysis for an independent samples t-test, conducted using the pwr.t.test function from pwr (Champely, 2020), indicated that for a Cohen’s d = 0.5, an alpha level of 0.05, and a desired power level of 80% required at least 64 participants in each group.

For a sensitivity power analysis, this sentence would look like:

A sensitivity power analysis for an independent samples t-test, conducted using the pwr.t.test function from pwr (Champely, 2020), indicated that with 64 participants in each group, and an alpha level of 0.05, a desired power level of 80% was reached for an effect size of d = 0.5.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

When a statement is expected

The module sorts each paper by where its data came from (the internal .data_source(); the signs and how the rule was tested are described in R/data-source.R): - own: the authors collected data from people or animals, for this paper, in an earlier study of their own, or (a protocol) will collect them; - existing_records: records about individual people that the authors obtained for this study, such as hospital records or a cohort; - existing_unclear: existing data about people from a source the module could not identify; - open_resource: an open resource any researcher can use, such as UK Biobank or NHANES; - none: no data about people or animals (a review, simulation, commentary, theory, tutorial, coding of published papers, or figures about groups); - uncertain: the signs were missing or pointed both ways; - no_text: the paper has no text.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

This module was developed by Lisa DeBruine, Daniel Lakens and Cristian Mesquida

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. The information in the preregistration is returned. An AsPredicted link that could not be read is named in the report, with the reason.

The module can’t extract information from non-structured preregistration templates (i.e., where the preregistration is uploaded in a single text field) and it can’t retrieve information in preregistrations that are stored as text documents on the OSF.

If you want to extend the package to be able to download information from other preregistration sites, reach out to the Metacheck development team.

How Marginal Significance works

List all sentences that describe an effect as ‘marginally significant’.

The marginal module searches for regular expressions that match a predefined pattern. The list of terms is a subset of those listed in a blog post by Matthew Hankins. The module returns all sentences that match terms describing ‘marginally significant’ results.

Some of the terms identified might not be problematic in some contexts, and there are ways to describe ‘marginal significance’ that are not detected by the module.

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). Full text

Abstract

Epidemiological evidence linking sleep to Alzheimer disease (AD) relies predominantly on self-reported sleep, whereas cohorts with polysomnography (PSG) and cohorts with AD biomarkers rarely share participants. Multifractal long-range-interdependency representations classify obstructive sleep apnoea severity accurately across cohorts, but whether such a physiological fingerprint can be transported between cohorts, between measurement modalities or over time has not been evaluated. We propose four axes of transportability and test them in the Sleep Heart Health Study (n = 5,614), MESA Sleep (n = 2,012), ADNI (n = 2,286) and MrOS Sleep (2,911 men; 1,026 re-examined after 6.37 years; 3,928 scored nights). Axis A1, cross-cohort construct convergence, passed: PSG-derived Sleep Coupling Disruption Index loadings agreed between SHHS and MESA (cosine 0.986; Wasserstein distance 0.0487). Axis A2, incremental validity beyond the apnoea-hypopnoea index, failed: the fully adjusted hazard ratio for incident cardiovascular disease was 1.009 (95% CI 0.941-1.085; p = 0.83) and the C-index was 0.8079 with or without the index; in MrOS, adding a multifractal coupling fingerprint increased R-squared by 0.00058 (likelihood-ratio p = 0.399). Axis A3, proxy identifiability, failed: the reliability ratio linking portable subjective complaints to objective physiological burden was 1.95 x 10-5, with a bootstrap 95% upper bound of 0.00261 and 0.0027 for a semantically optimised proxy, far below the 0.25 floor required for measurement-error correction. Under classical error this implies a 370-fold sample-size inflation; Monte-Carlo power at n = 10,000 was 0.177. A nominally significant association between night-time behaviour and dementia severity would require an implausible true physiological effect of 28.7 standard deviations, and it reversed to -0.0554 after adjustment for total neuropsychiatric burden. The prespecified ADNI primary outcome, plasma pTau217, was null (beta = 0.0033, p = 0.911), as were the MrOS six-year cognitive complaint outcome (beta = -0.0204, p = 0.375) and a 35-event self-reported dementia endpoint (OR = 0.921, p = 0.679). Axis A4, temporal stability, failed: six-year test-retest reliability was r = 0.157 (95% CI 0.096-0.216) for the fingerprint versus r = 0.455 (0.405-0.502) for AHI, despite stable concurrent validity (rho = 0.380 and 0.328 with same-night AHI). Spearman-Brown projection indicates that approximately nine nights must be averaged for the fingerprint to reach a reliability of 0.60, compared with two for AHI. A fingerprint can therefore be reproducible without being transportable. We provide a four-question decision workflow and an eight-item minimum reporting set; subjective sleep complaints should not be substituted for objective sleep physiology in aetiological inference.

Introduction

Slow-wave sleep facilitates interstitial solute clearance [2, 3], amyloid and tau deposition disturb sleep architecture [4], and cohort studies link sleep-disordered breathing and nocturnal hypoxaemia to mild cognitive impairment and dementia [5, 6]. Loss of slow-wave sleep predicts incident dementia in community cohorts [7], and obstructive sleep apnoea has been related to longitudinal amyloid accumulation [8]. The AT(N) framework now permits these hypotheses to be tested against plasma and PET biomarkers in vivo [9, 10]. The biological case for a sleep-AD relationship is therefore well established; the epidemiological difficulty is measurement.

Two structural problems recur. First, the large PSG cohorts that contain objective physiology -the Sleep Heart Health Study (SHHS) [11], MESA Sleep [12] and the National Sleep Research Resource more generally [13] -do not assemble cognitive or dementia outcomes, whereas AD cohorts such as ADNI [14] assemble plasma pTau217, amyloid and tau PET, MRI, cognitive composites and conversion endpoints but no PSG or actigraphy. No participant-level identifier is shared. Second, when a sleep variable is available in an AD cohort it is usually an informant-rated questionnaire item such as the night-time behaviour domain of the Neuropsychiatric Inventory (NPI-K) [15, 16]. Subjective and objective sleep measures disagree systematically [17, 18], so an association with a complaint item cannot be read as an effect of physiological sleep burden. The magnitude of the resulting exposure misclassification has rarely been quantified.

A third, newer problem concerns the representation of the physiological signal itself. Wang and colleagues [1] represented multichannel sleep signals as multifractal long-range-interdependency coupling matrices and classified apnoea severity with high accuracy across five cohorts, including SHHS and MESA. They identified extension beyond respiratory phenotyping as future work. Diagnostic accuracy, however, is a cross-sectional property. Before such a representation is used as a prognostic exposure, as a proxy in a cohort lacking PSG, or as a biomarker of a stable trait, its transportability must be established on at least four axes: convergence of the constructed phenotype across cohorts; incremental information beyond conventional indices; identifiability when only a proxy is measured; and stability over the intended prediction horizon. None of these is guaranteed by high classification accuracy.

We therefore executed a prespecified, real-data evaluation of these four axes across four cohorts. The programme produced predominantly null association results, which we report in full [31]. Its positive contribution is quantitative: we bound the reliability of subjective proxies for objective sleep burden, translate that bound into attenuation, sample-size and bias-re-estimation consequences, quantify the stateversus-trait behaviour of a multifractal coupling fingerprint over 6.4 years, and convert all of this into a decision workflow and a minimum reporting set for future sleep, cognition and signal-processing studies [30].

Methods

2.1 Design and the four-axis framework

Four axes were defined before the synthesis (Fig 1B). A1, cross-cohort construct convergence, was considered satisfied when independently fitted component loadings agreed at cosine >= 0.90 and standardised score distributions had Wasserstein distance <= 0.10. A2, incremental validity, required a positive gain in discrimination or R-squared over a model already containing demographics, comorbidity and the apnoea-hypopnoea index (AHI), with likelihood-ratio p < 0.05. A3, proxy identifiability, required a reliability ratio lambda >= 0.25 for SIMEX or regression calibration [19, 20]; 0.25 was the prespecified floor in the analysis plan and corresponds to an at most four-fold sample-size penalty. A4, temporal stability, required test-retest r >= 0.60 over the prediction horizon, the conventional threshold for grouplevel reliability [23]. Thresholds are pragmatic rather than universal; we report observed-to-threshold ratios for every axis so that readers may apply stricter criteria.

2.2 Data sources and archive integrity

2.3 Stage 1: index construction, convergence and incremental validity

Seven PSG-derived components, each oriented so that larger values indicate more decompensation, were winsorised at the 1st/99th percentile, residualised on age, sex and race/ethnicity within cohort and standardised on SHHS moments: log1p(AHI), log1p(percent of total sleep time with SpO2 < 90%), 100 minus minimum SpO2, log1p(arousal index), log1p(WASO), 100 minus sleep efficiency, and log1p(|REM AHI -NREM AHI|) as a state-dependence term. A one-component PCA fitted in SHHS defined the Sleep Coupling Disruption Index (SCDI); the fit was repeated independently in MESA.

Predictive validity used Cox models for incident CVD and CVD death in SHHS with censdate as time since baseline, adjustment for age, sex, race, BMI, smoking, hypertension, systolic pressure, diabetes and education, and exclusion of prevalent CVD. The protocol prespecified that absence of an AHI or CVD association would trigger a weight re-examination: no age adjustment; orthogonalisation of all components on log1p(AHI) followed by PCA of residuals, alone or blended with AHI; log1p(AHI) alone; and, as a post-hoc contrast, multifractal detrended fluctuation analysis [24, 25] of 5-min cardiac interbeat series with detrended cross-correlation analysis [26] between HRV channels to obtain a long-range coupling fingerprint. The last analysis is explicitly exploratory (n = 310, 46 events).

2.5 Stage 3: ADNI association and specificity analyses

The exposure was baseline NPI-Q night-time behaviour burden (NPIKSEV when NPIK was endorsed, 0 otherwise), z-standardised; NPIK = 2, -1 and NPIKSEV = -4 were treated as missing codes. A dictionary audit identified richer phenotypes: NPI sub-items NPIK1, NPIK2, NPIK7 and NPIKTOT, clinician-rated insomnia in BLSCHECK/ADSXLIST, and insomnia history in INITHEALTH. NPI uses a skip pattern, so sub-items are unasked when the domain is not endorsed; treating these as missing produced a symptomatic-only subsample and implausible effect sizes (MMSE beta = 32). All refined analyses coded unendorsed domains as zero symptoms. Outcomes were harmonised plasma pTau217 (prespecified primary), pTau181, Abeta42, Abeta40, total tau, CSF Abeta42 and pTau181, Centiloid and amyloid status, tau PET meta-temporal SUVR, FLAIR WMH, SPARE-AD, hippocampal volume/ICV, PHC memory and executive composites, MMSE, CDR sum of boxes, ADAS-Cog 13 and MoCA. Crosssectional models adjusted for age, sex, education, race and baseline diagnosis; extended models additionally adjusted APOE4 dose, polygenic hazard score, BMI and depressive symptoms. Benjamini-Hochberg FDR was applied within each outcome family. Linear mixed models estimated night-time burden x time interactions; Cox models estimated MCI-to-AD conversion. Specificity analyses added total NPI score; within-subject analyses demeaned exposure, outcome and visit month by participant and additionally adjusted visit-time trends and total NPI. Head motion (FD_postscrub) was a negative-control outcome. Measurement-error correction used an analytic lambda grid (0.05-0.75) and a Bayesian latentvariable sensitivity analysis with a Stage-2-informed prior.

2.6 Stage A: individual-level repeated PSG in MrOS

MrOS Sleep Visit 1 comprised 2,911 men (76.36 +/-5.47 years) with in-home PSG; Visit 2 re-examined 1,026 after 6.37 +/-0.98 years with repeat PSG. Each annotation file lists scored events with start time, duration and, for desaturations, SpO2 nadir and baseline. Events were mapped onto a common 30-s epoch axis to form five aligned channels: desaturation amplitude, respiratory-event count, arousal count, periodic-limb-movement count and scored sleep stage. MF-DFA [24, 25] with second-order polynomial detrending over 8-10 log-spaced scales and q from -5 to +5 yielded the generalised Hurst exponent h(q), the q = 2 Hurst exponent and the multifractal spectral width; DCCA [26] between channels produced a 5 x 5 coupling matrix whose spectral radius, mean absolute off-diagonal coupling, maximum coupling and Fiedler value constituted the fingerprint.

Event-interval series were supplementary. Completed features were obtained for 3,928 of 3,932 nights (99.9%). The prespecified primary model regressed Visit-2 sleeprelated cognitive/functional interference on baseline z-standardised LRI spectral radius with HC3-robust ordinary least squares, adjusting for demographics, comorbidity, follow-up interval, baseline sleep complaint and conventional AHI. Twenty-five exposures were tested against nine outcome families with within-family FDR correction; incremental value was quantified by delta-R-squared and likelihood-ratio tests. Rare binary endpoints used Firth-penalised logistic regression [27] with standard errors from an explicit numerical Hessian of the penalised negative log-likelihood; a BFGS inverse-Hessian approximation had produced spuriously narrow intervals at 35 events and was discarded. Twelve sensitivity analyses, two negative-control outcomes, an attrition model, positive controls, historyconsistency checks and cross-visit test-retest reliability were prespecified. The public MrOS release contains no objective cognitive test, AD biomarker or adjudicated dementia outcome; published MrOS analyses of cognitive decline [28, 29] use data not distributed here.

2.7 Stage D: quantitative synthesis

Four derived quantities turned the null association results into transferable methodological statements.

First, under classical measurement error with W = X + U, lambda = Var(X)/Var(W), the observed regression slope is attenuated to beta_obs = lambda x beta_true and the sample size required for a fixed power is inflated by 1/lambda. Required sample size was computed as n = (z_alpha/2 + z_beta)^2 / (beta_true^2 x lambda) for standardised variables, for beta_true in (0.10, 0.20, 0.30) and lambda in (0.0027, 0.0192, 0.05, 0.10, 0.25, 0.50, 0.75, 1.00). Second, bias re-estimation inverted the attenuation: an association reported for a proxy, forbidden to be interpreted as physiological, would require beta_true = beta_obs / lambda. We applied this to the observed CDR sum-of-boxes estimate and to hypothetical published standardised effects of 0.10-0.30. Third, Spearman-Brown projection, r_k = k r / (1 + (k -1) r), gave the number of exchangeable nights that must be averaged for a measure with observed six-year reliability r to reach 0.60 or 0.80 [23]. Fourth, Monte-Carlo simulation validated the algebra: for each lambda and n (862, 2,000, 10,000), 600 replicates of X ~ N(0,1), Y = 0.2 X + epsilon, W = X + U with Var(U) = (1 -lambda)/lambda were fitted by ordinary least squares; empirical power and the mean observed slope were recorded. Simulation output is reported only as a validity check and is labelled as such throughout.

Results

3.1 Cohorts and data integrity

Complete SCDI components were available for 5,614 SHHS and 2,012 MESA participants. The ADNI NPI-Q baseline sample comprised 2,286 participants (16.5% with any night-time behaviour disturbance), of whom 862 had plasma pTau217. MrOS contributed 2,906 Visit-1 and 1,022 Visit-2 nights with fingerprints and 1,021 men with two PSGs. All 12 dataset CSV and 3,932 annotation XML files were recovered from intact archive volumes (Table 1).

3.2 A1: the construct replicates across cohorts

PCA loadings fitted independently in SHHS and MESA were nearly identical (cosine 0.986), explaining 39.8% and 43.2% of standardised variance; the standardised SCDI distributions had Wasserstein distance 0.0487 (Fig 2A). SCDI correlated strongly with AHI (rho 0.792 SHHS, 0.846 MESA) and hypoxic time (0.793, 0.871), moderately with arousal index (0.449, 0.477) and weakly with Epworth sleepiness (0.071, 0.067) (Fig 2B). SCDI tertiles were monotonically related to BMI (26.2, 27.7, 30.6 kg/m2) and AHI (4.4, 11.6, 27.7 events/h). A1 therefore passed.

3.3 A2: reproducibility does not create incremental information

Among 3,776 SHHS participants without prevalent CVD and 754 incident events, the fully adjusted HR per SD of SCDI was 1.009 (95% CI 0.941-1.085; p = 0.83; C = 0.8079). Replacing SCDI with log1p(AHI), or adding both, did not change discrimination (C = 0.8079). All four prespecified reweightings and the pure AHI model produced HR between 1.007 and 1.011 with C between 0.8079 and 0.8099 (Fig 2C, D). The post-hoc HRV long-range coupling fingerprint was the only significant variant (HR 1.466, 95% CI 1.095-1.964; p = 0.010; bootstrap 95% CI 1.047-2.223; C 0.8049 to 0.8184; likelihood-ratio p = 0.0118), and was essentially orthogonal to AHI (rho = -0.037); it remains exploratory at 46 events. In MrOS, adding the LRI spectral radius to a model already containing demographics, comorbidity and AHI increased R-squared by 0.00058 (likelihood-ratio p = 0.399); mean coupling added 0.00237 (p = 0.088). A2 failed.

3.4 A3: the proxy is not identifiable, with quantitative consequences

Portable insomnia complaints did not predict SCDI (beta = +0.0044; p = 0.85; cross-validated R-squared = -0.0059; n = 1,995; Fig 3A). The bootstrap distribution of lambda had point estimate 1.95 x 10-5 and 95% CI upper bound 0.00261; the semantically optimised NPI-K-aligned model gave 0.0027 and the best subjective model of any kind gave 0.0192, all far below the 0.25 floor (Fig 3B). Under classical measurement error this implies attenuation to 0.27% of the true slope and a 370-fold sample-size inflation: for beta_true = 0.20 and 80% power, n rises from 196 to 72,674 (Fig 3C). Monte-Carlo simulation reproduced the expected slope (0.00057 observed versus 0.00054 theoretical at lambda = 0.0027) and showed that power reaches only 0.177 at n = 10,000, versus 1.000 when lambda = 1 (Fig 3D).

Re-estimating published proxy associations gave implausible requirements (Fig 3E). The nominally significant CDR sum-of-boxes association (beta = 0.0775; p = 5.6 x 10-5) would require a true physiological effect of 28.7 SD at lambda = 0.0027, or 29.6 SD at the bootstrap upper bound; hypothetical published effects of 0.10-0.30 SD would require 37-111 SD. No value lies within the plausible range.

Consistent with confounding rather than physiology, the CDR-SB estimate reversed to -0.0554 after adjustment for total NPI burden, and the strong within-person estimate (0.3093) fell to 0.2196 after controlling shared visit-time trends and to -0.0086 (p = 0.783) after additionally adjusting total NPI (Fig 4B). Analytic measurement-error correction was correspondingly uninformative: the corrected 95% CI widened from 0.46 at lambda = 0.25 to 2.30 at lambda = 0.05 and is unbounded at the observed lambda (Fig 3F). A3 failed.

3.5 ADNI primary and secondary outcomes

Night-time behaviour was not associated with plasma pTau217 (beta = 0.0033 per SD; 95% CI -0.0542 to 0.0608; p = 0.911; q = 0.911; n = 862), nor with plasma pTau181, Abeta42, the Abeta42-Abeta40 contrast, CSF markers, Centiloid (beta = -1.027; p = 0.272), tau PET, WMH, SPARE-AD, hippocampal volume/ICV, cognitive composites, MMSE, MoCA or ADAS-Cog 13 (Fig 4A). Linear mixed models showed no exposure x time interaction for memory (p = 0.704; 11,990 observations) or executive function (p = 0.922). MCI-to-AD conversion gave HR 1.098 (0.979-1.232; p = 0.111). Of 55 tests on the refined sleep phenotypes, 19 reached nominal p < 0.05 but most pointed opposite to the hypothesis; the most consistent finding was an association with depressive symptoms, compatible with informant-reporting bias. Thirteen sensitivity and stratified analyses left the primary null estimate unchanged (S1 Fig).

In 1,021 men with two PSGs, LRI spectral radius correlated r = 0.157 (95% CI 0.096-0.216; Spearman rho = 0.139) across 6.37 years, whereas conventional RDI 3% correlated r = 0.455 (0.405-0.502; rho = 0.490) in 1,026 men (Fig 5A, B). 4.2 Reproducibility is not transportability

Cosine similarity of 0.986 between independently fitted loading vectors is a strong result and is worth reporting. It is also the least informative of the four axes, because the same linear combination of correlated respiratory events will emerge from any cohort with similar PSG scoring rules. High diagnostic accuracy in a cross-sectional task [1] is likewise compatible with failure on A2-A4. We therefore suggest that studies reporting a novel sleep phenotype separate construct replicability from transportability, and that the latter be treated as conjunctive: the observed-to-threshold ratios in Table 2 make explicit how far each axis falls short.

4.3 Quantitative re-estimation of the subjective-proxy literature

The most transferable result of this programme is a bound. Subjective insomnia complaints cannot recover objective PSG burden: lambda is at most 0.0027 even under the most favourable alignment, and its bootstrap upper bound is 0.00261. Under classical measurement error, a reported standardised effect of 0.10 with such a proxy cannot be a physiological effect -it would require a true effect of 37 SD. The observed CDR sum-of-boxes association in ADNI is a worked example: nominally strong (p = 5.6 x 10-5), it reversed after adjustment for total NPI burden and disappeared in within-person models once shared visit-time trends were accounted for. NPI-K is a component of the total NPI score and is rated by an informant whose assessment changes with disease severity. Studies that use NPI-K as a sleep variable should adjust for total NPI and depression and should distinguish informant-reported from self-reported symptoms. More generally, the discrepancy between subjective and objective sleep measures [17, 18] should be treated as a quantified reliability problem rather than a qualitative caveat.

4.4 State markers, traits and the number of nights

The MrOS repeated-PSG analysis clarifies which part of the LRIA idea transfers. The multifractal coupling fingerprint retained concurrent validity with same-night AHI at both visits (rho = 0.380 and 0.328) but showed weak between-person stability over 6.4 years, whereas AHI was roughly three times more stable. Night-to-night variability in apnoea severity and physiological endotypes is well documented [21, 22] and predicts clinical outcomes independently of a single-night AHI [22]; our result extends this from conventional indices to multifractal coupling features. The practical consequence is that a coupling fingerprint computed from one night should be described as a state marker. Using Spearman-Brown projection, roughly nine exchangeable nights are needed for this fingerprint to attain a reliability of 0.60, and 22 for 0.80, against two and five for AHI. Repeated-night averaging, not reweighting of derived indices, is the more defensible route to a trait-level exposure. The exploratory SHHS finding that an HRV long-range coupling fingerprint predicted incident CVD independently of AHI (HR 1.466, 46 events) is consistent with the view that long-range temporal structure carries information that event counts do not, but it requires external replication before it can be used to argue for prognostic value.

4.5 A decision workflow and reporting set

Fig 6A turns the four axes into four sequential questions. In these data the workflow stops at Q2: the fingerprint adds nothing beyond conventional severity, so even a reliable proxy or a stable trait would not rescue the inference. Table 5 and Fig 6B give the corresponding minimum reporting set. Three items are easy to omit and costly to omit. First, rare-event analyses must verify their standard-error implementation: an earlier run of our own pipeline used a BFGS inverse-Hessian approximation and produced an apparent p = 5.2 x 10-5 that became p = 0.733 with an explicit numerical Hessian.

Second, self-reported lifetime disease history should be checked for reversals before defining incident endpoints; 14-38% of baselinepositive histories reverted in MrOS, and positive controls were null, so we classify that replication arm as indeterminate instead of negative. Third, informant-rated exposures should be adjusted for global symptom burden and shared time trends, as in the CDR-SB analysis. Reporting null results in full remains necessary for the evidence base [31].

4.6 Limitations

The public MrOS Sleep release contains no objective cognitive test, AD biomarker, dementia adjudication, dated events or mortality follow-up; all cognitive endpoints used here are self-reported and the dementia endpoint has 35 events. This study therefore cannot determine whether objectively measured sleep physiology predicts AD pathology, and our null MrOS results should not be read as evidence against the sleep-AD hypothesis. MrOS cognitive data exist [28, 29] and should be obtained from the coordinating centre; the 3,928 per-night features and all merging code can then be reused. ADNI has no PSG or actigraphy, and plasma/PET measurements were not always contemporaneous with the NPI assessment (244 identical-visit pairs). Population differences between community-based MESA/SHHS and the largely non-Hispanic White ADNI clinical cohort limit comparability. We did not recompute the full LRIA representation from raw waveforms; the fingerprint here is derived from scored event annotations, an intentional and reproducible simplification. The derivation of sample-size inflation assumes classical, non-differential measurement error and a single standardised exposure; differential error, as is likely with informant reporting, may bias in either direction and our 370-fold figure should be read as a lower bound on the problem rather than an exact correction. Complete-case analysis was used; multiple imputation, mediation and competing-risk models were not performed because primary effects were null. The HRV result is exploratory and based on 46 events. Finally, our thresholds (cosine 0.90, lambda 0.25, r 0.60) are pragmatic; the observed-to-threshold ratios are reported so that the framework can be re-evaluated under stricter criteria.

Conclusions

Reproducibility is not transportability. A PSG-derived multifractal coupling fingerprint replicated almost identically in two independent cohorts (cosine similarity 0.986) and carried information within a single night, yet failed the three tests that would justify moving it into an Alzheimer disease cohort: it added no prognostic value beyond AHI (Cox HR 1.009, p = 0.83; C-index 0.8079 for both models), could not be reconstructed from subjective complaints, and was only weakly stable over 6.4 years (r = 0.157 versus 0.455 for AHI). One of four axes passed. These results do not argue against a sleep-AD relationship; they delimit what can be inferred from these four cohorts. With the exposures, proxies and follow-up available here, the phenotype is not identifiable across cohorts, modalities or long prediction horizons, and an apparently strong association with a subjective sleep item is more parsimoniously explained by shared neuropsychiatric burden and visit-time trends than by sleep physiology.

The transferable output is a set of quantitative boundaries rather than a positive association. Three are hard enough to serve as design constraints. First, the reliability ratio linking subjective complaints to objective PSG burden stayed below 0.003 for any portable measure (point estimate 1.95 x 10-5; bootstrap upper bound 0.00261), which inflates the sample size needed to detect a standardised effect of 0.20 from 196 to 72,674 -a 370-fold penalty. Second, re-expressing the naive CDR-SB association as a physiological effect would require a true effect of 28.7 SD, outside the plausible range. Third, a single night of the coupling index behaves as a state rather than a trait, requiring nine nights of averaging to reach r = 0.60 and 22 nights to reach 0.80. MESA

Sleep contains both subjective questionnaires and objective PSG and therefore served as the calibration set. The portable complaint score was the mean of four z-scored Women's Health Initiative Insomnia Rating Scale items (difficulty falling asleep, frequent night waking, early awakening, difficulty returning to sleep). Four calibration models were fitted: the portable score; the first principal component of a 16-item subjective battery; physician-diagnosed insomnia alone; breathing symptoms alone; and a semantically optimised alignment that mapped MESA items onto the ADNI NPI-K sub-items NPIK1, NPIK2 and NPIK7. Ten-fold cross-validated R-squared and the partial R-squared attributable to the complaint were computed. The reliability ratio lambda = Var(E[SCDI | W]) / Var(SCDI), estimated as beta^2 Var(W) / Var(SCDI), is the quantity required for SIMEX and regression calibration. For the present synthesis we additionally obtained a nonparametric bootstrap distribution of lambda from 2,000 subject-level resamples of the calibration data.
