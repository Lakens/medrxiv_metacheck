Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (e.g., “decreased at the p < .05 significance threshold”).

To check Non-Significant P Value Check

What we found

We found 12 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Power analyses need to contain the following information to be interpretable: the type of power analysis, the statistical test, the software used, sample size, critical alpha criterion, power level, effect size, and an effect size metric. When a statement is expected

The module sorts each paper by where its data came from (the internal .data_source(); the signs and how the rule was tested are described in R/data-source.R): - own: the authors collected data from people or animals, for this paper, in an earlier study of their own, or (a protocol) will collect them; - existing_records: records about individual people that the authors obtained for this study, such as hospital records or a cohort; - existing_unclear: existing data about people from a source the module could not identify; - open_resource: an open resource any researcher can use, such as UK Biobank or NHANES; - none: no data about people or animals (a review, simulation, commentary, theory, tutorial, coding of published papers, or figures about groups); - uncertain: the signs were missing or pointed both ways; - no_text: the paper has no text.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

This module only checks statistical results reported in the running text of the manuscript. It cannot (yet) process statistics reported only in tables.

This module was developed by Daniel Lakens and Lisa DeBruine

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Bulk-tissue transcriptome-wide association studies (TWAS) have identified colorectal cancer (CRC) susceptibility genes, but cell-type-specific regulatory mechanisms remain poorly understood. Here, we performed single-cell TWAS integrating matched germline genotypes and single-cell transcriptomes from normal colorectal mucosa (381 donors) and polyps (84 donors), cell-type-specific chromatin accessibility, and GWAS from 132,261 cases and 1,752,398 controls. We identified 546 gene-cell-type associations implicating 347 candidate susceptibility genes across seven normal and nine polyp epithelial populations, including 213 previously unreported genes, with 74% exhibiting cell-type-specific associations. Integrated co-expression and ChIP-seq analyses revealed distinct TF-risk gene networks, highlighting GATA6, MAX and RAD21 in normal mucosa, and TFAP4-and CEBPB-associated networks in premalignant polyp populations. Further multi-omics analyses supported dysregulation of 233 genes (67%), while drug-target analyses identified 63 potentially druggable genes. Introduction

Genome-wide association studies (GWAS) have identified approximately 250 loci associated with colorectal cancer (CRC) susceptibility, providing important insights into the inherited genetic architecture of this malignancy [1] [2] [3] . However, translating these associations into the genes, cellular contexts and regulatory mechanisms underlying CRC susceptibility remains a major challenge. Most CRC-associated variants reside in noncoding genomic regions and are thought to influence disease risk by altering gene regulatory mechanisms, including transcription factor (TF) binding, chromatin accessibility, and cis-regulatory control of gene expression 4, 5.

Transcriptome-wide association studies (TWAS), which integrate genetically regulated gene expression (GReX) with GWAS, offer a systematic approach to identify candidate susceptibility genes 6, 7 . Previous CRC TWAS and other omics-based association studies [8] [9] [10] [11] [12] [13] [14] have implicated more than 500 genes, advancing our understanding of the genetic basis of CRC susceptibility. Despite these advances, previous studies have relied predominantly on GReX models trained in bulk normal colorectal tissue, potentially obscuring genetic regulatory effects restricted to specific epithelial populations or exhibiting opposing effects across cell types. Because regulatory variant activity is shaped by cell-type-specific chromatin accessibility and TF activity, bulk-derived models may overlook susceptibility genes and regulatory mechanisms operating within distinct epithelial states. Furthermore, genetic regulation in premalignant colorectal epithelialelium remains largely unexplored. CRC commonly develops from conventional adenomas or serrated polyps, which follow partially distinct molecular pathways toward malignancy [15] [16] [17] . The transition from normal mucosa to premalignant lesions involves extensive remodeling of epithelial differentiation programs, cellular composition, chromatin accessibility and transcriptional regulatory networks 15, [18] [19] [20] . These changes may expose context-dependent genetic effects that are undetectable in normal tissue. Integrating both normal and premalignant epithelial populations into TWAS therefore strengthen the discovery of susceptibility genes and regulatory mechanisms associated with colorectal tumorigenesis.

Advances in population-scale single-cell RNA sequencing (scRNA-seq) coupled with germline genotyping now enable GReX modeling within defined cellular populations 11, 21.

Incorporating cell-type-specific chromatin accessibility can further prioritize genetic predictors within biologically relevant regulatory regions, potentially improving model interpretability and the resolution of susceptibility-gene discovery 17 . Moreover, integrating cell-type-specific TWAS associations with TF-centered regulatory networks may reveal how inherited susceptibility genes are organized across normal and premalignant epithelial states 14, 22, 23 . Here, we developed a single-cell TWAS (scTWAS) framework integrating matched germline genotypes and single-cell transcriptomes from normal colorectal mucosa (381 donors) and polyps (84 donors), together with cell-type-specific chromatin accessibility data. We constructed GReX models across seven normal and nine polyp epithelial populations and integrated these models with European-ancestry and multi-ancestry CRC genetic association data comprising up to 132,261 cases and 1,752,398 controls. We further investigated cell-type-specific TFsusceptibility gene networks and integrated additional single-cell, spatial transcriptomic, bulk transcriptomic and proteomic evidence with drug-target annotations, cancer-dependency data 4 and CRISPR-Cas9 perturbation analyses. This integrative framework resolves CRC susceptibility associations across distinct epithelial populations, identifies candidate TF-risk gene regulatory networks associated with premalignant states and prioritizes susceptibility genes with potential functional and translational relevance for CRC prevention.

Results

A cell-type-specific scTWAS framework

We developed a scTWAS framework integrating scRNA-seq, germline genotype and cell-type-resolved chromatin-accessibility data from normal colorectal mucosa and colorectal polyps (Fig. 1a; Supplementary Table 1). For each epithelial population, we aggregated singlecell expression profiles at the donor level and trained GReX models using variants located within cell-type-matched accessible chromatin regions 23.

For normal colorectal mucosa, we analyzed matched scRNA-seq and genotype data from 381 individuals, comprising two cohorts of 103 participants from the Human Tumor Atlas Network (HTAN) COLON MAP 24 and Gut Cell Atlas studies 25 and 278 from the Wellcome Sanger Institute IBDverse cohort 21 (Fig. 1a; Supplementary Table 2). We built GReX models for each of seven epithelial populations: absorptive (ABS), crypt-top (CT), enteroendocrine (EE), goblet (GOB), stem (STM), transit-amplifying (TAC) and tuft (TUF) cells (Extended Data Fig. 1a, 1b). Annotations from the COLON MAP normal-colon dataset served as the reference, and published labels from the other datasets were harmonized to these seven populations (Supplementary Table 3). Cell-type-specific accessible chromatin regions was defined using scATAC-seq resources from our normal-colon dataset 26 and the Stanford HTAN colorectal atlas 17 , and merged for cell populations represented in both datasets (Methods; Supplementary Table 4). The resulting annotations contained 55,454-152,781 accessible regions across epithelial populations (Extended Data Fig. 1c; Supplementary Table 4) and were used to define the candidate regulatory variants for GReX prediction.

For colorectal polyps, we analyzed matched scRNA-seq and genotype data from 84 participants in the HTAN COLON MAP 24 study. Nine epithelial populations were defined, including the seven presented in normal mucosa plus adenoma-specific cells (ASC) and serrated-polyp-specific cells (SSC) (Extended Data Fig. 1d). Accessible chromatin regions in polyp epithelial populations were defined by integrating our polyp scATAC-seq dataset with scATAC-seq data from 48 adenomas in the Stanford HTAN atlas (Methods). Across the nine populations, the resulting annotations comprised 13,061-188,833 accessible regions (Extended Data Fig. 1e; Supplementary Table 4).

Under our sTF-TWAS, we developed cell-type-specific GReX prediction models using matched single-cell RNA-seq and genotype data (Methods; Extended Data Figs. 2 and 3). We integrated the cell-type-specific GReX models with summary statistics from two CRC GWAS meta-analyses: a European-ancestry analysis of 99,260 cases and 1,119,512 controls and a multi-ancestry analysis of 132,261 cases and 1,752,398 controls, which combined previously published CRC GWAS results 1 , with new data from BioVU 27 , the Million Veteran Program 28 , FinnGen release 13 29 , the UCLA ATLAS Community Health Initiative 30 , the Michigan Genomics Initiative Freeze 6 31 and the Taiwan Precision Medicine Initiative 32 (Methods; Extended Data Figs. 2 and 3; Supplementary Table 5). Significant associations from scTWAS analyses were further evaluated using Bayesian colocalization 33 and summary-data-based Mendelian randomization with the heterogeneity in dependent instruments test (SMR-HEIDI) 34 . We then evaluated prioritized genes across complementary regulatory and functional evidence layers (Fig. 1b-d): cell-type-specific TF-target networks anchored on 51 previously identified CRC susceptibility-associated TFs 23 (Supplementary Table 6); differential analyses using independent single-cell, spatial, TCGA-COAD 35 and CPTAC-COAD 36 datasets spanning normal mucosa to carcinoma, and assessed therapeutic relevance using DrugBank 37 , ChEMBL 38 , Therapeutic Target Database 39 , and Open Targets 40 , together with transcriptional signaturereversal analyses. Finally, we evaluated cancer dependency using DepMap 41 and performed experimentally tested selected genes using CRISPR-Cas9 (Fig. 1e). Accessions, versions and access conditions of all resources are listed in Supplementary Table 1.

Cell-type-specific susceptibility genes in normal colon epithelium cells

Across the model training in seven normal-colon populations in the two cohorts, 2,305-8,720 genes per cell type met prediction-performance criteria (cross-validated R² > 0.01) and were retained for downstream association analyses (Methods; Extended Data Fig. 4a).

Association P values obtained independently from the two cohorts were combined with the Cauchy combination test (Methods). Integrating the models with the European-ancestry CRC GWAS meta-analysis, we identified 305 gene-cell-type associations at cell-type-specific Bonferroni-corrected P < 0.05: 69 in ABS, 42 in CT, 14 in EE, 66 in GOB, 53 in STM, 42 in TAC and 19 in TUF cells (Fig. 2a-g; Supplementary Table 7). Of these, 105 had additional evidence supporting a shared genetic signal between gene expression and CRC risk, defined by either strong colocalization (PP.H4 > 0.8) or significant SMR with no evidence of heterogeneity by HEIDI (Methods; Supplementary Table 7). Applying the same models to the multi-ancestry CRC GWAS identified 92 additional gene-cell-type associations beyond those detected in the European-ancestry analysis, comprising 24 in ABS, 14 in CT, 3 in EE, 16 in GOB, 20 in STM, 9 in TAC and 6 in TUF cells (Extended Data Fig. 5; Supplementary Table 8), 28 of which had colocalization or SMR-HEIDI support.

In total, the European-ancestry and multi-ancestry analyses identified 397 gene-cell-type associations involving 241 unique genes in normal colorectal epithelium (Supplementary Tables 7 and 8). Of these genes, 127 had not previously been implicated by CRC genetic studies [1] [2] [3] [8] [9] [10] [11] [12] [13] [14] , substantially expanding the set of candidate susceptibility genes and resolving their genetically regulated effects across defined epithelial populations. The strongest associations were at 11q23.1, where COLCA1 (EUR P = 9.3 × 10⁻⁵⁰, STM), COLCA2 (P =2.4 × 10⁻⁴⁸) and C11orf53 (P = 1.9 × 10⁻⁴⁷) were each significant in at least four epithelial populations with colocalization support. In total 35 genes were highlighted in a single cell population with colocalization or SMR-HEIDI support, 17 of them previously unreported, including ZNF142 in 6 crypt-top cells (P = 1.8 × 10⁻¹⁵, PP.H4 = 0.90) and CD200R1 in tuft cells (P = 2.8 × 10⁻¹², SMR P = 9.9 × 10⁻⁴). These cell-type-restricted signals highlight susceptibility genes that may be obscured in bulk-tissue analyses.

Cell-type-specific susceptibility genes in colorectal polyps cells

We next conducted scTWAS to colorectal polyps based on model training from 84 individuals. Across the nine cell-type-specific models, a median of 1,227 genes per cell type met the prediction-performance criteria (Extended Data Fig. 4b). Integrating with the Europeanancestry CRC GWAS, we identified 109 gene-cell-type associations at Bonferroni-corrected P < 0.05: 21 in ASC, 10 in SSC, 31 in ABS, 23 in GOB, 9 in STM and 10 in TAC cells, with an additional 5 associations across EE, CT and TUF cells (Fig. 3a-f; Supplementary Table 9).

Twenty-one associations were supported by colocalization or SMR-HEIDI, including 10 in ABS, 4 in GOB, 2 in STM, 2 in TAC, and 3 in other cell populations. The multi-ancestry analysis identified an additional 40 associations, six of which were supported by colocalization or SMR-HEIDI (Extended Data Fig. 6; Supplementary Table 10). The polyp models therefore yielded 149 associations involving 137 unique genes, 94 of which had not been implicated previously 1- 3,8-14.

Combining all 16 epithelial models, we identified 546 gene-cell-type associations involving 347 unique CRC susceptibility genes, 213 of which had not been implicated previously [1] [2] [3] [8] [9] [10] [11] [12] [13] [14] . Among the seven cell populations represented in both tissue stages, 397 associations were found in normal mucosa and 102 in polyps, and only 17 associations involving 15 genes were shared (Fig. 4a). The lesion-restricted ASC and SSC models contributed a further 32 and 15 associations, respectively, with no gene shared between them.

Overall, 258 genes (74%) were prioritized in only one epithelial population, indicating substantial cell-type specificity (Fig. 4a; Supplementary Table 11).

Susceptibility TFs organize risk genes into cell-type-specific regulatory networks

To investigate whether susceptibility associations converge on shared transcriptional regulators, we analyzed 51 previously identified CRC susceptibility-associated TFs 14 , integrating TF-risk gene co-expression in donor-level pseudobulk profiles with TF ChIP-seq occupancy at GReX lead variants (Methods). Co-expression analyses identified 982 TF-gene pairs in normal mucosa and 415 in polyps (Pearson's r > 0.5; FDR < 0.05), involving 131 and 95 susceptibility genes, respectively (Supplementary Table 14; Extended Data Fig. 7a,c). ChIP-seq analyses identified 226 GReX lead variants overlapping TF-binding peaks, providing occupancy support for 160 of 241 susceptibility genes in normal mucosa and 93 of 137 in polyps (Supplementary Table 15; Extended Data Fig. 7b,d). These variants overlapped binding peaks for a median of 11 and 8 TFs, respectively, with POLR2A, RAD21, JUND and SP1 among the most frequently represented. The two evidence layers were only weakly correlated across TFs within cell types (Spearman ρ = -0.21 to 0.37; Extended Data Fig. 8a), and 55 genes in normal mucosa and 37 in polyps were supported by both (Extended Data Fig. 8b).

Integrating both layers, we prioritized 28 TFs from the top 20 ranked in each tissue stage, 12 of which were shared (Methods; Extended Data Fig. 8c,d). These TFs formed candidate regulatory networks connecting 124 susceptibility genes through 579 TF-gene links in normal mucosa and 81 genes through 292 links in polyps (Fig. 4b,c; Supplementary Tables 15 and 16). In normal mucosa, GATA6, MAX, RAD21, SP1 and ELF1 were among the most prominent TFs, each associated with numerous susceptibility genes through co-expression and/or TF occupancy. GATA6 and MAX showed particularly extensive co-expression with susceptibility genes, whereas RAD21, POLR2A and SP1 exhibited broad occupancy at riskassociated variants. In polyps, SP1, RAD21 and POLR2A remained prominent, although their associated gene sets were generally smaller than those in normal mucosa. Other TFs, including SMC3, CBX3, CEBPB and TFAP4, showed evidence of regulatory associations in both tissue stages.

We next tested whether TF-risk gene relationships were enriched within specific epithelial populations (Methods). In normal mucosa, 28 TF-cell-type combinations were significantly enriched (FDR < 0.05), predominantly in ABS, TAC, GOB and CT cells (Fig. 4d; Supplementary Table 17). In polyps, enrichments within ASC and SSC reached only nominal significance (Fig. 4e). Representative networks illustrate these differences (Fig. 4f-i). In normal mucosa, ABS networks prominently featured HNF4A, MAX and HOXA6, and GOB networks featured GATA6, CDX2 and PPARG, with candidate susceptibility genes such as WNT4, CDH1 and ERBB2. In polyps, ASC networks were characterized by KMT2B and TFAP4, and SSC networks by CEBPB, JUN, RELA and SP1. These analyses reveal distinct TF-susceptibility gene network organization across epithelial populations and between normal and premalignant colorectal tissues.

Independent multi-omic and spatial analyses support prioritized genes

We assessed whether scTWAS-prioritized genes showed concordant expression changes across tumorigenesis using donor-level pseudobulk differential-expression analyses of normal epithelium, adenoma, serrated polyp and carcinoma in the COLON MAP single-cell resource (Methods). Across eight epithelial-stage contrasts: normal mucosa versus ASC, SSC, microsatellite instability-high (MSI-H) or microsatellite-stable (MSS), and ASC or SSC versus MSI-H or MSS (Fig. 5a), we evaluated 397 normal-colon and 102 shared-polyp gene-cell-type associations. Along the direct normal-to-carcinoma trajectory, 118 (29.7%) normal-colon and 27 (26.5%) shared-polyp associations showed concordant expression changes in at least one MSI-H or MSS carcinoma comparison (Fig. 5a; Supplementary Table 18). Along the adenoma trajectory, 104 and 17 associations were supported in the normal-to-ASC transition and 87 and 20 in the ASC-to-carcinoma transition; corresponding numbers along the serrated trajectory were 108 and 29 (normal-to-SSC) and 123 and 31 (SSC-to-carcinoma). Among 32 ASC-specific genes, 12 and 11 showed concordant changes relative to normal STM and TAC cells, respectively, and two and four were additionally supported in ASC-to-MSI-H and ASC-to-MSS carcinoma comparisons. Among 15 SSC-specific genes, five showed concordant changes relative to normal GOB cells, and one and two were supported in SSC-to-MSI-H and SSC-to-MSS comparisons (Fig. 5b; Supplementary Table 19).

We then sought orthogonal support for all 347 genes in spatial GeoMx transcriptomic data 42 , TCGA-COAD 35 transcriptomes and CPTAC-COAD 36 proteomes (Methods). By the direction of the scTWAS association, 176 genes were risk-increasing and 171 risk-decreasing.

Overall, 109 genes showed directionally concordant evidence in at least one of the three datasets, including 57 risk-increasing and 52 risk-decreasing genes. Among the risk-increasing genes, 39 were supported by one dataset, 17 by two datasets and one by all three. The corresponding numbers for risk-decreasing genes were 32, 16 and four, respectively. Genes not measured on a platform were treated as untested rather than unsupported (Fig 5c; Supplementary Table 20). Combing all the omics-analysis, 233 genes (67%) had at least one directionally concordant differential-expression result across the single-cell, spatial, transcriptomic and proteomic datasets (Supplementary Table 20).

In addition, we examined the spatial localization of prioritized genes using CosMx singlemolecule imaging of 11 early CRCs, comprising 1,257,627 quality-controlled cells (Fig. 5d).

Seven tumors contained both carcinoma and residual normal or undefined epithelial compartments and were used for paired within-patient comparisons. Of the 233 susceptibility genes supported by the above analysis, 91 were represented on the CosMx panel, of which 27 showed nominally significant differential expression between the two compartments (paired Wilcoxon signed-rank P < 0.05), 20 of them in association directions consistent with the scTWAS (Supplementary Table 21). Among these, several established CRC-related genes, including CEBPB, GTF2I, HRAS, WNT4, ZNRF3 and SMARCD1, exhibited higher expression in carcinoma cells in six or seven of the seven patients analyzed (Fig. 5e-j).

Druggable susceptibility genes identify candidate therapeutic vulnerabilities

To assess the therapeutic relevance, we integrated drug-target relationships from DrugBank 37 , ChEMBL 38 , Therapeutic Target Database 39 , and Open Targets 40 . Of the 347 susceptibility genes, 63 (18.2%) encoded druggable proteins linked to 303 approved or clinicalstage compounds (Supplementary Table 22). Mechanism-of-action information was available for 172 drug-target interactions involving 43 genes and was predominantly inhibitory. Restricting the analysis to approved or phase II/III compounds identified 55 susceptibility genes linked to 193 clinically advanced drugs (Fig. 6). This recovered established therapeutic relationships, including ERBB2, targeted by trastuzumab, pertuzumab, tucatinib, neratinib, lapatinib and margetuximab, and identified additional genetically supported drug-target pairs: the proteasome components PSMA7, PSMD3 and PSMD13 (bortezomib, carfilzomib and ixazomib), DDR1 (imatinib), POLD3 (gemcitabine and cytarabine) and the mitochondrial complex I components NDUFA11 and NDUFS6 (metformin). Twenty-nine of the 347 susceptibility genes were represented in the COSMIC Cancer Gene Census 43 , with enrichment among druggable genes (11 of 63 versus 18 of 284; odds ratio = 3.1, two-sided Fisher's exact P = 0.009). KEGG Pathway enrichment analysis placed the druggable susceptibility genes within signaling, proteostasis and metabolic programs relevant to CRC biology and treatment (Methods, Supplementary Table 23).

We next tested whether approved drugs targeting susceptibility genes have potential to reverse risk-associated cell-type-specific transcriptional signatures. Among 43 compounds assessed using the iLINCS 44 large-intestine perturbation dataset, four showed significant negative connectivity after Benjamini-Hochberg correction: the proteasome inhibitors ixazomib (normalized connectivity score (NCS) = -0.19, FDR = 0.0043), targets PSMA7, PSMD3 and PSMD13, the ERBB2 inhibitor neratinib (NCS = -0.17, FDR = 0.014), bortezomib (targets PSMA7, PSMD3 and PSMD13, NCS = -0.15, FDR = 0.0043) and resorcinol (target CA14, NCS = -0.63, FDR = 0.019). These findings provide transcriptional perturbation-based support for prioritizing candidate drugs for further investigation in CRC prevention (Methods; Extended Data Fig. 9; Supplementary Table 24).

CRC susceptibility genes are enriched for cancer-cell dependencies and validated by genetic perturbation

We next evaluated whether the identified susceptibility genes contribute to CRC cell fitness. We compared median DepMap 41 gene-effect scores for 274 evaluable scTWAS risk genes with those for 466 background genes, 175 CRC consensus susceptibility genes and 52 Tier 1 colorectal driver genes of the COSMIC Cancer Gene Census (Methods; Supplementary Table 25). scTWAS risk genes showed stronger dependency than background genes (median gene effect, -0.078 versus -0.018; Holm-adjusted P = 1.1 × 10⁻⁶) and CRC consensus genes (median, -0.037; P = 0.043). Their dependency profile was comparable to that of established CRC drivers (median, -0.083; 17.3% with gene-effect scores < -0.5 versus 13.1% of risk genes; P = 0.71) (Fig. 7a).

Twenty-four prioritized genes had gene effects below -0.5 in at least 90% of colorectal adenocarcinoma cell lines (Methods; Fig. 7b; Supplementary Table 25). These included components of the proteasome (PSMA7, PSMD3 and PSMD13), RNA processing and splicing machinery (SF3A3, RBM22 and SNW1), ribosomal and translational machinery (RPS5, RPS21 and MRPL49), and DNA replication, repair and chromosome organization (DDB1, POLD3, POLA2, RAD21 and BANF1), indicating that a subset of inherited susceptibility genes maps to cellular processes broadly required for CRC-cell fitness. To evaluate risk-increasing genes directly, we additionally performed arrayed CRISPR-Cas9 knockout of 24 selected scTWAS genes in HCT116, RKO and SW480 CRC cells (Methods; Fig. 7c; Supplementary Table 26).

Thirteen genes significantly reduced cell viability in at least one cell line at nominal two-sided P < 0.05, yielding 18 significant gene-cell-line effects. All 18 were in the direction expected for genes whose increased genetically regulated expression is associated with higher CRC risk (one-sided binomial P = 3.8 × 10⁻⁶). Eleven significant effects were observed in SW480, five in HCT116 and two in RKO cells. The largest effects were for RPS5 (-46 percentage points in RKO and -32 in SW480), SF3A3 (-23 in SW480) and MAP2K5 (-19 in HCT116), and five genes (RPS5, MAP2K5, CCHCR1, DNMBP and HLA-E) had significant effects in more than one cell line. Together, these analyses identified 35 distinct scTWAS-prioritized genes with evidence of cellular fitness effects, comprising 24 DepMap dependencies and 13 arrayed CRISPR hits, with two genes (RPS5 and SF3A3) supported by both approaches.

Discussion

We present a cell-type-resolved map of inherited CRC susceptibility, built by learning GReX from matched genotype and scRNA-seq data in normal colorectal epithelium and premalignant polyps. Our previous studie 14, 22, 23 , have demonstrated through simulation and realdata analyses that incorporating regulatory annotations into variant selection can improve TWAS performance and risk-gene discovery. Building on this principle, we restricted predictors to putative regulatory variants within cell-type-specific accessible chromatin regions and tested 16 epithelial models against European-ancestry and multi-ancestry GWAS meta-analyses of up to 132,261 cases. We identified 546 gene-cell-type associations implicating 347 genes, 213 of which had not been linked to CRC susceptibility by earlier CRC genetic studies [1] [2] [3] [8] [9] [10] [11] [12] [13] [14] . A substantial fraction of associations had additional support from colocalization or SMR-HEIDI.

Our findings extend conventional bulk-tissue TWAS by resolving susceptibility associations across distinct epithelial populations and premalignant states, providing new insights into the cellular contexts and regulatory mechanisms through which inherited genetic variation may contribute to CRC development.

Our findings further reveal that inherited CRC susceptibility is associated with distinct epithelial cell populations and premalignant states rather than uniformly distributed across the colorectal epithelium. Notably, 74% of the 347 prioritized genes were identified in a single celltype model. Adenoma-associated and serrated-polyp-associated epithelial populations contributed 47 associations (32 and 15, respectively), with no genes shared between these populations and 36 genes uniquely prioritized in these premalignant states. Particularly, among the 32 ASC-specific genes, 12 and 11 showed differential expression between STM and ASC and between TUF and ASC, respectively, whereas five of the 15 SSC-specific genes were differentially expressed between GOB and SSC. These findings highlight the importance of celltype-resolved analyses in uncovering genetic regulatory effects that may be diluted or obscured in bulk tissue, while identifying the epithelial contexts in which inherited susceptibility may operate. Importantly, the identification of susceptibility genes in premalignant epithelial populations extends previous TWAS beyond normal colorectal tissue and provides insights into potentially distinct genetic regulatory mechanisms underlying conventional adenoma and serrated pathways. Nevertheless, these lesion-associated findings require validation in independent polyp cohorts to establish their reproducibility and biological relevance.

The TF-network analysis adds regulatory organization beyond gene lists. Lineagedefining factors including GATA6, MAX and RAD21 linked to many risk genes in normal mucosa, with HNF4A and HOXA6 featuring in absorptive and CDX2, GATA6 and PPARG in goblet networks, whereas SP1 was the most connected factor in polyps; yet only 13 of 871 TFgene links were shared between tissue stages. In polyps, TFAP4 and KMT2B characterized adenoma-specific and CEBPB, JUN, RELA and SP1 serrated-polyp-specific networks, pointing to distinct candidate regulatory programs in the two neoplastic routes. These enrichments reached only nominal significance, co-expression does not establish direct regulation, and the weak correlation between co-expression and occupancy indicates that the two layers capture different information. Moreover, because the tissue stages were profiled in different donor sets, limited sharing may partly reflect sampling and unequal power rather than tissue-stage-specific regulation. These networks are therefore hypotheses for perturbation in primary epithelial models.

Integration of independent multi-omics datasets provided complementary biological evidence supporting the prioritized CRC susceptibility genes. Overall, 233 genes (67%) exhibited directionally concordant differential expression in at least one single-cell, spatial transcriptomic, bulk transcriptomic or proteomic analysis, including 109 genes (31%) supported by GeoMx, TCGA or CPTAC datasets. These findings strengthen the biological relevance of genetically prioritized genes across colorectal epithelial states and tumor tissues, while providing insights into their potential involvement in colorectal tumorigenesis. Importantly, transcriptional and proteomic alterations in tumors may not consistently reflect the direction of genetically regulated expression in normal or premalignant epithelial cells, owing to somatic alterations, clonal selection and tumor microenvironmental remodeling. Thus, the absence of concordant differential expression does not necessarily weaken the underlying genetic associations. Rather, these orthogonal findings complement TWAS, colocalization and SMR-HEIDI evidence, collectively strengthening candidate gene prioritization and providing a foundation for subsequent functional investigation.

Integrating genetic evidence with druggability and functional perturbation analyses provides opportunities to prioritize therapeutic targets for CRC prevention. We identified 63 potentially druggable susceptibility genes (18.2%), including 55 targeted by 193 approved or late-stage compounds, with significant enrichment for known cancer genes (odds ratio = 3.1).

Prioritized targets included ERBB2, proteasome components (PSMA7, PSMD3 and PSMD13), DDR1, POLD3 and mitochondrial complex I genes. Particularly, four (FADS2, FAS, SMAD7 and STK39) from ASC and one (CA14) from SSC. Notably, SMAD7 has been implicated in CRC susceptibility through previous genetic studies 45, 46 , whereas FADS2 has been linked experimentally to lipid metabolism and ferroptosis sensitivity in CRC cells 47, 48 . The identification of these genes in ASC and SSC models suggests that inherited CRC susceptibility may involve potentially actionable regulatory mechanisms in distinct premalignant epithelial states.Furthermore, transcriptional perturbation analyses identified significant reversal of CRC risk-associated expression signatures by ixazomib, bortezomib and neratinib, providing additional support for drug-repurposing opportunities. However, these findings require further evaluation of target directionality, tissue specificity and therapeutic safety, particularly because perturbations in established cancer cells may not reflect early tumorigenesis. Functional validation in primary adenoma organoids and in vivo chemoprevention models will be essential to establish the preventive potential of prioritized candidates.

Dependency analyses showed that scTWAS genes were more essential in CRC cell lines than background (median gene effect -0.078 versus -0.018) and consensus susceptibility genes, and comparable to established drivers, with 24 broadly shared dependencies spanning the proteasome, splicing, translation and DNA replication. Thirteen of 24 genes tested by arrayed CRISPR-Cas9 knockout reduced viability in at least one line, and all 18 significant 12 effects were in the expected direction, giving 35 genes with fitness evidence in total. Genes such as RPS5 and SF3A3 play essential roles in fundamental cellular processes, including protein synthesis and RNA splicing, respectively, and their functions are not specific to colorectal biology. In contrast, DNMBP and CLIC1, exhibited concordant perturbation without widespread dependency across CRC cell lines, suggesting potentially more context-specific roles. These screens used nominal significance in three established malignant lines and do not test dependency in normal or premalignant epithelium.

Our study has several limitations. First, the performance of cell-type-specific GReX models depends on donor sample size, cell abundance and genetic regulatory effects. Rare epithelial populations and premalignant polyp models were particularly underpowered, as the latter were trained using only 84 donors compared with 381 for normal mucosa, yielding substantially fewer predictable genes. Consequently, fewer associations in polyps may reflect limited statistical power rather than fewer susceptibility mechanisms. Moreover, restricting genetic predictors to accessible chromatin regions may overlook distal regulatory variants or regulatory elements not captured by available scATAC-seq datasets. Larger cohorts with matched genotypes, single-cell transcriptomes and chromatin accessibility will improve model performance and expand gene discovery. Second, TWAS associations do not necessarily establish causal relationships, as linkage disequilibrium, correlated expression predictors and shared regulatory variants may implicate multiple genes at the same locus. Although colocalization and SMR-HEIDI analyses provided additional genetic support, they cannot fully exclude pleiotropy or complex allelic architectures. Furthermore, associations detected in only one cell type do not necessarily demonstrate exclusive cell-type-specific effects, particularly when statistical power differs across populations. Third, the predominance of Europeanancestry genetic data and limited diversity of single-cell reference cohorts may restrict the generalizability of our findings across ancestral populations. Differences in allele frequencies, linkage disequilibrium and regulatory architectures warrant further evaluation in diverse populations. In addition, the relatively small polyp cohort may not fully capture the molecular heterogeneity of conventional adenomas and serrated lesions. Finally, although integrating TFgene co-expression with ChIP-seq occupancy revealed candidate regulatory networks, these associations do not establish direct TF regulation or functional effects of susceptibility variants.

Similarly, multi-omics evidence supports biological relevance but does not independently demonstrate causality. DepMap and CRISPR-Cas9 analyses identified genes involved in CRC cell viability, whereas drug-target annotations and transcriptional signature reversal highlighted potential therapeutic candidates; however, these findings may not directly translate to tumor initiation or prevention. Further validation using allele-specific assays, CRISPR perturbations, patient-derived adenoma organoids and in vivo models will be essential to establish regulatory mechanisms and evaluate preventive potential.

Cohorts and single-cell RNA sequencing

Normal-colon scRNA-seq data originated from 52 participants from VUMC HTAN COLON MAP and 51 from the VUMC Gut Cell Atlas, yielding 103 VUMC donors 15, 23 . Sample collection, library preparation, sequencing, alignment and initial quality control have been described previously 15, 23 . Briefly, both datasets were generated using a modified inDrop protocol 49 with dual-indexed TruDrop libraries 50 , sequenced on an Illumina NovaSeq 6000, aligned to GRCh38 using STAR 51 and processed into unique molecular identifier (UMI) counts using dropEst 52 . RNA-seq data in normal colon tissues from Gut Cell Atlas project were derived from 18 healthy control and 34 IBD patients with a prior history of CD who had normal histology on the index colonoscopy as "normals". We preferentially retained ascending-colon samples from donors with multiple sampled sites, whereas COLON MAP data were restricted to normal mucosa. Genes detected in fewer than three cells and cells expressing fewer than 200 genes were excluded.

To harmonize cell-type annotations, we adopted seven COLON MAP epithelial populations as the reference vocabulary: ABS, CT, EE, GOB, STM, TAC and TUF. Fourteen cell type categories from Gut Cell Atlas annotation were mapped to the corresponding COLON MAP populations (Supplementary Table 3). Non-epithelial cells and ASC or SSC populations were excluded before integration. We performed single-cell normalization, integration, clustering and visualization were performed in Seurat v5.5.1 53 under R v4.5.0. Each dataset was normalized separately using SCTransform 54 (v0.4.3), regressing out mitochondrial transcript fraction. We selected 3,000 integration features, performed principal-component analysis and corrected for batch effects across three sequencing batches (one Gut Cell Atlas and two COLON MAP) using Harmony 55 (v2.0.5). The first 30 Harmony dimensions were used for shared nearest-neighbor graph construction, Louvain clustering (resolution 0.8) and UMAP visualization 56 . Initial clustering identified 25 clusters, including 18 absorptive clusters and one or two clusters for each remaining epithelial population. We excluded eight clusters because their cell-type annotations were inconsistent with the expected epithelial populations, as assessed by cluster composition, UMAP distribution and canonical marker-gene expression.

The retained cells were reprocessed from raw counts using the same normalization, integration and clustering workflow, yielding 120,891 cells across 25 clusters. Clusters were assigned their predominant harmonized cell-type label when it accounted for at least 60% of annotated cells.

Twenty-three clusters met this threshold (minimum proportion, 71.9%); the remaining two (52.4% and 41.0%) were annotated based on cluster composition and canonical marker-gene expression. The final annotations resolved seven epithelial populations (ABS, CT, EE, GOB, STM, TAC and TUF) for downstream pseudobulk aggregation of expression for model building.

The Wellcome Sanger Institute IBDverse cohort contributed 278 normal-colon donors 21.

Sample collection, library preparation, sequencing, alignment, quality control and cell-type annotation have been described previously 21 . Briefly, libraries were generated using 10x Genomics Chromium 3′ v3.0/v3.1 chemistry, aligned to GRCh38 with Cell Ranger 57 v7.2.0, and processed with CellBender 57 v2.1 and Scrublet 58 v0.2.1 to remove ambient RNA and multiplets.

Genotyping, imputation and quality control

Germline genotype data were obtained from two sources: previously generated genotypes from the IBDverse cohort and newly generated genotypes from the VUMC HTAN Colon Map cohort. All genotype data were aligned to the GRCh38 human reference genome.

Previously generated genotype data from the IBDverse cohort. Genotype data for 278 participants were obtained from the European Genome-phenome Archive (EGA; accession EGAD00001016069). As described in the original study, DNA extracted from blood or gastrointestinal tissue was genotyped using the Applied Biosystems UK Biobank Axiom Array. Genotypes were jointly called across five batches and subsequently imputed using the Michigan Imputation Server 60 with the TOPMed reference panel.

Newly generated genotype data from the VUMC HTAN Colon Map cohort. Germline genotyping was performed for 136 participants, including 52 with normal colorectal mucosa and 19 84 with colorectal polyps, using the expanded Illumina Multi-Ethnic Genotyping Array (MEGA). Initial variants were excluded for call rate below 95%, Hardy-Weinberg equilibrium P < 1 x 10 -6 within genetic-ancestry groups, concordance below 92% across duplicate and 1000 Genomes Project quality-control samples, or minor allele frequency (MAF) below 0.5%. Samples were excluded for call rate below 95% or relatedness PI_HAT above 0.2, retaining one individual from each related pair. Genetic ancestry was inferred by principal-component analysis against 1000 Genomes Project reference populations and genetic sex was estimated with PLINK v1.9. Alleles were aligned to the forward strand with McCarthy Group Tools, variants with MAF below 1% were removed, and imputation was performed on the TOPMed Imputation Server against the TOPMed v3 reference panel 59 . Approximately 11 million variants passing the imputation-quality filter were retained for both cohorts. Following genotype quality control, approximately 1.8 million genotyped variants on GRCh38 were submitted to the TOPMed Imputation Server.

Genotypes were phased using Eagle v2.4 and imputed against the TOPMed version R3 multiancestry reference panel using the server implementation of Minimac4 59, 60 . After excluding variants with minor allele frequency <1% or imputation quality (𝑅 2 < 0.3), approximately 10.2 million variants were retained for downstream association analyses. Imputed allele dosages were used in the GWAS.

Single-cell ATAC sequencing and cell-type peak definition

Cell-type-specific chromatin accessibility was derived from two independent resources.

For the Stanford HTAN colorectal atlas 17 (GSE201336), fragment files from 89 libraries were matched to the published sample metadata and analyses were restricted to normal-colon and colorectal-polyp samples. Barcode-level epithelial annotations released by the authors were harmonized to six populations (ABS, CT, EE, GOB, STM and TAC; Supplementary Table 3).

Arrow files were generated against hg38 with ArchR 61 , retaining nuclei with transcription-startsite enrichment of at least 6 and at least 1,000 unique fragments. Peak-calling groups were defined by tissue condition and cell type, groups with fewer than 100 nuclei were excluded, and reproducible peaks were called from pseudobulk replicates with MACS2 62 , retained when supported by at least two replicates, capped at 150,000 peaks per group and filtered against the ENCODE hg38 blacklist v2 63.

For the VUMC scATAC-seq resource 64 , pseudobulk BAM files were stratified by tissue condition and cell type, covering ABS, CT, EE, GOB, STM, TAC and TUF together with ASC and SSC. Alignments were restricted to properly paired reads with mapping quality of at least 30 on chromosomes 1-22 and X after removal of unmapped, secondary, duplicate, supplementary and quality-failed reads. Peaks were called per condition and cell type with MACS3 at q <= 0.01 and filtered against the ENCODE hg38 blacklist v2. For populations with fewer than one million usable fragments, reproducibility was assessed across three independent 80% subsamples and peaks supported in at least two of three subsamples were retained. Adenoma and serratedpolyp peaks were merged within each shared epithelial cell type, whereas ASC and SSC were retained as separate lesion-specific annotations.

For the six epithelial populations represented in both resources, accessible regions were integrated separately for normal colon and for polyps by combining the corresponding VUMC and Stanford HTAN peak sets, merging overlapping or directly adjacent intervals with bedtools merge -d 0 65 . TUF, ASC and SSC annotations were taken from VUMC resource alone. The resulting cell-type-specific accessible regions defined the candidate predictor space for GReX model construction.

CRC GWAS meta-analysis

BioVU CRC case-control ascertainment. We performed a CRC GWAS in BioVU, the VUMC DNA biobank linked to de-identified electronic health records 27, 66 . CRC cases were identified using ICD-9-CM codes 153 and 154 or ICD-10-CM codes C18-C20. To enrich for sporadic CRC, we excluded individuals with a documented family history of CRC (ICD-9-CM V16.0; ICD-10-CM Z80.0), inflammatory bowel disease (V18.59; Z83.79), or colorectal polyps (V18.51; Z83.71); those with familial adenomatous polyposis or Lynch syndrome; and those diagnosed with another malignancy (ICD-9-CM 140-209; ICD-10-CM C00-C96) more than six months before CRC diagnosis. Controls were defined as individuals without a recorded history of cancer. Genome-wide genetic variants were obtained from whole-genome sequencing (WGS) of DNA samples collected through Vanderbilt University Medical Center's BioVU biobank 27, 66 . Sequencing was performed on the Illumina NovaSeq 6000 platform with paired-end 150-bp reads, and variants were identified using the DRAGEN germline pipeline 67 (v3.7.8) against the GRCh38 reference genome. BioVU DNA was extracted from residual blood specimens collected during routine clinical care. Sequence reads were aligned to the human reference genome, and single-nucleotide variants (SNVs) and small insertions and deletions (indels) were identified through variant calling. Quality control included assessment of sequencing coverage, genotype quality, missingness, sex concordance and relatedness. Genetic ancestry was inferred using principal component analysis, and ancestry-specific datasets were constructed for downstream GWAS BioVU ancestry-specific GWAS. Ancestry-specific association analyses were performed using REGENIE v4 68 , adjusting for sex, age and the first five genetic principal components. In step 1, whole-genome ridge regression models were fitted using linkagedisequilibrium-pruned biallelic SNPs prepared with PLINK 2 69 . Linkage disequilibrium pruning used a 1,000-variant window, a 100-variant step and an r² threshold of 0.45. Variants were required to have a minor allele frequency (MAF) ≥ 1%, minor allele count ≥ 100, missingness ≤ 10% and Hardy-Weinberg equilibrium P ≥ 1 × 10⁻¹⁵. In step 2, association testing was performed for WGS-derived variants using leave-one-chromosome-out predictions from step 1 to account for polygenic effects and relatedness. Variants with association P < 0.01 were retested using approximate Firth logistic regression to reduce small-sample bias and improve the reliability of effect estimates for imbalanced case-control data. Following phenotype ascertainment and quality control, the final analyses included 2,581 CRC cases and 144,746 controls of European ancestry and 347 CRC cases and 26,048 controls of African ancestry.

Cell-type-specific TWAS analysis

Building scTWAS GReX models. Model training was restricted to participants with matched germline genotype and single-cell expression data, with one biospecimen retained per participant. For the integrated VUMC normal-colon dataset, COLON MAP 24 specimens were required to match the specimen metadata and be classified as normal mucosa; adenoma and serrated specimens were excluded. When multiple eligible specimens were available for a participant, one was selected according to the following anatomical-site priority: ascending colon, terminal ileum, cecum, descending colon, rectum, sigmoid colon, hepatic flexure, splenic flexure and transverse colon; ties were resolved by order of appearance in the expression matrix. Genotype data were matched to COLON MAP participants using unique participant identifiers, ensuring a one-to-one correspondence between participants and genotype samples.

For each cell type, gene-level expression counts were aggregated across cells from the same donor to generate pseudobulk expression profiles. Aggregated counts were converted to transcripts per million (TPM) and log₂-transformed. Expression values were then quantilenormalized across donors and subjected to a gene-wise inverse normal transformation. To account for potential confounding, normalized expression was adjusted for age, sex, the first five genotype principal components and probabilistic estimation of expression residuals (PEER) factors 72 . The number of PEER factors was determined by the number of donors in each training cohort following GTEx recommendations: 15 factors for the polyp and VUMC cohorts and 45 factors for the Wellcome Sanger IBDverse cohort. Residualized expression values were used as phenotypes for subsequent GReX model training.

Following the sTF-TWAS framework 23 , candidate genetic predictors were restricted to variants overlapping cell-type-specific accessible chromatin regions identified from single-cell ATAC-seq data. Variants were required to have a minor allele frequency (MAF > 0.05) and a Hardy-Weinberg equilibrium test P value >1 × 10⁻⁶. For each gene, eligible variants within ±1 Mb of the transcription start site were used to train an elastic-net regression model (α = 0.5), following the PrediXcan framework 6 . Predictive performance was evaluated as the coefficient of determination (𝑅²) between predicted and observed expression across held-out samples using three repeated tenfold cross-validation. Models with cross-validated 𝑅² > 0.01 were retained.

The same criterion applied to normal-colon and polyp models; for normal colon, a gene was carried forward for a given cell type if the model met this threshold in either training cohort.

Colocalization and SMR-HEIDI of scTWAS genes

For each significant gene-cell-type association, we assessed whether the cis-expression and CRC association signals were consistent with a shared causal variant. A cis region of ±500 kb around the transcription start site (GENCODE v26) was defined for each gene, and CRC GWAS summary statistics were harmonized with cell-type-specific cis-eQTL summary statistics from the cohort contributing the association. Alleles were aligned, strand-ambiguous variants were excluded and at least 50 overlapping variants were required.

Bayesian colocalization was performed with coloc 33 using the approximate Bayes factor approach. CRC was treated as a case-control trait (European-ancestry meta-analysis: 99,260 cases and 1,119,512 controls; multi-ancestry meta-analysis: 132,261 cases and 1,752,398 controls), and expression was treated as a quantitative trait using the corresponding cohort sample size. Minor-allele frequencies were obtained from the cis-eQTL data, and default prior probabilities were used (p1 = 1 × 10⁻⁴, p2 = 1 × 10⁻⁴ and p12 = 1 × 10⁻⁵). A locus was considered colocalized at PP.H4 > 0.8.

SMR and the HEIDI heterogeneity test 34 were performed over the same cis regions using SMR v1.4.2. For each gene, the variant with the smallest cis-eQTL P value among harmonized variants was used as the instrument and specified with --target-snp. HEIDI included 3-20 variants in linkage disequilibrium (𝑟² = 0.05 -0.9) with the instrument and with cis-eQTL P < 1.57 × 10⁻³. Variants with minor-allele frequency < 0.01 or an allele-frequency difference > 0.2 between datasets were excluded. Linkage disequilibrium was estimated from the genotypes of the cohort contributing the cis-eQTL signal, with a locus-specific PLINK reference restricted to harmonized variants. SMR support was defined as a Bonferroni-significant SMR association (adjusted P < 0.05) with HEIDI P ≥ 0.05. Associations satisfying either PP.H4 > 0.8 or the SMR-HEIDI criterion were considered to have evidence consistent with a shared causal signal.

TF-risk gene regulatory network analysis TF-risk gene co-expression analysis.

We investigated potential regulatory relationships between CRC susceptibility genes and 51 TFs previously implicated in CRC susceptibility by our previous TF-focused association study 23 . Analyses used scRNA-seq data from normal colorectal mucosa from 278 participants in the Wellcome Sanger Institute IBDverse cohort and colorectal polyps from 84 participants in the VUMC HTAN COLON MAP cohort. Within each epithelial population, single-cell expression profiles were aggregated to donor-level pseudobulk profiles summarize the count values from cells, and Pearson correlations were calculated between each TF and susceptibility gene. In total, 27,846 TF-gene pairs were tested, comprising 20,247 pairs in normal mucosa and 7,599 in polyps. P values were adjusted for multiple testing using the Benjamini-Hochberg procedure. Significant positive TF-risk-gene coexpression was defined as Pearson r > 0.5 and FDR < 0.05. A total of 1,397 TF-gene pairs met these criteria, including 982 in normal mucosa and 415 in polyps, and were retained for downstream regulatory network analyses (Supplementary Table 14). TF ChIP-seq analysis linking TFs to susceptibility genes. To identify TFs potentially regulating CRC susceptibility genes, we integrated GReX prediction models with TF ChIP-seq data. For each significant gene-cell-type association, variants included in the corresponding GReX model were ranked by their association P values in the CRC GWAS meta-analysis. European-ancestry GWAS results were used for associations significant in the Europeanancestry analysis, whereas multi-ancestry GWAS results were used otherwise. The variant with the smallest GWAS P value was designated the GReX lead variant and used to infer potential TF-risk gene regulatory relationships. A TF-risk gene link was established when the lead variant overlapped a ChIP-seq peak for the corresponding TF.

Integration of TF-risk gene regulatory evidence and TF prioritization.

To prioritize key TFs potentially regulating CRC susceptibility genes, we integrated two complementary measures within each tissue: (i) the number of unique susceptibility genes linked to each TF through co-expression and (ii) the number of susceptibility-gene lead variants overlapping the corresponding TF ChIP-seq peaks. Each measure was converted to a percentile rank across the 51 candidate TFs, with missing values assigned zero before ranking. The two percentile ranks were averaged to calculate a composite regulatory evidence score, reflecting both coexpression connectivity and TF occupancy at risk-associated variants. TFs were ranked separately in normal colorectal mucosa and adenomas, and the top 20 TFs from each tissue were selected for downstream regulatory network analyses.

Cell-type specificity of TF-susceptibility gene relationships.

To identify epithelial populations enriched for TF-linked CRC susceptibility genes, we included cell types with at least ten tested susceptibility genes: seven in normal colorectal mucosa (STM, TAC, ABS, GOB, EE, TUF and CT; 397 gene-cell-type pairs) and six in polyps (STM, TAC, ABS, GOB, ASC and SSC; 140 gene-cell-type pairs). EE, TUF and CT were excluded from polyp analyses owing to insufficient gene coverage. For each of the 51 candidate TFs, enrichment of co-expressed susceptibility genes within each cell type was assessed relative to the pooled remaining cell types from the same tissue using a one-sided Fisher's exact test, treating each gene-cell-type pair as an independent observation. In total, 357 TF-cell-type combinations were tested in normal mucosa and 306 in polyps. P values were adjusted separately for each tissue using the Benjamini-Hochberg procedure, with significant enrichment defined as FDR < 0.05 and at least three linked susceptibility genes (Supplementary Table 17). We selected two normal epithelial populations showing the strongest TF enrichment (ABS and GOB) and two polyp-associated populations (ASC and SSC) for network visualization.

Within each population, up to six TFs with the smallest nominal enrichment P values (P < 0.05) and at least three linked susceptibility genes were selected. Susceptibility genes co-expressed with at least two selected TFs were retained; when fewer than five genes met this criterion, all linked susceptibility genes were included. For TFs lacking connections to the retained genes, the two most strongly coexpressed susceptibility genes were additionally incorporated. Network edges represented significant positive TF-gene co-expression (Pearson r > 0.5, FDR < 0.05), with TF ChIP-seq occupancy overlapping the corresponding GReX lead variant highlighted to indicate complementary regulatory evidence.

Unless stated otherwise, a gene-resource pair was considered directionally supported when the gene was differentially expressed or differentially abundant at FDR < 0.05, showed |log2FC| > 0.5, and changed in the direction predicted by the sign of the scTWAS Z score. Drug-target annotation and functional enrichment analyses

Drug-target identification. Druggable CRC susceptibility genes and associated compounds were identified by integrating drug-protein interaction data from DrugBank 37 , ChEMBL 38 , TTD 39 and Open Targets 40 . For each compound, we extracted commercial names, highest clinical trial phase and approved indications, and classified susceptibility genes as druggable if they encoded targets of approved or clinical-stage compounds. Mechanisms of action were categorized as decreasing target activity (inhibitors, antagonists or negative allosteric modulators) or increasing target activity.

Annotation of Established CRC-Associated Genes.

Established cancer genes were identified by matching the 347 prioritized CRC susceptibility genes against approved gene symbols in the COSMIC Cancer Gene Census v103 (GRCh38; 763 genes, including 590 Tier 1 and 173 Tier 2) 81 . Census gene synonyms were additionally examined, yielding no further matches. Enrichment of Cancer Gene Census membership among the 63 druggable susceptibility genes relative to the remaining 284 susceptibility genes was assessed using a two-sided Fisher's exact test.

KEGG pathway enrichment.

Pathway over-representation was evaluated using human KEGG annotations retrieved from the KEGG REST API 82 . The reference universe comprised 9,290 genes annotated to at least one KEGG pathway, including 53 of the 63 druggable genes and 147 of the 347 prioritized susceptibility genes. We evaluated 119 pathways containing at least two druggable genes using two reference backgrounds: all 9,290 KEGG-annotated human genes, assessed by one-tailed hypergeometric tests, and the 147 KEGG-annotated susceptibility genes, assessed by one-sided Fisher's exact tests. Both analyses tested over-representation, with Benjamini-Hochberg correction applied separately across the 119 pathways within each comparison.

iLINCS connectivity analysis

To identify compounds capable of reversing genetically predicted CRC susceptibilityassociated transcriptional changes, we performed connectivity analysis using the iLINCS 44 LIB5 large-intestine perturbation library, comprising 16,767 compound perturbation signatures. We evaluated 43 prespecified compounds targeting prioritized CRC susceptibility genes, matching compounds between the drug annotation table and iLINCS 44 using PubChem compound identifiers (CIDs) rather than compound names. Each compound perturbation signature was compared with 18 cohort-level cell-type TWAS signatures containing more than 200 genes overlapping with the iLINCS 44 reference using normalized connectivity scores (NCS) 83 . Negative NCS values indicated opposing transcriptional responses, such that genes with genetically predicted risk-increasing expression were downregulated by the compound, whereas genes with risk-decreasing expression were upregulated. For each perturbation signature, NCS values were averaged across the 18 cell-type TWAS signatures. A compound-level mean NCS was then calculated across all available library signatures for that compound.

To account for variation in the number of perturbation signatures available per compound, we constructed a size-matched empirical null distribution by randomly sampling 5,000 sets of library signatures, with each set containing the same number of signatures as the compound under evaluation. The compound-level mean NCS was compared against the corresponding empirical null distribution using a one-sided test for negative connectivity.

Empirical P values were adjusted across the 43 compounds using the Benjamini-Hochberg procedure, with an FDR threshold of 0.05. Compounds were ranked by their observed mean NCS, and the null distribution for each compound was summarized by its mean ± 2 standard deviations (s.d.). Compounds represented by only one perturbation signature were retained for completeness but interpreted cautiously because their mean connectivity estimates could not be assessed for consistency across independent library signatures.

DepMap dependency analysis

Dependency data. Gene-level CRISPR knockout fitness data were obtained from the Cancer Dependency Map (DepMap) through the Open Targets Platform GraphQL API (release 26.09, depMapEssentiality). Records were restricted to the DepMap intestine tissue category, comprising 63 colorectal adenocarcinoma cell lines, and deduplicated by gene symbol and DepMap identifier. Dependency was quantified using Chronos gene-effect scores, where 0 indicates no detectable proliferation effect and -0.5 approximates the moderate effect of knocking out a common essential gene. For each gene, the median score across evaluable cell lines was used as the dependency measure.

Gene sets.

Four gene sets were evaluated against the same cell-line panel: (1) 347 prioritized scTWAS risk genes, of which 274 had scores available in more than 90% of cell lines; (2) 202 CRC consensus susceptibility genes supported by at least two of ten published studies 1- 3,8-14 , of which 175 were evaluable; (3) 52 Tier 1 CRC-associated driver genes from the COSMIC Cancer Gene Census v103 (GRCh38) 81 , all evaluable; and (4) 466 randomly selected background genes.

CRC driver genes were identified by systematically classifying tumour-type annotations in the census somatic and germline fields, excluding non-colorectal intestinal and gastrointestinal annotations. The background was derived from 500 genes randomly sampled from a 2,000-gene regulatory and protein-protein interaction network background, excluding prioritized risk genes and Hart core-essential (CEGv2) and non-essential (NEGv1) reference genes 84 . Genes overlapping any focal set were subsequently removed.

Dependency classification and statistical analysis.

A gene was classified as a broadly shared dependency if its median Chronos gene-effect score was below -0.5 and at least 90% of evaluable cell lines had scores below -0.5. Gene-set differences were assessed using the Kruskal-Wallis test, followed by two-sided Mann-Whitney U tests for six pairwise comparisons, with Holm correction for multiple testing. Individual genes were treated as the DharmaFECT reagent was added to wells for 20 min followed by addition of Cas9-expressing RKO or HCT116 cells with a final concentration of crRNA:tracrRNA of 50 nM. Two independently designed Edit-R non-targeting crRNA (#1 and #2) and lethal crRNA (#1) were also included on each plate as negative and positive controls, respectively. Cells were incubated for 72 hours to allow for gene-editing and effects on cell viability.

Statistical analysis of the arrayed CRISPR-Cas9 screen.

Cell viability was calculated as the percentage of PI-negative cells among total nuclei at 72 hours after transfection. For each target gene, viability was normalized to the corresponding non-targeting crRNA controls within each experiment. Differences in normalized viability between target-gene knockout and control conditions were evaluated using a two-sided paired Student's t-test across three independent biological replicates (n = 3), with experimental replicate as the matching factor. P values were adjusted across target genes within each cell line using the Benjamini-Hochberg procedure, with FDR < 0.05 considered statistically significant. Results were reported as mean ± standard deviation (s.d.).

Statistics and reproducibility

All donors and specimens meeting the prespecified cohort-specific quality-control criteria were included. Donors or patients were treated as independent biological replicates in single-cell, pseudobulk and spatial analyses. Exclusion criteria, including genotype and sample quality, minimum cell counts, gene detection thresholds and plate-level quality control, are described in the corresponding Methods sections. No donors were excluded after analysis. Statistical tests were two-sided unless otherwise specified. One-sided tests were used for prespecified directional hypotheses, including TF enrichment across cell types (Supplementary Table 17), KEGG pathway over-representation among druggable genes (Supplementary Table 23) and empirical tests for negative drug connectivity. Cancer Gene Census enrichment was assessed using a two-sided Fisher's exact test. The HEIDI test was used to assess heterogeneity, with P ≥ 0.05 indicating no statistically significant evidence of heterogeneity. Multiple-testing correction was performed using the Bonferroni method for scTWAS associations within each cell type, the Benjamini-Hochberg procedure for differential expression, co-expression, enrichment, drug connectivity and spatial analyses, and the Holm method for pairwise gene-dependency comparisons. Statistical significance was defined as adjusted P < 0.05 unless otherwise specified. Arrayed CRISPR-Cas9 experiments were performed in three independent biological replicates. For each target gene, normalized cell viability was compared with matched nontargeting controls using a two-sided paired Student's t-test, followed by Benjamini-Hochberg correction across target genes within each cell line. All replicates passing plate-level quality control were included. Randomization and blinding were not implemented for the computational analyses; experimental randomization and blinding were not reported. Exact P values are provided where computationally representable.
