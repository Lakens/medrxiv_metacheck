To check Non-Significant P Value Check

What we found

We found 1 non-significant p value that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Metacheck does not yet analyze automatically whether sentences which include non-significant p-values are correct, but we recommend manually checking the sentences below for possible misinterpreted non-significant p values.

p = 0.053 Ever-smoking was associated with lower odds of 236 retinopathy (OR 0.64; 0.47-0.88; p = 0.007), and the association with systolic blood pressure 237 was borderline (OR 1.01 per mmHg; 1.00-1.02; p = 0.053).

Murphy S, Merz R, Reimann L, Fernández A (2025). “Nonsignificance misinterpreted as an effect’s absence in psychology: Prevalence and temporal analyses.” Royal Society Open Science, 12(3), 242167. doi:10.1098/rsos.242167.

How Exact P-Values works

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Background

Retinopathy and age-related macular degeneration (AMD) are among the most common findings when the retina of an older adult is photographed, and both are leading retinal causes of visual impairment in ageing populations [1] [2] [3] [4] [5] [6]. Beyond that, they have little in common.

Retinopathy is a disorder of the retinal microvasculature, ranging from an isolated microaneurysm or hemorrhage to proliferative disease, and it is studied mostly in people with diabetes, in whom chronic hyperglycemia is its main driver [1, 2]. AMD is a degenerative disease of the macula in which drusen and pigmentary change may progress to geographic atrophy or neovascularization, and its dominant correlate is age [3, [7] [8] [9] [10].

Because both conditions concentrate in older adults and appear on the same fundus photograph, services that plan eye care or retinal screening for an ageing population have to deal with both at once. The evidence, however, has accumulated separately. Different samples, grading protocols and definitions of visual loss make it hard to say, for a single population, which condition is more common, who is affected by each, and how much vision each costs.

The US National Health and Nutrition Examination Survey (NHANES) 2005-2008 can answer these questions. It remains the most recent nationally representative US survey in which adults aged 40 years and older underwent fundus photography graded for both retinopathy and AMD, with visual acuity measured at the same examination [11] [12] [13]. The landmark analyses of these data each addressed one question. Zhang et al. found retinopathy in 28.5% (95% confidence interval [CI] 24.9-32.5) of adults with diabetes [11]. Klein et al. reported any AMD in 6.5% (5.5-7.6) and late AMD in 0.8% (0.5-1.3) of adults aged 40 years and older [12]. Chou et al. showed that presenting visual impairment affected 7.5% (6.9-8.1) of the same age group, about two-thirds of it correctable with refraction, and that AMD was strongly associated with nonrefractive impairment (odds ratio [OR] 4.52; 95% CI 2.50-8.17) . whereas retinopathy was not (OR 2.55; 0.68-9.51) [13]. Elsewhere, the relation between diabetes or diabetic retinopathy and AMD has been examined in population cohorts, claims data and a meta-analysis [14] [15] [16] [17], and cardiovascular correlates of AMD in the Beaver Dam Eye Study [18].

Those reports used different analytic samples (1006, 5553 and 5222 participants) and different models, so their estimates cannot be set side by side. We therefore re-analyzed NHANES 2005-2008 in one fixed sample of adults whose photographs were gradable for both conditions, applying the same methods to each. We asked four questions. How common is each condition, overall and across age, sex and race/ethnicity? Which factors are independently associated with each when an identical model is used? How do measured visual acuity and self-rated vision differ between people with neither condition, one condition or both? And are the two conditions associated with each other?

Methods

Data source and participants

NHANES is a continuous program of cross-sectional surveys of the civilian, noninstitutionalized US population that combines a household interview with a standardized examination in a mobile examination center (MEC) [19]. We pooled the 2005-2006 and 2007-2008 cycles and linked nine public-use modules per cycle (demographics, retinal imaging, vision examination, vision questionnaire, diabetes questionnaire, glycohemoglobin, blood pressure, body measures and smoking) by participant identifier. Coding was identical across cycles except for age, which was top-coded at 85 years in 2005-2006 and at 80 years in 2007-2008; we capped age at 80 years in both cycles. Source files, download dates and checksums are archived with the analysis code [20], and the NHANES variables used are listed in Additional file 1: Table S1.

. Participants were eligible if they were aged 40 years or older, attended the MEC examination and had a person-level (worse-eye) grade for both retinopathy and AMD. All eligible participants were included. The study is reported according to the STROBE statement [21].

Fundus photography and grading

Two 45° non-mydriatic digital photographs were taken of each eye, one centered on the macula and one on the optic disc, with a Canon CR6-45NM camera fitted with an EOS 10D digital back. Images were graded at the University of Wisconsin reading center by graders masked to diabetes status, and every photographed participant was graded for both conditions whether or not they had diabetes [11] [12] [13]. Retinopathy was graded with NHANES categories adapted from the Early Treatment Diabetic Retinopathy Study classification [22, 23], and AMD with a modified Wisconsin Age-Related Maculopathy Grading System [24]. The NHANES files label AMD as "age-related maculopathy"; we use AMD throughout.

Definitions

Retinopathy was defined as a worse-eye retinopathy level of 2 or higher, which corresponds to mild retinopathy or worse [23]. Because grading did not depend on diabetes status, retinopathy in the full sample includes participants without diabetes; we use the term diabetic retinopathy only for retinopathy within the diabetes subpopulation. AMD was defined as early or late AMD in the worse eye, comparable to the "any AMD" definition of Klein et al. [12]. Late AMD (53 participants) was too infrequent to analyze separately. From the two outcomes we formed four mutually exclusive groups: neither condition, retinopathy only, AMD only, and both.

Diabetes was defined as self-reported diagnosed diabetes (a "borderline" response was not counted) or an HbA1c of 6.5% or higher, as in Zhang et al. [11]. Diabetes defined the population for the retinopathy model but did not restrict the prevalence estimates. Among . participants with self-reported diabetes, duration was calculated as age minus self-reported age at diagnosis, and insulin use as current use reported at interview. Visual acuity was measured as presenting acuity, with habitual distance correction if any, using a Nidek ARK-760 autorefractor; eyes with presenting acuity of 20/30 or worse were retested after objective refraction [19]. Subjectively refined best-corrected acuity was not measured in these cycles [13]. We used the better eye, or the only eye measured. Visual impairment was defined as better-eye presenting acuity worse than 20/40, and refractionaided impairment, a secondary outcome, as better-eye acuity still worse than 20/40 after objective refraction. For continuous analysis, acuity was converted to logMAR; the NHANES category "worse than 20/200" (4 participants) was scored as 20/200 (logMAR 1.0).

Self-rated vision came from the vision questionnaire (five categories, excellent to very poor)

and was dichotomized as poor or very poor versus better; "don't know" was treated as missing.

Both regression models included the same covariates: age (years), sex, race/ethnicity (non-Hispanic White, non-Hispanic Black, Mexican American, other Hispanic, and other or multiracial), HbA1c (%), body mass index (kg/m²), systolic blood pressure (mean of the first three readings, mmHg) and lifetime smoking of at least 100 cigarettes, giving ten parameters per model.

Statistical analysis

All estimates accounted for the complex survey design, using the MEC examination weights divided by two for the pooled cycles, 31 strata and 62 primary sampling units (31 design degrees of freedom), with variances estimated by Taylor series linearization [25, 26].

Subpopulations were analyzed as domains rather than by subsetting the data, so that all participants contributed to variance estimation. Tests were two-sided at α = 0.05. Counts, . group sizes and baseline characteristics are unweighted; prevalence, odds ratios, proportions with visual impairment and mean logMAR are survey-weighted.

Weighted prevalence of retinopathy and AMD was estimated with 95% Wald CIs based on the t distribution, overall and by age group (40-49, 50-59, 60-69 and 70 years or older), sex and race/ethnicity. Because the race/ethnicity groups differ in age structure, we also standardized their prevalence directly to the weighted age distribution of the analytic sample in nine bands (40-44 to 75-79 years, and 80 years), with CIs for the standardized estimates obtained by Taylor linearization.

To examine associated factors we fitted two survey-weighted logistic regression models with the same specification. The retinopathy model was fitted in the diabetes subpopulation, the conventional setting for diabetic retinopathy [11, 13], and the AMD model in the full sample.

Retinopathy therefore appears in two forms in this paper, as any retinopathy in the full sample for prevalence and as diabetic retinopathy for modeling, and we state which applies throughout. Because HbA1c contributes to the definition of diabetes, we refitted the retinopathy model in participants with self-reported diabetes, whose diabetes status does not depend on HbA1c, adding diabetes duration and current insulin use. We also fitted the AMD model with retinopathy, and separately with diabetes, as the exposure of interest, keeping the same covariates.

For vision, we estimated the weighted proportion with presenting visual impairment, and secondarily refraction-aided impairment, in each of the four groups, together with the weighted mean better-eye logMAR. Differences in logMAR between groups were tested with an overall Wald F test from survey-weighted linear regression. Because the groups differ markedly in age, we compared presenting impairment across them in a survey-weighted logistic model adjusted for age, and estimated age-adjusted mean logMAR at the sample . mean age. Agreement between measured impairment and self-rated poor or very poor vision was summarized at the individual level by unweighted Cohen's κ.

Eight sensitivity analyses were specified in advance (Table 4): a stricter retinopathy threshold of level 3 or higher (S1); the four groups redefined using diabetic retinopathy only (S2); eyespecific rather than person-level grades (S3); restriction to participants with both eyes gradable (S4); comparison of participants with and without an HbA1c measurement (S5); alternative visual acuity thresholds (S6); the retinopathy model refitted in the full sample, giving a same-sample comparison with the AMD model (S7); and separate estimates for each survey cycle (S8). S8 also served as a check on the 2007-2008 glycohemoglobin file, which NCHS withdrew in November 2011 and republished unchanged in March 2012. We used 10 events per model parameter as a guide for fitting models [27, 28].

Covariates were handled by complete-case analysis. Within the analytic sample, HbA1c was missing for 177 participants (3.16%), systolic blood pressure for 104 (1.86%), body mass index for 43 (0.77%) and smoking status for 2 (0.04%) (Additional file 1: Table S2), leaving 984 participants (297 events) for the retinopathy model and 5287 (409 events) for the AMD model. The 34 participants with no acuity measurement in either eye were excluded from the vision analyses (n = 5559), and 18 participants with presenting impairment but no refractionaided measurement were excluded from the secondary outcome.

The statistical analysis plan was finalized on 7 October 2026, after preliminary data checks and before the main analyses. Analyses added after the plan were the age-adjusted comparison of visual impairment, refraction-aided impairment by group, the AMD models with retinopathy or diabetes as exposure, the agreement analysis, a three-category coding of smoking within S7, the self-reported diabetes model and age-standardized prevalence.

Analyses were performed in SAS/STAT 9.4 (TS1M8) on SAS OnDemand for Academics; the self-reported diabetes model and age standardization were performed in R 4.5.2 with the . survey package, version 4.5 [29]. Every reported value was checked against independently computed reference values. The analysis code and derived dataset are publicly available [20].

Large language model tools were used to assist with language editing, reference formatting, and figure preparation. All analyses were designed, performed, and verified by the authors, who reviewed all AI-assisted output and take full responsibility for the integrity and accuracy of this work.

The 277 proportion rose from 4.91% (4.23-5.60) among participants with neither condition to 7.09% 278 (4.93-9.25) with retinopathy only, 14.57% (9.86-19.27) with AMD only and 26.15% (14.22-279 38.08; 15 of 57) with both (Fig. 4). Weighted mean better-eye logMAR followed the same order (0.069, 0.079, 0.134 and 0.207; Wald F(3, 31) = 18.8, p < 0.001).

Adjustment for age separated the two conditions. Relative to participants with neither condition, the odds of impairment were not clearly raised with retinopathy only (OR 1.32; 0.91-1.90) but were more than doubled with AMD only (2.23; 1.54-3.23) and quadrupled with both conditions (4.09; 2.28-7.37). Age-adjusted mean logMAR at the sample mean age of 56.3 years was 0.071, 0.074, 0.110 and 0.172.

After objective refraction the gradient was steeper. Among 5541 participants with a refraction-aided measurement, 93 remained impaired: 0.53% (0.36-0.69) with neither condition, 1.65% (0.34-2.95) with retinopathy only, 5.53% (3.08-7.99) with AMD only and 10.69% (2.75-18.63) with both. Impairment was thus about ten times as common with AMD only as with neither condition, compared with three times for presenting acuity.

Most measured impairment was mild. Of the 456 participants with presenting impairment, 332 (73%) had a better-eye acuity of 20/50, one line below the threshold, and 40 had 20/200 or worse (Table 4, S6).

Self-rated vision barely separated the groups. Among the 5588 participants who rated their vision, poor or very poor vision was reported by 2.75% of those with neither condition, 4.21% with retinopathy only, 5.92% with AMD only and 5.71% with both, a spread of about 3 percentage points against 21 for measured impairment. Agreement between the two measures was slight (unweighted κ = 0.15): 12% of participants with measured impairment rated their vision as poor or very poor, and 39% as fair or worse.

Discussion

Graded from the same photographs in one national sample, retinopathy and AMD behaved as two different problems. Retinopathy was about one and a half times as common, but AMD carried more of the measured visual loss: with age held constant, impairment was more than . twice as likely with AMD alone and four times as likely with both conditions, whereas retinopathy alone carried no clear excess. The conditions had different correlatesglycemia, diabetes duration and male sex for retinopathy, age for AMD -opposite race/ethnicity gradients, and no association with each other. Self-rated vision captured little of this.

Our estimates reproduce the single-disease analyses of the same survey: 27.83% retinopathy among adults with diabetes against 28.5% [11], and 6.52% any AMD against 6.5% [12]. The contrasts between the conditions therefore reflect the conditions, not an unusual sample or definition. Presenting impairment (5.82%) was lower than the 7.5% reported by Chou et al. [13], most likely because we required photographs gradable for both conditions. Ungradable non-mydriatic images in older adults usually result from media opacity, small pupils or unsteady fixation, all of which also reduce acuity, so this requirement removed a disproportionate share of people who see poorly. Our estimates of visual impairment are, if anything, conservative.

In people with diabetes, retinopathy tracked glycemia: the odds rose by about half for each percentage point of HbA1c, in line with its central role in diabetic retinopathy [1, 2]. The association was not an artifact of HbA1c helping to define the subpopulation. Among participants with self-reported diabetes, for whom HbA1c plays no part in the definition, it held (OR 1.44), and diabetes duration, one of the strongest correlates of diabetic retinopathy [1], and insulin use, a marker of more advanced diabetes, entered with the expected strength.

Once duration was included, age lost its association, so the age gradient in the main model reflects time with diabetes rather than ageing. Systolic blood pressure, borderline in the main model, was associated in this fuller model. Male sex was associated with retinopathy in every model we fitted (ORs 1.53 to 1.89).

. Non-Hispanic Black adults had the highest prevalence of retinopathy and the lowest of AMD, and both contrasts survived age standardization. For retinopathy, the adjusted OR for non-Hispanic Black participants was similar in every model (1.32 to 1.47) and was statistically significant in the full sample, where precision was greatest (1.47; 1.07-2.01). An excess that persists after adjustment for HbA1c, blood pressure and body mass index points to factors these single measurements do not capture, such as cumulative glycemic exposure and access to diabetes and eye care. The lower prevalence of AMD in Black adults agrees with multiethnic and earlier NHANES analyses [10, 12]. The lower crude prevalence of AMD among Mexican American adults, in contrast, vanished after standardization (6.73% vs 6.87% in non-Hispanic White adults) and in the adjusted model (OR 0.98), and so reflects the younger age structure of this group rather than lower age-specific occurrence.

Half of the retinopathy in this population occurred in people without diabetes, and almost all of it was mild. In the full-sample model it was associated with blood pressure as well as HbA1c (Additional file 1: Table S3), matching an analysis of participants without diabetes in this survey, in which 98% of retinopathy was minimal to mild and its correlates were male sex, systolic blood pressure and HbA1c [30]. The full-sample prevalence is therefore a prevalence of retinal microvascular signs, not of diabetic retinopathy, which is why we modeled retinopathy within the diabetes subpopulation.

Ever-smoking was inversely associated with retinopathy in the diabetes model (OR 0.64), but the association weakened among participants with self-reported diabetes once duration and insulin use were included (0.69; 0.45-1.05) and was absent in the full sample (0.94; 0.71-1.24), where former and current smokers diverged (0.77 and 1.23). This pattern points to confounding and selective survival of smokers with less vascular disease rather than protection, and mirrors a meta-analysis in which smoking was associated with lower risk of diabetic retinopathy in type 2 diabetes and higher risk in type 1 diabetes [31].

. AMD was associated with age and little else, its odds rising about 2.4-fold per decade.

Smoking, the strongest established modifiable risk factor for AMD [8, 9], was not associated, which most likely reflects the measure available: lifetime smoking of at least 100 cigarettes merges long-term former smokers with current smokers and carries no information on dose.

Neither diabetes nor retinopathy was associated with AMD in identically adjusted models.

The meta-analytic association between diabetes and AMD is strongest for late disease [17], of which this sample contained 53 cases; for early AMD, which made up most cases here, our data give no indication of shared metabolic determinants.

The visual consequences of the two conditions show why prevalence is a poor guide to burden. Chou et al. found AMD, but not retinopathy, associated with nonrefractive impairment [13]; comparing the same people with age held constant sharpens that finding.

AMD alone doubled the odds of presenting impairment, and after objective refraction, which removes most of the impairment due to uncorrected refractive error, the AMD-only group had ten times the impairment prevalence of people with neither condition. The anatomy explains the difference: AMD involves the macula by definition, whereas retinopathy at the threshold used here is mostly mild nonproliferative disease, which seldom reduces central acuity. One in four participants with both conditions was impaired. Photographs taken for diabetic eye screening already include the macula; grading them for AMD as well would extend screening, without additional imaging, to the condition that carried more of the visual loss.

Self-rated vision barely registered these differences. Only one in eight participants with measured impairment described their vision as poor or very poor, and fewer than two in five as even fair. Most of this impairment was mild -73% of those affected read 20/50 -but 20/50 falls short of the 20/40 better-eye standard for an unrestricted driving licence in all but . three US states [32]. Gradual, bilateral loss is easily accommodated, and expectations of sight decline with age. Measuring acuity finds these people; asking them does not.

Strengths and limitations

Both conditions were graded on the same photographs, centrally and masked to diabetes status, in a national probability sample analyzed with design-based methods and identical models; the analysis plan, code and derived data are public. The design is cross-sectional, so the associations carry no temporal order. The data were collected in 2005-2008, and diabetes care and anti-vascular endothelial growth factor (VEGF) treatment of neovascular AMD have changed since, but no later US national survey has graded retinal photographs. Requiring gradable photographs for both conditions excluded 1204 participants (969 not photographed and 235 with ungradable images), which likely biases the prevalence of visual impairment downward. Two 45° non-mydriatic fields miss peripheral lesions, and NHANES measured presenting and refraction-aided rather than best-corrected acuity. Smoking was recorded as lifetime exposure, age was capped at 80 years, and estimates for the group with both conditions and for other Hispanic participants, for whom NCHS does not recommend separate estimates [25], are imprecise.

Conclusions

In US adults aged 40 years and older, retinopathy is the more common retinal finding, but AMD carries more of the measured visual impairment, independently of age. The two conditions have different correlates and are not associated with each other, and self-rated vision misses most measured loss.
