statistical_tests To identify combinations of baseline variables that moderate the treatment effect of priovi, we will use model-based recursive partitioning (Seibold et al., 2016, 2018). This approach combines a parametric base model for the treatment effect with a non-parametric, data-adaptive search for subgroups in which the treatment-effect parameter is unstable across candidate moderators. Both outcomes are analysed separately at the primary time point T1, and the same modelling pipeline is then repeated at T2 and T3 as exploratory sensitivity analyses (see Exploratory analysis).

The analyses rely on two outcome-specific base models, in which the group (treatment) parameter is the parameter of primary interest for partitioning. For the continuous outcome (change in BSL-23 from T0 to T1), the base model is a baseline-corrected ANCOVA, lm(delta_bsl23 ~ bsl23_T0 + group), which adjusts the estimated treatment effect for regression to the mean. For the binary responder outcome, the base model is a bias-reduced logistic regression, glm(responder ~ group, family = binomial(“logit”), method = “brglmFit”), fitted with the brglm2 package. We chose bias-reduced logistic regression over standard maximum-likelihood logistic regression because brglmFit yields finite, well-defined coefficient estimates even under near-separation conditions that may occur in small terminal nodes with extreme responder rates, while remaining virtually identical to standard maximum likelihood in the absence of separation. Because brglm2 objects inherit from glm, the score function and information matrix used by model4you::pmforest() for parameter-instability testing remain available.

For each outcome, we fit a model-based random forest with model4you::pmforest() using the corresponding base model. The seven candidate split variables described under Measured variables are passed to the forest via zformula = ~ bsl23_T0 + phq9_T0 + gad7_T0 + suicide_attempts_T0 + life_threatening_events_T0 + psychotherapy_T0 + medication_T0. Each forest consists of 500 trees (ntree = 500) grown on subsamples of size 0.632·N drawn without replacement (perturb = list(replace = FALSE, fraction = 0.632)) and stratified by group (strata = group), so that the treatment-arm balance is preserved in every subsample. At each split, three candidate variables are randomly selected (mtry = 3), and partitioning is governed by ctree_control(teststat = “quad”, testtype = “Univ”, mincriterion = 0, minbucket = 50, lookahead = TRUE, saveinfo = FALSE). The combination of minbucket = 50 with stratified resampling is intended to keep the treatment-effect parameter stable and to limit overfitting: given the observed arm balance of 52.1%/47.9% (302 IG vs. 278 CG) and the fact that all candidate split variables are independent of group at baseline by randomization, the probability of any terminal node containing fewer than 15 observations in either arm is approximately 0.3% per node.

For each outcome, four sets of results will be reported. First, we test the global null hypothesis of no treatment-effect heterogeneity across the candidate split variables using the omnibus parametric-bootstrap test model4you::pmtest() with B = 1000 bootstrap replicates. To clarify the role of the two resampling schemes in this pipeline: parameter instability itself is assessed at every potential split inside each tree by a deterministic score-based M-fluctuation test on the base-model score residuals, and the ensemble of 500 trees stabilises the resulting variable-selection signal and treatment-effect estimates by averaging over stratified subsamples; the B = 1000 parametric-bootstrap replicates in pmtest() (under which new outcome values are simulated from the fitted base model rather than permuted) are used solely to construct the null reference distribution against which the observed forest-level instability statistic is compared in order to obtain the omnibus p-value. Second, we quantify the relative contribution of each candidate split variable using conditional permutation variable importance (Strobl et al., 2008), computed via model4you::varimp() with conditional = TRUE, OOB = TRUE, nperm = 5, and threshold = 0.2. The conditional version of the importance measure is used to adjust for correlations among candidate split variables, which are expected to be substantial between baseline BSL-23, PHQ-9, and GAD-7 sum scores; for comparison and transparency, unconditional importance (conditional = FALSE) will additionally be reported in the supplement. Third, to obtain an interpretable summary of the moderating structure, we fit a single representative MOB tree to the full dataset using model4you::pmtree() with the same base model and the same zformula, but with testtype = “Bonferroni”, mincriterion = 0.95, and minbucket = 50. Fourth, for the three candidate split variables with the highest conditional permutation importance, we will produce partial dependence plots that display the predicted conditional average treatment effect (CATE) as a function of each moderator while averaging over the empirical distribution of the remaining variables.

The entire MOB-RP pipeline described above is fitted once to the complete-case dataset for each outcome at each follow-up time point. Specifically, we (i) fit the model-based forest with pmforest() and the corresponding base model, (ii) compute the omnibus heterogeneity p-value with pmtest() (B = 1000 parametric-bootstrap replicates), (iii) compute conditional permutation variable importance scores with varimp(), and (iv) fit a single representative MOB tree to the complete-case dataset with pmtree() (testtype = “Bonferroni”, mincriterion = 0.95, minbucket = 50). The omnibus p-value from pmtest(), the point estimates and rank order of the conditional permutation importance scores, and the representative tree are read directly from this single fit.

To attach uncertainty to the importance scores and to the subgroup treatment effects without relying on distributional assumptions, we use a nonparametric bootstrap that resamples participants with replacement, stratified by randomization arm to preserve the arm balance (B = 1000 bootstrap resamples). In each bootstrap resample we (a) refit the forest and recompute the conditional permutation variable importance scores, and (b) re-estimate the conditional average treatment effect (CATE) within each subgroup defined by the representative tree fitted on the original complete-case dataset. The tree structure is defined once on the original complete-case data and held fixed; the bootstrap re-evaluates these fixed subgroups so that the reported subgroup CATEs and their 95% confidence intervals reflect sampling variability while keeping the interpretation anchored to a single, reportable tree. For each importance score and each subgroup CATE, the 95% confidence interval is obtained from the 2.5th and 97.5th percentiles of its bootstrap distribution. As a stability summary, we additionally refit the representative tree in each bootstrap resample and report the empirical frequency with which each candidate split variable is selected at the root split.

Fallback for computational cost. The pre-specified pipeline (per outcome and per follow-up time point: one 500-tree forest, a 1,000-replicate pmtest(), and a 1,000-resample stratified nonparametric bootstrap in which the forest is refit and the conditional variable importance recomputed) is computationally demanding, and we will run it as specified whenever feasible on the available compute. If the analysis proves computationally intractable in practice, we will apply, in a single pre-specified step, the following reduction: ntree is lowered from 500 to 200, the number of parametric-bootstrap replicates B in pmtest() is lowered from 1,000 to 200, and the number of nonparametric bootstrap resamples is lowered from 1,000 to 500. All other settings (mtry, perturb, strata, the ctree_control parameters, and minbucket) remain unchanged, as does the pooling of bootstrap percentile confidence intervals. If this fallback is triggered, it is applied consistently to both outcomes and to all follow-up time points, and its use is transparently reported in the final paper.

All analyses will be performed in R (≥ 4.4) using the packages model4you (≥ 0.9-8) (Seibold et al., 2019), partykit (Hothorn & Zeileis, 2015), brglm2 (Kosmidis, 2017), and ggplot2 (Wickham, 2011). The forest fitting and the nonparametric bootstrap will be parallelised across cores to keep the pipeline tractable. To ensure exact reproducibility, set.seed(1234) is fixed before the analysis is initiated and propagated to the bootstrap resampling; the package versions, the random seed, and the full analysis script will be deposited on OSF together with this preregistration.
statistical_power Closed-form power calculations for model-based recursive partitioning are not available because the procedure is data-adaptive (splits, depth, and node sizes are estimated from the data). We therefore quantify expected power using a heuristic anchor based on classical interaction power calculations.

Following (Brookes et al., 2004), detecting a treatment × moderator interaction of the same standardized magnitude as a main effect requires approximately four times the sample size to attain the same power. Given the average treatment effect of priovi at T1 reported in the main publication (Cohen’s d = 0.24 on BSL-23), we anchor the expected power for the present subgroup analyses on this value.

Because the confirmatory analysis is performed on a complete-case basis, the relevant sample size for the T1 analysis is the complete-case N of 530 (267 IG, 263 CG), on which we anchor the power calculation.

Specifically, with N = 530 (267 IG, 263 CG) at T1, the present sample provides:

- approximately 80% power to detect a between-subgroup difference in the standardized treatment effect of d = 0.25 at uncorrected alpha = 0.05;
- approximately 80% power to detect a between-subgroup difference of d = 0.35 after Bonferroni correction across the seven candidate split variables (alpha = 0.05 / 7 = 0.0071), as applied within the recursive partitioning splitting rule.

Smaller heterogeneity (e.g., a subgroup contrast of d ≤ 0.15) is unlikely to be reliably detected with the present sample. We therefore interpret the present analysis as well-powered for moderately sized effect heterogeneity (subgroup contrasts of d ≥ 0.35 in the standardized treatment effect) and underpowered for smaller heterogeneity.
inference_criteria All confirmatory tests are two-tailed, in accordance with the non-directional primary hypothesis (see Hypotheses). The nominal significance level is alpha = 0.05.

The forest uses unadjusted p-values with mincriterion = 0 to maximize variable-importance signal.

In the representative tree, model-based recursive partitioning performs two-tailed score-based parameter-instability (M-fluctuation) tests at each split. To rigorously control the family-wise error rate during the recursive partitioning process, p-values for potential splits are adjusted using a Bonferroni correction over the seven candidate split variables.

Across outcomes: the two outcomes (BSL-23, responder status) will be tested in a fixed hierarchical sequence to control the family-wise error rate across outcomes: BSL-23 is the primary outcome and is tested first; the responder analysis is only interpreted confirmatorily if the BSL-23 omnibus test is significant. Otherwise, the responder analysis will be reported as exploratory.

Across time points: only T1 analyses are confirmatory. T2 and T3 analyses are exploratory and no further multiplicity adjustment is applied across time points.

Primary inference (non-directional): confirmation of the primary hypothesis as well as the secondary hypothesis A regarding treatment response is based on (i) the two-tailed omnibus p-value from pmtest(), (ii) conditional permutation variable importance scores together with their rank order, (iii) bootstrap-based 95% confidence intervals for subgroup CATEs in the representative tree (B = 1000 nonparametric bootstrap replicates in which the original tree structure is fixed), and (iv) the calibration and discrimination metrics described in Reliability and Robustness Testing. Subgroup CATEs whose 95% bootstrap CI excludes zero are interpreted as evidence of meaningful heterogeneity.

The secondary directional hypothesis (secondary hypothesis B) is evaluated descriptively only; no formal one-sided test is performed.
assumption_violation_model_non_convergence A key advantage of using model-based random forests is their inherent robustness to several classical statistical assumptions. Unlike traditional global regression models, this approach does not assume linear relationships between the covariates and the treatment effect, nor does it require a pre-specified functional form for interactions. By employing a non-parametric recursive partitioning strategy, the forest effectively accommodates non-normal distributions and handles complex non-linear dependencies. Furthermore, the use of ensemble averaging across 500 trees mitigates the influence of individual outliers and reduces the risk of model misspecification, ensuring stable and reliable estimates even in the presence of minor heteroscedasticity or skewed outcome data.

The use of model-based recursive partitioning ensures high numerical stability, as the local estimation of parameters within each node is less prone to the convergence issues typically encountered in complex, global longitudinal models. Furthermore, the linear and logistic base models utilized in this framework rely on robust estimation procedures that consistently reach stable solutions within our sample size of n = 530.
reliability_and_robustness_testing To prevent overfitting and ensure the validity of the identified subgroups, the model-based recursive partitioning algorithm employs formal statistical parameter-instability (score-based M-fluctuation) tests for each split in the representative tree, so that a split is only performed if there is statistically significant change in the model parameters.

In addition, we conduct a global omnibus test for significant heterogeneity of the treatment effect (pmtest()).

Beyond these built-in safeguards, we use two outcome-specific validation strategies, both of which are based on out-of-bag (OOB) predictions from the model-based forest. Using OOB predictions ensures that calibration and discrimination metrics are estimated honestly without requiring an additional sample-splitting step. Both metrics are computed on the complete-case dataset, and their 95% confidence intervals are obtained from the same stratified nonparametric bootstrap (B = 1000 resamples) used for the variable importance scores and subgroup CATEs:

1) Quartile-based calibration analysis (BSL-23, continuous outcome). Each participant’s predicted CATE is obtained from the trees in which the participant was not part of the bag (OOB prediction). Participants are then partitioned into quartiles based on these predicted CATEs. Within each quartile, the average observed treatment effect is calculated by re-fitting the ANCOVA base model on the participants in that quartile. Alignment between predicted and observed treatment gains across quartiles supports the calibration of the model. Quartile-specific observed CATEs and their 95% percentile confidence intervals are obtained from the stratified nonparametric bootstrap.
2) Concordance probability for benefit (responder, binary outcome). We compute the concordance-for-benefit statistic (van Klaveren et al., 2018), again using OOB predictions of treatment-specific responder probability, to quantify the probability that the model correctly identifies which of two randomly matched patients (one IG, one CG; matched on baseline BSL-23 within ± 0.2 SD) derives a greater benefit from the treatment. The c-for-benefit statistic and its 95% percentile confidence interval are obtained from the stratified nonparametric bootstrap.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

This module checks references and warns for citations of original studies for which replication or reproduction studies exist in the FLoRA database.

The Replication Check module compares the reference list against studies in the FLoRA (FORRT Library of Replication Attempts) database based on the DOI. If a study in the database is found, a reminder is provided that a replication or reproduction of the original study exists, and should be cited. No reminder is given when the paper already cites that replication or reproduction (matched by its DOI).

The module requires that the reference has a DOI: the DOI in the paper’s reference list, or one looked up with add_bib_match() before the module runs (see ref_table()). References without a DOI are not checked.

It is possible the original study was cited for other reasons than the empirical claim tested, or that the replication/reproduction in the FLoRA database is for only one of the studies in the paper, and not the study the authors discuss.

The database can be manually updated with the FLoRA_update() function. For more information, see https://forrt.org/FLoRA/.

Full text

Abstract

The digital therapeutic priovi has small average effects for borderline personality disorder (BPD). In this preregistered secondary analysis, we aimed to explore the heterogeneity and potential moderators of these effects. Adults received priovi plus treatment as usual or treatment as usual alone. At the 3-month primary endpoint (N = 528), model-based recursive partitioning showed heterogeneous effects on Borderline Symptom List-23 (BSL-23) change (p = 0.022) and on clinically relevant response (p = 0.007). Benefit was larger at higher baseline symptom load: a representative tree split on Patient Health Questionnaire-9 at a score of 23, and the higher-score subgroup had roughly twice the BSL-23 reduction (conditional average treatment effects -0.40 versus -0.19). Baseline BSL-23, depressive symptoms, and recent life-threatening events ranked as the leading moderators. Quartile calibration of predicted CATEs was weak and non-monotonic. The moderators are hypothesis-generating and should not guide patient selection without external validation.

Introduction

Borderline personality disorder (BPD) is a common and burdensome condition associated with pronounced emotional instability, interpersonal difficulties, self-harm and elevated suicide risk, as well as substantial functional impairment and high healthcare costs 1, 2 . Evidence-based psychotherapies exist but are resource-intensive and not universally accessible, motivating scalable digital interventions to bridge treatment gaps.

priovi is a self-guided digital therapeutic based on schema-therapy principles, designed as an add-on to routine care. In the EPADIP-BPD randomized controlled trial, adding priovi to treatment as usual (TAU) produced a small average reduction in borderline symptom severity relative to TAU alone at the primary 3-month endpoint 3 . As is typical for complex psychosocial and digital interventions, this average may obscure meaningful variation in individual benefit.

Understanding for whom a digital intervention works is central to precision mental health care. The central question in precision health care is "what works best for whom".

Addressing this question is relevant for patients, therapists, and the society. For an individual patient, it is important to know whether she:he with her:his individual characteristics will benefit from a digital intervention or not. If no benefit is expected, patients can save time and resources by skipping digital interventions without expected benefit for them and select and engage in digital interventions with a high probability of treatment success. Therapists also want to know if their individual patients will have a benefit from a digital intervention and whether they should recommend or prescribe a digital intervention to their individual patients. In societies with public reimbursement for empirically evaluated digital interventions, as for example in Germany for "DiGAs", it is also of high financial relevance to know which patients with which characteristics benefit from a DiGA or not. Identifying the specific patient characteristics for which an intervention works most is challenging as there are potentially endless characteristics of patients that might be relevant to consider. Most of the past research, therefore, selected clinically relevant variables that might statistically moderate the effect of an intervention on the outcome to identify subgroups of patients with more or less treatment success 4, 5 . Yet, traditional one-moderator-at-a-time subgroup analyses are underpowered, prone to false positives under multiplicity, and unable to capture combinations of characteristics that jointly shape benefit. Model-based recursive partitioning (MOB-RP) and its ensemble extension, the model-based random forest, address these limitations by pairing a parametric treatment-effect model with an algorithmic search for regions of the moderator space in which that parameter shifts 6, 7 , producing interpretable, individualized estimates while guarding against overfitting.

In this preregistered secondary analysis of EPADIP-BPD, we applied MOB-RP to identify baseline characteristics that moderate the benefit of priovi on (i) change in BSL-23 and (ii) the probability of a clinically relevant response at the primary 3-month followup. We asked: (1) whether the treatment effect is heterogeneous; (2) which of seven prespecified candidate moderators are most influential; and (3) whether higher baseline psychopathology is associated with larger absolute benefit. Analyses at 6 and 12 months were prespecified as exploratory.

Results

Sample characteristics

The confirmatory T1 analysis sample comprised 528 participants with an observed BSL-23 outcome at three months (263 control, 265 intervention). Baseline characteristics by randomization arm are summarized in Table 1.

Differential effect of priovi on borderline symptom severity at T1 (confirmatory)

The confirmatory analysis of change in BSL-23 at T1 was based on N = 528 participants. The omnibus test rejected the global null of a homogeneous treatment effect (p = 0.022), supporting the primary hypothesis of treatment-effect heterogeneity.

By conditional permutation importance, the most influential moderators were Baseline BSL-23, Baseline PHQ-9, and Life-threatening events (3 months) (Table 2), identifying baseline psychopathology as the dominant class of moderators.

Consistent with this, the representative tree split on Baseline PHQ-9 at a cut-point of 23 (Figure 1).

The subgroup with the larger benefit comprised participants with higher baseline PHQ-9 (terminal node 3, n = 60) and had a CATE of -0.40 BSL-23 points, versus -0.19 points in the smaller-benefit subgroup (node 2, n = 468); more negative values denote a greater reduction in symptom severity favoring priovi. The 95% bootstrap CIs of both subgroup CATEs excluded zero (Table 3), but they overlapped substantially and the higher-symptom subgroup was small, so the difference between subgroups is not firmly established. This split was the most stable feature of the analysis: Baseline PHQ-9 was selected as the root moderator in 70% of bootstrap trees.

Notably, the single sharpest split point was thus defined by baseline depressive symptoms rather than by baseline BSL-23 itself, even though baseline BSL-23 ranked among the most important moderators overall.

The directional secondary hypothesis (that higher baseline psychopathology is associated with larger absolute benefit) was supported descriptively, as the subgroup defined by higher baseline depressive symptoms showed the larger reduction in BSL-23. Calibration across quartiles of the predicted CATE was weak and non-monotonic (Figure 2; r = -0.65): predicted and observed subgroup effects were inversely associated across quartiles, indicating poor calibration of the prediction model despite detectable group-level heterogeneity.

Differential effect of priovi on treatment response at T1

Because the BSL-23 omnibus test at T1 was significant (p = 0.022), the responder analysis is interpreted confirmatorily.

The responder analysis was based on N = 528 participants (41% responders under control vs. 57% under priovi). The omnibus heterogeneity test yielded p = 0.007. The most influential moderator by conditional permutation importance was Baseline BSL-23, followed by Medication at baseline and Psychotherapy at baseline (Table 4).

The representative tree split on Baseline BSL-23 at a cut-point of 1.83 (Figure 3), and Baseline BSL-23 was selected at the root in 66% of bootstrap trees, making it a highly stable moderator. Notably, however, the estimated risk difference in favor of priovi was virtually identical across the resulting subgroups (approximately +0.15 in both; Table 5), so the split separated patients' baseline probability of responding rather than their benefit from priovi; the corresponding subgroup confidence intervals overlapped almost completely.

Individual-level discrimination was limited: the concordance-for-benefit statistic was 0.47, close to the 0.5 chance level, indicating that the model did not reliably rank patients by their benefit from priovi. Even so, Baseline BSL-23 was the most frequent root moderator across bootstrap trees (83%). The concordance-for-benefit statistic was 0.51.

For treatment response, baseline BSL-23 was the most stable moderator across all three time points, selected at the root of bootstrapped trees in 66%, 76% and 83% of resamples at T1, T2 and T3, respectively. As at T1, baseline symptom severity (baseline BSL-23 and PHQ-9) dominated the conditional importance rankings for the continuous outcome, and where an interpretable subgroup emerged the larger benefit again fell to patients with higher baseline severity, consistent with the directional secondary hypothesis. The exploratory analyses also revealed limits to this pattern: at some time points the omnibus test was significant while no single split survived the representative tree's Bonferroni threshold; subgroup estimates were imprecise with widely overlapping confidence intervals; and individual-level validation remained weak (concordance-for-benefit near 0.50). By the 12-month follow-up the subgroup treatment effects were close to zero with confidence intervals including zero, in line with an intervention benefit that attenuates over time. These time points were prespecified as exploratory and are not interpreted confirmatorily.

Discussion

Adding priovi to treatment as usual produced a heterogeneous rather than a uniform benefit at the three-month endpoint. For borderline symptom severity, the global test of heterogeneity was significant (p = 0.022), and both the representative tree and the bootstrap root-split frequency identified baseline depressive symptoms as the most stable moderator, whereas conditional variable importance ranked baseline BSL-23 highest; both findings point to baseline symptom severity as the central axis of moderation. Patients with a higher baseline symptom load showed the larger absolute reduction in BSL-23, consistent with our directional hypothesis. For clinically relevant response the heterogeneity test was likewise significant (p = 0.007) and baseline BSL-23 was the dominant, highly stable moderator, but the resulting subgroups differed mainly in their baseline probability of responding rather than in the absolute benefit derived from priovi. Across both outcomes, predictive performance was weak: quartile calibration for BSL-23 change was non-monotonic and the concordance-for-benefit for response was close to chance, indicating that, although moderation is detectable at the group level, the present model is not ready to guide individual-level treatment decisions.

Exploratory analyses at 6 and 12 months were broadly consistent in identifying baseline symptom severity as the recurring moderator, most stably for treatment response, but the subgroup structure became less clearly defined and the treatment benefit . attenuated toward the 12-month follow-up, underscoring that these moderators are hypothesis-generating and require prospective external validation.

In the main EPADIP-BPD trial, adding priovi to treatment as usual produced only a small average reduction in borderline symptom severity at the three-month endpoint 3 . This modest average effect is consistent with the broader treatment literature for BPD, in which even established face-to-face psychotherapies such as dialectical behavior therapy and psychodynamic approaches produce only small to moderate effects that are frequently unstable at follow-up 8, 9 . It also aligns with the emerging evidence on digital interventions for BPD, where benefits have been shown for specific targets such as suicidal ideation but not consistently for overall symptom severity 10, 11 . Our analysis qualifies this average: the benefit was not uniform but was concentrated among patients with higher baseline symptom severity, in whom the estimated reduction in BSL-23 was approximately twice as large. A pattern in which more severely affected patients derive larger absolute benefit, having more room for improvement, has been described for other psychological and digital interventions 12 . In particular, an individual-patient-data network meta-analysis of internet-based cognitive behavioral therapy for depression identified baseline severity as the most important modifier of relative efficacy, with larger benefits at higher baseline severity 13 , closely paralleling the severity gradient we observed for priovi. Importantly, in the binary responder analysis higher baseline severity was also associated with a higher baseline probability of response, so part of the apparent moderation reflects differences in baseline prognosis rather than in the treatment benefit itself, a distinction between prognostic (risk) modeling and effect modification 14 that is central to predictive approaches to treatment-effect heterogeneity 15,16 . Methodologically, our approach applies established model-based recursive partitioning and model-based forest methods for subgroup and individualized treatmenteffect estimation 6, 7 together with conditional permutation importance 17 . Finally, the weak out-of-bag calibration and near-chance concordance-for-benefit we observed are consistent with broader concerns that reliable individual-level treatment-benefit prediction is difficult to achieve in single trials of moderate size 18.

Our analysis has several strengths. First, it followed a preregistered protocol, which fixed the outcomes, candidate moderators, and analytic strategy in advance and thereby kept the confirmatory three-month analysis clearly separate from the exploratory follow-up analyses, reducing the risk of data-driven or selective reporting.

Second, rather than testing one candidate moderator at a time, we used a data-adaptive approach (model-based recursive partitioning and model-based forests) that weighs many baseline characteristics jointly and lets the data determine which of them, and in what combination, modify the treatment effect, while built-in complexity control guards against overfitting. Third, we assessed predictive performance honestly: calibration and the concordance-for-benefit were estimated on out-of-bag observations that had not contributed to the trees generating a given prediction, so they reflect genuine out-ofsample behavior rather than in-sample optimism. Fourth, we quantified uncertainty with a distribution-free bootstrap, obtaining subgroup confidence intervals that do not depend on parametric assumptions about the shape of the treatment-effect distribution.

These strengths are balanced by several limitations that temper our conclusions.

Because the analyses were complete-case in the presence of differential dropout, their validity rests on the assumption that missingness is conditionally ignorable, that is, missing at random given the observed baseline variables and randomization arm; if unmeasured factors jointly drive both dropout and outcome, the estimates could be biased in ways the present design cannot rule out. Statistical power adds a further constraint, as the study was adequately powered only for moderate heterogeneity (standardized subgroup differences of about d ≥ 0.35) and underpowered for smaller but potentially meaningful differences in benefit, so the absence of a given moderator signal cannot be read as firm evidence that no such moderation exists.

A second set of caveats concerns how the severity signal should be interpreted. The candidate moderators were baseline characteristics that were observed rather than manipulated, and although randomization renders the average treatment effect unconfounded, the association between a moderator and the magnitude of benefit is itself observational and may be confounded by unmeasured correlates of baseline severity. This is compounded by the construction of the responder outcome, which combines a reliable-change criterion with a shift to a less severe severity grade and uses baseline BSL-23 both as the reference for change and as a candidate moderator; together these features can make baseline severity mechanically influential and should be borne in mind when interpreting its prominence. Precision was a further concern: the subgroup with the largest benefit at T1 was small (n = 60) and its confidence interval wide, while calibration and the concordance-for-benefit indicated poor individual-level discrimination, so the moderation is best regarded as hypothesis-generating rather than clinically actionable. The same caution applies to the later time points, where analyses beyond the primary endpoint were exploratory and multiple and the attenuation of effects by twelve months coincided with degenerate representative trees, limiting their interpretation. One prespecified moderator, suicide attempts in the previous three months, was too rare (reported by only 6.4% of participants) to yield an admissible split in any tree, so its zero variable importance reflects a lack of statistical resolution for a low-prevalence variable rather than a moderator that was evaluated and excluded.

Finally, because the findings derive from a single trial with differential dropout and were not externally validated, their generalizability remains uncertain 16, 19 . priovi is a low-threshold, scalable, and low-risk digital add-on to standard care, and our results speak to how confidently it can be offered across the range of patients seen in practice. Baseline symptom severity was the most consistent signal across outcomes and time points, and patients with a higher baseline symptom load showed the largest absolute reduction in BSL-23. Because more severely affected patients often carry the greatest unmet need and can be harder to reach with resource-intensive care, it is encouraging that a self-guided digital option appears to benefit them at least as much as others. This lends additional support to offering priovi broadly as a complement to standard treatment, with particular promise for patients presenting with greater baseline severity. These implications remain provisional: individual-level calibration was weak, concordance-for-benefit was close to chance, and the subgroup benefit attenuated by twelve months, so the results do not yet support tailoring treatment to individual patients. Baseline severity, like any other candidate moderator, would need to be confirmed prospectively and validated in independent samples before it could formally inform clinical practice 20, 21.

In this preregistered secondary analysis, the three-month benefit of priovi was heterogeneous and most pronounced in patients with higher baseline symptom severity, yet validation of the predicted treatment effects was weak and the effect attenuated by twelve months. Baseline severity is thus a promising but not yet actionable moderator. More broadly, this first preregistered heterogeneity analysis of a digital therapeutic for BPD shows that group-level moderation can be detected while reliable prediction of treatment benefit remains out of reach in a single trial of moderate size. Realizing the promise of personalized digital care will require prospective external validation in larger, ideally multi-site samples, and evaluation of the clinical utility of acting on such predictions, before baseline severity or any other moderator can guide patient selection.

Methods

Study design and participants

This is a preregistered secondary analysis of the EPADIP-BPD trial; its full design, procedures and primary results are reported in the main publication 3 . In brief, that trial enrolled adults whose BPD diagnosis was confirmed with the SCID-5-PD and who showed at least moderate symptom severity (a BSL-23 mean item score ≥ 1.07), while excluding people with a comorbid substance use or psychotic disorder. Using a pragmatic, rater-blinded, two-arm parallel-group design, 580 participants were randomized in Germany, 302 to priovi added to TAU and 278 to TAU alone. Each

Treatment condition

The randomization arm (group) is the treatment variable of primary interest, coded as a binary factor with levels 0 (control; TAU only) and 1 (intervention; priovi added to TAU).

Because all candidate moderators were measured at baseline, they are independent of the arm by design.

Measures

Outcomes. The BSL-23 was scored as the mean item score (the sum of the 23 items divided by 23; range 0-4), and all BSL-23 quantities below are reported on this scale.

The continuous outcome was the change in the BSL-23 22 mean item score from baseline to the respective follow-up (T0-to-T1 for the confirmatory analysis). The binary outcome was clinically relevant response, defined as meeting both the reliable-changeindex criterion 23 and showing a change in the BSL-23 score toward a less severe severity grade relative to baseline 24 (1 = responder,0 = non-responder).

Baseline covariate. For the BSL-23 outcome, the baseline BSL-23 mean item score entered the base model as a covariate to adjust for regression to the mean.

Candidate moderators.

Seven prespecified baseline variables were supplied as candidate moderators: (i) baseline BSL-23, (ii) baseline PHQ-9 25 , (iii) baseline GAD-7 26 , (iv) number of suicide attempts in the three months before baseline, (v) number of life-threatening events in the three months before baseline, (vi) psychotherapy status at baseline (1/0), and (vii) medication status at baseline (intake of sedatives or antidepressants; 1/0). Medication status was derived from recorded Anatomical Therapeutic Chemical (ATC) codes as any regular or as-needed intake of an agent classified under N06A (antidepressants) or N05C (hypnotics/sedatives). Baseline BSL-23 enters in two roles (as a covariate in the BSL-23 base model and as a candidate moderator) so that partitioning can detect moderation by baseline severity; splitting responds to instability in the treatment-effect parameter itself (detected via the score function), not to its average level.

Missing data and analysis samples

We used complete-case analysis throughout: for each follow-up we included only participants whose outcome at that time point was observed, and we did not impute missing outcomes. Because complete baseline data were a prerequisite for randomization, inclusion is governed solely by outcome availability. Dropout differed between arms (higher under the intervention).

Statistical analysis

Following our preregistered plan, we used model-based recursive partitioning (MOB-RP) and model-based random forests to identify combinations of baseline characteristics that jointly modify the effect of priovi 6, 7 . Both outcomes were analyzed separately at the primary 3-month endpoint (T1). The same procedure was repeated at 6 and 12 months (T2 and T3) as exploratory analyses. The primary analyses were complete-case: participants without an observed follow-up BSL-23 at the relevant time point were excluded. As a robustness check against differential dropout, we repeated the two T1 analyses after a single stochastic imputation of follow-up BSL-23 (predictive mean matching, fitted separately within each randomization arm, one completed dataset, seed 1234); the binary responder was derived from the imputed BSL-23 using the same definition as in the primary analysis. Full single-imputation results confirm the complete-case analysis and are reported in the Supplementary Information (Supplementary Note 1 and Supplementary Tables 7 8 9 10 11). The complete-case analysis remains the primary analysis.

Base models. For each outcome we specified a simple model whose treatment-effect parameter was the target of partitioning. For the continuous outcome this was a baseline-adjusted (ANCOVA-type) linear model of the change in BSL-23, with baseline BSL-23 as a covariate. For the binary responder outcome it was a logistic model estimated with bias reduction, which keeps the treatment-effect estimate finite even in small subgroups while remaining virtually identical to maximum likelihood otherwise.

Model-based recursive partitioning then searched the seven prespecified baseline moderators (baseline BSL-23, PHQ-9, GAD-7, suicide attempts, life-threatening events, current psychotherapy, and current medication) for cut-points across which the model parameters changed. Because this instability is assessed over the whole score vector of the base model, a split can reflect a difference in the size of the treatment benefit, a difference in baseline prognosis, or both.

Forest, omnibus test, and variable importance. To estimate this heterogeneity robustly, we aggregated 500 such trees into a model-based random forest. Each tree was fitted to a group-stratified subsample of 63.2% of observations drawn without replacement; at each split, three candidate moderators were considered at random, with a minimum of 50 observations per terminal node. We tested the global null hypothesis that the treatment effect does not vary with any baseline characteristic using a parametric-bootstrap permutation test with 1000 replicates. We ranked the moderators by conditional permutation variable importance 17 , which evaluates each moderator within strata defined by the remaining moderators and therefore reflects its contribution conditional on the others. Unconditional permutation importance, which permutes each moderator independently and therefore reflects its marginal association, is reported in the Supplementary Information (Supplementary Tables 1 2 3 4 5 6).

Model assumptions and inference.

The omnibus heterogeneity test used a parametric-bootstrap permutation procedure (B = 1000) based on score contributions from the base model and therefore does not depend on residual normality of the linear BSL-23 model. For the binary outcome, bias-reduced logistic regression was used to avoid infinite estimates in small subgroups.

Representative tree, subgroup effects, and partial dependence. For interpretability we fitted a single representative tree with the same base model and the same seven moderators, Bonferroni-corrected split tests across those moderators (minimum criterion 0.95), and a minimum of 50 observations per terminal node. For each terminal subgroup we report the conditional average treatment effect (CATE): the group coefficient for the continuous outcome and a g-computation risk difference for the binary outcome. For the three most important moderators we also visualized how the predicted effect varied across the moderator, averaging over the observed distribution of the remaining moderators (partial-dependence profiles; Supplementary Fig. 1 2 3 4 5 6).

Uncertainty, calibration, and discrimination.

Uncertainty for the importance scores and the subgroup CATEs was obtained from a stratified nonparametric bootstrap (1000 resamples with replacement within arm). The tree structure was fixed on the original data and re-evaluated in each resample; 95% confidence intervals are the 2.5th and 97.5th percentiles of the bootstrap distribution. We also recorded how often each moderator defined the first split of a tree refitted in each resample. For the continuous outcome we assessed calibration by grouping out-of-bag predicted CATEs into quartiles and comparing them with the observed treatment effect in each quartile. For the binary outcome we computed the concordance-for-benefit statistic from out-of-bag predictions 15 . Both metrics used the same stratified bootstrap.

Multiplicity.

All confirmatory tests were two-sided at α = .05. The two outcomes were tested hierarchically, BSL-23 first, with the responder analysis interpreted confirmatorily only if the BSL-23 omnibus test was significant and exploratorily otherwise. Only the T1 analyses were confirmatory. Subgroups whose 95% CI for the CATE excluded zero were interpreted as evidence of meaningful heterogeneity; the directional secondary hypothesis was evaluated descriptively.

Statistics and reproducibility.

Analyses used R (v4.6.1) 27 with model4you (v0.9-9) 28 , partykit (v1.2-27) 29 , brglm2 (v1.1.0) 30 and ggplot2 (v4.0.3) 31 ; forest fitting and the bootstrap were parallelized. A fixed seed (set.seed(1234)) was set before analysis and propagated to the bootstrap. The code used for analysis can be found at https://osf.io/ker2t/.
