Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. For more information, see StatCheck.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

Version 0.4.4.3 reported 419 p-values as imprecise, 388 of them correctly (93%), and missed 50 (89% found). How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Potent sex effects on the prevalence and presentation of autism could theoretically reflect overlapping neurobiology, but tests in brain gene expression have so far been limited to bulk tissue -overlooking cell type heterogeneity. Here, we use newly available single-nucleus RNAsequencing datasets, to test if regional, cell type-specific sex effects on gene expression overlap with those of autism (using schizophrenia as a comparison condition). Cellular gene expression effects were estimated for sex across six cortical regions (169 samples, 30 individuals), and for autism (63 individuals, 33 cases), and schizophrenia (140 individuals, 65 cases) in frontal cortex.

Genes with significant sex effects showed a stronger overlap with those differentially expressed in autism than schizophrenia. Multivariate analyses revealed a significant shared axis of transcriptomic effects between sex and autism (but not schizophrenia). This axis featured a protein-protein interaction network enriched for autism risk genes and synaptic biology, downregulated in autism across cell types, and female biased in fusiform neurons, but male biased in angular gyrus glial cells. Thus, the autism transcriptomic signatures in frontal cortex show cell type-and region-specific alignments with sex effects on gene expression -pointing to a complexity in overlaps that informs theoretical models of sex modulation of autism liability. limited to few brain regions, and it has recently been shown that sex differences on cell type gene expression can vary by brain region 45 . Thus, there is a pressing need to reappraise transcriptomic overlaps between sex and autism at single-cell scale -in a manner that takes advantage of the latest multi-region single-cell surveys of sex effects on brain gene expression 45.

Here, we leverage newly available single-cell datasets from postmortem human cortical tissue to test for the overlapping effects of sex 45 and autism 46 on cell type-specific gene expression. We also perform a parallel single-cell analysis of transcriptomic overlaps between sex and schizophrenia 47 -a less sex-biased condition at early onset 48, 49 . We test for transcriptomic overlaps using multiple complementary analytic methods, which converge on the same core findings. First, sex differences in cortical gene expression overlap more strongly with gene expression changes in autism than in schizophrenia. Second, transcriptomic overlaps between sex and autism are most consistently prominent for excitatory and inhibitory neurons -especially for neuronal sex effects in the fusiform gyrus. Third, within these neuronal populations, the transcriptomic convergence between sex and autism highlights genes enriched for synaptic biology, which harbor genetic risk for autism, are downregulated in autism, and upregulated in females. These findings highlight a region-and cell type-varying version of the "female protective effect" model 42,50 for sex differences in autism -whereby females may possess a higher liability threshold for manifestation of autism through a female-bias of autism-relevant synaptic pathways in select neural cell types that is more prominent in some cortical regions than others.

Introduction

Almost all neuropsychiatric conditions show sex differences in prevalence, presentation, and treatment response [1] [2] [3] . For example, males show higher prevalence of early childhood conditions, such as autism spectrum conditions (henceforth autism) [3] [4] [5] and attention-deficit/hyperactivity disorder (ADHD) 3, 6, 7 , whereas females show higher rates of adolescent-emergent anxiety and major depressive disorder 8 . These observations may in part reflect intersections between the neurobiology of sex and neuropsychiatric conditions 9 -motivating study designs capable of testing for, quantifying and localizing such intersections, which remained to be assessed with cell type resolution in human tissue.

Autism is one of the most strongly sex-biased conditions, with a 3-to-5-fold greater prevalence in males than females 10, 11 that is seen across diverse sociocultural contexts [11] [12] [13] . There are also marked sex differences in the average profile of clinical features: females with autism show fewer restricted behaviors, more internalizing symptoms [14] [15] [16] [17] [18] , and a higher likelihood for comorbid intellectual disability 19, 20 than males. The differential fit of these presentations with autism diagnostic criteria originally established in male-biased cohorts 21 may lead to diagnostic biasing [22] [23] [24] , yet different presentation in males and females itself represents a fundamental sex difference. Moreover, the male bias in autism prevalence is shared with several other phenotypically distinct neurodevelopmental disorders of early childhood onset 25 (e.g. ADHD 7 , obsessive compulsive disorder 26 , and disorders of language and motor coordination 27 )suggesting that there may be more fundamental intersections between the neurobiology of sex and these early emerging conditions, which is seen most strongly for autism.

Several studies have tested for overlaps between neurobiological correlates of sex and autism 14, 28, 29 , although this literature has focused on neuroimaging data 28, [30] [31] [32] [33] [34] [35] [36] [37] , with fewer reports considering measures of gene expression 23, [38] [39] [40] that can be more directly integrated with known genetic risk factors for autism 41 . The "female protective effects" model posits a higher liability threshold for autism in females 42 , with empirical support from greater etiological load in females with autism than males 43 . There is emerging evidence, from studies of bulk brain tissue, in support of this that there may be an overlap between female-biased genes enriched for synaptic annotations and genes that are downregulated in autism 44 . However, the exclusive use of bulk tissue has meant this work is unable to account for a key new insight afforded by single-cell sequencing technology 45, 46 : that effects of sex and autism on gene expression are both cell typespecific. Results

Datasets overview and analytical framework

We leveraged recently published single-cell datasets to test for and localize shared transcriptomic signatures between sex and autism across human brain cell types. As a comparison condition to benchmark the results, we performed a parallel analysis on sex and schizophrenia -which has a smaller sex bias than autism in early development (44).

Cell type-specific gene expression effects were estimated using available single-nucleus RNAsequencing (snRNAseq) post-mortem data as follows: (i) for sex in 169 samples across 6 cortical regions [fusiform gyrus (FusGyr), inferior lateral temporal occipital cortex (InfLTO), caudal insula (CauIns), intraparietal sulcus (IntParSul), retrosplenial cortex (RetCor), angular gyrus (AngGyr)] from 30 individuals (15 male / 15 female) 45 ; (ii) for autism in frontal cortex from 63 individuals (33 cases / 30 controls) 46 ; and (iii) for schizophrenia in frontal cortex from 140 individuals (65 cases / 75 controls) 47 (Fig 1A; Table S1). From these datasets, we extracted differential gene expression statistics, using log fold-changes (logFC) and false discovery rate (FDR) adjusted pvalues (q). We tested for transcriptomic overlap between datasets using two complementary analytic strategies: first, testing for overlaps among statistically significant differentially expressed genes (DEGs) in each condition; and second applying regularized canonical correlation analysis (rCCA) 52 as an efficient multivariate framework to simultaneously integrate threshold-independent genelevel logFC estimates between conditions across multiple cell types. This dual approach retained the distinctive strengths of both threshold-dependent and threshold-independent views of differential gene expression and helped identify the most robust results that jointly influence sex and autism or schizophrenia.

Sex and autism share a multivariate axis of transcriptional effects that highlights specific cell classes and biological pathways and is enriched for autism risk genes

To complement the DEG-based analyses, which are sensitive to thresholding by arbitrary statistical cut offs for DEG definition and insensitive to the full multivariate pattern of logFC in each dataset snRNAseq database, we next integrated gene expression effects in sex and autism using a regularized Canonical Correlation Analysis (rCCA) 65 (Fig 3A). Briefly, we used rCCA to take the full gene-by-celltype logFC matrices created by differential gene expression analysis of snRNAseq in two datasets and define an ordered set of maximally correlated canonical variates between the two input datasets. Each canonical variate is the linear combination of logFC values in one dataset that is maximally correlated with its corresponding canonical variate in the other.

We utilized a regularization approach (parameters lambda A = 0.1, B=0.1; Fig 3B) to stabilize the column loading. Regularization explicitly engages with the known correlational structure of logFC values between different cell types and region-by-cell type combinations for each dataset (Fig. S3A-B) 66 . The rCCA framework produces multiple interpretable outputs, including correlation magnitudes and gene scores for each pair of canonical variates (An, Bn, Fig 3B). Use of rCCA to find aligned transcriptional effects of sex and autism not only avoids arbitrary binarization of logFC values (as is required for DEG overlap analysis), but is compatible with powerful rank-based methods for biological annotation, which have several advantages over testing for enrichments in variably sized sets of overlapping DEGs 67 . Given that inclusion of sex chromosomes induces a major shift in logFC correlations within the sex difference dataset (reflecting disparate X-and Ychromosome dosage between males and females), but not the autism dataset (Fig S3C) -we ran all rCCA analyses with and without inclusion of sex chromosome genes (Fig S4, Methods).

Across all genes (n=16515), rCCA revealed a statistically significant CCA1 component between the sex and autism datasets (CCA1(Sex, Autism) r= 0.28, empirical pperm = 0.046 vs. 1000 permutations of the sex dataset, Methods, Fig 3C). This was significantly greater than the sex and schizophrenia CCA1 (z-score = 5.02, p = 5.18e-07; Methods), which did not reveal a significant shared axis (CCA1 (Sex, Schizophrenia) = 0.12, p perm =0.618, Fig 3D). The effect size between sex and autism was preserved in rCCA analyses run after exclusion of sex-chromosome genes: (CCA1 Auto (Sex, Autism) = 0.27; albeit with a slightly raised permutation-based p-value of pperm = 0.10, Fig S4A) and remained larger than that of the sex-schizophrenia CCA1 (CCA1 Auto (Sex, Schizophrenia) = 0.12, Fig S4B).

Sensitivity analyses supported the robustness of the sex-autism CCA1. Restricting to genes with complete case rows (n=3749) yielded a consistent signature (CCA1 Complete Case (Sex, Autism) = 0.36; Fig S4C; Table S3), with highly correlated gene scores for sex and autism to the original CCA1 (mean rCCA1-CCA1complete =0.92). Additionally, when sexautism matrices were randomly downsampled 1000 times to match the dimensions of the sexschizophrenia analysis (11145 rows × 25 columns), the sex-autism CCA1 never fell below the sex-schizophrenia CCA1 of 0.12 (Fig S4D).

Analysis of structure correlations of autism CCA1 gene scores within each cell class (mean gene score structure correlation with all constituent cell types, Methods, Fig 3E) revealed a broadly positive correlation of autism CCA1 scores with logFC values in autism vs. controls across multiple cell types (i.e. genes with low autism CCA1 scores tend to be downregulated in autism vs. controls across frontal cortex cell classes). For sex however, there were region and cell class specific correlations between sex CCA1 scores and logFC values in males vs. females (meaning that the direction of transcriptional alignment between sex and autism varies depending on cell class and region where sex effects are measured). A mirrored profile is seen for genes at the opposite positive pole of the shared transcriptional axis between sex and autism: these genes tend to be upregulated across cell classes in autism, male biased in FusGyr neurons, and female biased in multi-regional glial cell classes (Fig 3E). We next focused on characterizing the significant CCA1 axis of shared transcriptional effects between sex and autism (Fig 4A; Table S3). A prominent feature of this axis was the high positive-ranking of Y-chromosome genes (CCA1 sex: normalized enrichment score (NES) = 2.18, FDR q = 8.17e-5 / CCA1 autism: NES = 1.84, FDR q = 0.02; Table S4). A similar pattern was seen for gene scores on the weaker and statistically insignificant CCA1 from comparison of gene expression effects of sex and schizophrenia (CCA1 sex: NES = 2.46, FDR q = 1.58e-29 / CCA1 schizophrenia: NES = 1.87, FDR q = 0.11; Fig S5A; Table S4). Indeed, Y-linked genes received identically ranked mean CCA1 scores for the sex-autism and sex-schizophrenia analyses (Fig S5B). By contrast, X-linked genes did not show a significant enrichment amongst genes ranked by CCA1 score for the sex-autism analysis (CCA1 sex: NES =1.14, FDR q = 0.48 / CCA1 autism: NES = 1.13, FDR q = 0.25) (Table S4). Profiling Y-linked gene expression in all datasets revealed the expectedly ubiquitous and large difference in Y-linked gene expression in the contrast between males and females (Fig S5C), alongside small, sparse and directionally variable differential expression in the case-control contrasts for autism and schizophrenia (Fig S5D,E).

These observations indicate that the high-ranking of Y-linked genes on both the sex-autism and sex-schizophrenia CCA1 components analyses reflects the aliasing of sex with Y-chromosome dosage rather than a substantial patterning of altered Y gene expression in autism or schizophrenia that contributed to their shared transcriptional axis with sex. Supporting this conclusion, sex-autism CCA1 gene scores were highly correlated between rCCA analyses run before and after exclusion of sex chromosome genes from analysis (mean r = 0.94, Fig S4F,G).

We next biologically characterized the stable and statistically significant shared CCA1 axis of transcriptional change between sex and autism through functional enrichment testing. To simplify rank-based annotation of this CCA component by gene set enrichment analysis (GSEA) 68 ; Methods), we derived a single gene ranking for annotation by averaging the sex and autism CCA1 scores into a single number ("CCA1 score") for each gene. The CCA1 scores defined a shared axis that was biologically distinct at both poles. GSEA identified more significant enrichments at the negative vs. positive CCA1 pole (Fig S6A, B; Table S4). Genes at the negative sex-autism CCA1 pole were significantly enriched for multiple glutamatergic synaptic signaling annotations and risk genes for both autism and schizophrenia (although more statisticallysignificantly so for autism vs. schizophrenia risk genes; Fig 4B, Table S4). We found the neuronal autism risk genes had significantly more negative CCA1 scores than gene expression regulation autism risk genes (Wilcoxon rank-sum test: W = 1039; p = 1.19e-04), as annotated by Satterstrom et al. 58 , revealing that autism risk genes related to the synapse annotated were preferentially associated with the negative sex-autism CCA1 pole. In contrast, genes at the positive pole were significantly enriched for mitochondrial energy metabolism (Fig 4C) and immune annotations (Fig S6E) but lacked any enrichment for risk genes (Table S4). Both the negative and positive poles were enriched for sex-autism shared global DEGs (negative: OR = 9.46, p = 4.27e-10; positive: OR = 5.04, p = 1.94e-04), indicating that the threshold-dependent and threshold-independent analyses converge. We next tested enrichment of the localized DEGs from the sex-DEGs in the fusiform gyrus inhibitory neurons and autism-DEGs in the excitatory neurons. The negative pole showed a trend towards enrichment of these shared DEGs (OR = 5.84, p =0.05), whereas the positive pole showed a significant enrichment (OR = 22.30, p = 7.99e-07). This agrees with the DEG-based localization, in which most of these shared DEGs were male-biased and upregulated in autism (Table S2, Fig. S2B), consistent with the positive pole's stronger enrichment.

Considered alongside structure correlations for the sex-autism CCA1 gene scores (Fig 3E), these findings indicate that genes at the negative sex-autism CCA1 pole -which are enriched for autism genetic risk and glutamatergic synapse annotations-tend to be downregulated across almost all cortical cell classes in autism, female biased in multiple FusGyr cell classes, and male biased in multiple glial cell classes across the AngGyr, CauIns and InfLTO junction (Fig S7A-B).

Correspondingly, genes at the positive sex-autism CCA1 pole-which lacked enrichment for autism genetic risk but tagged energy metabolism and immune terms-showed the opposite expression profile: upregulated in autism across all cell classes, male biased in multiple FusGyr cell classes and female biased in almost all glial cells across the AngGyr, CauIns and InfLTO junction (Fig S7A-B). Thus, sex and autism converge on a shared transcriptional axis with two opposing poles, the negative pole defined by autism risk and synaptic signaling, downregulated in autism, female biased in FusGyr, and male biased across other cortical brain regions; and the positive pole defined by metabolic and immune function, upregulated in autism with the reciprocal sex-bias pattern. Molecular networks at the transcriptional overlap between sex and autism

We next harnessed protein-protein interaction (PPI) analysis to test for biological interactions amongst genes at the negative pole of the sex-autism CCA1 axis (bottom 0.5% CCA1 gene score), which showed enrichment for autism risk genes (Fig 5). Parallel results are provided throughout for the positive CCA1 pole in supplementary material (Fig S8).

Genes at the negative pole of the sex-autism CCA1 (N=79) were enriched in PPI edges compared to a degree-matched null permutation (Methods, pperm < 0.001). Of these, 62 (78.5%) of these mapped genes coalesced into a single connected network comprising 159 interactions (Fig 5A).

Network analysis revealed that the ten most connected nodes ("hubs") were NRXN1, GRIN2A, NRXN3, GRM5, CNTNAP2, PTPRD, RBFOX1, DLGAP1, CNTN4, and DPP10 (Fig 5B). All ten hub genes were differentially expressed in autism and half were differentially expressed in sex (Fig 5A-B), linking the CCA-based, threshold-independent analysis with the DEG-overlap, threshold-dependent analysis. The network was strongly enriched for autism risk genes (34 of 62 genes, 54.8%, versus 7% of the CCA1 background; OR = 16.2, p < 0.001), and each of the ten network hub genes were risk genes. This indicates that the convergent signal between sex and autism captured by the negative pole concentrated on highly connected, established risk genes. This reflected a broader tendency within this network that autism risk genes were more interconnected than chance, based on retesting connectedness with shuffled autism risk gene assignment (Methods) (pperm <0.001 in each degree bin from two-to-ten), and showed significantly higher node degrees than non-risk genes (Wilcoxon rank-sum test: W = 718, p = 5.27e-04; Fig. 5C).

In line with expectations from rank-based enrichment analyses of sex-autism CCA gene scores (Fig 4B ; Fig S7; Table S4), negative-network hub genes were downregulated in autism, female biased in FusGyr neurons, and male biased across cell classes in AngGyr (Fig 5D). These genes were also strongly enriched for neuronal communication terms, including neuron cell-cell adhesion (FDR q = 2.49e-04), neuron recognition (FDR q = 3.41e-05) as well as other domains, including learning (FDR q = 3.48e-05), vocalization behavior (FDR q= 6.64e-03), and startle response (FDR q = 1.39e-03) (Fig 5E).

Given the important developmental dynamisms of sex and autism effects, i.e. pre-natal expression of autism risk genes, we predicted genes at the negative pole would show peaks of expression during specific developmental windows, particularly pre-and early postnatal period and puberty. Genes in the negative pole showed dynamic expression patterns similar to the trajectories of the collated autism risk genes: increasing throughout prenatal development, with a slight reduction postnatally and a slight rise in late adulthood (Fig 5F).

Finally -noting this prenatal dynamism in expression of genes defined by our analysis of shared transcriptional effects of sex and autism in adulthood -we asked how the signal of sex effects on cell type gene expression in adulthood related to those described for the prenatal and postnatal human brain 69 (Methods). Discussion

Our study integrates newly published single nucleus RNAseq studies of human cortex to reveal transcriptional overlaps between sex and autism, which localize to specific brain regions, cell classes and molecular pathways, and show enrichment for known neurodevelopmental risk genes. Our findings advance the understanding of biological intersections between sex and autism in three main directions as detailed below.

First, by combining differentially expressed genes across cell types, we show that these new snRNAseq results complement several findings from prior bulk RNAseq studies of transcriptomic overlaps between sex and autism 23, 38, 44 . Specifically, previous reports, primarily from bulk cortical RNAseq studies have reported that: female-biased genes are enriched among synaptic genes downregulated in autism and among neuronal/synaptic genes; and male-biased genes are found to be enriched among genes upregulated in autism and among microglial/immune genes 38, 44, 71, 72.

Our results corroborate and extend these observations with cell type resolution for synaptic pathways. We confirm that synaptic genes are indeed enriched amongst those that are both female-biased and down-regulated in autism within neurons. However, these same synaptic pathways are enriched amongst genes that are male-biased within glial cell types across multiple brain regions. In glia, these pathways are thought to support glial-neuronal interactions at the "tripartite synapse" 73 . Speculatively, if female-biased expression of these genes in neurons imparts resilience to genetic risk for autism, and male-biased expression of these genes in glial cells reflects a male-biased criticality of function, then this could set up two compounding pathways for sex-biased resiliency to genetic risk for autism at the synapse. We also recover the signal from prior bulk RNAseq studies of converging transcriptional signatures between sex and autism in immune-related biology 44, 74, 75 . However, these enrichments were comparatively weaker in snRNAseq data, and no immune GO terms were enriched in the shared DEGs between sex and autism, which may relate to the theorized non-genetic etiology of immune-gene dysregulation 76 , or subtle cell type proportion effects of sex and autism biasing bulk-RNAseq findings. Notably, we find that the nature of this overlap between sex and autism effects on immune-gene sets also differed by cellular context, a finding that would have been masked in bulk tissue. We show that immune pathways tend to be upregulated in autism broadly across all cell classes, upregulated in males within fusiform gyrus and caudal insula neurons, but upregulated in females within glial cells across many brain regions. This observation for immune pathways also invites the idea that intersections of sex and autism could potentially involve convergences of different mechanisms between interacting cell types. Taken together, these findings from new snRNAseq datasets further strengthen the idea that there is significant biological intersection between sex and autism at the level of gene expression. Strikingly, both complementary analytic approaches in our paper -the DEG-based and the CCA analysis -find that the strength of this intersection appears to be more prominent than that between sex and schizophrenia, a difference which aligns with the greater sex bias in autism vs. schizophrenia prevalence 4, 51.

Second, our use of snRNAseq measures of sex effects on gene expression from multiple brain regions lets us test if cell type transcriptional alignments between sex and frontal cortex signatures of autism vary by the brain region where sex effects are estimated. This test relies on measures of autism effects in frontal cortex alone because the field currently lacks multiregion snRNAseq datasets in autism. However, large-scale multiregion studies using bulk RNAseq suggest that transcriptomic signatures of autism are highly correlated across cortical regions 54 . We find that transcriptional effects of autism as captured by snRNAseq data in the frontal cortex show regionally-varying alignment with sex effects on cortical gene expression -with the strongest transcriptomic overlap being observed with sex effects on gene expression in the fusiform gyrus. This alignment -which echoes the prominently large and distinctive nature of sex effects on cell type gene expression in the fusiform gyrus as compared to the other regions under analysis 45 is particularly striking given the fusiform's well-established role in facial perception 77, 78 , a domain which has been implicated in both sex differences 79, 80 and autism 81, 82 . Further, the fusiform gyrus lies downstream of occipital visual cortex within the ventral visual stream, which may be meaningful as the visual network has been demonstrated to show the greatest transcriptomic disruption in autism 54 . The region and cell class dependence of transcriptional overlaps between sex and frontal cortex signatures of autism may help to reconcile some of the conflicting reports from prior studies 38, 83 . For example, other studies have reported female-biased (rather than malebiased) expression of immune genes and male-biased (rather than female-biased) expression of synaptic genes 75, 84 , with no substantial correlation to autism signatures in that context 85 . The directional variability we observe from different brain regions and cell types in sex may help explain why prior reports of sex effects on autism risk have been heterogeneous, which underlines the need for greater spatial sampling of brain tissue in future work. Additionally, only a subset of localized overlaps based on DEGs involved the same cell types in sex and autism, a finding that also would have been masked in bulk tissue, and interpretation of this differs based on what the cell types are. By pursuing a more comprehensive sampling of brain regions and cell types, future work will be able to further probe the model evoked by our current findings: connections between the neurobiology of sex and autism may be more prominent, and perhaps mechanistically pertinent, in some brain regions and cell types than others.

Third, we use our region and cell-class resolved view of transcriptional overlaps between sex and autism as input to protein-protein interaction (PPI) networks -revealing specific sets of interacting partner molecules that are not just enriched for convergent transcriptomic effects of sex and autism, but also for autism risk genes. We resolve a synaptic PPI network -which tends to be female biased in neurons and male biased in glial cells -that is highly enriched for genes that increase autism risk when haploinsufficient 86, 87 . Interestingly, while autism risk genes have been characterized into multiple domains, e.g. chromatin regulation, and synaptic 58, 88 , the overlapping effects of sex and autism concentrated on synapse-related risk genes. Some of these autism risk genes have previously been shown to exhibit region-specific expression across the brain 89, 90 , and our evaluation further revealed that while autism risk genes are ubiquitously downregulated in autism across most frontal cortex cell types, their sex-biasing exhibits two modes, with patterns of female biasing, consistent with female-protective effects, present in fusiform gyrus and retrosplenial cortex, and patterns of male biasing distributed across angular gyrus, caudal insula, and inferior later temporal occipital junction. This raises the possibility that it is the female-biased expression of risk genes in certain brain regions that may be especially salient to the risks and biology of autism. Future work is required to systematically evaluate the regional expression patterns of these risk genes across development and to fully delineate the meaning of the direction of their sex biasing.

Our findings should be considered in light of several important caveats and limitations. First, we operationalize sex as a binary variable based on genomically confirmed sex chromosome dosage, but there are other criteria by which sex can be measured, and there are groups of individuals who have mixed profiles of these criteria -meaning that sex is not strictly binary 91 . Second, we do not incorporate measures of gender -a complex multidimensional psychosocial construct that is entangled with sex and may account for some measured associations between sex and neurobiology. Third we characterize transcriptomic features of autism using associations between gene expression and a binary grouping of donors into those that met criteria for autism vs. those that did not. This approach is appropriate given the current sample sizes of postmortem brain snRNAseq data in autism but cannot engage with the well-established heterogeneity of autism at clinical, neurobiological and genetic levels of analysis 92 . Additionally, the autism snRNAseq data used here was exclusively from the frontal cortex. Previous work in bulk tissue found that signatures of autism are correlated across the cortex 54 , and we provide preliminary evidence that our findings hold using smaller non-frontal snRNAseq datasets in autism. However, it will be important for future work to further characterize overlaps of sex and autism across multiple brain regions. Fourth, expanding datasets will also make it possible to more fully probe how factors such as developmental stage and brain region might modulate cell type transcriptomic overlaps between sex and autism, especially regarding the more developmentally stable sex differences in fusiform gyrus compared to other brain regions. These expanded datasets would also benefit from investigating the sex-specific signatures of autism. Finally, our study of postmortem gene expression in humans is necessarily descriptive. While this design provides a powerful screen for potential transcriptomic overlaps between sex and autism, other study designs in model system will be needed to experimentally test the hypotheses raised by our work.

Notwithstanding these limitations, our work captures a significant intersection of gene expression for sex and autism and places this intersection in a more granular cellular context than was previously possible. We find overlaps between sex and autism effects within autism risk genes, which previous reports did not find 38, 93 . Our findings strengthen prior theories that synaptic and immune pathways may be points of biological convergence between sex and autism but show that the nature of this convergence -its magnitude and paired directions of fold change in sex and autism -varies as a function of both brain region and cell type.

Methods

Differential gene expression across datasets

Cell type resolved measures of differential gene expression in autism, and schizophrenia were drawn from recently-published landmark studies by Wamsley et al. 46 and Ruzicka et al 47 , respectively. Both of these studies applied limma 94 to single-nucleus RNA-sequencing (RNAseq) data from samples of frontal cortex in sex-balanced case-control samples (autism cases = 33 [males = 29, females =4], autism controls = 30 [males =23 ,females =7]; schizophrenia cases = 65 [males = 42, females = 23], schizophrenia controls = 75 [males = 43, females =32]). Both studies used group contrast where cases were compared to controls, so that positive logFC indicates higher expression in autism or schizophrenia. We generated analogous measures of cell type differential expression between males and females by applying limma-voom 94 to the recently-published snRNAseq dataset from DeCasien et al 45 which spans 169 cortical samples from 15 males and 15 females across 6 cortical regions [FusGyr, InfLTO, CauIns, IntParSul, RetCor, and AngGyr]. Single-cell library preparation, read mapping, and quality-control was previously conducted on this dataset by DeCasien et al. 45 . For differential gene expression, the counts were aggregated and normalized across cells for each cell type and sample to create a pseudobulked counts matrix. Differential gene expression for sex was run accounting for relevant covariates chosen by the original analysis 45 , including post-mortem interval, age, RNA-integrity number, total number of reads, and total number of cells. Sex-associated differential expression was assessed using a contrast comparing male versus female samples, thus positive logFC indicates a male bias and negative logFC indicates a female bias.

Differentially expressed gene overlaps

Differentially expressed genes (DEGs) were defined in the autism and schizophrenia datasets according to the published criteria applied to limma-voom outputs in the respective publications (False Discovery Rate (FDR) q < 0.05; |logFC| > 0.2 and >0.1 in the autism 46 , and schizophrenia 47 datasets, respectively). A more relaxed statistical threshold was applied to the sex-differences dataset (FDR q < 0.1), in line with previous work 95 , to ensure capture on expectedly small sex effects autosomal gene expression. Prior work in this dataset has established that FDR q < 0.05 thresholds to limma-voom output primarily detect sex DEGs on the dosage-disparate X-and Ychromosome, and fail to recover those distributed sex effects on autosomal gene expression that are otherwise detectable by multivariate adaptive shrinkage (MASH) 96 methods 45.

Pairwise DEG overlaps were analyzed at two levels of resolution. First, DEGs were collapsed across all cell types ("global" DEGs) in each of the three datasets and used to test for enriched overlaps for each of three pairwise comparisons by Fisher's exact test vs. the respective background: sex and autism, sex and schizophrenia, and autism and schizophrenia. To compare the odds ratio of the tests, we followed standard methodology for comparing two independent estimated quantities, dividing the difference between the log-transformed odds ratios by the standard error of that difference, calculated as the square root of the sum of the squared standard errors of each log odds ratio. The resulting z-statistic was compared to the standard normal distribution to obtain a two-sided p-value 97.

Fisher's exact testing p-values were adjusted for multiple comparisons via Benjamini-Hochberg FDR correction. Each global overlap set was then tested for functional enrichments with enrichGO from the clusterProfiler package 63 compared to their respective shared background, with minGSSize = 10 and maxGSSize = 500. Second, for the sex and autism comparison, DEGs overlaps were also assessed at finer resolution -for collapsed DEG sets within each broad cell class ("localized DEGs"). The localized overlapping DEG sets were evaluated by comparison to a null distribution of localized overlap counts using sex DEG sets from 1000 runs of limma-voom 94 on the sex differences snRNAseq dataset after sex permutation by donor. For all cell class combinations showing significant DEG overlaps (pperm < 0.05), we quantified the proportion of overlapping DEGs within the 4 possible combinations of mean logFC direction (meanlogFC across the constituent cell types within each cell class) between datasets: (1) male>female and upregulated in autism; 2) male>female and downregulated in autism; 3) female>male and upregulated in autism; or 4) female>male and downregulated in autism. We then tested the enrichment of each of these four directional combination sets using Fisher's exact test, with pvalues adjusted for multiple comparisons via Benjamini-Hochberg FDR correction 98 . All DEG overlap analyses were conducted with and without exclusion of sex chromosome genes as a sensitivity analysis.

Regularized canonical correlation analysis

Regularized canonical correlation analysis (rCCA) was used to identify multivariate patterns of shared gene expression changes between datasets -thereby taking advantage of the full distribution of observed logFC values of all genes, without imposing arbitrary statistical thresholds for defining DEGs 99, 100 . This multivariate approach also directly accommodates and models correlated fold change profiles between cell types for each condition, e.g. as recently reported for sex effects on gene expression 45.

The inputs of rCCA were gene-by-cell type matrices of logFC values, with genes as rows and cell types as columns. We applied rCCA twice -once for the sex and autism comparison, and again for the sex and schizophrenia comparison. For the sex matrix (matrix A), columns represented each cortical region-by-cell type combination; for the autism and schizophrenia matrices (matrix B), columns represented cell types. Cell type labels were harmonized into broad classes across datasets, but fine-grained differential-expression contrasts were retained within each matrix.

Genes were matched between dataset pairs by gene symbol; genes absent from either matrix were excluded, and missing gene-by-cell type estimates were treated as missing values. The sex-autism analysis included N = 16,515 matched genes.

The regularization aspect of rCCA prevents overfitting by penalizing the weights (λ A and λ B ) applied to columns for definition of canonical axes (Eq. 1; 66 ).

(1)

To select appropriate regularization parameters, we implemented a grid search optimization by calculating the mean correlations across canonical covariates across a range of regularization values from 0.1 to 1 in increments of 0.1 for both λA and λB. The optimal parameters were defined as the values of λA and λB that yielded the maximal mean canonical correlation across dimensions.

Analyses were performed using the rcc function from the CCA R package (v.1.2.2) 65 . The outputs of rCCA included the vectors of gene scores for each canonical axis corresponding to each input matrix. To test for statistical significance of rCCA components, we compared observed magnitudes of correlation across the canonical axes to a distribution of null correlations generated after re-running rCCA 1000 times using sex logFC matrices from permutations of the sex variable.

To determine which cell types and region-by-cell type pairs contributed to each canonical axis, we calculated structure correlations. For each column of an input matrix, a structure correlation is computed as the Pearson correlation across genes between columnar logFC values and gene scores on the canonical variate 66 . Structure correlations were averaged across the constituent fine cell types in each dataset (and nested by region for the sex dataset) to map how shared axes of gene expression change manifest across the cell classes and regions represented in our datasets.

To compare the magnitude of CCA1 of the different tests, we followed the same procedure for odds ratio comparison, but without log transformations 97 . To determine confidence intervals for the CCA1 stability, we generated 1,000 bootstrap samples for the sex-autism and sexschizophrenia analyses using row resampling. The outputs of rCCA, i.e. statistical significance of rCCA components, their structure correlations and gene scores, were also tested for stability after exclusion of sex chromosome genes from analyses.

Enrichment testing

We ran Gene Set Enrichment Analysis (GSEA) using the fgsea (v 1.36.2) R package 68 for biological annotation of the statistically significant shared CCA1 axis between sex and autism. For these analyses, genes were ranked by the mean gene score of the two canonical variates. We tested for rank-based enrichment of the following gene sets: Gene Ontology 62 functional pathways, SFARI gene database 56 score 1 and score 2 genes, Fu et al. 57 , Satterstrom et al. 58 , Trubetskoy et al. 101 and Singh et al. 102 , as well as the union of each condition's individual risk gene sets, which generated a collated risk gene set for autism and schizophrenia. Statistical significance was determined using multilevel Monte Carlo (nperm =1000) and corrected for multiple comparisons via Benjamini-Hochberg FDR 98 correction across all tested gene sets.

Protein-Protein Interactions

Protein-Protein Interaction (PPI) networks were determined using the STRING database with the STRINGdb (v.2.20.0) R package 103 . PPI networks for the CCA1 scores were derived from the top 0.5% of the scores for the positive and negative pole (generating gene sets for PPI networks analysis). After removing unmapped entries, edges were defined as protein-protein interactions between mapped genes with a score threshold >400, following default parameters. The resulting networks were modeled using the igraph (v 2.3.3) 104,105 R package to calculate node degrees for each gene. Network connectivity was defined as the number of edges within the induced subgraph of each gene set (n_edges). To test whether observed connectivity was significantly elevated relative to chance, we implemented a node degree-matched permutation procedure. First, we constructed a PPI network from the full CCA1 gene background (n = 16,515 genes). For every gene in this background network, we computed its degree (degree (graph_network, mode = "all")), and then all 16,515 genes were partitioned into 30 bins based on the quantiles of this degree distribution.

We generated a null distribution by drawing 10,000 permuted gene sets matched to the degree profile of the genes from the respective network being tested. We extracted an induced subgraph from the full PPI network (induced_subgraph), and the same connectivity statistic (n_edges) was computed as for the observed gene set, which was then used to calculate an empirical p-value (pperm). To test whether autism risk genes were more interconnected than other genes in the same set, risk-gene labels were randomly reassigned among the network genes. Null sets of the same size as the observed autism risk-gene set, annotated based on the collated autism risk genes, were drawn from all network genes, matched on full-network degree using (2-10) quantile bins, with 10,000 permutations per setting. The statistic and P value were calculated as above. To assess sensitivity to binning, the analysis was repeated across 2 to 10 bins.

Genes that mapped onto the respective PPI network were submitted for enrichment testing of Gene Ontology 62 terms using enrichGO from the clusterProfiler (v 4.18.4) R package 63 compared to the CCA1 background (n=16515 genes) with minGSSize = 10 and maxGSSize = 500. Lastly -for genes along the poles of sex-autism CCA1, we also profiled trajectories of developmental expression in bulk RNAseq using previously published methods Stauffer et al. 2023 106 as applied to the PsychENCODE dataset of regional cortical gene expression spanning 8 post-conception weeks-40 years of age 70 . For an input gene set of interest this methods maps its mean-centered cortical expression across 9 developmental windows (window 1: post-conceptional week (PCW) 8-9, window 2: PCW 12-13, window 3: PCW 16-18, windows 4: PCW 19-22, window 5: PCW 35-PY 0.3, window 6: post-natal year (PY) 0.5-2.6, window 7: PY 2.8-10.7, window 8: PY 13-19, window 9: PY 21-64).

Stability of sex differences from adulthood, as tested in DeCasien et al. 45 , compared to developmental sex differences were evaluated by inputting the ranked adulthood sex differences logFCs by broad cell class and brain region into enrichment testing of DEGs from the developmental sex differences characterized by Velmeshev et al 69 . This reference evaluates sex differences across developmental stages starting at the second trimester to determine sex effects on cellular lineage and development. We ran functional enrichment analysis with fgsea following the same procedure as described above. The gene lists for testing were the differentially expressed genes by both lineage and direction of sex-biasing. Enrichment values with positive indicates male biased in adulthood and negative indicates female biased in adulthood, and gene list of origin indicated the direction of sex-biasing in development.
