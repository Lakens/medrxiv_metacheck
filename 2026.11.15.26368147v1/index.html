How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

How Non-Significant P Value Check works

This module checks for imprecisely reported p values. If p > .05 is detected, it warns for misinterpretations.

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Multiplex immunohistochemistry (mIHC) enables simultaneous biomarker profiling, yet unmixing colocalized targets with identical spectra, such as dual-DAB marking Tau and Amyloid-β in Alzheimer's pathology, remains mathematically ill-posed. We propose MorphoStain, an unsupervised, physics-guided framework for morphological stain decomposition with epistemic uncertainty quantification. MorphoStain models stain separation via a conditional Latent Diffusion Teacher operating on a Beer-Lambert optical-density manifold, guided by pathology foundation models. To enable real-time clinical throughput, the teacher is distilled into a FastStudentU-Net (0.12M parameters, > 1,400× compression), while a Symmetric Morphological Routing Module dynamically disentangles identical chromogen overlap. Evaluated on 9,908 held-out patches from the SEA-AD cohort, MorphoStain achieves 40.56 dB PSNR and 0.9961 SSIM at 140.1 FPS, showing statistically significant gains over InverseAE (Cohen's d = 3.52) and NMF (Cohen's d = 7.02), with p < 0.001 for both comparisons.

I. INTRODUCTION

M ULTIPLEX immunohistochemistry (mIHC) visualizes multiple molecular biomarkers within a single tissue section using distinct chromogens, enabling spatially resolved profiling with standard brightfield RGB scanners [1]- [4]. In Alzheimer's disease (AD), co-staining amyloid-β (Aβ) and tau captures interacting pathologies, making accurate computational stain unmixing essential for downstream quantification. However, because plaques and neuritic structures are fine, weakly stained, and spatially adjacent, standard RGB sensors face a fundamental physical limit: under the Beer-Lambert model, optical density (OD) is a linear combination of stain absorption vectors [5], making the inversion of m > 2 overlapping stains ill-conditioned or strictly underdetermined.

Beyond this loss of identifiability, severe spectral crosstalk amplifies ambiguity. Precipitates like 3,3'-diaminobenzidine (DAB, brown) vary strongly in intensity and approach black at saturation, competing with the hematoxylin (blue) counterstain. Consequently, pixel-wise color matching [5]- [7] often misassigns signals or fragments fine structures. Resolving overlapping chromogens requires spatial morphology and learned priors (Fig. 1). While supervised deep models [8], [9] learn spatial context, they require costly annotations. Unsupervised methods like InverseAE [10]- [12] avoid annotations but remain deterministic, yielding a single point estimate without quantifying decomposition ambiguity across weakly stained plaques. Conversely, diffusion models [13]- [15] can model multi-modal posteriors and provide uncertainty estimates, but deploying them across gigapixel whole-slide images (WSIs) incurs prohibitive latency, and uncalibrated stochastic sampling may violate physical image-formation constraints.

To bridge this gap, we introduce MorphoStain, a physicsguided latent diffusion teacher paired with a compact distilled student for uncertainty-aware Aβ/tau stain unmixing. Our contributions are fourfold: • Physics-Guided Latent Diffusion Teacher: We combine a calibrated Beer-Lambert projection (S AD ∈ R 3×2 ) with a latent diffusion model conditioned on the Phikon pathology foundation model [16], using Monte Carlo sampling to estimate calibrated epistemic uncertainty (u var ).

• Lightweight Student: Through knowledge distillation with dilated residual blocks (d ∈ {1, 2, 4, 8} [17]- [19]), we achieve a > 1,400× compression (169.67M → 0.12M parameters) for real-time WSI inference.

• Symmetric Morphological Routing (M attn ): A dedicated attention module that disentangles Aβ and tau morphologies, suppresses bleed-through, and preserves fine neuritic structures.

• Comprehensive Benchmarking: Extensive evaluation across 9,908 test patches, including zero-shot out-ofdistribution (OOD) generalization and scanner illumination shifts [20], demonstrating promising reconstruction fidelity [21]- [23], morphological preservation, and uncertainty calibration.

II. RELATED WORK

II. RELATED WORK

A. Classical Color Deconvolution

Classical unmixing operates in OD space via the Beer-Lambert law. Early methods rely on fixed OD vectors [5], singular value decomposition (SVD)-based plane estimation [6], or unsupervised matrix factorization [7], [24]- [26]. Because three RGB channels cannot uniquely resolve high-plex mixtures pixel-wise, sparse regression [27], [28] and groupsparsity priors [29] introduce regularization. However, lacking spatial context, pixel-wise methods frequently produce morphologically implausible decompositions under heavy spectral overlap, motivating our integration of physical forward models with deep structural priors.

B. Deep Stain Decomposition

Deep networks leverage spatial context to overcome pixelwise ambiguity [9], though weakly supervised methods still rely on manual point annotations [8]. The state-of-the-art (SOTA) unsupervised baseline, InverseAE [10], [11], trains a conditional autoencoder with an inverse-image reconstruction loss. Despite strong performance on general mIHC, InverseAE struggles with dark DAB saturation, assumes a single dominant stain per pixel, and smooths out high-frequency microtextures. While generative adversarial network (GAN)-based unmixing [12] improves texture preservation, both approaches are strictly deterministic. In contrast, we model the full posterior distribution over physically valid decompositions specifically tailored to co-localized AD pathologies.

C. Diffusion Models and Knowledge Distillation

Diffusion models [13], [15] and Latent Diffusion Models (LDMs) [14] excel at capturing complex multi-modal distributions, with recent adaptations like PathLDM [30] targeting histopathology synthesis. However, unconditional synthesis does not guarantee physical consistency with an observed RGB image, nor does raw sample variance guarantee calibrated uncertainty. We constrain latent diffusion with an explicit Beer-Lambert decoder and condition it on self-supervised pathology features from Phikon [16]. Finally, to overcome the high latency of iterative sampling on gigapixel WSIs, we distill our physics-informed teacher into a lightweight student for clinical-grade throughput.

III. METHODOLOGY

Fig. 2 illustrates the proposed MorphoStain architecture. MorphoStain introduces a physics-guided teacher-student framework that couples classical Beer-Lambert OD principles with foundation-model-conditioned latent diffusion for morphological stain decomposition and epistemic uncertainty quantification in mIHC. IV. EXPERIMENTAL SETUP

IV. EXPERIMENTAL SETUP

A. Dataset and Preprocessing

We evaluate MorphoStain on 10 middle temporal gyrus (MTG) WSIs from 5 donors in the SEA-AD cohort [1], featuring paired tissue sections stained for Tau (AT8) and Amyloid-β (6E10) (Supplementary Tables S1 and S2). Slides were digitized using an Aperio scanner at 20× magnification (0.5016 µm/pixel). Discarding non-overlapping 512×512 tiles with < 30% tissue coverage or optical defocusing yielded an initial 49,576 candidate patches. Following a secondary quality-control screening to remove sparse tissue or background artifacts, 37,538 high-quality patches remained. To prevent anatomical data leakage, these were partitioned into strictly isolated donor-level splits: H20.33.001/002/005 for training (N train = 24,510), H19.33.004 for validation (N val = 3,120), and H20.33.004 for testing (N test = 9,908).

B. Baselines and Implementation Details

We benchmark MorphoStain against seven representative unmixing methods spanning analytical, matrix factorization, and deep learning paradigms: classical color deconvolution (Ruifrok and Johnston [5]), SVD-based plane estimation (Macenko et al. [6]), pixel-wise L 1 -regularized regression (Las-soReg [27]), OD NMF [25], L 1 -regularized Sparse NMF [24], structure-preserving dictionary learning (Vahadane et al. [7]), and the SOTA unsupervised autoencoder InverseAE [11].

The Phikon-conditioned [16] teacher (Latent UNet) and student (FastStudentUNet) are both trained for 10 epochs using AdamW (η = 2 × 10 -4 for teacher and 3 × 10 -4 for student, with cosine annealing) using a batch size of B = 32. Training is conducted using mixed precision on a single NVIDIA RTX 6000 Ada (48GB) GPU. Grid-search sensitivity analyses for λ ov and K smooth are detailed in Supplementary Section S3 (Supplementary Fig. S1 and Supplementary Table S3). We assess RGB reconstruction fidelity via peak signal-to-noise ratio (PSNR), mean squared error (MSE), root mean squared error (RMSE) [21], and structural similarity index (SSIM) [22]; spectral alignment via Cosine Similarity [32]; perceptual texture preservation via LPIPS [23]; and computational efficiency via single-batch inference throughput (frames per second, FPS, at 512 × 512, B = 1).

V. BENCHMARK RESULTS AND ANALYSIS

A. Comparative Quantitative Analysis

As detailed in Table I, MorphoStain sets a new standard for physical unmixing. Across the complete N = 9,908 held-out test cohort, it achieves a mean reconstruction PSNR of 40.56 dB and an SSIM of 0.9961 (see Supplementary Figs. S3 and S4 for qualitative unmixing across pathological ratios and the complete empirical PSNR density distribution). With these metrics, MorphoStain outperforms classical matrix decomposition baselines [5]- [7], [25] by margins of +5.17 dB to +19.16 dB (and by +22.19 dB over pixel-wise L 1 regression [27]). Furthermore, it significantly surpasses the deep learning SOTA, InverseAE [11] (40.56 dB vs. 38.84 dB, a +1.72 dB gain).

Unlike InverseAE, which lacks morphological routing capabilities and consequently suffers catastrophic crosstalk bleed when resolving overlapping identical brown DAB chromogens into constituent Tau and Amyloid-β channels, MorphoStain successfully isolates these structures. Finally, MorphoStain achieves superior perceptual feature consistency (LPIPS = 0.0141) while providing real-time throughput at 140.1 FPS, capable of unmixing and stitching complete gigapixel WSIs (> 50,000 × 40,000 pixels) in under 12 s (Supplementary Fig. S6).

Crucially, paired patch-level hypothesis testing confirms that all performance gains over baselines are statistically significant (p < 10 -16 ) with exceptionally large effect sizes (e.g., Cohen's d = 3.52 vs. InverseAE, d = 7.02 vs. NMF). Patch-level variance reveals high consistency with a median PSNR of 40.52 dB and an interquartile range (IQR) of 1.42 dB (see Supplementary Tables S4 and S5).

B. Ablation Analysis and Structural Distillation

We dissect architectural components by evaluating four teacher configurations (M1-M4) against the distilled student model on a standardized calibration subset (Table II; see Supplementary Fig. S2 for training convergence trajectories).

1) Impact of Foundation Conditioning: Removing Phikon ViT semantics [16] (M2) causes severe collapse (∆PSNR = -10.72 dB), establishing that global pathological embeddings are critical for unmixing guidance and convergence stability relative to the full teacher model (M1). 2) Impact of Physics Constraints: Omitting Beer-Lambert optical losses (M3) drops PSNR to 24.19 dB, confirming that unconstrained diffusion drifts into ill-posed local minima and fails to preserve realistic spectral unmixing. Similarly, excluding overlap penalties (M4) leads to severe chromophore bleed (PSNR = 27.21 dB). 3) Student Distillation Dynamics: FastStudentUNet delivers 41.66 dB PSNR and 174.6 FPS (5.73 ms latency) while compressing model complexity by > 1,400× (169.67M → 0.12M parameters), demonstrating that continuous convolution smoothing bypasses the sampling variance present in iterative reverse diffusion.

VI. DISCUSSION, LIMITATIONS, AND FUTURE WORK

VI. DISCUSSION, LIMITATIONS, AND FUTURE WORK

A. Physical Disentanglement and Distillation Dynamics

Classical color deconvolution methods [5], [6] suffer from severe crosstalk bleed when resolving spectrally identical chromogens, whereas unconstrained generative models [11] drift into ill-posed solutions without physical priors (Table II). MorphoStain bridges this gap by anchoring a Latent Diffusion Teacher within a Beer-Lambert OD manifold. By fixing the distilled student's objectives to the analytical Moore-Penrose projection, it preserves exact spectral conservation and bypasses the high-frequency sampling variance inherent in iterative stochastic diffusion.

Furthermore, resolving dual-DAB mIHC in Alzheimer's pathology [1] typically forces standard matrix factorization into a single uninformative channel. Our Symmetric Morphological Routing Module (M attn ) circumvents this by leveraging slide-level cohort metadata as a weakly supervised prior, enabling zero-shot, label-free biomarker separation. Finally, the epistemic uncertainty head (u var ) provides an automated clinical safety gate; as shown in Fig. 5, predicted variance closely tracks local reconstruction error (ECE = 0.0125) to flag out-of-focus and boundary artifacts without human intervention.

B. Limitations and Future Directions

Despite strong generalization across external cohorts, three operational limitations motivate future work: 1) Static Calibration: Extreme over-staining may violate nominal OD bounds.

Future work will embed differentiable absorbance estimation within the Phikon ViT [16] for slide-specific stain adaptation. 2) Active Triaging: While u var reliably flags optical defocus (Fig. 5), our pipeline relies on upstream tile rejection. We aim to integrate these maps directly into WSI scanners for real-time human-in-the-loop clinical triaging. 3) Multiplexing Scope: Currently targeting M = 2, extending M attn to softmax-gated multi-head decoders for higher-order multiplex immunofluorescence (M ≥ 4) remains an important direction.

VII. CONCLUSION

MorphoStain introduces a physics-guided teacher-student framework that unifies Beer-Lambert constraints with pathology foundation models and latent diffusion to resolve the mathematically ill-posed stain decomposition problem. By distilling diffusion priors into a lightweight student anchored by morphological routing, the framework achieves SOTA realtime inference, separates overlapping identical chromogens without pixel-level annotations, and provides calibrated epistemic uncertainty for automated quality control. Extensive evaluations demonstrate significant statistical gains, zero-shot domain transferability, and robust resilience to optical shifts, establishing MorphoStain as a scalable and reliable tool for quantitative clinical neuropathology.
