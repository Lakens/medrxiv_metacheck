Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). When the sentence of a test says it is one-sided (“one-tailed”, “one-sided” or “directional”), a p-value that fits a one-sided test counts as consistent (statcheck’s OneTailedTxt setting; #695). When the paper says anywhere that its tests are one-sided, a p-value that fits a one-sided test in either direction counts as consistent too: half the two-sided p, or 1 minus that half for an effect against the predicted direction. Equivalence tests (TOST) are left out, as their p-values do not test the difference. A statistic written with “<” or “>” is read as a bound, and in a sentence about equal variances an F-test’s two-sided p (twice the one-tailed p) counts as consistent. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.), reported as exactly zero (e.g., p = .000), or impossible (below 0 or above 1, e.g., p = -.22).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold”, “legend” or “named”).

A p-value with the name of a correction or a test after the p (“pFWE < .05”, “padj < 0.05”, “p Wilcoxon = .02”) is flagged only when a test statistic comes before it in its clause (“t(37) = 7.17, p FWE < .05”). Without one it is mostly the rule that decided what was significant (“genes with padj < 0.05 were selected”); such a p-value is “named” in not_a_test. Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

A p-value below 0 or above 1 is impossible; it is listed apart and not also as imprecise. Often the statistic before it, or its minus sign, was copied into it (“t(134) = -2.32, p = -.13”, “Z = 3.091, P = 3.091”). A value above 1 is listed only after a test statistic in its clause: without one, a “P” above 1 was nearly always another quantity (a proportion, pH, a group’s mean, a model parameter). A number in scientific notation whose power of ten was lost when the PDF was read (“p = 2.4 x 10 -9” read as 2.4) is not listed. A “p” that is the subscript of another symbol (“r p = .64”, “²p = .02” for partial eta squared, “Δp = .33”), or a quantity with a unit, a logarithm or a ratio (“P = 2.9 µm”, “-log10 P = 7.5”, “Ca/P = 1.67”), is not read as a p-value at all (see extract_p_values()). Each p-value has its own row, also when the same one is written twice in a sentence.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

Read more in the metacheck manual.

The nonsignificant p-value check searches for regular expressions that match a predefined pattern. The module identifies all p-values in a manuscript and selects those that are not reported to be smaller than or equal to 0.05. It returns all sentences containing non-significant p-values.

In the future, the Metacheck team aims to incorporate a machine learning classifier to only return sentences likely to contain misinterpretations. If you want to help to improve the module, reach out to the Metacheck development team.

A p-value in a table note (“† p < .10, * p < .05”) or a figure legend (“dashed lines indicate non-significant paths (p > .05)”) is left out, as in stat_p_exact; the column not_a_test says why. A p-value next to words that state a threshold is kept, because such sentences often report a result against that level (“not significant at the conventional threshold (p = .054)”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables.

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). Embedded haven labels from data files are also harvested directly.

The module defaults to rules-only when llm_use(FALSE). When llm_use(TRUE), three optional LLM tiers run: parsing unstructured codebook text that the rules could not handle, fuzzy-matching still-unlabelled columns to still-unmatched codebook variables, and merging conflicting label definitions into a single canonical label.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

A link to a file-sharing service (Google Drive, Dropbox, OneDrive, Box, WeTransfer, MEGA, iCloud Drive, Baidu Netdisk, SURFdrive; see [file_share_links()]) gets a warning and makes the light yellow: such services are not repositories, as files can be changed or deleted at any time, get no DOI, and the link stops working when the account is closed. The report advises a stable repository such as Zenodo instead. Their files are not read, and summary_table$file_share_n counts the links.

Deposits in archives for sequence and expression data (GEO, the INSDC archives BioProject, SRA, ENA and DDBJ, and ArrayExpress; see [seq_archive_links()]), mostly named by accession number, are read for whose deposit they are. The authors’ own are listed with what they hold ([seq_archive_size()]) and are not downloaded or checked as data and code; summary_table$archive_own_n counts them.

R packages on CRAN ([cran_links()], [cran_info()]) are the paper’s own when a paper author is a package author and the paper presents the package; the paper’s own are listed with their version and not checked (summary_table$cran_own_n). A Handle link (hdl.handle.net/...) that leads to a repository read here is checked as a link to that repository ([handle_links()]).

Listing a repository’s files never requires an API key, but some hosts answer faster or more completely with one: OSF allows 100 requests/hour unauthenticated versus 10,000/day with a token (see [osf_pat()]), and Dryad enforces a strict per-IP daily quota on repeated listing (see cache below). Dryad is a special case beyond rate limits: listing a Dryad dataset’s files works without a key, but actually downloading file CONTENTS from Dryad fails with HTTP 401 unless a key is set, even for a fully public dataset (see [dryad_pat()] or [dryad_auth()]). Since this module only lists files and never downloads their contents itself, that limitation applies to data_check and code_check (which do download content), not here – see their own documentation.

When a linked OSF page is a registration, its registered_from project (the one it was registered from, which the manuscript itself may never link directly) is also checked: if that project is public its files are listed under its own URL, and if it is closed or otherwise inaccessible the report flags it explicitly, since some registrations only describe their content rather than mirroring it.

Whose deposit is each link? The ownership table gives, for every repository linked in the text and (with references = TRUE) every deposit cited in the reference list, one of six labels: own_this (made by the authors for this paper), own_earlier_data or own_earlier_code (the authors’ own, from earlier work), others_data or others_code (made by other people, reused here), or not_data (a publication such as a preprint, not a deposit), with ownership_group (“own”, “others”, “not_data”) and the reason. It is decided without a language model, from the sentence or reference that cites the link, the paper’s authors (names, ORCID iDs, affiliations), and what the deposit’s own record and files say (who made it, what it names, when, whether it is a software package; for an OSF project cited only in the reference list, its record alone). On a round of labelled links the rules had not been written from, the three groups were right for 98% of links in the main text (93 of 95) and 90% in reference lists (74 of 82); the labels were made by Claude agents from each link’s evidence, and disputed ones checked against the deposits. Telling this paper’s own deposit from the authors’ earlier one is less certain.

Only the deposits that are this paper’s own are checked. A deposit linked in the text that holds other people’s work (others_data, others_code) or the authors’ earlier work (own_earlier_data, own_earlier_code) is listed in the report, with the reason, but its files are left out of table and kept in table_not_checked: they count toward nothing here (files that do not belong in a repository, naming, READMEs, studies, the traffic light), and code_check, data_check and reproducibility_check, which read table, do not check them either. reproducibility_check still puts the files of theirs that the paper’s code names in the folder the code runs in, as a re-analysis needs the data it re-analyses. When every linked deposit is set aside, the traffic light is “na”. A deposit that is the paper’s own is counted as such when its README, title or description names the paper (its title or DOI).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability).

Provenance, kept so that a TRACE Research Object (TRO) declaration of the run can be written later from a stored result (metacheck #404; the helpers are in R/provenance.R). Only when code was run (execute = TRUE): * run_results$started_at, run_results$ended_at: when each run of a script started and ended (ISO 8601, UTC, milliseconds); NA for a script that was not started. A script run again in a later pass has the times of its last run. A TRO uses them for each trov:TransparentResearchPerformance. * run_results$exit_status: the exit status of the process that ran the script (0 = ended normally); NA when the process did not report one (a time limit, or Docker failing to start the container). * artifacts: one row per file, with stage (deposit: as downloaded from the repository, hashed from the downloaded file; before_run: the run folder just before the first script ran, after metacheck’s own changes, such as rewritten paths and unpacked archives; after_run: only the files the scripts made (status new), changed (changed) or removed (removed), as an unchanged file is the one listed before the run), path (relative to the run folder, as valid UTF-8, a byte of another encoding written as <xx>), size (bytes), sha256, mime_type (by extension, NA when unknown), source (the file’s address in the repository, for deposit). The package libraries metacheck installs in the run folder are left out, as are metacheck’s own files there (a script’s runner, and the statistical output it writes in statistical_output/). Files metacheck itself copied or made between passes (see modifications, output_copied, file_placed) show in after_run too. A TRO uses the rows as trov:ResearchArtifacts and each stage as a trov:ArtifactArrangement. * modifications$sha256_before, modifications$sha256_after: the hash of the changed script as downloaded and as it ran; NA when the script is not at the same path in both (a script made from an R Markdown file). * environment: the system that ran the code (trov:TransparentResearchSystem in a TRO): metacheck_version, started_at, ended_at, host (R version, platform, operating system), sandbox, network_isolated (TRUE only when every Docker run had --network none; the process sandbox does not stop the network), internet, timeout_per_script, total_timeout, python_local (the Python run outside Docker and its version), and docker: runs (for each kind of run, r_run, r_install, python_run, python_install, the image and the docker run arguments, such as --network none, --read-only, --cap-drop ALL, no-new-privileges, the process limit and the memory and processor limits) and images (for each image, its ID and digests from docker image inspect, its creation time and the R and Python versions its environment declares).

run_results$checked says what the run of each script shows about the code, in five groups, so that a script that does not reproduce is kept apart from one the check could not test: ran (it ran to the end); code_error (it did not reproduce: it stopped with an error of the code or the deposit, could not be read, or needs a file the deposit does not hold); dependency (a package or program was not available: a package that could not be installed or was not loaded, a program outside R and Python, a system library, or R crashing in a package’s compiled code); time (it did not finish within the time limit for one script, or was not started because the time for all scripts had run out); and not_checkable (it could not be checked automatically: it needs a person, the internet, a key or another setting of the authors’ computer, one platform such as Google Colab, Windows or OpenSAFELY, more memory than the run allows, a file that was not downloaded, a screen, or a program that runs it, or it is a file of a package of the code that Python runs only as a module of that package). It is NA for files run inside another script, files that are not an analysis, files not read, and a Docker failure. summary_table counts each group (repro_ran_n, repro_code_error_n, repro_dependency_n, repro_time_n, repro_not_checkable_n), and the report’s first sentence gives them. The traffic light reflects the static readiness signals by default; a script in code_error that stopped with an error makes it red, as a script that crashes on its own analysis is a genuine reproduction failure, and a script in one of the other three groups keeps it from being green. Calls that need a screen, which the run does not have (dev.print(), dev.copy2pdf(), dev.copy2eps(), savePlot(), windows(), win.graph(), x11(), quartz(), View()), are replaced before the run by calls that need none, which modifications records as screen_call_replaced. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Background. Clinical diagnosis often relies on a snapshot: a single measurement interpreted against a population threshold. Repeated (longitudinal) measurements, however, may reveal an individual's typical level and how it changes over time. Extracting this information is challenging when measurements are sparse and biological fluctuations may resemble sustained changes. Using data from the English Longitudinal Study of Ageing (ELSA), we investigated whether individual glycated haemoglobin (HbA1c) trajectories improved the prediction of incident diabetes beyond the most recent measurement, whether they were associated with incident diabetes, and how reliably they could be estimated.

In this secondary analysis of a prospective cohort study, we analysed venous HbA1c measured approximately every four years in ELSA, with a longer final interval of about seven years. A linear mixed model estimated each person's usual HbA1c level and rate of change (personal slope) from their measurements before each diabetes-free health visit, with model parameters estimated in other participants (cross-fitting). 1 Introduction

Laboratory diagnosis often relies on comparing a single measurement with a population reference interval or a fixed diagnostic threshold (Clinical and Laboratory Standards Institute, 2010; World Health Organization, 2011). Yet many analytes vary far less within individuals than between them (Harris, 1974; Fraser, 2001; Ricós et al., 1999), and laboratory measurements are often repeated over years. Viewed longitudinally, these measurements may reveal what a single measurement cannot: an individual's typical level and how it changes over time. A value considered normal for the population may therefore be unusual for a particular individual or reflect a sustained change from their personal baseline. Recent studies have demonstrated stable individual laboratory setpoints, their prognostic relevance, and the potential of Bayesian and machine-learning methods to construct personalised reference intervals (Foy et al., 2025; Zhang et al., 2026; Shah et al., 2026), building on earlier work in personal profiling (Chen et al., 2012; Price et al., 2017; Schüssler-Fiorenza Rose et al., 2019).

Three different claims are often merged under the label "personal reference". The deviation claim is that a value unusually high relative to the person's own baseline signals emerging disease. It is motivated by low indices of individuality (Harris, 1974; Fraser and Harris, 1989) and underlies personalised reference intervals (Coşkun et al., 2021) and the athlete biological passport, which flags values outside Bayesian person-specific limits (Sottas et al., 2011). The trajectory claim is that the direction and rate at which a person's values are moving -their personal slope-carries risk information beyond the current level. The best-known example is prostate-specific antigen (PSA) velocity, proposed as a marker of prostate cancer (Carter et al., 1992); for glycaemia, fasting glucose and HbA1c rise steeply in the years before diagnosis of type 2 diabetes (Tabák et al., 2009; Heianza et al., 2012). Yet where the trajectory claim has been 2 tested against the current level, the added value has often been small: a systematic review found little evidence that PSA velocity improves prediction beyond PSA itself (Vickers et al., 2009).

The third use of history is denoising: earlier measurements improve estimation of the current underlying level (Irwig et al., 1991; Glasziou et al., 2008; Robinson, 1991). A feature built from earlier values can therefore appear to carry deviation or trajectory information merely because it refines the estimate of the current level, and an apparent change between two values partly reflects regression to the mean (Barnett et al., 2005). These three uses of history have different implications for monitoring, yet they are rarely separated empirically.

Distinguishing these effects also depends on how longitudinal measurements are collected.

Electronic health records (EHRs) provide repeated observations, but tests are typically ordered for clinical reasons, making the timing and frequency of measurements informative. In one large hospital system, the timing of a test predicted survival better than its result for most laboratory tests (Agniel et al., 2018). Moreover, individuals who undergo repeated testing may differ systematically from those who do not, potentially distorting risk associations through informed presence (Goldstein et al., 2016; Hripcsak and Albers, 2013; Sisk et al., 2021). Population cohorts with scheduled measurements reduce the influence of clinically triggered testing (Steptoe et al., 2013), but introduce a different limitation: observations are typically sparse. Under such conditions, the reliability of estimated individual rates of change depends on the duration of follow-up and the number and precision of measurements (Willett, 1989; Raudenbush and Liu, 2001; Rast and Hofer, 2014; Brandmaier et al., 2018). How these constraints interact with biological fluctuations that persist over years remains poorly understood.

Even when individual trajectories can be estimated, their association with disease does not necessarily translate into improved prediction. A marker may be associated with an outcome yet provide little additional discrimination, particularly when the existing prediction model is already strong (Wald et al., 1999; Pepe et al., 2004; Cook, 2007). Conversely, a lack of predictive improvement does not establish that meaningful individual trajectories are absent: such trajectories may exist but be too poorly estimated to contribute useful information. Distinguishing these possibilities requires examining not only association and predictive performance, but also how reliably individual changes can be recovered from the available measurements.

Incident diabetes provides a natural setting in which to examine these issues. HbA1c (glycated haemoglobin) reflects average glycaemia over the preceding two to three months, the lifespan of erythrocytes being about 120 days (Cohen et al., 2008). It is measured repeatedly in several ageing cohorts, has an established diagnostic threshold of 48 mmol/mol (6.5%) (International Expert Committee, 2009; World Health Organization, 2011), and is strongly associated with diabetes risk as values approach that threshold (Zhang et al., 2010; Selvin et al., 2010; Tabák et al., 2012). Values of 42-47 mmol/mol (6.0-6.4%) are commonly described as prediabetes, or high risk of diabetes 1 (International Expert Committee, 2009; National Institute for Health and Care Excellence, 2012). People in this range progress to diabetes considerably more often than those below it, although many do not progress for years or revert to normoglycaemia (Tabák et al., 2012). We used the English Longitudinal Study of Ageing (ELSA), a cohort in England, where HbA1c is measured according to a study schedule rather than in response to clinical 1 Other guidelines use a lower bound of 39 mmol/mol (5.7%) (American Diabetes Association Professional Practice Committee, 2026; Landgraf et al., 2025).

suspicion, reducing bias from clinically driven testing. Previous studies have described average glycaemic trajectories retrospectively, aligned to the time of diabetes diagnosis (Tabák et al., 2009; Heianza et al., 2012), including an analysis of HbA1c in ELSA (Yu et al., 2023).

We address three questions. First, does longitudinal HbA1c history improve the prediction of incident diabetes beyond baseline HbA1c and conventional clinical risk factors (Lindström and Tuomilehto, 2003; Wilson et al., 2007; Hippisley-Cox and Coupland, 2017)? Second, is the rate of HbA1c change associated with incident diabetes after adjustment for baseline HbA1c, including when that level is estimated using previous measurements? Third, how reliably can individual HbA1c trajectories be estimated from sparsely sampled measurements in the presence of within-person variation?

To answer them, we compared a conventional clinical prediction model with models incorporating individual longitudinal features and with a self-supervised, time-aware Transformer trained on longitudinal histories (Tipirneni and Reddy, 2022). The features corresponded to the uses of history outlined above: deviation from the person's usual level (the deviation claim), personal slope (the trajectory claim), change since the previous measurement, and the forecast probability of reaching the diagnostic threshold. We estimated their associations with incident diabetes and, to separate trajectory information from denoising, examined whether the slope association persisted after adjustment for a history-informed estimate of the current underlying HbA1c level.

Finally, we modelled within-person variation as a serially correlated process (drift model) and used it to assess how reliably individual slopes can be estimated under different measurement schedules, varying the length of history and the frequency of measurement. The prediction models are not proposed for clinical use. The prediction analyses form a model development study with internal, participant-level cross-fitted validation; they ask whether personal HbA1c history adds information that could be used in repeated monitoring of older adults, not how well a specific model would perform in a new population.

2 Methods

2.1 Data

ELSA is a longitudinal study of adults aged 50 years and older living in England, with interviews conducted approximately every two years since 2002 and nurse-led health visits, including venous blood sampling, in selected waves (Steptoe et al., 2013). The sample is designed to represent adults aged 50 years and older living in private households in England. Analyses were unweighted, as the primary objectives were to estimate associations and assess predictive performance within the analytical cohort rather than to produce population-representative estimates. We used health-visit rounds 2 (2004-05), 4 (2008-09), 6 (2012-13), 8/9 (2016-2019; a single health-visit round spanning two waves) and 11 (2023-24) from the UK Data Service (SN 5050, End User Licence; Banks et al., 2026). Interview data were obtained from the Harmonized ELSA dataset (waves 1-10), produced by the Gateway to Global Aging Data and distributed with the ELSA data collection (Gateway to Global Aging Data, 2023), and from the wave-11 core interview file.

HbA1c was recorded as a percentage in rounds 2 and 4, on the scale of the Diabetes Control and Complications Trial (DCCT), and in units of the International Federation of Clinical Chemistry and Laboratory Medicine (IFCC; mmol/mol) thereafter (Lloyd and Light, 2025). Measurement units were identified from the study documentation, and percentage values were converted to IFCC units using the IFCC-DCCT master equation, mmol/mol = (% -2.15) × 10.929 (Hoelzel et al., 2004). Missing-value codes were removed, and a plausibility range of 15-200 mmol/mol was applied, which excluded fewer than 10 implausibly low values. Fasting glucose was measured only in participants who had fasted (as recorded at each health visit); because participants treated for diabetes were not asked to fast, its availability depended on diabetes status, and it was used to define diabetes but not as a predictor. Systematic between-round differences in HbA1c, which would otherwise appear as withinperson increases and inflate estimated slopes, were accounted for by round fixed effects in the mixed model used to estimate personal levels and slopes (Section 2.3); the estimated round effects, conditional on age and sex, were approximately +2 to +3 mmol/mol relative to round 2. These differences were already apparent between rounds 2 and 4, both recorded on the DCCT scale, and therefore cannot be explained by the subsequent change in measurement units. They may reflect changes in assay calibration, genuine calendar-time trends, or a combination of both.

2.2 Baseline visits and outcome

Diabetes was defined as the presence of any of the following: HbA1c ≥ 48 mmol/mol (≥ 6.5%), fasting glucose ≥ 7.0 mmol/l (World Health Organization, 2011; International Expert Committee, 2009), a self-reported physician diagnosis, or use of diabetes medication. Laboratory measurements were obtained at health visits, whereas diagnoses and medication use were recorded at interviews; once present, diabetes was considered present at all later visits. A single measurement exceeding a diagnostic threshold was sufficient for classification in this study, although a clinical diagnosis would generally require confirmation. HbA1c was measured by an external laboratory in the blood sample taken at the health visit.

We introduce a baseline visit as a health visit at which the risk of developing diabetes by the next health visit was assessed. Baseline visits were drawn from rounds 4, 6 and 8/9. Eligibility required valid HbA1c, age and sex at the baseline visit; no diabetes by the above definition up to and including that visit; and at least one earlier HbA1c measurement obtained at least three months before the baseline visit while the participant was free of diabetes.

Incident diabetes was defined as meeting either laboratory criterion (HbA1c or fasting glucose) at the next health visit, or reporting a first physician diagnosis or diabetes medication use at any interview after the baseline visit, up to and including that of the next health-visit round. Diabetes types were not distinguished; type 1 diabetes can begin in adulthood but accounts for only a small share of diabetes diagnosed after the age of 30 (Thomas et al., 2018), so most incident cases were expected to be type 2. The main analysis included baseline visits with HbA1c available at the next health visit, so that the laboratory criterion could be assessed for all.

A participant could contribute more than one baseline visit, each representing a separate prediction using the information available at that time. Risk was therefore estimated per baseline visit rather than per participant. All visits from the same participant were assigned to the same cross-fitting fold to prevent information leakage (Section 2.3), and within-participant dependence was accounted for by participant-clustered standard errors and bootstrap intervals.

The interval to the next health visit was approximately four years for rounds 4 and 6 and about seven years for round 8/9. Because the probability of observing incident diabetes increases with follow-up duration, all models included ln(years to next visit) as a covariate. The analysis therefore estimated the risk of diabetes detected by the next scheduled health visit, conditional on the interval between visits. Because the exact interval is not known at the baseline visit, this is an interval-adjusted prediction of diabetes detected at the next observed health visit rather than a fully prospective risk prediction. Detection or reporting of diabetes did not necessarily coincide with biological disease onset, and some cases may have been detected with delay.

2.3 Personal trajectories and longitudinal features

HbA1c trajectories were described by a linear mixed model (Laird and Ware, 1982; Verbeke and Molenberghs, 2000) fitted to non-diabetic visits: where y ij is the HbA1c value (mmol/mol) of person i at their j-th health visit, a ij = (age ij -65)/10 is age centred at approximately the sample median and expressed in decades, female i indicates female sex (1 = female,0 = male), and γ r(ij) is the fixed effect of health-visit round r(ij), common to all participants measured in that round, with round 2 as reference (γ2 = 0).

The fixed effects β 0 , . . . , β 3 and γ r describe the population trajectory. The personal intercept u 0i represents the person's deviation from this trajectory at age 65, and the personal slope deviation u 1i their deviation from the population age trend per decade; in mixed-model terms, both are random effects. We assumed (u 0i , u 1i ) ⊤ ∼ N (0, G), a normal distribution with mean 0 and covariance where σ u 0 and σ u 1 are the between-person standard deviations (SDs) of the intercept and slope and ρ their correlation, and ε ij ∼ N (0, σ 2 ) represents residual within-person variation between visits.

The analysis proceeded in two steps. First, the population parameters (the fixed effects, the covariance matrix G and the residual variance σ 2 ) were estimated by restricted maximum likelihood (REML), the standard estimator for variance components (Patterson and Thompson, 1971; Harville, 1977). Second, for each baseline visit, the person's intercept u 0i and slope u 1i were estimated by empirical Bayes: the population distribution N (0, G) served as a prior, which was updated with the person's HbA1c measurements preceding the baseline visit, and the resulting posterior means were used as individual estimates (Robinson, 1991). To keep each participant's data out of the parameters applied to them, we used cross-fitting (Chernozhukov et al., 2018): participants were split at random into five folds, a common choice that balances the amount of training data against computation, and the population parameters used for participants in one fold were estimated from the non-diabetic visits of the participants in the other four.

Each participant was thus excluded from the estimation of the population parameters used to construct their features, while their individual estimates used only measurements preceding the baseline visit (for the forecast, also the HbA1c measured at the baseline visit itself).

Four features were derived per baseline visit (Figure 1). The first two correspond to the deviation and trajectory claims; the other two are simpler and combined summaries of the history: • Deviation from the expected value (z): the baseline value minus the value predicted from the person's earlier measurements, divided by the predictive SD of a new measurement.

• Personal slope: the posterior mean of the person's rate of change at the reference age of 65 (population slope β 1 plus the person-specific slope deviation u 1i ), in mmol/mol per decade. Because the population trajectory includes an age-squared term, this is the rate of change at age 65, not a constant lifetime slope. Differences in this feature between individuals therefore reflect their estimated deviations from the population slope. With a single earlier measurement, no within-person change is observed: the feature is then the population slope plus a small term proportional to the deviation of that measurement from the population trajectory, with a weight that depends on the age at which it was taken (Supplementary Section S3).

• Change since last value: the baseline value minus the last earlier value, after subtracting each round's offset; the simplest summary of change, without a model.

• Forecast: the probability that the next HbA1c is ≥ 48 mmol/mol, from the posterior updated with the baseline value and projected over the interval to the next visit; it combines the current level and the personal trajectory.

Finally, as conventional summaries of between-and within-person variation under model (1), assuming independent residual variation (Harris, 1974; Fraser and Harris, 1989; Fraser, 2001), we calculated three measures:

The intraclass correlation (ICC) is the share of variance attributable to stable differences between individuals, and the index of individuality (II) compares within-person with between-person variability; values of the II below approximately 0.6 suggest that population reference intervals may be of limited use for interpreting individual measurements. Both use the between-person variance at the reference age of 65, σ 2 u 0 ; because people differ in their slopes, between-person variance changes with age. The reference change value (RCV) depends only on the withinperson variance σ 2 and gives the minimum difference between two measurements from the same individual that exceeds visit-to-visit variation at the 95% level. The drift model (Section 2.8) relaxes the assumption of independent residual variation on which the II and the RCV rely.

2.4 Prediction analyses

We examined whether longitudinal HbA1c features improved the prediction of incident diabetes beyond baseline HbA1c and conventional clinical risk factors. We compared five logistic regression models, beginning with a minimal model (A), extending it with clinical risk factors (B), and then adding alternative representations of personal HbA1c history (C-E). All models included ln(years to next visit) to account for differences in follow-up duration: • Model A: baseline HbA1c, age and sex; • Model B: Model A plus body-mass index (BMI), systolic blood pressure, high-density lipoprotein (HDL) cholesterol, log triglycerides, smoking, weekly vigorous activity and blood-pressure medication; • Model C: Model B plus change since the last HbA1c measurement; • Model D: Model B plus deviation z and personal slope; • Model E: Model B plus the logit of the forecast, i.e. the predicted probability that HbA1c reaches 48 mmol/mol at the next health visit (the forecast concerns HbA1c only, whereas the outcome also includes glucose, reported diagnoses and medication).

Model B included clinical predictors commonly used in established diabetes risk scores (Lindström and Tuomilehto, 2003; Wilson et al., 2007; Hippisley-Cox and Coupland, 2017; Noble et al., 2011; Abbasi et al., 2012) and available in ELSA; their sources and timing are described in Supplementary Section S2. The models were fitted on standardised predictors with a fixed L2 penalty to stabilise the estimates, maximising ℓ(β) -1 2 j β 2 j , where ℓ is the log-likelihood summed over baseline visits and the sum runs over the coefficients of the predictors (the intercept was not penalised); the penalty strength was not tuned and was the same in all models. Missing clinical covariates were imputed with the median, with an additional missingness indicator for each covariate with missing values (Sperrin et al., 2020). Predictions were generated out of fold using the same participant-level folds as for the longitudinal features: imputation medians, missingness indicators and standardisation parameters were estimated within each training fold and applied unchanged to the held-out participants, and the prediction models were fitted only to the training participants of each fold. The sample size was determined by the available eligible ELSA observations rather than by a prospective sample-size calculation; the relatively small number of incident cases limits the precision of the performance estimates. Final versions of models A and B, refitted to all baseline visits, are specified in Supplementary Section S2 and Table S4; models C-E are specified in the analysis code.

Performance metrics weighted each baseline visit equally, rather than each participant. We assessed discrimination (area under the receiver operating characteristic curve, AUC), calibration (intercept and slope from a logistic regression of the outcome on the logit of the predicted risk), and accuracy of predicted probabilities (Brier score). To examine the practical implications for screening, we also compared how many baseline visits followed by incident diabetes were identified when each model selected the highest-risk 5% or 10% of baseline visits; because participants could contribute more than one baseline visit, these counts refer to visits rather than individuals. Confidence intervals (CIs; 95%) for AUCs, AUC differences and differences in screening counts were obtained from a participant-cluster bootstrap of the out-of-fold predictions with 1,000 replicates (Efron and Tibshirani, 1993; Field and Welsh, 2007); they are conditional on these predictions and do not include the uncertainty from refitting the models. Differences in discrimination were also estimated in subgroups of baseline visits, to examine whether personal history adds information where baseline HbA1c is least informative or where more history is available: visits with HbA1c < 42 mmol/mol, visits with one and with at least two earlier HbA1c values, and visits with an approximately four-year interval to the next visit (rounds 4 and 6).

2.5 Association analyses

We estimated the association of each longitudinal feature with incident diabetes, adjusted for baseline HbA1c and for the established clinical risk factors of Model B, which may be related to both HbA1c change and diabetes risk.

For baseline visit k with feature e k , standardised to mean 0 and SD 1, we fitted where s(•) is a natural cubic spline in baseline HbA1c (4 degrees of freedom; boundary knots at the minimum and maximum, interior knots at the quartiles; Durrleman and Simon, 1989; Harrell, 2015), c k contains the other covariates of Model B (age, sex and clinical risk factors) and ln(years to next visit), with coefficient vector δ, and e θ is the odds ratio (OR) per SD of the feature at the same HbA1c and covariate values.

A flexible term for HbA1c was used because risk rises nonlinearly as HbA1c approaches the diagnostic threshold (Zhang et al., 2010; Selvin et al., 2010), and the longitudinal features, being derived from the same HbA1c series, may be correlated with baseline HbA1c; with a linear term, part of this nonlinearity could be attributed to the features. These models were fitted without penalty, with missing covariates imputed with the median and a missingness indicator, and standard errors clustered by participant (Liang and Zeger, 1986). For comparison, we also report the slope association without adjustment and adjusted only for follow-up duration, ln(years to next visit).

We repeated these analyses separately for baseline visits below and within the prediabetes range (HbA1c < 42 and 42-47.9 mmol/mol; International Expert Committee, 2009), where identifying differences in risk may be particularly relevant. Because a personal slope reflects observed within-person change only when at least two earlier HbA1c measurements are available, we report the slope association among these baseline visits alongside that in all baseline visits.

With a single earlier value, the estimated slope is determined by the deviation of that value from the population trajectory rather than by observed change (Section 2.3; Supplementary Section S3). We also tested whether the slope association varied with baseline HbA1c, using an interaction between the personal slope and HbA1c range (< 42 versus 42-47.9 mmol/mol) in a single model including all baseline visits, with covariate effects common to both ranges; the ratio of the slope ORs in the two ranges, e θ × for interaction coefficient θ × , provides a test and CI that separate subgroup models do not, because the same participant can contribute baseline visits to both ranges. Each feature was standardised by its SD within the analysed set of baseline visits, so that ORs in subgroups refer to the subgroup-specific SD; the interaction model used the SD in all baseline visits. As a sensitivity analysis, subgroup associations were also expressed per SD in all baseline visits, so that they refer to the same absolute increment in the feature.

An association between the personal slope and incident diabetes after adjustment for observed baseline HbA1c could arise without the rate of change carrying independent information.

A single measurement represents the underlying current HbA1c level imperfectly, and when within-person deviations persist over several years (slow drift; Section 2.8), earlier measurements may also provide information about that level. An estimated slope could therefore be associated with diabetes partly because it provides information about the current level not captured by the baseline measurement. To examine this possibility, we refitted model (4) for the personal slope, replacing observed baseline HbA1c with a history-informed estimate of the underlying current level obtained from the drift model (Section 2.8).

2.6 Sensitivity analyses

Unless stated otherwise, sensitivity analyses concerned the association of the personal slope with incident diabetes (Supplementary Section S3).

We examined sensitivity to slope estimation and adjustment for recent HbA1c level. In the primary analysis, personal slopes were estimated using only measurements preceding the baseline visit and therefore described the trajectory before the HbA1c measurement used for adjustment.

To assess the effect of incorporating the most recent observation, we repeated the analysis using slopes estimated from measurements up to and including baseline, while retaining adjustment for baseline HbA1c. In this analysis, the slope and the adjustment variable shared the baseline measurement. As an alternative adjustment for recent HbA1c level, we used the mean of the baseline and immediately preceding measurements, correcting the earlier value for the difference between round effects.

We also examined sensitivity to outcome definition and follow-up duration. We defined incident diabetes using only HbA1c ≥ 48 mmol/mol at the next health visit. For this analysis, we excluded baseline visits for which diabetes at follow-up was identified only through fasting glucose, self-reported diagnosis or medication use, because treatment may have lowered follow-up HbA1c below the diagnostic threshold. Because this exclusion depended on follow-up information, we also repeated the analysis with these visits classified as non-cases. Separately, we restricted the sample to baseline visits in rounds 4 and 6, which had an approximately four-year interval to the next health visit, to reduce variation in follow-up duration.

To assess sensitivity to missing covariates, we repeated the association analyses for all four longitudinal features (Section 2.3) using multiple imputation instead of median imputation (Rubin, 1987; White et al., 2011; van Buuren, 2018). To address selective follow-up, we weighted the analysis by the inverse probability of having an HbA1c measurement at the next health visit (Seaman and White, 2013). In a separate analysis, we extended outcome ascertainment to include baseline visits for which diabetes status at follow-up was known from interviews. For participants who died before the next health visit, we conducted a scenario-based analysis that included their baseline visits with hypothetical diabetes outcomes generated from prediction models using baseline HbA1c and clinical covariates, either including or excluding the personal slope.

Finally, we also examined the potential influence of participation history. Participants with at least two earlier HbA1c measurements had generally remained in the study longer; within this subgroup, we therefore modelled age with a natural cubic spline instead of a linear term, or additionally adjusted for birth cohort or for length of participation, one at a time.

2.7 Time-aware Transformer

To examine whether a flexible model could extract predictive information from longitudinal histories beyond that captured by the engineered features, we used a self-supervised time-aware Transformer for sparse, irregularly sampled data (STraTS; Tipirneni and Reddy, 2022). The model represented each participant's observations up to and including the baseline visit as (time, variable, value) triples covering 31 health-visit and interview variables. Within each training fold, the network was pretrained on all ELSA participants with at least two observation times, not only the analysis cohort, to forecast the first value of each variable within 2.5 years after a randomly chosen observation time, a window fixed in advance to cover the next biennial interview wave. It was then fine-tuned to predict incident diabetes. Test-fold participants were excluded from pretraining, fine-tuning and normalisation. An otherwise identical network trained without pretraining served as an ablation.

Both networks were evaluated using the same participant-level folds as the logistic regression models and compared with Model B using paired participant-cluster bootstrap intervals for differences in AUC. Because the Transformer received additional variables, including waist circumference, further laboratory markers and self-rated health, the comparison assessed whether a flexible model with access to the broader longitudinal record improved prediction, rather than isolating the effect of the architecture. Because fine-tuning weighted cases by the ratio of non-cases to cases, which shifts predicted risks upwards, the Transformer was compared with the logistic models by discrimination only; its predicted risks were not recalibrated. Three alternative configurations, varying model dimension or the number of encoder layers, served as robustness checks. Architecture, pretraining and optimisation details are provided in Supplementary Section S2 (Table S5).

2.8 Drift model

A persistent increase in a person's HbA1c may be difficult to distinguish from a fluctuation that lasts several years. The mixed model (1) assumes that deviations from the personal trajectory are independent from visit to visit. If deviations persist, measurements close in time are more similar than distant ones (serial correlation), and a temporary rise can resemble a personal slope.

To allow for this, we added a stationary Ornstein-Uhlenbeck (OU) process to the within-person variation (Uhlenbeck and Ornstein, 1930; Diggle, 1988; Diggle et al., 2002). For person i with HbA1c values y i measured at ages t i1 , . . . , t in i , where the rows of X i contain the fixed-effect terms of model ( 1) at each visit, so that X i β (with β including the round effects γ r ) is the population trajectory; the rows of Z i are (1, a ij ), so that Z i GZ ⊤ i is the covariance of the personal intercepts and slopes of model (1); and I is the identity matrix.

The term σ 2 w R i (τ ), which we call drift, describes deviations that persist for years but return towards the personal trajectory: drift values ∆ years apart have correlation e -∆/τ , so the time constant τ sets how long they last. The term σ 2 e I represents independent variation, including measurement error. The fraction of within-person variance due to drift is π = σ 2 w /(σ 2 w + σ 2 e ); with σ 2 w = 0, the model reduces to model (1) with independent noise (Figure 2). Slopes and drift differ in how differences between a person's measurements grow with the time between them. For two measurements ∆ > 0 years apart, half the expected squared difference of their deviations from the population trajectory (the semivariogram; Diggle, 1988; Diggle et al., 2002) is with ∆/10 in decades, the unit of the slope.

The drift term levels off once ∆ is several times τ , whereas the slope term keeps growing. Persistent slopes can therefore be separated from drift only through intervals that are long relative to τ ; additional measurements at short intervals mainly inform the noise and drift components.

Restricting the model to non-diabetic visits may truncate rising trajectories: after HbA1c crosses the diagnostic threshold, subsequent measurements are excluded, so a persistent increase can appear temporary (Hernán et al., 2004; Tobin et al., 2005). We therefore fitted two additional versions of the model, each including the same non-diabetic visits plus each participant's first HbA1c value ≥ 48 mmol/mol (the threshold-crossing value). The first used the observed crossing values. Because these values may reflect an accelerating rise before diagnosis (Tabák et al., 2009; Heianza et al., 2012), which a stationary drift process does not describe, the second used only the information that the threshold had been crossed, treating each crossing value as censored at 48 mmol/mol: instead of the density of its measured value, the participant's likelihood includes the model probability that HbA1c was at least 48 mmol/mol at that visit, given their earlier values (Supplementary Section S4).

For each fit, we estimated six covariance parameters: the intercept and slope SDs and their correlation, σ w , σ e and τ . Estimation used restricted maximum likelihood (REML), except for the censored fit, which used maximum likelihood. Because the data contain little information on τ , we examined its profile likelihood and obtained an approximate 95% interval (Venzon and Moolgavkar, 1988; Pawitan, 2001). We compared the drift model with the independent-noise model using the likelihood-ratio statistic and the Akaike information criterion (AIC; Akaike, 1974). Further details are given in Supplementary Section S4.

To separate trajectory information from denoising, the drift model also provided an estimate of each person's underlying current HbA1c level for the association analysis (Section 2.5 and Figure 2). We defined this level as the personal trajectory plus drift at the baseline visit, excluding the independent component, and estimated it by its conditional mean given the person's measurements up to and including that visit. Because the personal trajectory and drift persist over years, earlier measurements contribute to this estimate. For the two fits including crossing values, the model parameters were estimated once using all participants; association analyses using these estimates therefore did not use an out-of-sample adjustment.

Finally, we assessed whether adjustment for the estimated underlying current level could reduce an apparent slope association caused by imperfect measurement of the current level.

We simulated HbA1c histories for 12,000 hypothetical participants from a drift model with parameters close to those fitted with the crossing values, with values about four years apart, excluding participants with any value ≥ 48 mmol/mol. Incident diabetes was generated from the underlying current level alone, so that the personal slope carried no information of its own, and the slope association was then estimated with adjustment for either the observed last value or the estimated level (Supplementary Section S4).

2.9 Observability of personal slopes

Over short periods, persistent drift can look like a personal slope (Equation ( 6)), so how well the two can be separated depends on the number, spacing and duration of measurements. The fitted trajectory models (Equation ( 5)) allow us to quantify how reliably personal slopes can be recovered under different measurement schedules. We applied the calculation to the independentnoise model, the special case σ 2 w = 0, and to the two drift fits including threshold-crossing values (as observed and censored at 48 mmol/mol). We considered hypothetical schedules with measurements every 0.25 to 4 years over histories of 4 to 30 years. The shortest interval, three months, corresponds to the usual minimum interval for repeat HbA1c testing: because HbA1c reflects glycaemia over the lifespan of erythrocytes, more frequent measurements would largely share the same glycaemic history (Cohen et al., 2008).

For each schedule, we asked how much the measurements reduce the uncertainty about a person's slope, an approach used to compare longitudinal designs (Willett, 1989; Raudenbush and Liu, 2001; Rast and Hofer, 2014; Brandmaier et al., 2018). Before any measurement, this uncertainty is the between-person slope variance, G 22 . After the measurements, it is the posterior variance Var(u 1 | y). To compute it, consider a hypothetical person with intercept and slope u = (u 0 , u 1 ), measured at regular intervals over the observation period with the last measurement at age 65, the reference age of the personal intercept; y denotes these measurements, and the subscript i is omitted because no participant's data are involved. In equation ( 7), ZGZ ⊤ represents variation arising from personal intercepts and slopes, while V 0 represents drift and independent noise. Conditional on the fitted covariance parameters, the posterior variance depends only on the measurement schedule, not on the observed HbA1c values, and can therefore be calculated without simulating measurements. Independent fluctuations can be averaged out through repeated measurements, whereas serially correlated drift reduces the additional information provided by closely spaced observations (Diggle et al., 2002). We defined slope reliability as 1 -Var(u 1 | y)/G 22 , the fraction of between-person slope variance resolved by the measurements, ranging from 0 (no information) to 1 (perfect recovery).

Because û1 is computed from the full covariance matrix G, r also depends on the interceptslope correlation ρ. At ρ = 1, the slope is a fixed multiple of the intercept, u1 = c u 0 with c = G 22 /G 11 , so that û1 = c û0 and r = corr(û 0 , u 0 ): the correlation for the slopes then equals how well the person's level is estimated. Even a single measurement would then give a high r, although it contains no information on change over time. We therefore calculated r with ρ set to zero and the other fitted covariance parameters held fixed, so that û1 no longer draws on information transferred through the assumed correlation between the personal level at age 65 and the slope. This is a conditional calculation, not a separately fitted model. Its purpose is to examine the recoverability of personal change without information transferred from the personal intercept through the assumed correlation. 3.1 Cohort, measurement histories and HbA1c variation

Of 10,215 eligible baseline visits identified among 30,958 health-visit records in rounds 2 to 8/9, 5,828 visits from 3,603 participants had HbA1c measured at the next health visit and formed the analysis set (Figure 3). In total, 234 baseline visits (4.0%) were followed by incident diabetes over a median follow-up of 4.2 years. Mean age at baseline was 67.7 years, 57.0% of visits were from women, 98.5% of participants were of White ethnicity, and 20.5% had HbA1c of 42-47.9 mmol/mol (Table 1). Visits followed by incident diabetes had higher baseline HbA1c, BMI and waist circumference, more frequent use of blood-pressure medication, and less frequent weekly vigorous activity. Characteristics by HbA1c range are given in Supplementary Table S1.

HbA1c was unavailable at the next health visit for 4,387 eligible baseline visits. Compared with visits in the analysis set, these visits were from older participants (mean age 71.8 versus 67.7 years), with more frequent use of blood-pressure medication (35% versus 28%), but similar mean baseline HbA1c and estimated personal slopes (Table 1).

The histories available for estimating personal trajectories were sparse: 60.9% of baseline visits had only one earlier HbA1c measurement, 31.1% had two, and 7.9% had three. Consecutive measurements were a median of 4.0 years apart, and the first earlier measurement was a median of 4.3 years (IQR 3.9-7.9) before baseline (Supplementary Table S2). Because the primary slopes used only measurements before baseline, observed within-person change informed them for only 39.1% of visits.

Under the independent-noise trajectory model (Equation ( 1)), between-person variation in HbA1c at age 65 was greater than residual within-person variation (SDs 3.17 and 1.62 mmol/mol, respectively), giving an ICC at age 65 of 0.79 and an index of individuality of 0.51 (Table 2). The corresponding reference change value was 4.5 mmol/mol: a difference between two measurements had to exceed this to be distinguishable from fluctuation around the personal trajectory. The estimated between-person SD of personal slopes was 0.84 mmol/mol per decade, whereas the empirical Bayes slope estimates derived from the available histories had an SD of only 0.17 mmol/mol per decade, reflecting strong shrinkage towards the population slope.

Model diagnostics indicated departures from the assumed residual distribution and temporal structure. Standardised conditional residuals were approximately symmetric (skewness 0.02) but more peaked and heavier-tailed than a normal distribution (excess kurtosis 2.4). Empirical Bayes estimates of personal levels were approximately normal apart from the lower tail (Supplementary Figure S1). Residual correlations between rounds declined with increasing time between measurements more rapidly than implied by the fitted independent-noise model (Supplementary Figure S2), motivating the drift analysis reported in Section 3.4.

4 Discussion

In this work, we examined whether individual HbA1c trajectories of people without diabetes carry information about future diabetes beyond the current HbA1c value and conventional clinical risk factors. The question is motivated by the standard diagnostic approach, in which a single current value is compared with a fixed population threshold (World Health Organization, 2011; American Diabetes Association Professional Practice Committee, 2026). Our setting was a population-based cohort of middle-aged and older adults (ELSA) (Steptoe et al., 2013), in which

HbA1c was measured at health visits several years apart over a long period.

As the unit of analysis, we used baseline visits: visits at which a participant was free of diabetes, had at least one earlier non-diabetic HbA1c value, and had HbA1c measured at the next visit (Section 2.2). Using a linear mixed model with independent residual noise (Laird and Ware, 1982; Verbeke and Molenberghs, 2000), we estimated the population trajectory and, by empirical Bayes (Robinson, 1991), each person's expected trajectory from their earlier values (Section 2.3). From this model we derived the personal slope; the deviation of the baseline value from the person's expected value, which measures how surprising the current value is given the person's history; the change since the previous measurement; and a forecast, i.e. the predicted probability that HbA1c would reach the diabetic range at the next visit (Figure 1). Population parameters were estimated by cross-fitting (Chernozhukov et al., 2018), so that no person's features were derived from a model fitted to their own data.

We added these features to a clinical prediction model including baseline HbA1c, age, sex and established clinical risk factors (Lindström and Tuomilehto, 2003; Wilson et al., 2007; Hippisley-Cox and Coupland, 2017; Noble et al., 2011; Abbasi et al., 2012). None of them meaningfully improved discrimination, in all baseline visits or in any subgroup examined, including visits with more than one earlier measurement (Section 3.2, Table 3, Supplementary Table S3).

To examine whether this reflected the choice of features rather than a lack of information in the histories, we also evaluated a time-aware Transformer designed for sparse, irregularly sampled data (Tipirneni and Reddy, 2022; Vaswani et al., 2017). It had access to the full observation histories and to additional variables in ELSA, such as waist circumference, further laboratory markers and self-rated health, and was pretrained to forecast future values (Li et al., 2020; Rasmy et al., 2021) (Section 2.7, Supplementary Table S5). The Transformer did not clearly improve on the clinical model, although a small improvement cannot be excluded. Pretraining improved forecasts of other variables but not of HbA1c, and did not improve discrimination; alternative configurations gave similar results (Supplementary Table S6). This agrees with previous findings that more flexible machine-learning methods do not necessarily outperform conventional regression models in clinical prediction (Christodoulou et al., 2019).

The absence of predictive improvement does not imply that the trajectories carry no relevant information. After adjustment for baseline HbA1c, age, sex and clinical risk factors, the personal slope was associated with incident diabetes (Section 3.3, Figure 4A), so the estimated slope carries information beyond the current HbA1c value. The association was clearest where the slope reflected observed within-person change, i.e. among visits with more than one earlier measurement (Supplementary Table S8). The deviation, the change since the previous measurement and the forecast showed no clear association (Supplementary Table S7).

Association and prediction are not in contradiction here. A predictor can be associated with an outcome while adding little to discrimination, particularly when established predictors such as baseline HbA1c already separate future cases well (Wald et al., 1999; Pepe et al., 2004; Ware, 2006; Cook, 2007). An association of the size observed for the slope would be expected to change the ranking of only few individuals once baseline HbA1c and clinical risk factors are known.

Two qualifications apply to the slope association itself. First, it depended on the adjustment set, particularly on adjustment for age; one possible contributor is that the estimated slope itself depends on the ages at which the earlier values were measured (Supplementary Section S3).

Second, it concerns a model-derived prognostic feature and does not by itself establish a stable biological rate of change in each person.

The shortness of the histories may explain much of the gap between association and prediction.

For most baseline visits only one earlier value was available (Section 3.1, Supplementary Table S2), so that the estimated slope was determined by how far that value lay from the population trajectory rather than by observed change. This may explain why the slope contributed little to prediction in most people and why the association was clearer when change had actually been observed. Imprecisely estimated slopes also attenuate associations with the underlying trajectories, analogous to regression dilution when exposures are measured with error (MacMahon et al., 1990; Clarke et al., 1999; Carroll et al., 2006).

The slope association was not readily explained by the earlier measurements merely providing a better estimate of the current HbA1c level. It remained when baseline HbA1c was replaced by the drift model's estimate of the underlying current level (Figure 4B), whereas in simulated data in which risk depended only on the current level, the same adjustment largely removed the apparent slope association (Supplementary Section S4). The persistence of the empirical association is therefore consistent with information in the slope beyond the current level, although it remains conditional on the assumed drift model and cannot exclude this explanation entirely.

The association was also similar across sensitivity analyses addressing slope construction, outcome definition, follow-up, missing covariates and deaths before follow-up (Supplementary Tables S9 and S10).

Deviations of HbA1c from a person's own trajectory were not independent from visit to visit but persisted for years, as described by a serially correlated drift (Ornstein-Uhlenbeck) process (Uhlenbeck and Ornstein, 1930; Diggle, 1988; Taylor et al., 1994); this model fitted better than independent noise (Section 3.4, Table 4). How variation was divided between persistent slopes and drift, however, depended strongly on the treatment of the values at which HbA1c first crossed the diagnostic threshold, and in all drift fits the correlation between personal level and slope reached its boundary (Figure 5, Supplementary Table S11). The available data therefore could not reliably separate personal level, persistent slope and slow drift, whereas the presence of drift was consistent across specifications. Restricting trajectory analyses to disease-free observations can affect this separation (Hernán et al., 2004; Tobin et al., 2005), while measurements near disease onset may reflect the accelerating rise that often precedes diagnosis (Tabák et al., 2009; Heianza et al., 2012; Yu et al., 2023) and that neither persistent linear slopes nor stationary drift describe.

Serial correlation also limits what repeated measurements can reveal. When slopes could be inferred only from the measurements themselves, more frequent measurements improved slope recovery substantially under independent noise but little under drift, whereas longer observation periods helped more; even so, slopes remained poorly recovered over decades of observation (Section 2.9, Figure 6, Supplementary Table S12). Assuming independent variation would therefore overstate how reliably persistent individual change can be estimated, consistent with methodological work on the reliability of individual change (Willett, 1989; Raudenbush and Liu, 2001; Rast and Hofer, 2014; Brandmaier et al., 2018). The same applies to personal reference values: the index of individuality and the reference change value are usually interpreted with a single within-person variance (Harris, 1974; Fraser and Harris, 1989; Fraser, 2001; Coşkun et al., 2021), whereas under drift the expected difference between two measurements depends on the interval between them (equation ( 6)). Personal reference intervals remain a promising approach (Foy et al., 2025; Zhang et al., 2026; Shah et al., 2026), but their usefulness depends on the analyte, the outcome and how reliably a personal reference can be established. Much of the evidence on personal laboratory setpoints comes from electronic health records, in which testing frequency reflects clinical concern (Agniel et al., 2018; Goldstein et al., 2016; Sisk et al., 2021); scheduled measurements reduce this bias at the cost of sparse observations.

These results have implications for longitudinal biomarker monitoring. Estimating persistent individual slopes requires long histories, which favours long-term, routinely collected laboratory records, ideally in younger, working-age populations followed with regular health examinations.

Detecting an emerging acceleration towards diabetes, by contrast, may benefit from more frequent measurements around the onset of progression and from models that allow the rate of change to increase, for example at a changepoint (Skates et al., 2001), or joint models of longitudinal markers and events (Tsiatis and Davidian, 2004; Rizopoulos, 2012; Diggle et al., 2015). The choice of observations also depends on the purpose of the model. When the outcome is crossing a diagnostic threshold, a person's series ends at that point, so rising trajectories are cut off. A model that instead forecasts the biomarker itself could keep values above the threshold and exclude only measurements after the start of treatment, leaving the diagnostic decision to the clinician.

4.1 Strengths and limitations

An important strength of this work is the use of scheduled venous HbA1c measurements in a population cohort, which reduces bias associated with clinically triggered testing driven by symptoms or clinical suspicion. All representations of personal history were compared against a common clinical model, and personal features were constructed using participant-level crossfitting, an approach that can be applied to other biomarkers. Comparing adjustment for observed and estimated underlying HbA1c helped distinguish trajectory information from better estimation of the current level. In addition, we extended the independent-noise model to account for serial correlation and quantitatively assessed how reliably individual slopes could be recovered under different measurement schedules.

The main limitation is the sparsity of the histories, with only one earlier value for most baseline visits. Conclusions about trajectories estimated from longer or denser histories are therefore limited, and the limited predictive gain from personal slopes may depend on the measurement intervals available in ELSA. The number of incident cases was modest (234), limiting the precision of performance and association estimates, particularly in subgroups. Incident diabetes was classified from a single HbA1c measurement at or above the diagnostic threshold, a reported diagnosis or medication use. The absence of confirmatory testing may have introduced outcome misclassification, including cases reflecting transient HbA1c elevations.

Another important limitation is the substantial loss to follow-up: more than 40% of eligible baseline visits had no HbA1c measurement at the next health visit. Inverse-probability weighting, the inclusion of interview-reported outcomes and scenarios for participants who died yielded similar slope associations (Supplementary Section S3), but selection bias from unmeasured factors remains possible. Furthermore, baseline visits with several earlier values came from participants who had survived and remained in the study for longer, so the stronger association in this subgroup may not apply to all participants.

Generalisability is also limited by the composition of the cohort. Almost all participants were of White ethnicity, limiting our ability to assess generalisability across ethnic groups. This is relevant because the relationship between HbA1c and glycaemia has been reported to differ between ethnic groups (Ziemer et al., 2010; Herman and Cohen, 2012). Generalisability to younger populations also remains uncertain.

A further limitation concerns the modelling of individual trajectories. The longitudinal features were derived from the independent-noise model and were not re-estimated under the better-fitting drift model. The latter's parameters were not robustly determined: fits restricted to non-diabetic visits attributed almost no variation to persistent personal slopes, whereas variants allowing substantial persistent slopes required threshold-crossing measurements closely tied to the outcome (Table 4). The predictive value of features derived from alternative longitudinal models therefore remains uncertain. More generally, our representation of persistent change by linear personal slopes and of within-person fluctuation by independent noise or a stationary Ornstein-Uhlenbeck process may not capture nonlinear trajectories or other forms of within-person variation (Rasmussen and Williams, 2006; Hughes et al., 2017).

The observability calculations also depend on specific modelling assumptions. They used a reference scenario with the intercept-slope correlation set to zero, because a correlation of one would allow the slope to be inferred from the personal level rather than from observed change (Supplementary Section S4). These calculations therefore describe observability under the specified covariance assumptions rather than establishing a general limit on slope recovery.

Another limitation concerns the construction of features and the adjustment for the underlying current level. Participant-level cross-fitting excluded each participant's own data when estimating the population trajectory parameters used to construct their features. However, these parameters were estimated using other participants' measurements from all rounds, including rounds after a given baseline visit. Feature construction was therefore not strictly prospective. In addition, the drift model used to estimate the underlying current level was fitted to all participants, including the threshold-crossing values, rather than by cross-fitting. Performance under strictly prospective construction remains to be established.

Finally, the evaluation of the Transformer was limited to one main configuration and three variants without hyperparameter tuning. These results therefore do not establish the best performance achievable with this architecture.

5 Conclusion

ELSA provides an opportunity to investigate the value of personal laboratory histories in a population cohort with scheduled HbA1c measurements spanning almost two decades, reducing bias associated with clinically triggered testing. In this setting, estimated personal HbA1c slopes were associated with incident diabetes beyond baseline HbA1c and conventional clinical factors, most clearly where change had been directly observed, whereas deviations from estimated usual levels showed no clear association at the same baseline HbA1c. Nevertheless, neither these features nor a flexible sequence (Transformer) model showed clear evidence of improved discrimination beyond baseline HbA1c and conventional clinical factors, which captured nearly all the discrimination achieved by the evaluated models. Within-person variation was better described by serially correlated drift, as in an Ornstein-Uhlenbeck process, than by independent noise; under this description, persistent individual slopes were difficult to recover from measurements several years apart, which may explain part of this gap between association and prediction. These findings concern persistent individual slopes and do not exclude the predictive value of emerging nonlinear changes, including the acceleration in glycaemia that may precede diabetes.

More broadly, our results illustrate the importance of distinguishing longitudinal associations, incremental predictive value, and the observability of individual trajectories. This distinction is relevant beyond HbA1c: the usefulness of longitudinal biomarker information depends not only on its association with future disease, but also on whether that information can be recovered reliably from the available measurements.

Time-aware Transformer. The model follows STraTS (Tipirneni and Reddy, 2022), building on attention architectures (Vaswani et al., 2017), earlier models for irregular clinical time series (Che et al., 2018; Horn et al., 2020; Shukla and Marlin, 2021) and pretrained EHR representations (Li et al., 2020; Rasmy et al., 2021). Each person's history is a set of observations (time, variable, value); the network embeds every observation, lets the observations attend to each other, pools them into one vector, and adds static information. It is first trained to forecast future values (pretraining) and then to predict incident diabetes (fine-tuning). All settings are listed in Table S5.

Participants in the analysis cohort kept their folds from the main analysis, and the remaining pretraining participants were assigned to one of the five folds at random, so that no test-fold participant contributed to pretraining, fine-tuning, early stopping or normalisation. Pretraining used the complete observation histories of training-fold participants, including observations after their own baseline visits; this uses no information from test-fold participants but differs from a strictly chronological design.

Measurement history.

Among baseline visits with at least two earlier HbA1c measurements, the slope association was additionally adjusted, one at a time, for a natural cubic spline in age (replacing the linear term), for birth year, and for the time since the first HbA1c measurement, and was estimated separately below and above age 70; strata with fewer than 10 cases were not estimated.

Loss to follow-up. For inverse-probability weighting, the probability of having HbA1c at the next health visit was estimated among all eligible baseline visits by a ridge-penalised logistic regression (as in the prediction models) on age, sex, HbA1c, BMI, systolic blood pressure, HDL cholesterol, log triglycerides, smoking, weekly vigorous activity, blood-pressure medication, education, employment, the number of earlier HbA1c measurements and the baseline round (AUC 0.69). Predicted probabilities were bounded below at 0.05 before calculating inverse-probability weights, which were then scaled to a mean of 1 in the analysis set. The maximum weight was 4.75 (99th percentile 2.23), and the effective sample size was 5,259 of 5,828 baseline visits (90%).

The weighted analysis assumes that follow-up is independent of the missing outcome given these variables.

For the extended outcome set, baseline visits without HbA1c at the next health visit were added if the participant answered the diabetes question at an interview in the next health-visit round, or reported diabetes at any interview between the baseline visit and the next round. A report of no diabetes before the next round did not qualify, because diabetes could still have developed by that round. Incident diabetes in these visits was defined by the interview reports, or by fasting glucose at a next visit without valid HbA1c. Because known cases could enter more readily than non-cases, inclusion depended partly on the outcome. This analysis is therefore a sensitivity check rather than a removal of selection bias; its interpretation depends on the inclusion mechanism, including whether inclusion varied with the covariates, and on differences between interview-based and laboratory-based ascertainment of diabetes.

Deaths were identified from the harmonised interview status and the wave-11 end-of-life file.

For participants who died before the next health visit, hypothetical diabetes outcomes were drawn with probabilities predicted by a logistic model fitted to the analysis set, evaluated at the person's values at the baseline visit, with the follow-up interval set to the median of the baseline round in both outcome generation and the subsequent association model. The coefficients of the risk model were held fixed, so the pooled intervals do not reflect uncertainty in that model.

The predicted probabilities were multiplied by 1, 2 or 3 and capped at 1; the multiplier acts on the probability, not on the odds. For each scenario, 50 sets of outcomes were generated, the association model was refitted on all baseline visits, and estimates were pooled with Rubin's rules. In the first set of scenarios, the outcome-generating model included the personal slope; in the second, it did not.

Because the slope is correlated with baseline HbA1c and the other predictors, the hypothetical outcomes in these scenarios are not independent of the slope, but the outcome-generating model contains no explicit slope term. Death is a competing event, and the hypothetical outcomes describe a next visit that did not take place, not diabetes incidence after death.

Outcome definition. For the outcome defined by HbA1c alone, incident diabetes was HbA1c ≥ 48 mmol/mol at the next health visit. Visits that were cases only through fasting glucose, a reported diagnosis or medication were either excluded or classified as non-cases (Table S9); the first version selects visits using follow-up information and is therefore a sensitivity analysis in a selected sample. Because no case occurred at the lowest baseline HbA1c values, the spline was evaluated at max(HbA1c, c), with c the lowest baseline HbA1c of a case in each analysed sample, and the missingness indicators for HDL cholesterol and triglycerides were replaced by a single indicator that either value was missing.

Missing covariates.

For multiple imputation, the seven clinical covariates with missing values (BMI, systolic blood pressure, HDL cholesterol, log triglycerides, smoking, weekly vigorous activity and blood-pressure medication) were imputed 20 times by chained equations (scikitlearn IterativeImputer with Bayesian ridge regression and draws from the posterior predictive distribution, 10 iterations per data set); imputed values of binary covariates were clipped to [0, 1] and rounded to 0 or 1. The imputation model included the outcome, the four personal features, baseline HbA1c, age, sex, ln(years to next visit) and the health-visit round. Imputation was performed at the level of baseline visits and did not model the dependence between visits of the same participant. This sensitivity analysis therefore used an approximate imputation model: binary variables were imputed with continuous models, and within-participant dependence was not represented. In each imputed data set, the association model was fitted without missingness indicators and with participant-clustered standard errors; the estimates and these variances were pooled with Rubin's rules, with Rubin's degrees of freedom for the t reference distribution (Rubin, 1987; White et al., 2011; van Buuren, 2018). The analysis was run for all four features in all baseline visits and in the HbA1c range 42-47.9 mmol/mol, and for the personal slope among baseline visits with at least two earlier HbA1c measurements.

Supplementary Section S2: Prediction analyses

This section provides details of the prediction analyses summarised in Section 2.4. It describes the sources and construction of the clinical predictors, specifies the final models A and B refitted to all baseline visits, with the equation needed to calculate predicted risks, reports differences in discrimination in subgroups of baseline visits, and describes the architecture, training and robustness of the time-aware Transformer.

Predictors. Body-mass index (BMI) was taken preferentially from the health-visit variable bmival. If it was missing, we used the measured BMI of the Harmonized ELSA file (mbmi); if this was also missing, BMI was calculated from the measured weight (mweight) and the most recent measured height (mheight) at or before that wave, retaining values between 12 and 80 kg/m 2 (Gateway to Global Aging Data, 2023). Systolic blood pressure was ELSA's derived variable sysval, the mean of the second and third of three seated readings. HDL cholesterol and triglycerides were measured by an external laboratory in the health-visit blood sample, fasting or non-fasting. Current smoking (smoken), vigorous physical activity at least once a week (vgactx_e) and blood-pressure medication (rxhibp) were self-reported at the interview of the same wave as the health visit and taken from the Harmonized ELSA file, in which participants without diagnosed hypertension are coded as not taking blood-pressure medication.

Predictors were transformed as shown, missing values were replaced by their medians on the transformed scale, and a missingness indicator was added for each covariate with missing values. All resulting columns, including the missingness indicators, were standardised using their means and SDs across all baseline visits after imputation.

Supplementary Section S4: Drift model and slope observability

Fit of the trajectory models. Figure S2 compares the empirical correlation of residuals between pairs of health-visit rounds with the correlations implied by the independent-noise and drift models, and Figure S3 the empirical semivariogram with the curves implied by the fitted models (equation ( 6)). Both use deviations from the population trajectory, d ij = y ij -x ⊤ ij β, with the fixed effects of the independent-noise model; these deviations retain the personal intercept and slope. Model-implied correlations between two rounds were approximated by evaluating the fitted model at the mean ages of the participants measured in both rounds. The model curves describe the unconditional covariance structure; because the observed series were restricted by diabetes status and threshold crossing, the empirical correlations and semivariograms need not coincide exactly with these curves, even under the assumed model.

The profile likelihood for τ was evaluated at fixed values between 0.5 and 100 years (in steps of 0.5 years between 3 and 8 years, more widely spaced elsewhere, with additional values where the profile was flat near the interval limits). The approximate 95% interval comprised the values of τ whose log-likelihood was within 1.92 (half the 95th percentile of a χ 2 1 distribution) of the maximum, with limits interpolated on log τ between grid points; because τ is weakly identified, these intervals are approximate. The drift and independent-noise models have the same fixed-effect specification. Likelihood-ratio statistics and ∆AIC compared models fitted to the same observations with the same likelihood convention: REML for the uncensored data sets and maximum likelihood for the censored fit, in which the independent-noise model was obtained by setting the drift variance to zero. Because σ w = 0 lies on the boundary of the parameter space and τ is undefined under the independent-noise model, the likelihood-ratio statistic does not follow the usual χ 2 distribution (Self and Liang, 1987); we report it descriptively, without a p-value.

Threshold-crossing values. Series ending because of other diabetes criteria (fasting glucose, self-reported diagnosis or medication) with HbA1c below 48 mmol/mol were not extended by a crossing value. Including the crossing value makes the HbA1c-based stopping rule depend on an observed rather than an excluded value; under a correctly specified model, and if other dropout is missing at random, likelihood-based estimation then requires no separate model of the dropout process (Rubin, 1976; Diggle and Kenward, 1994; Little and Rubin, 2019). This does not address selection arising from diagnosis by other criteria, treatment or death.

In the censored fit, a participant with a crossing value contributed the density of their non-diabetic values multiplied by the model probability that the next value was ≥ 48 mmol/mol given those values; all other participants contributed the density of their values as before. The censored model was fitted by maximum likelihood; for the uncensored fits, maximum likelihood and REML gave nearly identical estimates. We verified the censored likelihood against an independent implementation based on full-covariance Gaussian conditioning. To examine how strongly the uncensored fit depended on the largest crossing values, we also refitted it with the crossing values capped at 48 to 80 mmol/mol (Table S11, Figure S4).

Simulation of the current-level adjustment.

The simulation used to check the level adjustment (Section 3.3) generated 12,000 hypothetical participants with two to four HbA1c values about four years apart, the first at age 55-70, under a drift model with parameters close to the fit including crossing values (intercept SD 3.0 mmol/mol, slope SD 0.8 mmol/mol per decade, intercept-slope correlation 1, drift SD 2.8 mmol/mol, τ = 5.6 years, independent SD 1.3 mmol/mol). The population trajectory was 38.6 + 0.94 a mmol/mol, with a = (age -65)/10 and no sex effect, and the spacing between values varied with SD 0.4 years (function simulate_selftest in the analysis code). The last measurement defined baseline. Histories containing any HbA1c value ≥ 48 mmol/mol were excluded, leaving 11,399 participants. A subsequent binary diabetes outcome was generated with probability expit{-3.2 + 0.45(L -40)}, where L was the underlying level at baseline, yielding 769 cases; the personal slope therefore carried no information beyond that level. The slope feature was the empirical Bayes slope from the earlier values under an independent-noise model with fixed parameters (intercept SD 3.4 mmol/mol, slope SD 1.1 mmol/mol per decade, correlation 0.69, residual SD 2.6 mmol/mol); the underlying level was estimated with the true drift parameters, which were therefore known rather than re-estimated. The slope association was estimated once, in a single simulated data set, with a natural cubic spline (4 df) in either the observed last value or the estimated level and no other covariates, and with the slope standardised by its SD within each analysed group: OR 1.26 (95% CI 1.12-1.42) and 1.02 (0.90-1.16) in all simulated participants, and 1.24 (1.11-1.38) and 1.09 (0.97-1.23) among those with a last value of 42-47.9 mmol/mol. An intercept-slope correlation of 1 was chosen to reflect the boundary estimates of the fitted drift models. The simulation illustrates that adjustment for the estimated current level can substantially attenuate an apparent slope association under this particular scenario; it does not establish that the empirical association is free of this mechanism.

Observability. Table S12 gives the expected correlation between estimated and underlying slopes with the intercept-slope correlation set to zero, as in the reference observability calculation (Section 2.9), and at its fitted value. Measurements were equally spaced and, where the history length was a multiple of the interval, the last was at age 65, the reference age of the model; a four-year history therefore contains two four-yearly values. The four-yearly 30-year schedule comprised values at ages 35 to 63 (28-year span), whereas the quarterly schedule spanned the full 30 years, so this comparison differs in duration as well as frequency. Calculations condition on the specified covariance parameters and do not incorporate their estimation uncertainty.

The schedules describe what repeated measurements over a given span can reveal; they do not reproduce the primary slope estimator, which used only values before the baseline visit and, for 61% of baseline visits, a single earlier value.
