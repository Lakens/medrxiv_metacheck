Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

Declaration of Helsinki - Declaration of Helsinki / Helsinki Declaration

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Accurate and timely probabilistic dengue forecasts can support public health preparedness, but producing reliable forecasts across locations and time horizons remains challenging. We evaluated five statistical, machine-learning, deep-learning, and foundation-model approaches for forecasting monthly reported dengue cases across 5,570 Brazilian municipalities at 1-, 3-, 6-and 12-month horizons, with forecasts backtested from January 2020 to August 2025. The time-series foundation model TimesFM maintained comparatively stable probabilistic forecast performance at longer horizons, while most other models showed declining performance. We then tested whether spatial representations of human and environmental context from a Population Dynamics Foundation Model (PDFM) could improve forecasts through post-hoc residual adjustment. PDFM adjustment improved mean probabilistic forecast performance, measured by the Weighted Interval Score (WIS), in 19 of 20 model-horizon combinations, although the magnitude and frequency of improvements varied across models, horizons and municipalities. The largest improvements were observed for N-BEATS, including a reduction in mean WIS of 1.13 at the six-month horizon (95% CI [0.84, 1.48]; Diebold-Mariano p < 0.0001), with improvements also observed for XGBoost. The proportion of forecasts improved by PDFM generally increased with locally reported dengue case counts, although this relationship varied between models. Covariate selection, spatial fitting and forecast aggregation strategies showed strong model-dependent effects, while monthly model retraining provided no consistent advantage in the settings evaluated. Together, these findings highlight the potential of pretrained representations for dengue forecasting, with benefits dependent on forecasting architecture, horizon and modelling configuration.

Introduction

Dengue is a major vector-borne disease, causing substantial annual morbidity and mortality as well as economic and social disruption. Dengue virus (DENV) is transmitted primarily by Aedes aegypti and, to a lesser degree, Ae. albopictus in tropical and temperate regions, with transmission intensity shaped by climatic, environmental, socioeconomic, demographic and biological factors, including population immunity and circulating DENV serotypes (1). The relative importance of these factors varies over time and by location and is highly context-specific (2). The number of reported dengue cases reached record levels in 2024, with more than 14 million cases reported worldwide. In Brazil alone, more than 10 million dengue cases were reported through surveillance notifications, alongside over 6,000 dengue-related deaths (3). The record epidemic in Brazil and the Americas coincided with El Niño-associated temperature anomalies and substantial southward geographical expansion of dengue transmission into previously less-affected temperate regions (4). Geographical expansion and increased cases in endemic areas highlight the vulnerability of cities in the Americas to climate-related shifts in temperature and precipitation, creating new challenges for dengue preparedness and response.

Anticipating where and when reported dengue cases will increase, and by how much, is therefore important for targeting preparedness and response. Probabilistic forecasts characterise uncertainty in these future outcomes rather than providing a single expected trajectory, and can support decisions about where and when public health resources are needed. Forecasts over longer time horizons, from several months to a year ahead, can inform advance planning and resource allocation across regions, while shorter-term forecasts can support more immediate decisions around healthcare capacity, risk communication and targeted vector-control interventions. In Brazil, dengue preparedness activities routinely include intensified vector surveillance and campaigns to reduce mosquito breeding sites before seasonal peaks, alongside emergency healthcare mobilisation and redistribution of clinical resources during major epidemics (5) (6) (7).

Current approaches to dengue forecasting have primarily relied on historical incidence alongside climatic, demographic and, in some cases, immunological predictors. Existing approaches include spatiotemporal models incorporating climatic predictors (8) (9) (10), probabilistic models for seasonal epidemic forecasting (11), and ensemble methods combining predictions across multiple models (12) (13) (14). For example, the 2024 edition of the Infodengue-Mosqlimate Dengue Challenge (IMDC24) evaluated probabilistic forecasts from seven statistical and machine-learning models across five Brazilian states, demonstrating substantial variation in performance across models, locations and epidemic seasons, and highlighting the potential value of ensemble approaches (15). However, local population dynamics that shape transmission risk, including human behaviour, mobility, and interactions with the social and built environment, remain difficult to capture fully using conventional epidemiological and climatic covariates (16). The increasing availability of digital data provides new opportunities to characterise these dynamics, including through aggregated signals of mobility, behaviour and population activity. Population Dynamics Foundation Model (PDFM) provides one scalable approach to integrating these heterogeneous factors, learning transferable spatial representations from multimodal information including aggregated search trends, mobility patterns, built-environment characteristics, weather and air quality (17). In Brazil, PDFM embeddings have recently shown utility for subnational population estimation, including improvements over traditional hand-crafted geospatial covariates in some settings (18). Whether these representations improve predictive performance beyond that achieved by existing infectious disease forecasting models using conventional epidemiological and environmental covariates remains, to our knowledge, unknown.

Beyond representing spatial and contextual information, foundation models can also learn representations of temporal dynamics through large-scale pretraining (19). Time-series foundation models are trained on large collections of time-series data spanning diverse domains, including those unrelated to infectious diseases, with the aim of learning representations that generalise across downstream forecasting tasks (20, 21). Some can be adapted or fine-tuned using taskspecific data to further improve performance (22). Recent studies have applied time-series foundation models to infectious-disease forecasting, including dengue and other communicable diseases (12, 23). Automated model development using multimodal data and foundation-model embeddings has also shown promise across geospatial prediction tasks, including infectious disease modelling (24).

Here, we evaluate whether pretrained temporal and spatial representations can strengthen forecasting of dengue epidemic dynamics, measured by monthly reported cases at 1-, 3-, 6-and 12-month horizons. The analysis encompasses 5,570 municipality-level administrative units across Brazil, including the Federal District and Fernando de Noronha (hereafter collectively referred to as municipalities). We test two complementary applications of foundation models: a time-series foundation model pretrained on large-scale temporal data, and spatial embeddings from PDFM representing human and environmental characteristics. We compare five forecasting models spanning statistical, machine-learning, deep-learning and foundation-model paradigms, and assess whether using PDFM embeddings improves probabilistic forecast performance beyond that achieved using historical incidence and conventional covariates. We further assess how covariate selection, spatial fitting strategy, forecast aggregation and retraining strategy influence forecasting performance. Finally, we use Empirical Research Assistance (ERA), an Artificial Intelligence (AI) system combining large language models and tree search to iteratively develop scientific software (25), to test whether PDFM embeddings are independently selected for dengue forecasting. ERA was provided with the same epidemiological, climatic and PDFM inputs as the primary forecasting models, alongside spatial information.

TimesFM maintains strong relative performance at longer forecast horizons

For São Paulo, the municipality which had the highest cumulative number of reported dengue cases among Brazilian municipalities over the study period, the five forecasting models produced distinct predictive distributions (Figure 2A). Across all municipalities, probabilistic forecast performance varied by model and forecast horizon (Figure 2B; Supplementary Table S1). At the 1-month horizon, TCN achieved the lowest mean WIS (1.27), followed by XGBoost (1.38), while SARIMA and TimesFM performed similarly (mean WIS 1.46). As forecast horizon increased, performance deteriorated for most models, while TimesFM remained comparatively stable, achieving mean WIS of 1.56, 1.53 and 1.51 at 3-, 6-and 12-month horizons, respectively. TCN was the next-best performing model at these horizons, with mean WIS of 1.89, 2.08 and 2.16, respectively. Mean WIS was calculated across all municipality-month forecasts within each model-horizon combination (n = 378,760), with each observation contributing equally. PDFM embeddings provide complementary predictive information

We next tested whether municipality-level PDFM embeddings provided predictive information complementary to the baseline forecasting models using residual adjustment (Methods). For example, at the six-month horizon in the municipality of São Paulo, PDFM adjustment altered the XGBoost predictive distribution, including during the major 2024 epidemic (Figure 2D). Averaged across all municipality-month forecasts, PDFM adjustment reduced mean WIS for 19 of 20 modelhorizon combinations, although the magnitude and consistency of improvement varied substantially between models and horizons (Supplementary Table S3). Improvements were largest for N-BEATS, for which mean ΔWIS (PDFM -base) ranged from -0.58 at one month to -1.13 at six and 12 months horizons, and XGBoost, for which improvements increased from -0.08 at one month to -0.29 at 12 months. For N-BEATS and XGBoost, 95% temporal bootstrap confidence intervals for mean ΔWIS excluded zero at all four horizons. Following Bonferroni correction across the 20 model-horizon comparisons, Diebold-Mariano tests supported improved predictive accuracy at all four horizons for N-BEATS and at the one-month horizon for XGBoost (Supplementary Table S3). TCN models showed improvements at 1, 3 and 6 months supported by temporal bootstrap confidence intervals, although only the one-month comparison remained statistically significant after Bonferroni correction of the Diebold-Mariano tests. At a 12-month horizon, the temporal bootstrap indicated improvement (mean ΔWIS = -0.10, 95% CI [-0.18, -0.03]), but the Diebold-Mariano test did not reject equal predictive accuracy (p = 0.14) and bootstrap inference was sensitive to block length (Supplementary Table S3). Evidence of benefit at 12 months was therefore inconclusive. For SARIMA and TimesFM, evidence of benefit was limited to the one-month horizon; at longer horizons, bootstrap confidence intervals spanned zero and Diebold-Mariano tests did not support improved predictive accuracy. PDFM effects also varied through time at longer forecast horizons (Supplementary Figures S2-S3).

Decomposition of ΔWIS showed that the largest PDFM improvements arose primarily from reductions in out-of-interval penalties, which outweighed increases in predictive-interval width, while changes in median forecast error were comparatively small (Figure 2E). This pattern was particularly pronounced for N-BEATS and XGBoost at longer horizons.

The effect of PDFM adjustment also varied with the number of locally reported dengue cases in the forecast target month (Figure 2F). Because absolute differences in WIS can increase with forecast-error magnitude, we examined the proportion of individual municipality-month forecasts improved by PDFM within each case-count stratum. The proportion improved generally increased with reported case counts for several models; for example, at the six-month horizon, PDFM adjustment reduced WIS for 96.2% of N-BEATS forecasts in the highest case-count stratum, with a mean ΔWIS of -5.05 (95% CI [-5.52, -4.66]). The corresponding mean ΔWIS was -0.19 (95% CI [-0.32, -0.09]) in the lowest positive case-count stratum, with a high-minus-low difference of -4.87 (95% CI [-5.21, -4.54]; Supplementary Table S4). Conversely, PDFM adjustment worsened performance for zero-case observations in several models, including N-BEATS at six months (mean ΔWIS = +0.36, 95% CI [0.30, 0.41]). These exploratory findings indicate that the magnitude and direction of PDFM effects vary with observed case counts, with substantial differences between forecasting models.

The benefits of PDFM residual adjustment also varied geographically, with patterns differing across forecasting architectures (Supplementary Table S5). At the 12-month horizon, TCN and XGBoost showed particularly large absolute reductions in WIS in the South (mean ΔWIS = -0.306 and -0.524, respectively). However, for TCN, these larger absolute improvements did not translate into significantly greater log-relative skill than in the Northeast or Southeast. In contrast, N-BEATS showed consistently greater relative benefits in the Southeast and South than in the Northeast across all four horizons, while XGBoost showed greater relative benefits in the Central-West than in the Northeast at longer horizons. These findings indicate that the geographical distribution of PDFM benefits depends on the forecasting architecture and the measure of improvement considered, rather than following a consistent regional pattern across models.

Forecasting performance depends on modelling strategy

We next examined whether forecasting models benefited consistently from increasing the number of epidemiological and environmental covariates included. We compared the full covariate specification with a minimal set comprising log(1 + cases) at lag 1, the mean of minimum temperature over lags 1-2, and the mean of precipitation over lags 1-2. Models additionally retained their architecture-specific historical dengue case inputs or autoregressive structure (Table 2). The effect of covariate complexity was strongly model-dependent (Figure 3A; Supplementary Table S6). N-BEATS and SARIMA consistently benefited from the minimal covariate set, which yielded lower mean WIS, averaged across evaluation months within each municipality, in 79-87% of municipalities for N-BEATS and >97% for SARIMA across forecast horizons. TCN showed the opposite pattern, with the full covariate set producing better forecasts across horizons and approximately 73-76% of municipalities favouring the full configuration. XGBoost showed a horizon-dependent transition: the minimal covariate set modestly improved performance at one month, produced little difference at three months, while the full covariate set performed better at six and 12 months (Figure 3A; Supplementary Table S6). TimesFM was comparatively insensitive to covariate inclusion, with little difference between the full and minimal covariate sets across forecast horizons (Figure 3A; Supplementary Table S6). To assess the effect of model fitting strategy, we compared municipality-level forecasts from models fitted independently to each municipality with forecasts for the same municipalities from models fitted jointly across municipalities within each state. The comparison included the 20 municipalities with the highest cumulative reported dengue case counts over the study period (Methods). The effect was strongly model-and horizon-dependent (Figure 3B; Supplementary Table S7). N-BEATS consistently and substantially favoured independent municipality-level fitting, with median municipality-level ΔWIS becoming more negative from -3.58 at one month to -10.57 at 12 months. TimesFM consistently favoured the state-grouped configuration, while TCN showed an advantage for state-grouped fitting at one month with little difference thereafter. XGBoost shifted in the opposite direction with horizon: effects were small at one and three months, while independent fitting was favoured at six (median ΔWIS = -0.78) and 12 months (-1.10). SARIMA showed little difference between fitting strategies.

Generating forecasts at coarser spatial scales introduces a distinct choice: whether to aggregate municipality-level case series before fitting a model, or to fit municipality-level models and subsequently aggregate their probabilistic forecasts. We compared these approaches across all 27 Brazilian states (Figure 3C; Supplementary Table S8). The effects of spatial aggregation were strongly model-and horizon-dependent. TCN consistently favoured aggregation of municipalitylevel forecasts, while TimesFM showed the same pattern with smaller effects. N-BEATS showed the opposite pattern: at one-month forecast horizon there was no consistent advantage for either aggregation strategy across states (median ΔWIS = -0.31; p = 0.25), whereas direct fitting to aggregated case series was favoured from three to 12 month horizons (median ΔWIS = -3.15 to -5.30; Supplementary Table S8). XGBoost shifted from favouring aggregation of municipalitylevel forecasts at one month horizons (median ΔWIS = +0.78) to favouring direct fitting to aggregated case series at six and 12 months horizons (-0.49 and -1.16, respectively). SARIMA differences were comparatively small and inconsistent across horizons.

Monthly iterative retraining did not consistently improve forecast performance

Updating forecasting models as new observations become available may improve performance by incorporating recent epidemic dynamics, but frequent retraining incurs significant additional computational cost. We therefore compared the initial training regime, in which models were fitted once using data from January 2010 to December 2019, with monthly iterative retraining. For computational tractability, this secondary analysis was restricted to municipality-level experiments in Ceará and São Paulo. TimesFM was excluded because its pretrained model parameters were not fitted or fine-tuned to the study data, making iterative retraining inapplicable. SARIMA showed little difference between training strategies in either state, whereas XGBoost consistently favoured initial training across all horizons in both states (Supplementary Table S9). TCN similarly favoured initial training across all horizons in Ceará. A valid N-BEATS retraining comparison could not be made in either state due to numerical instability. Overall, monthly retraining provided no consistent performance advantage among the models and settings for which valid comparisons were available.

AI-guided model development independently selects PDFM embeddings for dengue forecasting

In ERA model development, we used data available through August 2023 and optimised mean WIS across 1-, 3-, 6-and 12-month forecast horizons. The resulting ERA-derived forecasting model was then frozen and evaluated across all Brazilian municipalities during an independent hold-out period from September 2023 to August 2025 (Methods). The ERA-derived model did not consistently outperform the primary forecasting models across horizons (Supplementary Table S10). However, ERA independently selected temporal epidemic dynamics, spatial propagation, climatic information and PDFM embeddings in its final forecasting model (Supplementary Table S11). The selection of PDFM embeddings through this independent model-development process provides additional evidence that their predictive contribution is not specific to the residualadjustment approach used in the primary analyses.

Discussion

Our findings demonstrate how pretrained temporal and spatial representations can contribute to probabilistic infectious disease forecasting, while highlighting the importance of forecasting architecture and modelling configuration in determining their predictive value. Across Brazil, the relative performance of the five architectures evaluated depended strongly on forecast horizon, while the benefits of PDFM residual adjustment varied according to the underlying model and epidemiological setting. These findings extend previous dengue forecasting research demonstrating substantial variation in predictive performance across models, locations and epidemic seasons (12) (13) (14) (15), and suggest that the value of pretrained representations depends not only on the information they encode but also on how that information is incorporated into forecasting systems.

The comparatively stable performance of TimesFM at longer horizons is particularly relevant given the challenges of forecasting dengue dynamics beyond the short term (12, 15). Whereas most architectures evaluated showed deteriorating probabilistic performance with increasing horizon, TimesFM maintained relatively stable WIS across 3-, 6-and 12-month forecasts. One possible explanation is that large-scale temporal pretraining enables the model to exploit patterns learned across diverse time series, potentially supporting generalisation beyond the historical dynamics represented in the Brazilian dengue training data. However, this mechanism cannot be established from the present comparisons, and the observed advantage may also reflect differences in model architecture, probabilistic forecast construction or the configurations evaluated. TimesFM's performance should therefore be interpreted as evidence for the potential utility of temporal pretraining, rather than demonstrating its superiority over other dengue forecasting approaches.

The potential value of maintaining forecasting performance at seasonal to annual timescales is particularly apparent in the context of dengue's geographical expansion. The record 2024 epidemics in Brazil and across the Americas, coinciding with El Niño-associated temperature anomalies and expansion into previously less-affected regions (4), highlight the challenges of anticipating changing epidemic dynamics. Reliable longer-horizon forecasts could support earlier public health preparedness, including advance allocation of resources and planning of vectorcontrol and healthcare responses. However, their operational value will depend on performance under changing epidemiological conditions and the availability of timely surveillance data.

The model-dependent benefits of PDFM adjustment suggest that pretrained spatial representations can provide predictive information beyond historical dengue cases and conventional covariates, although their utility depends on the forecasting architecture and the errors remaining in its predictions. PDFM embeddings capture aspects of population activity, connectivity, the built environment and environmental context that may not be fully represented by conventional predictors. However, larger improvements following adjustment do not necessarily indicate that these representations contain more useful information for a particular model or setting. Our WIS decomposition showed that improvements arose primarily through reductions in out-of-interval penalties, suggesting that PDFM adjustment may be particularly valuable when baseline predictive distributions fail to capture observed epidemic outcomes. The geographical analyses further demonstrated that regional differences in absolute WIS improvements were sometimes attenuated when evaluated using log-relative skill, consistent with a contribution from the magnitude and distribution of baseline forecast errors to the apparent heterogeneity. This interpretation is consistent with the greater improvements observed at higher reported dengue case counts, where forecast errors may also be larger. Together, these findings suggest that PDFM adjustment benefits depend on the interaction between contextual information, forecasting architecture and residualerror structure, although the specific mechanisms and embedding components responsible remain unresolved.

Geographical variation in baseline forecasting performance was also evident, particularly in southern Brazil. Although TCN achieved the lowest mean one-month WIS across all five macroregions, its advantage over TimesFM was substantially weaker in Rio Grande do Sul and Santa Catarina than elsewhere. This raises the possibility that pretrained temporal representations may be comparatively useful where epidemic dynamics differ from historical patterns, although our exploratory analyses of historical dengue activity and changes in reported cases and population-adjusted incidence did not establish a consistent association with relative model performance. Geographical differences were also apparent in PDFM adjustment benefits, particularly for N-BEATS and XGBoost, suggesting that the contribution of residual adjustment varies across epidemiological settings as well as forecasting architectures. Together, these findings reinforce the importance of evaluating forecasting approaches across diverse geographical and epidemiological conditions (15).

The model-dependent effects of covariate selection and spatial fitting suggest that forecasting architecture and modelling configuration should be considered jointly rather than as independent choices. Additional covariates may improve performance when an architecture can exploit their predictive information, but may provide little benefit or introduce unnecessary complexity when historical epidemic dynamics already capture much of the relevant variation. Similarly, joint fitting across municipalities may allow models to exploit shared temporal patterns, whereas independent fitting may better preserve locally specific dynamics. Our results indicate that neither approach is consistently preferable across the architectures evaluated, highlighting the importance of assessing configuration choices within individual forecasting systems rather than assuming that greater model complexity or information sharing necessarily improves performance. The comparison of state-level forecast aggregation strategies further demonstrates that the preferred approach depends on the forecasting architecture and horizon.

Together, these findings highlight substantial variation in forecasting performance across the models, horizons and modelling configurations evaluated, arguing against a single optimal strategy. Our comparisons contribute to existing evidence on dengue forecasting in Brazil by informing choices concerning forecasting architecture, horizon, covariate selection, spatial fitting and forecast aggregation (Supplementary Table S12). The observed heterogeneity motivates exploring ensemble approaches that combine forecasts from different models or configurations, potentially exploiting complementary strengths across epidemiological settings and forecast horizons. Evaluating whether such combinations improve predictive performance, and how their contributions should be weighted across locations and horizons, represents an important direction for future research.

The absence of consistent benefits from monthly retraining highlights a potential trade-off between incorporating recent epidemiological information and maintaining stable forecasting performance. Although frequent updating may allow models to respond to changing epidemic dynamics, it may also introduce variability in fitted parameters without improving predictive accuracy, particularly when recent observations reflect short-term fluctuations rather than persistent changes in transmission. The numerical instability encountered with N-BEATS further illustrates that computational and implementation considerations can influence the feasibility of frequent model updating. These findings suggest that retraining frequency should be evaluated as a model-specific design choice, balancing potential improvements in responsiveness against forecast accuracy, computational cost and numerical stability. However, because our experiments compared only initial training with monthly retraining in Ceará and São Paulo, they do not establish whether alternative updating schedules or adaptation strategies would improve performance.

The ERA experiment provides an independent perspective on the predictive value of PDFM embeddings. Unlike the primary analyses, which incorporated PDFM through post-hoc residual adjustment, ERA independently selected embedding dimensions to parameterise municipalityspecific characteristics of its forecasting model, including climate sensitivities and forecast uncertainty. This suggests that PDFM-derived information may contribute to dengue forecasting through modelling approaches beyond residual correction, although neither approach identifies which components of the multimodal representation are responsible for the predictive signal. The ERA-derived model did not consistently outperform the primary architectures over the hold-out period, but its independent selection of PDFM embeddings provides further support for their contribution to dengue forecasting.

More broadly, our findings illustrate three distinct roles for AI in infectious-disease forecasting. Time-series foundation models such as TimesFM can transfer representations learned through large-scale temporal pretraining, potentially supporting forecasting across longer horizons. Geospatial foundation models such as PDFM can provide representations of human and environmental context that augment disease-specific forecasting models, although their benefits depend on the underlying architecture and how these representations are incorporated. AI-guided model development offers a third approach, identifying and combining predictive information within models developed for a particular task. These approaches are not necessarily interchangeable, and their relative value will depend on the forecasting objective, available information and modelling framework. Together, they demonstrate different ways in which AI can contribute to epidemic forecasting, while highlighting the need to evaluate their benefits within specific epidemiological and operational settings.

The variation in forecasting performance across architectures, horizons and modelling configurations highlights the need for flexible, reproducible frameworks that support systematic comparison of forecasting approaches. The modular Thucia framework (Methods) used in this study was designed to facilitate such comparisons by separating data acquisition, model fitting, probabilistic forecasting, residual adjustment and evaluation into interchangeable components. This flexibility is particularly relevant when forecasting objectives, data availability and operational requirements differ across geographical settings or change over time. More broadly, our findings reinforce the importance of benchmarks that evaluate forecasting approaches across different epidemiological contexts, spatial scales and modelling configurations, rather than relying on performance under a single experimental setting. Such evaluations could help inform model selection and adaptation for operational forecasting, while establishing whether the contextdependent patterns observed in Brazil generalise to other pathogens, geographical settings and surveillance systems.

Limitations and future directions

We acknowledge several limitations. First, our primary analysis is restricted to Brazil; although this provides a stringent test across diverse epidemiological and climatic settings, generalisability to other countries, pathogens and surveillance systems requires further evaluation. Second, although we examined correlations among PDFM embedding dimensions and their associations with external spatial characteristics, we did not isolate the contributions of individual embedding components to forecasting performance. The latent nature of these representations limits mechanistic interpretation, and further component-specific analyses would be needed to establish which behavioural, built-environment or environmental characteristics drive the observed improvements. Third, the forecasting architectures were selected to represent distinct modelling paradigms rather than to provide an exhaustive benchmark of dengue forecasting methods. Modelling configurations and hyperparameters were selected pragmatically rather than through exhaustive optimisation, and alternative choices could alter the relative performance of individual models. Comparisons with additional dengue-specific statistical models and established ensemble approaches would help establish whether the benefits of pretrained representations generalise to other forecasting systems. The comparison of independent municipality-level and joint stategrouped fitting was also restricted to 20 municipalities with high cumulative reported dengue case counts, limiting the extent to which these configuration-specific findings can be generalised across Brazil. Direct comparison with recent initiatives such as IMDC24 is further complicated by differences in surveillance outcomes, spatial and temporal resolution, forecast origins and evaluation protocols. In particular, IMDC24 evaluated weekly forecasts of probable dengue cases at state level over epidemiological seasons, whereas our study evaluates monthly forecasts of notified cases at municipality level across fixed forecast horizons. A further limitation concerns the potential overlap between TimesFM's pretraining data and the data used in this study. Although TimesFM was applied without task-specific parameter fine-tuning, potential overlap between the study data and its pretraining corpus cannot be completely ruled out because the composition of the pretraining data is not exhaustively identifiable at the individual-series level. Fourth, the retraining analysis was restricted to monthly updating in Ceará and São Paulo, and a valid comparison could not be made for N-BEATS because of numerical instability. Finally, all primary analyses were retrospective and depended on the quality and completeness of the underlying surveillance data. Historical reporting vintages were not reconstructed, and forecasts were generated and evaluated using a frozen retrospective InfoDengue extraction in which historical case counts may incorporate revisions made after the corresponding forecast origin. The evaluation also encompassed the COVID-19 pandemic and subsequent large dengue epidemics, during which epidemiological and surveillance changes may have affected relationships learned from historical data. Furthermore, historical PDFM embeddings aligned to individual forecast origins were unavailable, and a single October 2023 snapshot was used throughout the evaluation period. These limitations mean that the findings should be interpreted as retrospective evidence rather than established operational forecasting performance.

Conclusion

In conclusion, our findings demonstrate the potential of pretrained temporal and spatial representations to strengthen probabilistic dengue forecasting in Brazil. Among the five architectures evaluated, TimesFM maintained stronger relative performance at longer forecast horizons, while PDFM-derived spatial representations provided additional predictive information for several models through residual adjustment. However, these benefits depended on forecasting architecture, horizon and geographical setting, with modelling configuration further influencing predictive performance. Together, these findings highlight the importance of evaluating forecasting approaches across different epidemiological and operational contexts, rather than assuming that any single architecture or configuration will perform consistently best. Integrating pretrained representations into dengue forecasting systems therefore offers opportunities to improve predictive performance, but their practical value will require further validation under operational forecasting conditions.

Materials & Methods

Epidemiological data

Municipality-level dengue case data were obtained from the InfoDengue application programming interface (API) (26) for January 2010 to August 2025. Data were extracted on 10 November 2025 using Brazilian Institute of Geography and Statistics (IBGE) municipality codes. We used notified dengue cases (casos), rather than probable dengue cases or InfoDengue nowcast estimates. Weekly reported cases were assigned to the calendar month containing the start of the corresponding epidemiological week and summed to obtain monthly reported case counts, with monthly totals comprising four or five epidemiological weeks. This aggregation was applied consistently across all forecasting models. Municipalities were subsequently aligned to Global Administrative Areas Database (GADM; 27) administrative level-2 regions, and the resulting dataset was frozen for all analyses. Historical reporting vintages were not reconstructed, so case counts reflect the values available at extraction rather than necessarily those available at each forecast origin.

Forecast training and evaluation

SARIMA, TCN, XGBoost and N-BEATS were fitted once using data from January 2010 through December 2019, after which the fitted models were held fixed while generating forecasts at 1-, 3-, 6-and 12-month horizons. Before model fitting, spatial units with no reported dengue cases during the January 2010-December 2019 training period were excluded from the fitting dataset. Forecast evaluation was defined by target month, with a common evaluation window of January 2020-August 2025 at each horizon. Consequently, for early target months at longer horizons, the nominal forecast origin precedes the December 2019 model-fitting cutoff; these forecasts should therefore be interpreted as horizon-specific retrospective predictions from models fitted to a fixed training period, rather than strictly prospective forecasts using only information available at the nominal forecast origin. TimesFM was applied without fitting or fine-tuning its pretrained model parameters to the study data. Forecasts targeting months after August 2025 were excluded from evaluation because corresponding observed outcomes were unavailable.

Covariate data

Modelling framework

We conducted all analyses using Thucia (https://github.com/kraemer-lab/Thucia), a modular opensource forecasting framework developed to standardise the acquisition, aggregation, modelling and evaluation of epidemiological data across spatial and temporal scales. Thucia separates data engineering, model fitting, probabilistic forecasting, residual adjustment and evaluation into interchangeable components, allowing different models and modelling strategies to be evaluated within a consistent experimental workflow. In the present analysis, Thucia was used to implement the five forecasting models and the different covariate, spatial fitting, aggregation and retraining configurations described below.

We selected five forecasting models spanning distinct statistical, machine-learning, deep-learning and foundation-model paradigms. SARIMA provides a conventional statistical approach to modelling autoregressive and seasonal dynamics. TCN and N-BEATS provide complementary deep-learning architectures for modelling temporal dependencies (35, 36), while XGBoost represents flexible nonlinear machine learning using lagged reported dengue case counts and environmental covariates (37). TimesFM allows us to evaluate the potential benefits of large-scale time-series pretraining (21). This selection was intended to assess whether the predictive contribution of PDFM embeddings generalises across different forecasting architectures, rather than to exhaustively benchmark all available dengue forecasting methods. We evaluated forecasts at monthly resolution to assess predictive performance across seasonal to annual horizons relevant to public health preparedness, while maintaining a consistent temporal resolution across forecasting architectures. Forecasts were evaluated at 1-, 3-, 6-and 12-month horizons (see Forecast training and evaluation). Where supported by the model, multi-step forecasts were generated jointly over the corresponding horizon rather than by recursively feeding one-monthahead predictions back into the model. Forecast horizons denote complete calendar-month lead times between the nominal forecast origin and target month. For example, a July 2024 target evaluated at the three-month horizon represents incident cases during July 2024 at a nominal threemonth forecast lead.

In the primary analysis, municipality-level time series were grouped by state. TCN, N-BEATS and XGBoost were fitted jointly across municipalities within each state, allowing model parameters to be shared across local time series. SARIMA was fitted independently to each municipality, reflecting its implementation as a univariate statistical model, while TimesFM generated forecasts from individual municipality-level histories using pretrained model parameters without taskspecific fine-tuning. These approaches reflect differences in how the forecasting architectures accommodate multiple time series, rather than an attempt to optimise the spatial fitting strategy separately for each model.

Model hyperparameter tuning was intentionally limited to evaluate established forecasting architectures under computationally feasible configurations, rather than optimising each model exhaustively for the study setting. Where choices were required, study-specified settings were selected pragmatically based on established time-series modelling practice, computational tractability and exploratory runs on training-period data using the 645 municipalities of São Paulo state. For example, neural and tree-based models used 48 months of historical input, while SARIMA used a 12-month seasonal period; SARIMA model orders were otherwise selected automatically using AutoARIMA. These settings were subsequently held fixed in the primary Brazil-wide analyses rather than optimised separately by municipality or against the evaluation period. Several broader modelling choices, including covariate specification, independent municipality-level versus joint state-grouped fitting, spatial aggregation and retraining, were evaluated explicitly as configuration analyses rather than selected through hyperparameter optimisation. Table 2 reports both study-specified settings and fixed or automatically determined properties of the model implementations.

Covariate time series were scaled by their mean absolute value calculated over the training period to maintain comparable magnitudes and improve numerical stability. For the primary forecasting analyses, case counts were transformed as log(1 + cases) for model fitting and WIS evaluation. SARIMA, TCN, N-BEATS and XGBoost were implemented using the Darts time-series forecasting library (38), with XGBoost accessed through the corresponding Darts forecasting interface.

Forecast modelling configuration analyses

We conducted three analyses to assess how modelling configuration influenced forecast performance. First, we compared the full covariate specification with the minimal covariate set comprising log(1 + cases) at lag 1, the mean of minimum temperature over lags 1-2, and the mean of precipitation over lags 1-2 (Table 1). Second, for the 20 municipalities with the highest cumulative reported dengue case counts over the study period, we compared municipality-level forecasts from models fitted independently to each municipality with forecasts for the same municipalities from models fitted jointly across municipalities within each state. Third, we compared two approaches to generating state-level forecasts across all 27 Brazilian states: fitting models directly to state-level aggregated case series and aggregating municipality-level probabilistic forecasts after model fitting.

For the state-level forecast-aggregation analysis, municipality-level predictive distributions were combined using Monte Carlo simulation because quantiles of municipality-level forecasts cannot be directly summed to obtain quantiles of the state-level predictive distribution. For each municipality, a predictive distribution was approximated by interpolation between forecast quantiles. Joint draws from municipality-level distributions were generated using a Gaussian copula with a fixed dependence parameter of ρ = 0.3, selected pragmatically to represent moderate positive dependence between municipality-level forecasts without assuming either independence or strong spatial dependence. Simulated municipality-level case counts were summed within each state, and quantiles of the resulting simulated state-level distribution were used as the aggregated probabilistic forecast. Observed state-level case counts were obtained by summing reported municipality-level cases.

For each of the three modelling-configuration comparisons, forecasts were paired by spatial unit, target month and forecast horizon. Differences in WIS were calculated between paired configurations and averaged across the January 2020-August 2025 target-month evaluation period within each spatial unit. The resulting municipality-or state-level mean differences were summarised by their mean, median and interquartile range. Two-sided Wilcoxon signed-rank tests were applied to the paired spatial-unit summaries where inferential comparisons were reported. Thus, the inferential unit for these analyses was the municipality or state after averaging forecastperformance differences through time.

As a separate secondary analysis, we evaluated monthly iterative retraining in municipality-level experiments in Ceará and São Paulo. Under the initial training regime, each model was fitted once using data from January 2010 to December 2019 and was not subsequently retrained during the evaluation period. Under monthly retraining, models were refitted at each monthly forecast interval using an expanding training window, retaining the original January 2010 start date and incorporating all observations available up to the corresponding forecast origin. WIS was averaged across the January 2020-August 2025 target-month evaluation period within each municipality, and paired municipality-level means were compared using two-sided Wilcoxon signed-rank tests.

Retraining comparisons were reported only for model-state combinations for which usable paired forecasts were available; numerical failures were recorded separately. TimesFM was excluded because its pretrained model parameters were not fitted or fine-tuned to the study data, making iterative retraining inapplicable.

Model evaluations

Models were evaluated primarily using the Weighted Interval Score (WIS), a proper scoring rule for probabilistic forecasts (40) that assesses predictive calibration and sharpness. WIS was calculated on the log(1 + cases) scale to reduce the influence of differences in absolute reported case counts across municipalities and time. Lower WIS values indicate better probabilistic forecast performance. The coefficient of determination (R²) was used as a complementary measure of agreement between point predictions and observed reported case counts.

For the analysis in Figure 2C, we constructed a seasonal reference forecast separately for each municipality and calendar month using only observations from the January 2010-December 2019 training period. For each municipality-calendar-month combination, the seasonal reference forecast was defined as the mean log(1 + cases) across the corresponding calendar month in the training years. This value was used for all predictive quantiles, yielding a degenerate predictive distribution centred on the historical seasonal mean, and was held fixed throughout the January 2020-August 2025 evaluation period. The baseline was scored using the same quantile grid and WIS implementation as the forecasting models. For each matched municipality and target month, model skill relative to the seasonal baseline was calculated as log(1 + WISseasonal) -log(1 + WISmodel), such that positive values indicate lower WIS, and therefore better probabilistic forecast performance, for the forecasting model.

To characterise how PDFM adjustment affected probabilistic forecast performance, we separated the constituent WIS terms (40) into contributions from median forecast error, predictive-interval width and out-of-interval penalties. For each paired PDFM-adjusted and base forecast, the change in each component was calculated as the PDFM-adjusted contribution minus the corresponding base-forecast contribution, such that negative values indicate an improvement. Component-wise differences were then averaged across municipality-month forecasts; their sum equals the total mean ΔWIS.

To examine whether the effect of PDFM adjustment varied with observed dengue case counts, municipality-month forecasts were stratified retrospectively according to the number of reported cases in the forecast target month. Observations with zero reported cases formed a separate stratum. Within each target month and model-horizon combination, observations with positive reported case counts were divided into low, moderate and high strata using the 33rd and 67th percentiles of their case-count distribution. For each stratum, we calculated the proportion of paired forecasts for which PDFM adjustment reduced WIS (ΔWIS < 0). To quantify the magnitude of these effects, mean ΔWIS was calculated within each stratum and target month, then averaged equally across target months. High-minus-low contrasts were calculated as paired differences between monthly mean ΔWIS values in the highest and lowest positive case-count strata. Uncertainty was estimated using a temporal moving-block bootstrap with three-month blocks and 2,000 replicates, with sensitivity analyses using six-and twelve-month blocks. These stratified analyses were exploratory, and confidence intervals were not adjusted for multiple comparisons.

For comparisons involving PDFM residual adjustment, mean differences in WIS were evaluated using a temporal moving-block bootstrap (41) to account for chronological dependence. For each model and forecast horizon, ΔWIS was first averaged across municipalities within each target month to form a chronological sequence, from which contiguous blocks of three months were resampled with replacement. The 95% confidence interval was defined by the 2.5th and 97.5th percentiles of 2,000 bootstrap replicates. Sensitivity analyses used block lengths of 6 and 12 months. As a complementary test of predictive accuracy, we applied two-sided Diebold-Mariano tests (42, 43) to chronological target-month sequences of mean WIS, obtained by averaging WIS across municipalities within each target month. The dependence parameter was set to the forecast horizon, with a Bartlett variance estimator and Harvey small-sample correction. To account for multiple testing across the 20 model-horizon comparisons, statistical significance was assessed using a Bonferroni-adjusted threshold of α = 0.0025 (0.05/20).

SARIMA produced occasional extreme predictions in a small number of municipalities, particularly at longer forecast horizons. Across the evaluation period, the forecast median exceeded one million cases in 13 of 1,515,584 municipality-month-horizon forecasts (<0.001%): none at the 1-month horizon, one at 3 months, three at 6 months, and nine at 12 months.

These finite extreme forecasts were retained in the quantitative WIS evaluation to avoid artificially improving estimated forecast performance, but were excluded from selected visualisations where their magnitude would otherwise obscure the displayed forecast trajectories.

AI-guided model development

As a complementary analysis, we used Google's Empirical Research Assistance (ERA) to develop a probabilistic dengue forecasting model across all Brazilian municipalities. ERA was provided with historical reported dengue case counts, climatic and ecological covariates, municipality-level spatial adjacency and static PDFM embeddings, and was tasked with minimising mean Weighted Interval Score (WIS) across 1-, 3-, 6-and 12-month forecast horizons. Model development preserved temporal ordering of the epidemiological observations, such that forecasts at each origin used only observations assigned to that date or earlier; the static PDFM embeddings were fixed across forecast origins as described above. Model development and optimisation used target observations through August 2023. The resulting forecasting function was then frozen and evaluated against the September 2023-August 2025 hold-out period, which was not used during model development or optimisation.

The final ERA-derived model used municipality-and month-specific historical reported case counts to define seasonal baselines, adjusted according to recent deviations from local seasonal patterns. Recent epidemic momentum was partially propagated between neighbouring municipalities through the spatial adjacency network and progressively damped with increasing forecast horizon. Climatic information was incorporated through the Oceanic Niño Index (ONI) and six-month Standardized Precipitation Index (SPI-6). Selected dimensions of the static PDFM embeddings parameterised municipality-specific climate sensitivities, baseline dispersion and forecast volatility (Supplementary Table S11). Expected case counts were converted to probabilistic forecasts using Negative Binomial distributions, with dispersion varying by municipality and forecast horizon. Quantile forecasts were generated at each of the four horizons and evaluated using WIS over the independent hold-out period.
